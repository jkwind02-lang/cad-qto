# 构件计算清单格式

`scripts/calculate_concrete_formwork_pairs.py` 接受 UTF-8 JSON 清单。它只复算清单已经明确选择的来源、尺寸和接触面，不识别构件类别，不推断图层语义，不决定清单标准。

## 顶层字段

```json
{
  "manifest_version": "qto-concrete-formwork-manifest/2.0",
  "case_id": "稳定案例编号",
  "object": {"id": "主体编号", "name": "主体名称", "blinding_id": "垫层编号", "blinding_name": "垫层名称"},
  "scope": {"project": "项目", "building": "楼栋", "area": "区域"},
  "source": {
    "dwg_path": "冻结来源绝对路径",
    "dwg_sha256": "64位哈希",
    "entity_stream_path": "原生实体流绝对路径",
    "entity_stream_sha256": "64位哈希",
    "metadata_path": "缓存元数据绝对路径",
    "metadata_sha256": "64位哈希",
    "source_unit": "Millimeters",
    "expected_adapter": "经确认的原生适配器",
    "expected_schema_version": "缓存结构版本",
    "expected_unit_status": "单位状态",
    "expected_unit_basis": "单位确认依据",
    "expected_row_count": 1,
    "expected_entity_count": 1
  },
  "evidence_entities": [],
  "calculation": {},
  "project_rule_gate": {}
}
```

路径必须指向原始/中性证据。清单若引用旧 Skill、旧归档、旧项目计算脚本、旧结果或旧验证文件，脚本拒绝运行。

## 证据实体

每项至少包含 `handle`、`entity_type` 和要核验的事实。支持：

- 尺寸：`expected_measurement_mm` 为实体流预期原始测量，`adopted_mm` 为图面标注采用值，二者差异必须在 `tolerance_mm` 内；
- 文字：`text_contains`，用于厚度、外扩或图名等直接说明；
- 轮廓：`closed`、`candidate_physical_id`、`layer`，用于唯一对象与几何交叉检查。

脚本要求每个 handle 在实体流中唯一，并核对行内 `source_sha256`。尺寸采用标注值时，清单必须说明显示精度或采用依据；不能借容差把任意量图值改成目标值。

## 当前确定性计算类型

当前源实体计算器只支持 `orthogonal_notched_raft_with_blinding`，字段包括：

- 由证据句柄映射的主体长、主体宽、四边外伸、角缺口长宽；
- 筏板厚度、垫层厚度和垫层外扩；
- 轮廓句柄及文字说明句柄；
- `template_conditions` 必须按限定面分别声明：筏板外侧成型方式、筏板底面局部拓扑、筏板顶面是否敞开、垫层侧面是否支模；
- 四个面键为 `raft_exterior_side`、`raft_bottom`、`raft_top`、`blinding_side`。每面提供 `{state, evidence_handles, reason}`：`included` 按该面几何计算，`excluded` 输出有依据的零，`unresolved` 保留几何候选和未决。纳入或排除还必须有 `coverage: complete`；引用实体须在本次证据流中。面条件由模型依当前图纸识别，程序核对引用并执行，不预设某个面一定支模或一定未决。

计算式：

```text
L = 主体长 + 左外伸 + 右外伸
W = 主体宽 + 上外伸 + 下外伸
A = L×W - 角缺口长×角缺口宽
P = L + W + (L-缺口长) + 缺口宽 + 缺口长 + (W-缺口宽)
V筏板毛 = A×筏板厚
A垫层 = A + P×外扩 + 4×外扩²
P垫层 = P + 8×外扩
V垫层毛 = A垫层×垫层厚
```

程序核对轮廓必须与尺寸链对应的单角缺口矩形一致（允许四个角及长宽方向交换），且无自交；不能把任意同面积/周长多边形套用此公式。输入中每个尺寸仍须大于零，来源为毫米。其他实体、单位和局部净量不能靠此特定计算类型包办。

## 规则与版本边界

`project_rule_gate` 如有则原样保留在证据中，不强制某个项目状态。此计算器输出物理名义毛量与面条件量，不自动输出合同清单净量。局部洞口、下沉和材料适用须由独立对象链处理；不能把名义毛量当完整净量。

2.0取消旧1.0内嵌的项目名称、尺寸、实体句柄、固定答案和特定未决状态。旧输入需补 `object` 并按原图将四个面迁移为结构化条件，不直接沿用旧案例结论；旧项目结果和案例断言在测试历史保留，运行时不加载。验证器依据本次清单重读源文件复算，比较成果、证据和明细，不比对某个案例预设总数。

## 输出

脚本生成：

1. 计算证据 JSON：来源身份、对象证据、坐标几何交叉值、标注尺寸法、条件值和未决项；
2. 构件明细 CSV：每一步公式、输入、原始值、单位和状态；
3. `qto-result-minimum/1.0` 试运行成果 JSON：主体和垫层名义毛体积、四个面的模板值/有据零/未决及其源证据。

脚本不会回写项目目录或旧成果；输出路径必须由调用者显式指定。
