# 结果检查与输出

## 输出层次

1. **对象明细**：构件、几何、尺寸、面片、洞口、相交、毛量、扣减、补回和来源；
2. **工程量结果**：按物理/清单口径及 `m³`/`m²` 分列；
3. **未决事项**：影响对象、当前处理和所需输入；
4. **复核摘要**：范围覆盖、规则状态、结构验证、专业验证和限制。

## 形成成果前的专业检查

- 每个构件编号唯一，同一几何签名同时回链混凝土与模板；
- 原始文件、实体流、行内来源哈希和单位一致；
- 图示尺寸与坐标几何差异已解释，采用依据明确；
- 混凝土毛量、扣减、补回和净量能逐项复算；
- 模板逐面说明接触对象，普通、永久和条件量分列；
- 洞口物理/清单体积和模板主面/洞侧四链分开；
- 相交体和重叠面有唯一归属及防重复键；
- 柱、墙、梁、板、楼梯没有沿用旧合并分类或旧水平投影算法；
- 不同材料、构件、口径和单位没有静默合并；
- `null`、部分结果和真零符合公共状态不变量。

## 命名与状态

- 净量未闭合时使用“名义毛体积”“若支模候选面”“已确认部分”等限定名称，不使用“总量、合计、完整、全部、全量”。候选面不进入工程量采用汇总。
- 数值为 `null` 时状态只能是待确认/证据不足/不适用，并关联未决事项。
- 部分结果必须有数字、来源和至少一个影响完整性的未决项。
- 真零必须有结构化零值复核；“未发现”“没资料”“暂未计算”不是零。
- 条件候选值只放专业检查或证据中，正式工程量数值保持 `null`。

## 脚本验证

```powershell
python scripts/calculate_concrete_formwork_pairs.py --manifest <清单.json> --evidence-out <证据.json> --detail-csv <明细.csv> --result-out <成果.json>
python ../_qto-shared-evidence/scripts/validate_minimum_result.py <成果.json>
python scripts/validate_concrete_formwork_result.py <成果.json> --evidence <证据.json> --detail-csv <明细.csv> --manifest <清单.json>
python scripts/validate_concrete_formwork_result.py --self-test
```

失败时不修改成果来迎合旧数值。先判断是来源漂移、尺寸冲突、规则不适用、对象重复、公式错误还是未决状态表达错误；只有新证据闭合后才更新相应部分。

## 成熟度结论

结构和脚本通过只证明可执行性；真实项目前向、独立复核、触发边界、旧资产隔离和专业失败风险都通过后，规则才可从候选提升到试运行。当前 Skill 仍为候选，正式安装属于后续阶段。

否定结论（“图上无”“未见”“不存在”等）是否都附检索记录，反向核对是否写明覆盖的图纸集合并覆盖所有可能含该类对象的图；没有检索记录的否定结论报待确认，不作为不计或判定清单有误的依据。格式见公共[通用成果字段与状态](../../_qto-shared-evidence/references/通用成果字段与状态.md)“否定结论与检索证据”。
