# 材料基层矩形分区

本入口用于同一母面、同一局部框架下，已经由原图和做法解释的材料矩形分区。使用既有 `calculate_surfaces_envelope.py`，方法为 `material_partition_net`。它计算物理面积，材料语义、基层归属和施工层适用性仍须有项目证据。混凝土基层区域不能伪装成洞口；面积合计闭合不能证明材料判断正确。

## 数量项入口

沿用表面清单的来源、证据、规则、物理表面、层、侧别、状态和未决契约。新方法只输出 `unit: m²`、`quantity_role: physical_area`。每个材料及正面积未知区域各有一个数量出口：

```json
{
  "method": "material_partition_net",
  "inputs": {
    "partition_evidence_ref": "EV-PARTITION",
    "source_pointer": "/partitions/face-1-substrate",
    "output_kind": "material",
    "material_id": "CONCRETE"
  },
  "frame_binding": {
    "frame_evidence_ref": "EV-FRAME",
    "source_pointer": "/partitions/face-1-substrate/local_coordinate_frame",
    "edge_evidence_ref": "EV-EDGE",
    "edge_source_pointer": "/edges/edge-1"
  }
}
```

未知出口使用 `output_kind: unknown`，不带 `material_id`。`inputs` 不接受预计算面积、直接矩形或补差答案。所有正面积材料和未知出口必须齐全，不能只交已知材料而省略未知区；正面积未知存在时，全组保留 `scope_status: partial` 和未决引用，未知出口只能是 `reference`。默认按完整母面分区；仅量明确条带等有限区域时，使用下文有源 `selected_regions` 模式，不把本项范围外背景伪称未知设计。

`local_coordinate_frame` 仍为[表面与构造层清单格式](表面与构造层清单格式.md)中的九字段规范框架，数量项必须完整声明，并与分区源对象内的同名字段绑定。框架证据和分区证据必须引用同一个 JSON 来源；框架 Pointer 固定为分区 Pointer 加 `/local_coordinate_frame`。源边可以来自另一条明确证据和来源。程序独立核对原点、正反向、有限源边区间及长高，材料矩形不会绕过坐标校验。

## 源事实对象

示例来源文件已登记为 `file_role: json`、`source_role: calculation_evidence` 并核验 SHA。下列参数仅用于演示通用契约：

```json
{
  "edges": {
    "edge-1": {"edge_id": "edge-1", "coordinate_system_id": "LOCAL-1", "start": [0,0,0], "end": [6,0,0], "unit": "m"}
  },
  "partitions": {
    "face-1-substrate": {
      "partition_id": "PART-1",
      "parent_surface_id": "FACE-1",
      "layer_scope_id": "VISIBLE-SUBSTRATE",
      "scenario": {"scenario_id": "DESIGN-1", "status": "determined", "condition": "本范围已解释的材料事实，专业适用性见证据"},
      "local_coordinate_frame": {
        "coordinate_system_id": "LOCAL-1", "origin_m": [0,0,0],
        "x_axis": [1,0,0], "up_axis": [0,0,1],
        "source_edge_id": "edge-1", "source_edge_direction": "same",
        "source_edge_interval_m": [0,6], "vertical_range_m": [0,3], "vertical_origin_m": 0
      },
      "face": {
        "region_id": "FACE-RECT-1", "physical_object_id": "FACE-1",
        "rectangle": [0,0,6,3], "unit": "m", "source_evidence_ref": "EV-FACE"
      },
      "actual_openings": [
        {"opening_id": "DOOR-1", "physical_object_id": "DOOR-1", "rectangle": [2,0,3,2], "unit": "m", "source_evidence_ref": "EV-DOOR"}
      ],
      "material_regions": [
        {"region_id": "COLUMN-BAND-1", "physical_object_id": "COLUMN-1", "material_id": "CONCRETE", "rectangle": [0,0,1,3], "unit": "m", "source_evidence_ref": "EV-COLUMN"}
      ],
      "unknown_regions": [
        {"region_id": "UNKNOWN-1", "physical_object_id": "SILL-1", "reason": "该局部带材料未明确", "rectangle": [4,0,5,0.2], "unit": "m", "source_evidence_ref": "EV-SILL"}
      ],
      "base_material": {
        "material_id": "AAC", "physical_object_id": "BASE-WALL-1",
        "basis": "来源明确声明除列明区域外的基层为AAC；适用范围见原条款", "source_evidence_ref": "EV-BASE"
      }
    }
  }
}
```

`actual_openings`、`material_regions`、`unknown_regions` 必须显式给数组；无适用对象时给 `[]`。`base_material` 必须显式为有源对象或 `null`，没有该字段不能被解释为默认基层。方案必须有 `scenario_id`、`status` 和 `condition`；`status: conditional` 只能形成参考方案量，不得进入采用量。

各矩形为 `[x_min,z_min,x_max,z_max]`，坐标位于所绑定局部框架的基准 `origin_m`，横轴沿 `x_axis`、竖轴沿 `up_axis`。它们不是相对已经加过竖向偏移的 `surface_origin_m`，避免重复平移。母面必须对应 `[0,zlo,源边有效区间长度,zhi]`。各记录可以使用不同明确物理长度单位，统一换算为米；不接受像素、零宽高、布尔值或非有限值。

母面内记录继承其共同框架、层范围和方案。若记录额外给出 `parent_surface_id`、`layer_scope_id`、`scenario_id` 或 `coordinate_system_id`，其值必须与母面一致，不能把其他墙面、层或方案悄悄拼入。材料/未知记录的 `region_id` 在分区内唯一；真实洞口的 `opening_id` 唯一。物理对象可以由多个有源区域表达，但来源身份和各局部范围应保留。

分区证据为本项的 `surface_geometry`，`object_keys` 包含 `parent_surface_id` 和当前数量项的 `physical_surface_id`。每条记录的 `source_evidence_ref` 也须在本项 `evidence_refs` 中，并同时绑定母面、记录的 `physical_object_id` 及当前数量出口。真实洞口使用 `opening_union`，其余面、材料、未知区和补集声明使用 `surface_geometry`。程序保存分区 JSON 的 SHA、各条记录的实际 JSON Pointer，以及其原始证据的来源 SHA 和定位。JSON 中坐标的专业解释仍需回原图复核，源哈希并不自动证明解释正确。

存在真实洞口并集扣减时，继续给既有项级 `opening_union_evidence_ref`；完整范围、零值、规则及材料施工层适用证据继续遵守原有契约。

## 计算与冲突处理

1. 母面裁切真实洞口，洞口先并集再扣除，避免重叠洞口重复扣减。
2. 所有材料矩形和明确未知矩形均裁切至扣洞口后的有效母面。同材料有效区域求并集，保留重叠去重面积及全部原物理对象身份。
3. 不同材料仅在有效母面上判断交叠。只在洞口内交叠、或只共边共点，不构成材料面积冲突。有效面异材料交叠进入冲突未知区，程序不设默认材料优先级。
4. 明确未知区和冲突区均从已知材料区域剔出。对显式未知覆盖到已有材料候选的部分，保留候选及扣留面积，不把候选直接当确定材料。
5. 默认完整母面模式下，有来源的 `base_material` 最后填充未被任何材料或未知区占据的补集。无补集声明时，剩余有效母面进入 `unassigned_without_base`，作为未确定区域单列。不能先补基层再忽略 unknown。

已知材料面积之和与未知面积之和须等于扣真实洞口后的有效母面。这个等式只检查几何覆盖分账；异材料冲突、未确定区域及条件方案仍明确存在，不能用守恒等式把它们销项。

## 仅计有源选定区域

接缝网带、局部附加层等正向计量，通常只涉及明确条带。条带之外的母面不必是设计未知，也不能为了凑完整母面而伪造“无网材材料”或洞口。这类分区必须在源 plan 内显式声明：

```json
{
  "coverage": {
    "mode": "selected_regions",
    "physical_object_id": "SCOPE-JOINT-BANDS",
    "basis": "本次只计来源明确的接缝条带；母面其余范围不属于本数量出口",
    "source_evidence_ref": "EV-JOINT-SCOPE"
  },
  "base_material": null
}
```

范围证据须是本项 `surface_geometry`，绑定母面、范围的 `physical_object_id` 及各数量出口；审计保留其 JSON Pointer、源 SHA 与证据原始定位。不得仅在清单里写一个跳过补集的开关。省略 `coverage` 默认为 `full_surface`，原默认完整性约束不变。显式提供 `coverage` 时也须提供可绑定物理身份与证据；支持的模式仅这两种。

`selected_regions` 只改变未选中背景的范围归属，不改变区域几何算法：同材料并集、真实洞口扣减仍正常执行，材料冲突及 `unknown_regions` 仍须作为未知出口单列。该模式禁止 `base_material`，防止同时声称只量条带又把背景补满。源事实未声明的接缝或宽度不能由程序推补。

结果额外输出 `outside_selected_scope` 的面积、面域及矩形分解，表示不在本项计量范围的背景，不建立对应未知材料数量项。守恒关系为“已知选定区域＋未知/冲突区域＋本项范围外背景＝有效母面”。`full_surface_coverage` 固定为 `false`；没有未知区时，分区状态为 `selected_regions_measured`，不能冒称全母面材料已完成。数量项的 `complete` 如有明确范围证据，仅表示所声明选定区域的完整，不表示整墙、所有接缝或所有施工层完成；实际仍有未明条带或条件方案时保留 `partial`/未决和 `reference`。

## 输出及施工层接入

`专业检查.输入审计.material_partition` 保留母面、层范围、场景、各材料有效已知区域、真实洞口并集、显式未知、材料冲突、无补集声明的剩余区域以及逐记录来源。每个区域导出：

- `area_m2`：实际区域面积。
- `polygons_m`：外环与孔洞分别保存，孔洞不会被当成第二个面重复计量。
- `rectangles_m`：与面域等效、互不重叠的矩形分解，可直接回看及用于后续有来源施工层输入；分解面积再次核对。

材料分区的身份和小计同时包含母面、`layer_scope_id`、`scenario_id`、材料/未知出口和材料编号。同一 `layer_id` 下可有不同材料分项，不需要为避免混加而改层名称；不同层范围或方案不互相制造冲突，也不进入同一个小计。一个母面、同一层范围和同一场景不能同时引用不同分区版本，不能重复输出同一材料，也不能遗漏正面积材料或未知出口。

`layer_scope_id` 描述此次分区覆盖范围，不强制等于施工成果 `layer_id`。建议先输出基层材料域参考，再按有证做法决定施工层是否适用。同一几何用于不同施工层时，应保留各层真实适用范围与明确的分区层范围，不能因基层是混凝土就自动套用AAC底灰配方。

结果公式使用“母面面积－真实洞口并集－本出口之外区域”，最后一项是排除其他材料/未知区以选择本数量出口的算术，不是把实体区域伪装为洞口。已知材料结果和未知面积有不同身份与小计，不能把未知材料面积直接采用为某一确定施工做法。

## 执行与复核

```powershell
python scripts/calculate_surfaces_envelope.py --manifest <运行清单.json> --output <新成果.json>
python ../_qto-shared-evidence/scripts/validate_minimum_result.py <新成果.json>
python scripts/validate_surfaces_envelope_result.py --calculator scripts/calculate_surfaces_envelope.py --manifest <运行清单.json> --binding <新成果.json>
```

实际插件入口为既有计算器，新 `material_rectangle_partition.py` 只承担局部矩形几何。运行不依赖旧安装缓存。完整绑定验证从源文件重算并比对全部区域，单独移动一个等面积区域或修改矩形分解，即使总面积不变也不能通过。反之，源事实本身是否正确解释了原 CAD，仍由图面证据与专业审阅负责，不能仅因数值重算成功就宣称成立。
