# 表面与构造层清单格式

运行清单版本为 `qto-surfaces-envelope-manifest/1.0`，顶层包含 `task`、`sources`、`evidence`、`rules`、`unresolved` 和 `items`。

## 资料与证据

每项资料声明：

- `source_id`、`path`、`sha256`；
- `file_role`：物理文件角色；
- `source_role`：项目图纸、中性实体流、元数据、项目文档、批准方案、覆盖报告、标准或测试夹具；
- `selection`、选择原因、拟提取中性事实和未使用影响。

CAD 元数据必须断言图纸哈希、实体流哈希、适配器、schema、单位和守恒状态。中性实体流必须绑定图纸与元数据并声明预期行数，复算时逐行核对来源 SHA 和 schema。

盖章或其他明确版本的PDF可登记为`project_drawing`；文件格式通过不等于该版本有效，仍需逐项记录选择依据。每个有数值的参考或采用项都必须有`source_identity`、`surface_geometry`、`layer_assignment`。几何、洞口、坡面、覆盖和做法证据的`object_keys`须包含本项`physical_surface_id`；做法还须包含`layer_id`，不能仅凭证据存在就跨房间或跨构造层使用。

候选规则可以`试用`并形成`reference`量，不得通过改写为“试运行/采用”绕过状态。小计按`quantity_role`分开；相同平方米单位的物理面积与清单候选量不能相加。

每项证据声明 `evidence_class`、`fact_status`、定位、事实、提取方式、质量状态和对象键。实体句柄必须真实存在于绑定实体流。

## 数量项字段

```json
{
  "item_id": "QTY-WALL-01",
  "name": "东立面外墙板轴线口径参考面积",
  "object_type": "facade_panel",
  "physical_surface_id": "SURF-FACADE-EAST",
  "layer_id": "LAYER-EXTERIOR-PANEL",
  "side_scope": "外侧",
  "measurement_basis": "axis_projection",
  "method": "rectangle_net",
  "unit": "m²",
  "scope_status": "partial",
  "adoption_role": "reference",
  "quantity_role": "physical_area",
  "result_use": "几何复核，不作为完整采用量",
  "evidence_refs": ["EV-SOURCE", "EV-GEOMETRY", "EV-OPENINGS", "EV-LAYER"],
  "rule_refs": ["R-SURFACE", "R-OPENING"],
  "unresolved_refs": ["U-OUTLINE"],
  "opening_union_evidence_ref": "EV-OPENINGS",
  "inputs": {
    "length_m": 10.0,
    "height_m": 3.0,
    "side_factor": 1,
    "opening_union_area_m2": 4.0,
    "other_deductions_area_m2": 0.0,
    "reveal_or_return_area_m2": 0.0
  }
}
```

`complete` 还必须声明 `coverage_evidence_ref`。采用轴线口径时必须有 `basis_approval_evidence_ref`。洞口扣减大于零时必须有 `opening_union_evidence_ref`。零值还必须声明 `zero_meaning`。

## 矩形表面的洞口裁切和并集

`method: rectangle_openings_net`适用于已经定位的一块单侧矩形墙面或平面。`inputs`示例：

```json
{
  "length_m": 4.0,
  "height_m": 3.0,
  "openings": [
    {"opening_id": "DOOR-01", "rectangle_m": [0.5, 0.0, 1.4, 2.2]},
    {"opening_id": "WINDOW-01", "rectangle_m": [2.0, 1.8, 3.0, 3.3]}
  ],
  "other_deductions_area_m2": 0.0,
  "reveal_or_return_area_m2": 0.0
}
```

坐标为本表面局部展开坐标的米值`[x_min,y_min,x_max,y_max]`，表面范围为`[0,0,length_m,height_m]`。从不同墙裙高度、地坪或标高基准换算时，先保留换算依据；不得直接输入PDF像素。程序先将各洞口裁切到本表面，再求几何并集，输出逐洞口交集和并集面积。重叠、嵌套和同位几何只扣一次；同一编号重复则报错。无洞口须显式给空数组，缺字段不等于零洞口。

逐墙的 `surface_geometry` 证据须记录局部原点、水平正向、竖向基准及其对应源边。面积展开坐标与踢脚沿边坐标不同时，显式记载转换；例如同一条长度为 `L` 的直边反向后，区间 `[a,b]` 转为 `[L-b,L-a]`，并回图核对两端。不能只因反向前后洞口面积或扣减总长相同，就省略定位核验。需要程序检查源边与局部坐标的一致性时，使用下一节的显式绑定；只有文字描述或旧 `local_coordinate_frame` 字段不等于已经通过此检查。本计算器不自动证明源图到局部坐标的工程语义正确。

两侧做法或窗台高度不同应分别建表面，本方法不支持`side_factor=2`。同时提供`opening_union_area_m2`时，必须等于几何复算值；该数值不能覆盖几何计算。不规则、多边形或曲面继续用有独立面域并集证据的既有方法，本方法不近似替代。

旧标量净面方法仍可使用已证明的并集面积；扣减总和不得超过毛面积，增加面不能抵消非法扣减。`area_direct`只接收`area_m2`，防止静默忽略附带的扣减。`not_applicable`必须为空值，零值必须在完整范围检查下成立。

## 矩形面积：源边区间与局部坐标绑定

`rectangle_net` 和 `rectangle_openings_net` 可以在数量项上声明 `frame_binding`，把已有矩形长高和局部框架绑定到已登记 SHA-256 的 JSON 事实。此能力核对声明之间的几何一致性，不以方位名称、侧别名称或项目名称推断坐标。无绑定的旧输入保持兼容：结果 `专业检查.输入审计.frame_validation.status` 为 `unbound`（带有旧坐标描述）或 `not_provided`（没有坐标描述），不能据此宣称源图定位已核验。

源事实示例。目录键可以自定，程序只读显式 JSON Pointer：

```json
{
  "edges": {
    "edge-A": {
      "edge_id": "edge-A", "coordinate_system_id": "declared-frame-1",
      "start": [0, 0, 0], "end": [12, 0, 0], "unit": "m"
    }
  },
  "surface_frames": {
    "face-A": {
      "coordinate_system_id": "declared-frame-1",
      "origin_m": [10, 0, 0], "x_axis": [-1, 0, 0], "up_axis": [0, 0, 1],
      "source_edge_id": "edge-A", "source_edge_direction": "reverse",
      "source_edge_interval_m": [8, 10],
      "vertical_range_m": [0.1, 2.8], "vertical_origin_m": 0.1
    }
  }
}
```

数量项在既有物理表面、层、侧别、计量口径和证据字段之外声明：

```json
{
  "frame_binding": {
    "frame_evidence_ref": "EV-FRAME",
    "source_pointer": "/surface_frames/face-A",
    "edge_evidence_ref": "EV-EDGE",
    "edge_source_pointer": "/edges/edge-A"
  },
  "local_coordinate_frame": {
    "coordinate_system_id": "declared-frame-1",
    "origin_m": [10, 0, 0], "x_axis": [-1, 0, 0], "up_axis": [0, 0, 1],
    "source_edge_id": "edge-A", "source_edge_direction": "reverse",
    "source_edge_interval_m": [8, 10],
    "vertical_range_m": [0.1, 2.8], "vertical_origin_m": 0.1
  },
  "inputs": {"length_m": 2, "height_m": 2.7, "openings": []}
}
```

上述 `inputs` 对应 `rectangle_openings_net`；标量 `rectangle_net` 继续使用其既有扣增字段。绑定规则如下：

- `frame_binding` 只接受示例的四个字段，不接受直接坐标或计算答案覆盖。框架证据和源边证据均须为本项 `evidence_refs` 中的 `surface_geometry`，`object_keys` 同时包含当前 `physical_surface_id` 和对应 `edge_id`；允许两者引用同一证据，也允许来自不同已核验 JSON 源。
- 源框架和 `local_coordinate_frame` 必须具有示例九个规范字段，并逐字段一致。边的 `coordinate_system_id`、源框架及声明框架的坐标系标识必须相同。该标识由取证者明确指定，不能只把不同坐标系改成相同字符串；单位、图块变换或坐标转换应在形成源事实时完成并保留取证链。本工具不自动执行跨坐标系转换。
- `origin_m`、`source_edge_interval_m`、`vertical_range_m`、`vertical_origin_m` 固定以米表示；`x_axis`、`up_axis` 是无量纲的三维单位向量并须正交。源边 `start/end` 支持二维或三维，二维补第三坐标零；其明确物理长度 `unit` 独立换算为米。全部数值须有限，布尔值、像素或未知单位不能作为几何值。
- `source_edge_interval_m=[lo,hi]` 是从源边 `start` 沿 `start→end` 计的单个有限正区间，须位于源边内。它可以是源边的子段，不要求矩形长度等于整条源边。`same` 时从 `lo` 点出发、水平轴同向；`reverse` 时从 `hi` 点出发、水平轴反向。程序从源边独立推出原点和水平轴，防止源框架与清单框架共同复制了同一错误。一个矩形不接受多段离散区间；多个面应分别建项。
- `origin_m` 是基准边上选定端点，尚未加竖向偏移。`vertical_range_m=[zlo,zhi]` 是源事实明确声明的沿 `up_axis` 范围，须有正高度，`vertical_origin_m` 必须等于 `zlo`。实际表面原点为 `origin_m + up_axis × zlo`。矩形 `length_m=hi-lo`、`height_m=zhi-zlo`，不一致时拒绝；这里仅核来源已经给定的高度范围，不推断设计净高或做法起止标高。
- 长度、原点及框架比较采用绝对 `1e-8 m` 容差，并允许最多 8 个对应浮点数 ULP 的表示误差；不按平移坐标值使用相对误差。端点仅在该数值容差内裁切到边界，裁切后仍强制有效区间有正长度。不得利用容差把整段越界区间或零长矩形标为已核验。
- 旧 `positive_x: north`、`vertical_positive: up` 等非规范字段可以作为标签保留，程序列入 `unchecked_annotation_fields`；它们不参与数值轴推导，也不作为已核实方向。建议迁移时用明确数值轴替代自由文字。

通过后状态为 `bound_consistent`，审计保留两套源 SHA、证据与 Pointer、规范框架、源边端点、绑定长高、实际表面原点以及四个三维角点。成果验证器检查审计结构并从原运行清单和源文件重新计算，篡改框架、角点或绑定状态不能通过完整绑定复算。绑定只定位基础矩形，既有侧数、洞口局部并集、扣增和材料口径仍按各自证据处理；它不证明洞口的三维来源定位、不同侧面的实际偏移、设计解释正确性或项目范围完整。源事实应保留设计版本与解释过程，不能用清单输入抄写一份来源反过来证明清单正确。

## 踢脚长度：逐源边与洞口区间

踢脚沿边长度使用 `object_type: skirting_finish`、`method: boundary_intervals_net`、`unit: m` 和 `quantity_role: physical_length`。有已确认合同计量口径时可用 `bill_quantity_candidate`，仍与物理长度分账。面积方法继续输出 `m²`；踢脚高度有依据时可另建面积项，但不能把长度和面积相加或用固定高度暗中转换。

长度输入沿用本节已有 `sources/evidence` 及物理表面、层、侧别、口径和覆盖契约。每条起终点和洞口区间从已登记 SHA-256 的 JSON 事实文件读取，清单只声明选择与源位置，不接受 `total_length`、`net_length` 等预计算答案回填。

例如，在一个 `source_role: calculation_evidence`、`file_role: json` 的来源文件中保存：

```json
{
  "edges": {
    "south": {"edge_id": "south", "start": [0, 0], "end": [10, 0], "unit": "m"},
    "east": {"edge_id": "east", "start": [10, 0], "end": [10, 4], "unit": "m", "effective_intervals": [[0.5, 3.5]]}
  },
  "openings": {
    "door_on_south": {"opening_id": "DOOR-01", "edge_id": "south", "interval": [2, 3.2], "unit": "m"}
  }
}
```

边起终点须由原图已解释边界取得，二维或三维均可；`start → end` 定义沿边距离正方向，不能把另一侧或另一边的区间直接套入。`unit` 是原始坐标或沿边距离的物理长度单位，程序换算为米；边和洞口可以使用不同明确单位。源事实文件应保留原图及实例路径的取证链；本计算器验证当前 JSON 的哈希、引用和值域，不冒充自动判断边界和洞口专业归属。

对应数量项的输入为：

```json
{
  "boundary_edges": [
    {"edge_id": "south", "geometry_evidence_ref": "EV-SOUTH", "source_pointer": "/edges/south", "effective_scope": "whole_edge"},
    {"edge_id": "east", "geometry_evidence_ref": "EV-EAST", "source_pointer": "/edges/east", "effective_scope": "source_intervals"}
  ],
  "openings": [
    {"opening_id": "DOOR-01", "edge_id": "south", "opening_evidence_ref": "EV-DOOR", "source_pointer": "/openings/door_on_south"}
  ]
}
```

- `source_pointer` 使用 JSON Pointer，定位到完整边/洞口对象；不得用表达式。程序读取所引用证据的 JSON 来源，检查源对象的 `edge_id/opening_id` 与选择一致。
- 几何证据类别为 `surface_geometry`，`object_keys` 至少含当前 `physical_surface_id` 和 `edge_id`；洞口证据类别为 `opening_union`，至少含当前表面、边和洞口编号。各证据均须列入本项 `evidence_refs`，做法证据仍须绑定 `layer_id`。
- `whole_edge` 取整条源直边；`source_intervals` 必须从该边源对象读取显式 `effective_intervals`，其范围不得越出源边。重叠或相邻有效区间先并集，记录去重长度。
- `openings` 必须显式给数组，无适用洞口时为 `[]`。先把每个洞口沿边区间裁切到该边的有效区间，再对交集求并集扣除。门、落地窗是否打断踢脚由本次设计与图面解释，普通高窗不能仅因是“洞口”就扣踢脚。
- `(opening_id, edge_id)` 在本项内唯一。同一个物理门跨两条相邻源边时可在两条边各有一条有源位置的区间，分别裁切；同边重复记录拒绝。不同洞口在同边重叠只扣一次，不把邻边同距离的区间串用。
- 同一侧、同一数量项中，不同源边编号覆盖同一物理有效直线段时拒绝重复计量。相邻边仅共端点可以继续；不以名称不同放过重叠。
- 有扣减时仍需项级 `opening_union_evidence_ref`；`complete` 和零值继续遵守既有完整覆盖证据要求。做法范围或接口缺失可保留部分结果/未决，不用零值代替缺失。

结果审计保留每条边的实际长度、有效区间、洞口裁切区间、并集扣减、净长及来源 SHA/证据/JSON位置。小计按单位和数量角色区分，来源绑定复算校验同时检查米与平方米不得混加。该方法只处理已解释的直线边界，不自动确定踢脚完成面偏移、门套返边、接缝或施工损耗；有设计依据的其他边段需按其实际边界另行绑定。

## 运行

同一母面中的混凝土、砌体和局部未知基层，可使用 [材料基层矩形分区](材料基层矩形分区.md) 的 `material_partition_net`。该方法绑定原图解释的材料矩形及真实洞口，分别输出各材料和未知区域；不得用伪洞口表示另一材料区域。它沿用本文件的来源、证据、框架、层和成果契约。

```powershell
python scripts/calculate_surfaces_envelope.py --manifest <运行清单.json> --output <成果.json>
python ../_qto-shared-evidence/scripts/validate_minimum_result.py <成果.json>
python scripts/validate_surfaces_envelope_result.py --calculator scripts/calculate_surfaces_envelope.py --manifest <运行清单.json> --binding <成果.json>
```

结构校验和绑定复算不能证明材料表适用范围、合同口径或项目完整性，仍需专业复核。
