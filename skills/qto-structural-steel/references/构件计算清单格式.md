# 构件计算清单格式

`scripts/calculate_structural_steel_items.py` 只接受已由人工或上游证据链确认的对象事实。它不会识别图纸、匹配标签、判断节点或选择标准。

## 顶层字段

```json
{
  "manifest_version": "qto-structural-steel-manifest/1.0",
  "case_id": "唯一案例编号",
  "scope": {
    "project": "项目",
    "building": "楼栋",
    "area": "区域",
    "drawing_type": "图纸类型",
    "drawing_version": "版本身份",
    "output_dimension": "输出维度"
  },
  "sources": [],
  "evidence": [],
  "rules": [],
  "unresolved": [],
  "items": [],
  "summary_requests": []
}
```

所有选用来源必须提供现存文件路径、预期 SHA-256、物理 `file_role` 和受控 `source_role`。当前文件角色支持 `dwg / dxf / pdf / json / gzip_ndjson / spreadsheet / document / csv / text / image`；语义角色使用 `project_drawing / cad_entity_stream / cad_metadata / project_document / approved_plan / coverage_report / standard_reference / test_fixture`。二者必须满足兼容矩阵，不能靠修改自由文本 `source_type` 把元数据冒充方案或覆盖报告。`test_fixture` 只在显式 `test_mode=true` 的测试清单中接受。

`cad_metadata` 必须提供六项 `json_assertions`：源图 SHA、实体流 SHA、适配器、模式版本、单位和守恒状态。绑定的 `gzip_ndjson` 会逐行解压，核对 JSON 对象、源图 SHA、模式版本及元数据行数守恒。旧 Skill、旧归档、旧项目方法脚本和旧结果目录不能作为来源。

每条证据必须提供 `evidence_class` 和 `fact_status`。证据类别使用 `source_identity / object_geometry / object_mapping / material_property / rule_clause / plan_approved / coverage_complete / requirement / third_party_reference / visual_geometry`；事实状态使用 `verified / reference / candidate / test_only`。来源语义角色与证据类别必须兼容。密度和单位重依据只接受 `material_property` 或 `rule_clause`；方案量只接受带批准状态、批准位置、批准主体、范围、版本和适用对象编号的 `plan_approved`；真零必须有 `coverage_complete`，并列明覆盖范围、方法和当前对象编号。采用量不得由 `candidate` 或生产模式下的 `test_only` 证据支撑。

`object_geometry` 和 `object_mapping` 必须列出 `object_keys`。中性实体流对象键采用 `handle:<句柄>`，且句柄必须实际存在于绑定实体流。对象身份签名由来源 SHA 和对象键生成，不依赖可随意改名的 `physical_object_id`；同一对象即使改别名，也不能把毛重、净重等口径相加。缓存来源证据还必须填写 `cache_id`。

## 支持的计算方法

| `method` | 必需输入 | 输出 |
|---|---|---|
| `profile_length` | `length_total_m`、`unit_mass_kg_m`、`unit_mass_basis` | `t` |
| `built_up_section_length` | `cross_section_area_mm2`、`length_total_m`、`density_kg_m3`、`density_basis` | `t` |
| `plate` | `quantity`、`net_area_mm2`、`thickness_mm`、`density_kg_m3`、`hole_treatment`、`density_basis` | `t` |
| `count` | `quantity`、明确的 `unit` | `套/个/根/块` 等 |
| `area` | `area_m2`、`area_basis`、`opening_rule`、`overlap_rule` | `m²` |
| `surface` | `surface_area_m2`、`area_basis`、`treatment_scope` | `m²` |
| `deferred` | 明确 `unit`、未决事项和原因 | `null` |

## 对象类别

`object_type` 使用：

- `main_member`
- `node_plate`
- `connection_hardware`
- `profiled_sheet`
- `coating`
- `measure`
- `other_permanent_steel`

`mass_inclusion` 使用 `permanent`、`separate_reference` 或 `not_mass`。连接件、压型板参考质量和措施用钢不得误标为永久钢构件。

`adoption_role` 与质量归属分开：`adopted` 表示当前项目采用量，`reference` 表示条件、等效或替代口径。数值参考项统一输出 `结果用途=reference_only`，不得进入永久钢质量小计；正式采用量缺决定性输入时另列 `deferred + null`。

每个 `item` 还必须提供：

- `physical_object_id`：本次计量粒度下唯一物理对象；
- `measurement_basis`：理论表重、组焊净截面、矩形毛板、物理扣孔、表面毛面积、正式清单采用量等明确口径；
- 同一物理对象存在毛重/净重、模型重/理论重等互斥口径时，应附同一 `alternative_group`；即使删除该字段或改写对象别名，汇总仍会按对象身份签名拒绝重复相加。

## 状态

- `complete`：数值闭合，无关联未决事项；
- `partial`：保留已证实数字，必须关联完整性未决事项；
- `unresolved`：结果为 `null`；
- `not_applicable`：结果为 `null` 且说明不适用。

零值必须附 `zero_evidence`，包括覆盖范围、证据和规则。缺少零值证据时脚本拒绝输出 0。

## 汇总

`summary_requests` 必须列出 `item_ids`、预期 `unit`、对象类别、完整性和未决事项。脚本只汇总同单位、同对象类别且物理对象不重复的成员；同一板件的毛重和扣孔净重、同一构件的模型重和理论重不能相加。主构件和节点钢件需要分别请求。部分小计名称不得使用“完整”“总量”“全部”或无条件“合计”。
