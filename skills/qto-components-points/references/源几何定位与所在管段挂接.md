# 源几何定位与所在管段挂接（T20，显式启用）

用于族原点远离外形、点位需要列出所在管段系统及规格候选的情形。沿用 `scripts/build_component_instances_from_neutral.py` 的既有 CAD 清单、冻结识别配置与识别台账入口，在 profile 增加 `point_host_attachment` 才启用；不填时保持既有插入点及计数行为。

## 位置及候选

```json
{
  "point_host_attachment": {
    "schema_version": "qto-point-host-attachment/1.0",
    "tolerance": 0.02,
    "large_offset_warning": 1,
    "segments": {"path": "所在管段.json", "sha256": "冻结文件SHA256"},
    "outlets": [
      {"physical_id": "PT-CAD-EXAMPLE", "quantity_outlet": "independent_point", "host_layers": ["管段源图层"]}
    ],
    "receptions": []
  }
}
```

容差、位移阈值均用 profile 的 `unit.output_coordinate_unit`，不是固定毫米。INSUNITS 未知时可用 `raw_DU`、factor=1检查原始几何关系；这不会绑定物理比例或使米制数量就绪。`segments` 可省略：仍输出位置，宿主保持未决，不补系统/规格。

管段文件顶层为 `schema_version=qto-point-host-segments/1.0`，另有 `source_sha256`、`coordinate_system=WCS`、`coordinate_unit`、`layout` 和 `segments` 数组。每段声明 `segment_id`、`source_record_id`、`instance_path`、`part_index`（默认0）、`space_id`、`system`、`spec`、`classification_evidence_ids`。源几何为当前 CAD 清单内的实际直线 part；完整路径与适配器一致：顶层 `CAD-实体ID`，嵌套 `CAD-插入ID/块名/CAD-定义实体ID`。端点按逐级变换及 profile 比例从源几何计算；不允许另填任意端点替代。原始宿主分支只支持源直线part。风管另有下文的冻结生成器重放分支，允许有据合成中线和完整曲线；跨图坐标配准未支持。

系统及规格不能仅靠几何路径或一个非空证据ID成立。`classification_evidence_ids` 必须唯一解析到本轮ledger的 `evidence`，或管段文件 `classification_sources=[{path,sha256}]` 指向的冻结分类来源。后者顶层为 `schema_version=qto-host-segment-classifications/1.0`、本轮 `source_sha256` 和 `evidence` 数组。两种证据记录均须保留原始资料 `path/sha256/source_sha256/locator/observation`，并显式列出本段分类事实，例如：

```json
{
  "evidence_id": "HOST-CLASS",
  "path": "原始分类资料文件",
  "sha256": "原始分类资料SHA256",
  "source_sha256": "本轮原图SHA256",
  "locator": "原图或已冻结表格的可复核位置",
  "observation": "该来源明确提供对应段的系统及规格",
  "host_segment_classifications": [{
    "segment_id": "H0",
    "system": "本轮有据系统",
    "spec": "DN100",
    "scope": {
      "kind": "source_instance_part",
      "layout": "Model",
      "space_id": "明确楼层及空间范围",
      "source_record_id": "CAD-实体ID",
      "instance_path": "完整实例路径",
      "part_index": 0
    },
    "basis": "模型或专业人员依据来源形成的工作分类判断",
    "source_locator": "支持该段具体值的原始来源定位"
  }]
}
```

记录的原图SHA、段ID、完整路径、源实体、part、layout、楼层空间及明确系统规格值须逐项对应当前段。不存在ID、无关标题证据、旧版值、越界scope、重复来源或原始资料SHA变化均只保留待核候选，不带出系统规格。解析后的原始资料路径/SHA、ledger或分类bundle路径/SHA、完整证据记录指纹及单段事实进入 `classification_proofs` 和请求指纹；同值换来源也须重新核对接收。模型有据分类仍为工作候选，不冒称人工批准或正式量。没有segments的独立设备不依赖该分类契约。

`点位位置与管段挂接.json` 保存插入点、源几何范围中心、位移、来源SHA、清单及流文件路径/SHA、每个叶图元完整路径与变换、几何问题及排除注记。TEXT/MTEXT/属性/POINT/LEADER/MLEADER/DIMENSION不拉大构件外形。未知/不支持叶使外形部分可用或不可用，不宣称完整。旋转、镜像、非等比及嵌套变换先作用于实际曲线，再计算WCS范围，避免变换局部矩形造成虚大范围。

完整源几何外形中心只是实例位置依据，不是物理端口或连通证明。唯一近邻也只标 `unique_spatial_candidate`，带出 `inherited_system/spec`；不写回原识别系统和规格，不升为确认量。多段、同位、交叉、跨空间、未声明允许源图层、缺系统/规格或分类依据均保留待核，不按最近距离静默挑选。既有instance_grouping合并的组合对象仅有主角色外形时，标`grouped_primary_geometry_only`并保持挂接未决。启用后网络端口缺少显式坐标时保持未决，不能自动拿外形中心交端口。

## 唯一数量出口及实际管网消费

每个已识别实例在 `outlets` 中声明且只声明一次：`independent_point` 为本点位入口单计；`inline_network` 从点位计数及末端交接移出，等待管网实际接收。缺出口、多出口、零条/多条管网接收均阻断闭合，不将未接收当作0或自动转回点位计数。独立设备计数子范围不因另一个inline未接收而被升级或重复；总流程仍保留未决。`work_quantity_ready`、人工复核和正式采用继续分开。

运行既有适配器：

```text
python skills/qto-components-points/scripts/build_component_instances_from_neutral.py --cad-manifest CAD中性取证清单.json --profile 识别配置.json --adjudication-ledger 识别台账.json --output-dir 首轮输出
```

启用T20时，在任何成果写入前先检查新增的 `点位位置与管段挂接.json`：目标已存在（包括硬链接、目录或原输入）即要求另存新目录，输出路径含symlink/reparse别名也拒绝，最终报告使用独占新建。不能把profile本身命名为该报告后输出到其父目录。未启用T20的旧profile维持既有行为，此保护不扩改legacy成果写入规则。

管网消费 CLI 不从空间候选新造阀件或连接关系。先由管网工作形成真实 `infer_pipe_network.py` 输入，其中已有对应valve、源物理ID及显式连接依据，再运行：

```text
python skills/qto-components-points/scripts/receive_point_inline_components.py --attachment-report 首轮输出/点位位置与管段挂接.json --network-input 实际管网输入.json --output-dir 管网接收输出
```

consumer只接受新目录或确实为空的目录，拒绝任何现存文件、硬链接及symlink/reparse输出别名。写前统一检查三固定目标 `管网实际消费结果.json`、`管网在线附件数量接收.json`、`实际管网消费日志.json` 和生产者的 `管网实际消费结果_*_复核摘要.md` 命名空间，同时核对实际输入与冻结来源/证据路径及SHA。实际生产者在内部新临时目录计算，完整输出清单确认后再独占新建到业务目录；不得追加或覆盖混合旧目录，也不能把输入命名成固定日志名后输出到其父目录。receipt只引用最终业务位置，日志的 `published_artifacts` 提供实际结果、摘要和receipt的最终路径及SHA；历史命令中出现的内部运行路径不作最终成果引用。冲突拒绝时原输入、源证据及已有成果字节保持不变。

管网输入原有契约仍需满足，并额外绑定顶层 `source_sha256/coordinate_system/coordinate_unit/layout/space_id`。每个实际 valve 必须含 `source_object_id`（点位physical_id）、`source_sha256/source_instance_path/source_record_id/quantity_unit/attachment_request_sha256`，坐标等于本轮源几何位置、`connected_segment_ids`等于唯一候选段。实际segment保留相同源SHA/源实体/完整路径和实际端点、系统、空间。额外字段不改变既有管网推算规则。

valve 还需 `connection_source_id` 和 `connection_evidence={path,sha256}`，后者为独立冻结关系依据对象：`schema_version=qto-inline-connection-evidence/1.0`、对应 `evidence_id`、原图SHA、physical_id、segment_id、layout、space_id、`relationship=inline_connection`、`basis`及`source_locator`。这份依据须来自本轮可复核的专业连接判断，不能从bbox最近邻自动生成。该凭据不等于人工审批。

CLI 与接收重放共同调用同一个 `validate_pipe_request`，核验原请求冻结、来源范围、源实体路径、离散计数单位及连接依据schema等全部请求约束，避免绕过公开CLI另造receipt后放宽条件。CLI 实际运行现有管网推算入口，再核对输出valves原始明细、阀件汇总与数量守恒、对象及段的完整来源、明确连接、系统、规格和离散计数单位，生成 `管网在线附件数量接收.json`；保留实际生产者SHA、输入/结果SHA、原始行定位及请求指纹。未分类、非显式连接、非离散单位或来源不符不得接收。

核对使用实际管网输入和结果的valves全集：本报告独立设备一旦出现在其中就拒绝，不能通过从receipt漏报该行绕过。报告内实际inline明细与接收数量行按physical_id、valve_id和原始行index一一守恒，遗漏或重复均拒绝。允许实际管网结果包含本报告外的合法其他包对象，但必须有稳定source_object_id并在receipt的 `quantity_scope` 显式列出 `request_physical_ids`、`received_inline_physical_ids`、`outside_request_physical_ids`，与实际全集逐一对应。报告外旁路不获得本报告的全局唯一出口保证，也不能把当前报告独立设备伪报为旁路。管网只接收本报告inline子集时，剩余inline仍未接收并阻断相应闭合，独立设备合法子范围可继续计数。

将接收文件路径及SHA加入**另存的新profile**的 `point_host_attachment.receptions` 后重跑点位适配器。原请求profile与报告保持冻结，不能覆盖后继续声称原证据未变。适配器重新核对源几何请求指纹，重放相同版本真实管网消费者并对比输出；过期输入、篡改结果、两个接收结果和改成独立设备的重放都不能闭合数量出口。

## 风管生成宿主及实际数量接收

风管接入按[有源批量建网与覆盖差集](../../qto-duct-air-systems/references/有源批量建网与覆盖差集.md)。除原始直线part外，可在所在管段文件顶层另给 `generated_duct_input={path,sha256}` 指向冻结的风管批量生成输入，`segments` 每条仅列 `{segment_id}`。生成输入必须有同一原图SHA、layout、space、coordinate_unit及 `neutral_binding`；points使用固定风管生成器重新读取来源及识别配置，逐字段比较重建结果，不接受任意手填中心线、规格或系统。

该分支支持完整同面双线及唯一局部重叠区间的合成中心线、普通中心线与完整ARC/bulge/仿射曲线。保留所有原始成员与区间几何证据、生成器及验证器SHA；同XY不同Z用完整三维距离分别核对，曲线投影使用真实参数曲线而不是弦。当前要求点位保留相同源坐标单位且factor=1；缺截面的独立位置与几何候选可以保留，但不会继承有效规格或闭合inline出口。来源变化、未知ID、附加手写端点/分类字段或生成器重建不符均拒绝。

风管实际数量入口为 `qto-duct-air-systems/scripts/receive_duct_inline_components.py`，实际调用 `infer_duct_fittings_vertical.py` 后生成 `风管在线附件数量接收.json`，并由固定owner dispatcher重放核验。仍须显式连接证据、原物理实例、请求指纹、宿主系统/规格、离散单位及唯一出口；从point原category改分类时另需同源实例的分类依据。冻结生成风管宿主不能套pipe schema接收。原pipe消费者、已有输出保护和重放规则继续保留；风管无真实接收或零条/多条接收时继续未决，不能用profile自填received=true或普通valves候选替代。上述为通用能力及工作层级对账，不能称为真实DWG工程量验收或原项目复跑完成。
