# 结果检查与输出

- 每个实例是否有唯一 ID、位置、类别、系统、规格、状态和来源；
- 图例、示意、备用、拆除、详图和表格汇总是否被排除或正确对账；
- CAD 实例、平面编号、系统图节点和表格行是否重复；
- 点位数量是否只由本 Skill 输出，线路和洞口消费方是否只引用；
- `个/套/台/樘` 与 `m²/m` 是否分成果项；
- 覆盖范围不完整时是否分列已确认子集、规则推算、方案暂估和未决影响；
- 数值是否绑定证据、规则、假定编号、置信等级和发布状态；候选规则不得无标识支撑正式量；
- 向相邻网络输出的端点是否只提供约束，没有重复设备数量。
- 端点来源实例是否逐一完成 deliver/not_applicable/unresolved 对账，交付数是否与消费 Skill 实际接收数一致。

建议输出实例账、排除清单、来源映射表、差异表、分组数量、端点事实、明确尺寸派生量、假定与裁决清单和未决事项。

用户可见汇总不得把不同数量层级压成一个没有组成的标题数字。每个对象类别至少分列确认实例、规则推算、方案暂估和未决影响；例如“48个洁具”同时包含30个直接命名和18个几何识别时，首页应直接显示 `30确认 + 18推算`。

存在设备/洁具端点且相邻管网需要规格约束时，端点事实表必须通过 `build_network_endpoint_handoff.py` 实际交付给消费Skill；只在报告中说“可作连接定位”或只传类别、系统、规格而没有坐标/端口角色，不算完成交接。

点位核验图应按实例密集区域裁切，使用可显示中文的字体，并区分确认、推算、排除和未决标记。标题乱码、对象在大幅空白画布中不可辨认或没有图例时，只能算生成成功，不能算视觉复核通过。

否定结论（“图上无”“未见”“不存在”等）是否都附检索记录，反向核对是否写明覆盖的图纸集合并覆盖所有可能含该类对象的图；没有检索记录的否定结论报待确认，不作为不计或判定清单有误的依据。格式见公共[通用成果字段与状态](../../_qto-shared-evidence/references/通用成果字段与状态.md)“否定结论与检索证据”。
