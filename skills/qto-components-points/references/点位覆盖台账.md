# 点位覆盖台账

用途：一个专业的整个图纸集合里，每个块候选、图例的每一行都要有去向。还有没去向的，不能说“这一类算完了”。已经证实的子量照常往下做，台账不完整只拦交付“该类全部数量”。

## 怎么跑

```
python scripts/build_point_coverage_ledger.py --input 覆盖台账输入.json --output-dir <目录>
```

- 计数前跑一次，计数和图例覆盖表填完后再跑一次。
- 续作先看台账里的待识别和无去向，以及适配器的 `点位未决全量.csv`（全部未决实例，不截前 15），不看已识别点数。
- 待识别确认是实物、要计数时，回到适配器回填，不往计数输入里追加：
  1. 在模型识别台账加 include 条目，`object_ids` 写台账里的候选编号（编号格式与适配器相同）；
  2. 识别配置加对应规则；
  3. 重跑这张图纸的适配器，计数用新的 `点位唯一实例计数输入.json`，覆盖台账里这张图改指新的 `reports` 再跑。
  - 原因：实例集指纹覆盖全部实例，往计数输入里追加，指纹必然对不上。
  - 没用过适配器的图纸（中性来源加自己的计数表），要回填就改走适配器；计数表只作算术复核。
- 输出：
  - `点位覆盖台账.json`、`点位覆盖台账.csv`：分组的去向，以及汇总；
  - `图例覆盖表_待填.csv`：自动部分，已填过的值原样带上，接着填就行。
- `status`：`COMPLETE` 或 `INCOMPLETE`。输入有问题时退出码 2，状态为 `INPUT_REQUIRED`，并列出全部问题。

## 输入 `qto-point-coverage-input/1.0`

```json
{
  "schema_version": "qto-point-coverage-input/1.0",
  "scope_id": "项目-区域-专业点位",
  "drawings": [
    {"drawing": "D006", "reports": ["…/点位识别报告.json"]},
    {"drawing": "D013", "neutral_dir": "…/neutral/D013"},
    {"drawing": "D022", "neutral_dir": "…/neutral/D022", "expand_blocks": ["1#主厂房A区晶圆1F防雷接地"]},
    {"drawing": "D031", "note": "只有图例覆盖表手填行"}
  ],
  "auto_exclude_sheet_kinds": ["图例", "系统图"],
  "detail_copy_sheets": [{"drawing": "D006", "sheet_id": "D01EP-DTL-01", "basis": "大样放大的就是 A1 一层的那几台，平面已计"}],
  "count_tables": [{"path": "…/fix.csv", "constants": {"drawing": "D013"}, "columns": {"handle": "handle", "category": "attrA"}}],
  "handle_exclusions": [{"path": "…/D013_重叠图元.csv", "constants": {"drawing": "D013", "basis": "与 {handle_a} 重叠，计数前剔除"},
                         "columns": {"handle": "handle_b"}}],
  "sheets": [{"path": "…/D006_图页台账.csv", "constants": {"drawing": "D006"},
              "columns": {"sheet_id": "图页编号", "title": "图名", "sheet_kind": "状态", "x1": "x1", "y1": "y1", "x2": "x2", "y2": "y2"},
              "value_maps": {"sheet_kind": {"说明/图例/材料表": "图例"}}}],
  "legend_coverage": "…/图例覆盖表.csv",
  "search_records": ["…/否定结论检索/否定结论检索记录.json"],
  "version_conflicts": [{"conflict_id": "VC-01", "drawing": "D006", "object_ids": ["PT-CAD-7C10"], "basis": "两版不一致，待设计确认"}],
  "excluded_classes": [{"class_id": "EX-01", "drawing": "*", "block_pattern": "^(AXIS|DOOR)", "basis": "建筑底图噪声块"},
                       {"class_id": "EX-02", "drawing": "D006", "block_pattern": "^箱体框$", "sheet_kind": "系统图", "basis": "系统图上的箱体示意框"}]

```

- **图纸集合**：从图纸目录取全。每张图纸的候选来源选一种：
  - 用了适配器的，写 `reports`。候选是适配器处置清单里的全部实例，含块内嵌套。
  - 没用适配器的，写 `neutral_dir` 和自己的计数表 `count_tables`（必须带图元句柄列）。候选是中性布局 `Model` 里的全部顶层块。
  - 楼层整层画在一个块里的图，在这张图纸的 `expand_blocks` 写容器块的精确块名（区分大小写）。脚本只展开这些块（块里又有声明的块就逐级展开），块内每个 INSERT 都成为候选，编号同适配器：`PT-CAD-<顶层句柄>/<块名>/CAD-<块内句柄>`。容器本身记有据排除，不能再进计数表。
  - 没声明展开、而顶层块里有本图已计或图例页上出现过的块名时，台账报 `unexpanded_container_blocks`（块名、个数、块里有哪些），说明有对象还看不到，不能说完整。
  - 两者都没有的，只能靠图例覆盖表的手填行；连图例行也没有的，列为“未覆盖图纸”。
  - 同一张图纸不能同时写两种来源。
- 表的写法同图面视图映射：`path`、`columns`、`constants`（可以写 `{列名}` 模板）、`value_maps`，相对路径按输入文件所在目录解析。
- **计数表**的键：`drawing`、`handle`、`category` 必填，`sheet` 可选（只作对照）。
  - `handle` 写顶层句柄，或已展开容器里的路径编号。句柄不分大小写；路径编号的前缀 `PT-CAD-`、`CAD-` 要大写，块名要和图中一致。
  - 句柄指向顶层文字等非块图元的（以箱号文字作实例键），记为非块计数对象，算已计。
  - 判输入问题的情况：句柄查不到；是块内图元（在已展开的容器里时改写路径编号）；路径编号格式不对、指向没声明展开的块、或查不到；同一图纸重复计了两次；既在计数表又在排除表；已展开的容器本身进了计数表。
- **排除表** `handle_exclusions`：`drawing`、`handle`、`basis` 必填。用于重叠剔除、他图计入、同一实物另一图之类。
- **图页**：按块的图形范围（块定义经累计变换后的包围框中心）定图页，同时落进几张时取面积最小的；量不出图形范围的退回插入点；落不进的写“图页未定”。插入点和图形不在同一图页时列 `insert_geometry_sheet_mismatch`。图形范围和点位适配器的范围裁剪用同一套规则：无几何的填充不计入、注记按插入点计，这样得出的定位依据记“图形范围中心（范围不完整：未含填充或注记按插入点计）”；SPLINE、DIMENSION、REGION 等无几何对象，取证带有效 bbox3d 的按它计入、不算不完整，bbox3d 只是一个点的（DIMENSION 常见）按注记计。定页和裁剪只差一处：块内有不带 bbox3d 的这类对象或展不开的子块时，定页照 0.3.10 跳过它们、用块内其余图元估算，依据记“图形范围中心（范围不完整（估算）：跳过了取不到范围的对象）”，插入点和估算的图形不在同一图页时同样列 `insert_geometry_sheet_mismatch`；裁剪不跳过，整块取不到范围、保守保留。剩不下可量的图元时，按插入点定页。否定结论检索用同一个函数和同样的依据写法。来自适配器报告的实例，适配器按插入点护栏保留的（范围不完整且落在包外）记“插入点（范围不完整且落在包外，按插入点保留）”。`placement_basis_counts` 按这几种依据计数。
  - 图例页上的待识别候选，自动算有据排除（图例样例）。
  - 系统图页默认不排除；项目确认系统图上的图符只是示意时，写 `"auto_exclude_sheet_kinds": ["图例", "系统图"]`，系统图页上的待识别记“系统图页上的示意，不单独计数”。这个数组只收图例、系统图，写详图判输入问题。
  - 详图页可能是某个对象唯一的表达，不自动排除：详图页上的待识别照旧待识别，依据里提示“可能是复制件”。核对过是复制件的详图页，逐页写进 `detail_copy_sheets`（`drawing`、`sheet_id`、`basis`），其上的待识别才改为有据排除。引用的图页要在图页表里、类型是详图。
  - 已计的候选落在这些页上不改去向，列进提醒。
  - 汇总里 `auto_excluded_by_sheet_kind` 按图例、系统图、详图（已确认）单列个数，`unconfirmed_detail_sheets` 列出还没确认的详图页。
- **整类排除** `excluded_classes`：按块名或图层正则，必须写依据；可加 `sheet_kind` 只排某类图页上的（与块名、图层条件同时满足，不收详图）。只把待识别改成有据排除，不动已计的；已计的命中了也只列提醒。
  - 匿名块（`A$C…`、`*U…`）的名字不说明用途，不能按名字整类排除。
  - 规则命中的块名也出现在同图纸图例页上（或被图例行的 `matched_symbols` 认领）时，台账报 `excluded_class_hits_legend_symbol`，列出规则、块名、图例行，去向不变，要专业核对后改写规则。只算图例页以外的命中。图例行写了“不计”也照样提示：“不计”常是照着规则填的，要回图核对。
  - 规则排掉了平面页上的块，而同名块（去掉外部参照前缀）在本输入别处已计时，报 `excluded_class_hits_counted_symbol`，去向不变，要回图核对是不是实物。
- **版本冲突**：按候选编号或块名命中，单列，不进合计。
- **漏页检查** `frame_blocks`（建议写）：图页表是按包的范围写的，漏掉一整张图页时别处没有提示。写图框块名正则 `{"block_pattern": "^(A0|A1|A2|A3)$"}`，或引用已写的图框整类排除 `{"class_id": "EX-FRAME"}`，可加 `drawing`。
  - 图框中心落在某张图页里，或图框与某张图页框重合过半（图页框只框图面区时），算在表里；都不是的报 `frame_outside_sheet_table`（句柄、块名、插入点、图形中心、图形范围）；有来源却没有任何图页的图纸整图报 `frames_without_sheet_table`。
  - 嵌在图框里的图签随外框不单核；定不出图形范围、插入点又不在图页里的图框报 `frame_extent_unknown`，记“没核”，核图后处理。
  - 汇总 `frame_coverage.conclusion`：有未覆盖图框时写“可能漏页：N 个图框不在图页表里”，补页后重算。只报，不自动补图页。
  - 图例页上的图框、图签不生成图例行；已填图例覆盖表里这些行丢掉并列在 `frame_coverage.legend_frame_rows_dropped`。

## 五种去向

| 去向 | 含义 |
|---|---|
| 已计 | 进了实例计数，写类别 |
| 有据排除 | 写排除依据：适配器排除和不适用、重复剔除、排除表、整类排除、已展开的容器块、图例样例、系统图示意（项目打开时）、确认的详图复制件、图例行“归他专业”“不计” |
| 待识别 | 还不知道是什么：适配器未决、没进计数表的顶层块、图例行“待识别” |
| 版本冲突 | 单列，不进合计 |
| 无去向 | 非块图例行有实例、没去向；模型识别台账列了、适配器没承接的对象 |

`coverage_complete` 只在待识别、无去向、未覆盖图纸、没去向的图例行都为 0 时才是 true。

**哪一类不完整**：

- 待识别的块写了疑似类别的，只拖累那一类；
- 没写的，拖累同一图纸上的所有类别；
- 疑似类别写在图例覆盖表里。

## 图例覆盖表（CSV，英文列键）

列：`drawing, legend_row, legend_handle, legend_text, symbol, symbol_kind, matched_symbols, plan_count, count_source, variant_flag, destination, target_or_reason, suspected_category, search_record_id`。

1. 脚本自动列出图例页上的每个顶层块：
   - 填块名、句柄，以及平面实例数（同一图纸非图例、非详图页、非自动排除图页上该块的候选数，含图页未定）；
   - 比块名时先去掉外部参照前缀（`XREF$0$GPB` 当 `GPB`，多层 `A$0$B$0$C` 当 `C`）；
   - 同一块名出现在两行以上时，标“同块多变体”；
   - 该块的平面候选全部已计、而且只有一个类别时，预填去向“已计”和类别；
   - 行号按插入点排序编 `A001` 起；带了已填的图例覆盖表时，句柄在表里的沿用表里的行号，新出现的块用本图表里没用过的号续编。图例页上的块因定页变化（插件升级、重提取证）离开图例页时，已填行照旧保留，告警 `legend_handle_not_on_legend_sheet`，其余行的行号不动。
2. 平面上的块和图例块名字不同、确是同一类时，在 `matched_symbols` 写平面块名（几个用“；”隔开），或写 `@识别记录编号`（适配器来源，按该记录采用的实例数）。脚本按它数平面实例，`count_source` 写 `matched_symbols`。
   - 写了本图没有的块名或识别记录编号，判输入问题；
   - 同一个块被两行图例认领（其中至少一行是 `matched_symbols` 写的），两行都列“matched_symbols 冲突”，不算有去向；
   - 去向“已计”、类别只对应这一行图例的块行，没写 `matched_symbols` 时，脚本把本图已计为该类别的块名作默认值，`count_source` 写“类别一对一默认”；一个类别对应几行图例时不给默认；
   - 非块行写了 `matched_symbols` 的，实例数由脚本按块数，不再另加候选（那些块已经在台账里）；
   - 图形相同、块名不同而没写的，不自动归类，照零实例处理；
   - 同一个块在图例里是几行（如龙骨灯白光、黄光同为一个块）时，每行写 `块名::类别`，只数该类别的平面实例（类别取计数结果里的类别，只认领已计的）。这个块名下没有该类别判输入问题；一行写了类别、另一行没写，或两行写同一类别，都报冲突。
3. 专业会话补：
   - 图例文字、去向、理由、疑似类别、检索记录。去向只能是已计、归他专业、不计、待识别，或留空。
   - 非块图符（比如画成 HATCH 的接地端子板）手加一行：`symbol_kind=非块`，实例数手填，并写明怎么数的。
4. 实例数为 0 的行必须写检索记录，否则判“待确认”，不算有去向。
   - 检索记录用公共脚本 `search_negative_evidence.py` 出（公共《否定结论检索》），`search_record_id` 写记录编号（`NS-…`，几条用“；”隔开），输入里 `search_records` 写检索记录文件路径（一个或数组）。
   - 给了 `search_records`：编号要在文件里，记录要齐全，而且是“全覆盖未命中”，才算有去向。有命中的记“实例数为 0 不成立”，待确认的记“实例数为 0 未确认”，都列进没去向的图例行。文件读不了、不是检索输出、编号重复，判输入问题。
   - 没给 `search_records`：只查编号非空，并在提醒 `search_record_ids_not_checked` 里列出这些行。
5. 同块多变体、图上又没有区分依据时，数量照计；受影响的派生量（如竖向长度）按方案分列，写明还要补什么依据，不默认取其中一种。
6. 块行手填的实例数与自动数不一致时列冲突，以自动数为准。
7. 不在图例页上的待识别块，可以手加一行 `symbol_kind=块`、`legend_handle` 留空，只用来写疑似类别，不要求填去向。疑似类别也作用到该行 `matched_symbols` 里的块。
