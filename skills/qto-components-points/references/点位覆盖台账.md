# 点位覆盖台账

用途：一个专业的整个图纸集合里，每个块候选、图例的每一行都要有去向。还有没去向的，不能说“这一类算完了”。已经证实的子量照常往下做，台账不完整只拦交付“该类全部数量”。

## 怎么跑

```
python scripts/build_point_coverage_ledger.py --input 覆盖台账输入.json --output-dir <目录>
```

- 计数前跑一次，计数和图例覆盖表填完后再跑一次。
- 续作先看台账里的待识别和无去向，以及适配器的 `点位未决全量.csv`（全部未决实例，不截前 15），不看已识别点数。
- 输出：
  - `点位覆盖台账.json`、`点位覆盖台账.csv`：分组的去向，以及汇总；
  - `图例覆盖表_待填.csv`：自动部分，已填过的值原样带上，接着填就行。
- `status`：`COMPLETE` 或 `INCOMPLETE`。输入有问题时退出码 2，状态为 `INPUT_REQUIRED`，并列出全部问题。

## 输入 `qto-point-coverage-input/1.0`

```json
{
  "schema_version": "qto-point-coverage-input/1.0",
  "scope_id": "项目-区域-专业点位",
  "drawings": [
    {"drawing": "D006", "reports": ["…/点位识别报告.json"]},
    {"drawing": "D013", "neutral_dir": "…/neutral/D013"},
    {"drawing": "D022", "note": "只有图例覆盖表手填行"}
  ],
  "count_tables": [{"path": "…/fix.csv", "constants": {"drawing": "D013"}, "columns": {"handle": "handle", "category": "attrA"}}],
  "handle_exclusions": [{"path": "…/D013_重叠图元.csv", "constants": {"drawing": "D013", "basis": "与 {handle_a} 重叠，计数前剔除"},
                         "columns": {"handle": "handle_b"}}],
  "sheets": [{"path": "…/D006_图页台账.csv", "constants": {"drawing": "D006"},
              "columns": {"sheet_id": "图页编号", "title": "图名", "sheet_kind": "状态", "x1": "x1", "y1": "y1", "x2": "x2", "y2": "y2"},
              "value_maps": {"sheet_kind": {"说明/图例/材料表": "图例"}}}],
  "legend_coverage": "…/图例覆盖表.csv",
  "version_conflicts": [{"conflict_id": "VC-01", "drawing": "D006", "object_ids": ["PT-CAD-7C10"], "basis": "两版不一致，待设计确认"}],
  "excluded_classes": [{"class_id": "EX-01", "drawing": "*", "block_pattern": "^(AXIS|DOOR)", "basis": "建筑底图噪声块"}]
}
```

- **图纸集合**：从图纸目录取全。每张图纸的候选来源选一种：
  - 用了适配器的，写 `reports`。候选是适配器处置清单里的全部实例，含块内嵌套。
  - 没用适配器的，写 `neutral_dir` 和自己的计数表 `count_tables`（必须带图元句柄列）。候选是中性布局 `Model` 里的全部顶层块；块内嵌套的设备块不单独成为候选。要逐个核块内设备的，用适配器。
  - 两者都没有的，只能靠图例覆盖表的手填行；连图例行也没有的，列为“未覆盖图纸”。
  - 同一张图纸不能同时写两种来源。
- 表的写法同图面视图映射：`path`、`columns`、`constants`（可以写 `{列名}` 模板）、`value_maps`，相对路径按输入文件所在目录解析。
- **计数表**的键：`drawing`、`handle`、`category` 必填，`sheet` 可选（只作对照）。
  - 句柄指向顶层文字等非块图元的（以箱号文字作实例键），记为非块计数对象，算已计。
  - 判输入问题的情况：句柄查不到、是块内图元、同一图纸重复计了两次、既在计数表又在排除表。
- **排除表** `handle_exclusions`：`drawing`、`handle`、`basis` 必填。用于重叠剔除、他图计入、同一实物另一图之类。
- **图页**：插入点落进哪张图页就归哪张，同时落进几张时取面积最小的；落不进的写“图页未定”。
  - 落在图例页、详图页上的待识别候选，自动算有据排除（复制件）；
  - 已计的候选落在这类页上不改去向，列进提醒。
- **整类排除** `excluded_classes`：按块名或图层正则，必须写依据。只把待识别改成有据排除，不动已计的；已计的命中了也只列提醒。
- **版本冲突**：按候选编号或块名命中，单列，不进合计。

## 五种去向

| 去向 | 含义 |
|---|---|
| 已计 | 进了实例计数，写类别 |
| 有据排除 | 写排除依据：适配器排除和不适用、重复剔除、排除表、整类排除、图例或详图复制件、图例行“归他专业”“不计” |
| 待识别 | 还不知道是什么：适配器未决、没进计数表的顶层块、图例行“待识别” |
| 版本冲突 | 单列，不进合计 |
| 无去向 | 非块图例行有实例、没去向；模型识别台账列了、适配器没承接的对象 |

`coverage_complete` 只在待识别、无去向、未覆盖图纸、没去向的图例行都为 0 时才是 true。

**哪一类不完整**：

- 待识别的块写了疑似类别的，只拖累那一类；
- 没写的，拖累同一图纸上的所有类别；
- 疑似类别写在图例覆盖表里。

## 图例覆盖表（CSV，英文列键）

列：`drawing, legend_row, legend_handle, legend_text, symbol, symbol_kind, plan_count, count_source, variant_flag, destination, target_or_reason, suspected_category, search_record_id`。

1. 脚本自动列出图例页上的每个顶层块：
   - 填块名、句柄，以及平面实例数（同一图纸非图例、非详图页上该块的候选数，含图页未定）；
   - 同一块名出现在两行以上时，标“同块多变体”；
   - 该块的平面候选全部已计、而且只有一个类别时，预填去向“已计”和类别。
2. 专业会话补：
   - 图例文字、去向、理由、疑似类别、检索记录。去向只能是已计、归他专业、不计、待识别，或留空。
   - 非块图符（比如画成 HATCH 的接地端子板）手加一行：`symbol_kind=非块`，实例数手填，并写明怎么数的。
3. 实例数为 0 的行必须写检索记录（按公共《通用成果字段与状态》“否定结论与检索证据”），否则判“待确认”，不算有去向。
4. 同块多变体、图上又没有区分依据时，数量照计；受影响的派生量（如竖向长度）按方案分列，写明还要补什么依据，不默认取其中一种。
5. 块行手填的实例数与自动数不一致时列冲突，以自动数为准。
6. 不在图例页上的待识别块，可以手加一行 `symbol_kind=块`、`legend_handle` 留空，只用来写疑似类别，不要求填去向。
