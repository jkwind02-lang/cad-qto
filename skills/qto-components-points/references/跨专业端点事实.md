# 跨专业端点事实

## 目的

点位数量仍由本 Skill 唯一输出，但设备、洁具、风口、电气末端和井类可以向管网、风管或电气线路提供连接约束。接口事实不是新的数量出口。

## 端点字段

每个可连接实例至少输出：物理实例 ID、端点 ID、对象类型、系统、楼层/房间、坐标或拓扑位置、端口角色、直接标注规格、设备表规格、常规接口规格候选、证据编号、规则编号、置信等级、假定编号、允许传播范围和限制。

## 强制交接对账

识别规则未声明端口时按 unresolved 输出，不能自动判为 not_applicable。模型交付端口须有实际连接坐标；确已查明插入基点就是连接点时才可声明 `use_instance_anchor=true`。未分类块和未完成的识别另列范围缺口；空交接不能证明相关点位工作包完整。

点位与相邻网络同时进入一个任务时，使用 `scripts/build_network_endpoint_handoff.py` 生成交接文件。来源实例必须逐一处置为：

- `deliver`：生成一个或多个稳定端点并交给消费 Skill；
- `not_applicable`：有证据证明本实例在本网络中无连接端口；
- `unresolved`：可能需要连接，但坐标、系统、端口角色或类型仍缺失。

交接同时记录物理实例数和端口数；端口总数必须等于已交付、不适用和未决之和。消费方实际接收的 `terminals[]` 数量必须等于已交付端点数；点位存在而管网 `terminals[]` 为空时，除非全部端口已有“不适用”依据，否则不得通过跨工作包业务验收。未决端口不阻断其他已交付端点和网络基线继续计算。

## 证据强度

1. 设备属性、设备表端口或明确接口标注：可作为直接端口规格；
2. 图例/编号与实例唯一映射后得到的接口：可作为规则推算种子；
3. 仅由设备类型对应的常规连接规格：只能作为方案暂估种子；
4. 最近设备、同房间或块名相似：只能提示候选，不能自动绑定。

## 使用边界

- 端口规格只约束设备连接点和允许传播范围，不自动证明整条上游管网、风管或线路规格；
- 管网、风管和电气 Skill 决定如何沿自己的拓扑传播，并负责变径、分支、回路和冲突处理；
- 接收方引用端点 ID、事实 ID 和假定编号，不重复统计设备数量；
- 一个设备有多个端口时分别建端点，不能用设备实例数代替端口数；
- 表格只给典型规格而未绑定实例时，输出类型级候选规则，不伪造成实例事实。
