# 跨能力范围拆分

## 工作包字段

每个工作包至少有：编号、主责 Skill、业务专业、主要物理对象、系统、楼栋/楼层/区域、资料版本、输入证据、输出名称与单位、共享事实、相邻接口、排除项、成熟状态、未决事项和完成条件。

只有范围与物理对象已确认后才建立已确认的数量工作包。仅泛称“全专业”且不能确定实际涉及的对象或系统时，可以列潜在检查清单，但已确认必需能力和数量工作包为空；不得凭惯例补齐十三专业。

## 参与能力与数量工作包

必需参与能力包括当前范围已经明确需要的数量计算能力及接口事实提供方，不等于已确认的数量工作包。当前请求或项目证据已明确涉及哪些对象或系统时，应保留相应的必需参与能力；缺少规格、排布或批准深化方案会影响计算就绪与数量归属，不应抹去已经确定的参与关系。

例如综合支吊架的承载系统已明确时，相关管网、风管或电气通道能力负责提供各自接口事实；仅列当前确实涉及的系统。批准方案和唯一归组尚未闭合时，支架数量工作包仍待定，`ownership_resolved=false`、`calculation_input_required=true`、`execution_ready=false`；不能给多个参与方分别分配同一支架数量，也不能把提供接口等同于已经完成支架计算。

## 拆分顺序

1. 按物理对象拆：土体、桩、混凝土、钢筋、结构钢、砌体、表面层、骨架、流体管、风管、电气路径、离散实例。
2. 再按系统/材料/规格/区域/版本分包，使一个工作包只使用一套可闭合规则。
3. 指定唯一主责 Skill；相邻 Skill 只能消费稳定事实或承接自己的子对象。
4. 明确交接：例如桩 ID/桩长给钢筋笼，门窗洞口给砌体与围护，设备端点给线路/管网，墙体边界给面层与龙骨。交接事实包含事实 ID、证据强度、置信等级、假定编号和允许用途。
   对设备/洁具等离散实例到网络的交接，必须额外记录来源实例数、已交付端点数、不适用数、未决数和消费方接收数，并满足来源守恒与交付=接收。点位候选存在但网络端点为空时，只有全部候选均有“不适用”依据才允许关闭交接。
5. 每包独立判断数量层级、计算完整性和发布状态；低成熟度包不阻断安全独立包，也不阻断其自身形成推算或暂估，但阻断未经披露的“全范围正式完成”声明。

## 典型拆分

- “喷淋系统”：管段/管件/在线阀门 → 管网；喷头/箱体 → 点位；电控线路 → 电气。
- “幕墙”：面板 → 围护；立柱横梁/连接 → 骨架；开启扇实例 → 点位；主体承重钢件 → 钢结构。
- “地基基础”：土方 → 土方；桩身/地基处理 → 桩基；承台/筏板模板混凝土 → 混凝土模板；钢筋笼与承台钢筋 → 钢筋。
- “道路室外”：道路结构层/缘石/边沟 → 道路；路床以下挖填 → 土方；雨污管 → 管网；井类 → 点位；挡墙实体按混凝土/钢筋/砌体拆分。
- “暖通”：风管 → 风系统；水/冷媒管 → 管网；设备/风口 → 点位；供电控制线路 → 电气。

## 状态汇总

协调结果不把不同专业的状态“向上取最好”。只有全部必需工作包范围闭合时才可称范围完成；任一必需包仍有未决，整体列出未决和影响量，同时保留其他包的独立成果及该包已形成的推算/暂估成果。
