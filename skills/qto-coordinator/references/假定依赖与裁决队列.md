# 假定依赖与裁决队列

## 协调职责

协调器只登记跨工作包假定、依赖和用户裁决，不创建专业推算规则。专业 Skill 负责提出候选事实、数量、置信等级和替代方案；协调器负责让同一假定只有一个编号、一个当前状态和一组可回算的消费方。

## 最小字段

每项至少包含：假定编号、提出工作包、事实提供方、使用规则、优选方案、替代方案、置信等级、影响成果项、影响单位与差值、消费工作包、确认状态、所需确认方和重算范围。

## 依赖图

用“假定编号 → 直接成果项 → 下游派生项”登记依赖。例如：

`设备端口 DN → 末端连接管 DN → 阀门规格 → 保温外径映射`

假定变化时只把直接和间接消费者标为需要重算。其他独立工作包保持原状态；不得因一个专业未确认而撤销其他专业已闭合结果。

## 裁决队列

只把以下事项提交用户：低置信、高影响、多个互斥方案、跨工作包唯一出口冲突、会改变正式口径。相同原因产生的同类事项应成组提交，并同时给出：

- 推荐方案及依据；
- 替代方案；
- 各方案数量影响；
- 不确认时采用的内部工作口径；
- 确认后需要重算的成果。

高置信、低影响且规则允许自动接受的推算不逐项打断，但仍保留假定编号并限制正式发布。

## 汇总

协调成果按单位分别列确认小计、规则推算小计、方案暂估小计、当前工作量、正式可用量和待确认影响量。协调器只汇总专业 Skill 已明确允许进入对应小计的成果，不改变其数量层级、置信等级或发布状态。
