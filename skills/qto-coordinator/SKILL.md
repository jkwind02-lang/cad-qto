# 全专业算量协调

只问分工或缺输入时，形成参与能力与必要交接清单即可；计算时再展开专业规则。同一上下文已完整读取且未变更的公共条款可复用，压缩缺失时补读。输出诊断字段时读取 [入口与就绪状态](../_qto-shared-evidence/references/通用成果字段与状态.md#入口路由与执行就绪状态)。

## 触发判定

使用本 Skill 的情形：

- 用户明确要求整栋、全项目、全专业或多个业务专业算量；
- 一个业务专业天然需要两个以上算量能力，例如暖通含水管、风管和设备点位；
- 请求混有多个物理对象，需先拆为独立计算链；
- 暂时无法唯一判断对象归属，需要建立互斥清单。

对象归属清楚的单一计算链直接进入对应专业，不经本协调器。

## 协调流程

原图任务先执行公共 [人工思路识图与算量流程](../_qto-shared-evidence/references/人工思路识图与算量流程.md)：先共同读图认识范围和系统，再由各专业沿工程关系识别、计算和回图核对。模型工作识别无需先取得逐对象人工核定；协调器区分识别未完成、真正缺资料、人工复核和正式发布，不能把能力限制写成全项目等待人工识图。

1. 锁定用户授权范围、项目/楼栋/楼层/区域、图纸版本、业务专业、物理对象、成果口径和排除项。
   若当前请求和项目证据尚不能确定实际涉及的对象类别或系统，只列“潜在能力清单”，不得建立已确认专业工作包；已确认必需能力保持为空并标记 `INPUT_REQUIRED`。已明确涉及的对象或系统，其必需参与能力与数量工作包的就绪状态分开判断，见 [跨能力范围拆分](references/跨能力范围拆分.md#参与能力与数量工作包)。
   用户要求独立复测、盲测或历史只作对比时，同时按公共 [缓存身份与复用条件](../_qto-shared-evidence/references/缓存身份与复用条件.md) 隔离旧结果；协调器负责统一冻结点和历史暴露声明。
2. 读取 [业务专业与算量能力映射](references/业务专业与算量能力映射.md)，按主要物理对象而非文件名或业务专业名称初分能力。
   高成本取证前读取本目录及已确定必需参与能力的 `capability.json`，披露能力档位、自动范围、必需输入、采用层级、业务采用许可和限制；同时说明其承担数量计算还是接口事实交接，不把参与清单当成已具备算量条件。
3. 读取 [跨能力范围拆分](references/跨能力范围拆分.md)，建立工作包：每包只有一个主责 Skill、明确输入证据、输出单位、交接事实和未决事项。
4. 读取 [重复归属检查](references/重复归属检查.md)，给每个物理对象和成果项指定唯一数量出口；共享事实用同一事实 ID，只读引用，不复制数量。
   当点位与管网/风管/电气路径同时存在时，来源实例必须逐一对账为已交付端点、不适用或未决；消费工作包的端点明细数必须等于已交付数。只建立两个工作包而没有实际交接文件，不算协调完成。
5. 读取公共 [推算、假定与发布分层协议](../_qto-shared-evidence/references/推算假定与发布分层协议.md) 和 [假定依赖与裁决队列](references/假定依赖与裁决队列.md)。专业 Skill 提出推算与方案，协调器只统一假定编号、跨包依赖、批量确认和重算范围。
6. 各专业 Skill 按自己的 `SKILL.md` 读取必要规则和公共证据资源。协调 Skill 不替专业 Skill 选择公式、扣减或成熟状态。
7. 汇总只建立成果索引：按专业 Skill、系统、区域、对象、口径、单位、数量层级和发布状态分组。不同单位、不同口径或不同覆盖范围不得相加。
8. 专业规则、项目规则、合同规则或版本冲突时，先保留各专业形成的确认量、规则推算量或多方案暂估；只有无法形成任何候选时才保留 `null`。协调层不得自行用经验覆盖，也不得把待确认方案混入正式量。

## 协调输出

至少包含：

- 总任务范围、已排除范围和资料版本；
- 工作包编号、主责 Skill、对象、区域、输入、预期输出和单位；
- 共享事实与提供方/消费方；
- 跨网络端点交接对账：来源实例数、已交付端点数、不适用数、未决数和消费方实际接收数；
- 唯一数量出口和互斥对象表；
- 各工作包状态：未开始、证据不足、候选参考、试运行、已闭合；
- 分单位成果索引和整体未决事项；
- 分单位的确认小计、规则推算小计、方案暂估小计、当前工作量、正式可用量和待确认影响量；
- 每个存在数字或候选实例的专业工作包都有用户可见汇总入口；管网断口、管件、阀门/附件等不能只列证据文件索引；
- 跨工作包假定依赖图、批量裁决队列和假定变化后的重算范围；
- 明确声明哪些专业/分支仍为候选，不能称为全专业正式能力。

## 正式采用停止与局部继续

以下条件只阻断受影响工作包的正式采用或整体完整声明。其他安全工作包继续；受影响工作包仍应输出原始事实、候选对象、规则推算或多方案暂估，只有不能形成有意义候选时才使用 `null`：

- 用户范围、项目版本或业务口径无法锁定，且不同选择会改变工作包；
- 同一物理对象存在两个数值出口且无法裁决；
- 共享事实身份不一致或来源版本冲突；
- 需要把项目专属做法提升为通用规则；
- 需要进入报价、成本、单价、采购或对外发布；
- 有专业 Skill 缺失或规则/案例成熟度不足，却要求宣称完整核准。

## 禁止

- 不保存或重写任何专业公式，不成为所有单专业请求的必经入口；
- 不以“全专业”名义自动扩大用户授权范围；
- 不把 m、m²、m³、kg/t、个/套/台/樘相加为综合总量；
- 不把候选参考量、局部试运行和正式结果混成同一状态；
- 不替专业 Skill 选择推算方案，也不把待确认假定静默计入正式量；
- 不调用旧 Skill、旧归档脚本或旧结果作为运行输入。

## HTML图面复核交付

多个专业形成对象明细后，默认按公共[HTML交互复核与批注](../_qto-shared-evidence/references/HTML交互复核与批注.md)生成可离线点选的复核页，支持问题分组、成员例外、结论与原因、保存和处理回执。保持对象专业归属及独立计量单位，沿用共享生成器，不在项目重写前端；收到意见后由各对象所属专业复算并更新采用状态，用户方法意见不自动等于数值确认。纯问答、无图表内复核及用户指定其他形态按实际范围处理。

## 已识别对象的路径与重算接续

本轮对象关系已由模型读图形成后，按公共[按人工算量顺序执行与重算](../_qto-shared-evidence/references/按人工算量顺序执行与重算.md)使用完整曲线分段、跨图接口、端口坐标或电气路径台账；修改已确定的参数/规则时保留依赖重算结果。只读取与本任务相关的小节，不自动扩大专业范围。原始识图责任、候选成熟度和正式采用边界不变。
