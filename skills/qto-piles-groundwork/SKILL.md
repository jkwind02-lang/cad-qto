# 桩基与地基处理算量

先按用户目标定阶段：范围/能力问答只读相关边界与能力披露；用户仅要求已有明细复核时做表内复核；原始资料算量执行下文。用户要求检验或改进独立算量能力、底稿仅作参照时，执行[原图独立算量实测](../_qto-shared-evidence/references/原图独立算量实测.md)，不得因已有底稿或历史结果改成表内复核。表内复核不核准原图，细则按需见 [分阶段读取](../_qto-shared-evidence/references/按任务阶段读取.md)。

原图算量先读取并执行 [人工思路识图与算量流程](../_qto-shared-evidence/references/人工思路识图与算量流程.md)。模型负责依据图纸识别工程对象并形成可复核工作量，工具负责取证和计算；人工复核与正式采用另列，不以“用户尚未逐对象核定”代替模型识图。

从桩位图、桩表、说明和详图识别每根桩及处理区，逐桩核对类型、截面和顶底标高；分开计算设计、成孔、灌注及附属量，再回图对点和对表。

以“桩/处理区唯一身份—桩型/工法—桩顶桩底标高—截面—施工与设计口径”为主线。当前为完整常规逻辑候选，后续按真实项目逐分支修正升级。

## 边界与执行

先读 [范围与对象边界](references/范围与对象边界.md)。桩身、成孔和灌注由本 Skill 唯一输出；钢筋笼由 `qto-rebar`；承台、筏板和基础梁由 `qto-concrete-formwork`；基坑及大面土方由 `qto-earthwork-terrain`。

1. 锁定项目、单体/区域、桩型或处理工法、桩位图/桩表/详图/地勘/变更版本、设计与施工标高、物理/清单/合同口径。
2. 原始资料按 [资料提取与来源核对](../_qto-shared-evidence/references/按任务阶段读取.md#原始资料与计算) 选择相应公共资源；未进入提取阶段时不展开其他资料类型。
3. 读取 [计算与证据流程](references/计算与证据流程.md)、[常规计算逻辑](references/常规计算逻辑.md)、[专业规则与成熟状态](references/专业规则与成熟状态.md) 和公共 [推算分层协议](../_qto-shared-evidence/references/推算假定与发布分层协议.md)，形成采用/试用规则清单。未升级规则可形成推算/暂估，不静默进入正式量。
4. 建每根桩/处理单元稳定 ID，绑定坐标、桩型、截面、桩顶桩底、有效长度、施工增加、状态和来源；试桩、工程桩、废桩、补桩分开。
5. 已核定桩组的根数、单根有效长度和截面闭合时，可用 `scripts/calculate_pile_groups_reference.py` 复算总长和理论实体体积；脚本不识别桩位、持力层、超灌或清单口径。
6. 按 [结果检查与输出](references/结果检查与输出.md) 与公共 [成果约定](../_qto-shared-evidence/references/通用成果字段与状态.md) 输出；案例门见 [案例与接入清单](references/案例与接入清单.md)。

## 正式采用停止与局部分支继续

以下条件只阻断受影响结果进入正式量；已确认桩位、候选桩长/桩径方案和独立桩组继续输出，无法形成有意义候选才使用 `null`：

- 桩位图、桩表、详图、地勘、设计变更或施工记录版本冲突；
- 桩顶/桩底/孔口/自然地面标高及其基准混乱；
- 设计有效长度、成孔长度、灌注长度、超灌和截桩口径未分清；
- 桩径/截面、扩底、充盈、空桩、护筒、接桩或工法会改变数量但缺依据；
- 试桩、废桩、补桩、工程桩身份或覆盖范围未裁决；
- 清单/合同量缺适用计量规则。

受影响正式结果为 `null`；安全独立桩组、规则推算和方案暂估按数量层级分列。

## 禁止

- 不以桩位圆形图元周长当桩径或桩长；
- 不按最近文字把桩表参数传播给邻近桩；
- 不默认超灌、充盈系数、空桩、护筒长度、接头或截桩量；
- 不把钢筋笼、承台、基坑土方重复并入桩身量；
- 不调用旧 Skill、旧归档脚本或旧结果。

## HTML图面复核交付

原图算量形成对象明细后，默认按公共[HTML交互复核与批注](../_qto-shared-evidence/references/HTML交互复核与批注.md)生成可离线点选的复核页，支持问题分组、成员例外、结论与原因、保存和处理回执。沿用共享生成器，不在项目重写前端；收到意见后由本专业复算并更新采用状态，用户方法意见不自动等于数值确认。纯问答、无图表内复核及用户指定其他形态按实际范围处理。
