# 龙骨与支承骨架算量

先定阶段：范围/能力问答只读相关边界与能力披露；已有明细仅作表内复核；原始资料算量执行下文。表内复核不核准原图，细则按需见 [分阶段读取](../_qto-shared-evidence/references/按任务阶段读取.md)。

原图算量先读取并执行 [人工思路识图与算量流程](../_qto-shared-evidence/references/人工思路识图与算量流程.md)。模型负责依据图纸识别工程对象并形成可复核工作量，工具负责取证和计算；人工复核与正式采用另列，不以“用户尚未逐对象核定”代替模型识图。

先读系统做法、分格排布和连接节点，按立柱、横梁或主副龙骨逐件建立清单；核对端部、洞口加密和接长后计算，回图验证分格覆盖。

按“骨架系统—分格/排布—构件角色—规格—连接实例”建立对象链。室内龙骨与幕墙骨架分别建分支，不能互套经验规则。当前整体为候选。

## 边界

先读 [范围与对象边界](references/范围与对象边界.md)。主体承重钢构件归 `qto-structural-steel`；面板、石膏板和涂饰归 `qto-surfaces-envelope`；砌体墙归 `qto-masonry-secondary`；门窗和开启扇实例归 `qto-components-points`。管道、风管、桥架各自的专用支吊架跟随对应机电 Skill；跨系统综合支吊架缺批准深化方案时保持未决。

## 执行

1. 锁定项目、楼栋、楼层/立面、系统类型、设计/深化/变更版本、材料规格和物理量/清单量口径。
2. 原始资料按 [资料提取与来源核对](../_qto-shared-evidence/references/按任务阶段读取.md#原始资料与计算) 选择相应公共资源；未进入提取阶段时不展开其他资料类型。
3. 读取 [计算与证据流程](references/计算与证据流程.md)、[常规计算逻辑](references/常规计算逻辑.md)、[专业规则与成熟状态](references/专业规则与成熟状态.md) 和公共 [推算分层协议](../_qto-shared-evidence/references/推算假定与发布分层协议.md)，形成本次采用/试用规则清单。未经真实案例升级的规则可形成推算/暂估，不静默进入正式量。
4. 对每个构件绑定系统、角色、端点/所在分格、规格、数量、净长、接头和来源；立柱、横梁、主龙骨、副龙骨、沿边构件及连接件分别输出。
5. 只有明细表已明确构件数量、单件净长及单位质量时，才可用 `scripts/calculate_framing_reference.py` 做参考算术；脚本不从间距或分格自动生成构件。
6. 按 [结果检查与输出](references/结果检查与输出.md) 和公共 [最小成果字段](../_qto-shared-evidence/references/通用成果字段与状态.md) 出具结果；对照 [案例与接入清单](references/案例与接入清单.md) 标成熟度。

## 正式采用停止与局部分支继续

以下条件只阻断受影响结果进入正式量；已确认骨架、常规排布方案和多方案敏感性继续输出，无法形成有意义候选才使用 `null`：

- 分格、排布起止、端部收口、洞口加固或转角做法会改变数量但未明确；
- 只有“@间距”而无净范围、首末根、避让及加密规则；
- 型材规格、壁厚、单位质量、搭接/接头或损耗口径缺失；
- 设计图与深化图、材料表、节点图冲突；
- 幕墙构件是否属于主体承重钢结构无法裁决；
- 综合支吊架没有批准方案和荷载/排布清单。

受影响正式结果为 `null`；可复算的常规排布另列方案暂估，不得按面板面积乘隐藏经验含量补齐。

## 禁止

- 不用最近文字、图层名或相同颜色自动确定规格和归属；
- 不把面板面积、墙面积或吊顶面积直接换算龙骨量；
- 不默认首末根、加密、接长、损耗、连接件或单位质量；
- 不与主体钢结构、机电支吊架、围护面板重复计量；
- 不调用旧 Skill、旧归档脚本或旧结果。

## HTML图面复核交付

原图算量形成对象明细后，默认按公共[HTML交互复核与批注](../_qto-shared-evidence/references/HTML交互复核与批注.md)生成可离线点选的复核页，支持问题分组、成员例外、结论与原因、保存和处理回执。沿用共享生成器，不在项目重写前端；收到意见后由本专业复算并更新采用状态，用户方法意见不自动等于数值确认。纯问答、无图表内复核及用户指定其他形态按实际范围处理。
