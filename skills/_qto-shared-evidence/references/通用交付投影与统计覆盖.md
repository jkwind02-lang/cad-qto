# 通用交付投影与统计覆盖

本入口只把明确业务事实投影成共享交付数据，不识图、不重新量算、不替代采用依据或人工核准。原图/原清单、原量、本次量、未知值、旧意见和历史明细不得截断或改写。

## 正式入口

```text
python skills/_qto-shared-evidence/scripts/convert_qto_review_delivery.py --input 原视图.json --mapping 字段投影映射.json --output 新交付视图.json --report 转换回执.json
python skills/_qto-shared-evidence/scripts/build_qto_review_html.py --input 新交付视图.json --output 交付复核页.html --local-only
```

映射使用 `qto-review-delivery-projection/1.0`；示例为同目录 `delivery-projection-example.json`，对应去标识合成用例 `tests/test_review_projection_statistics_20261018.py::projection_case`。不同项目提供数据与JSON映射，不新增项目Python适配器或修改项目JS。输出不覆盖已有文件。映射表达式只读JSON，不执行Python、JavaScript、模板代码或外部命令。

映射顶层包含 `assistant_work_complete: true`、`items`、`row_sources`，可选 `retired_member_keys`、`missing_groups`、`missing_grouping`、`decision_targets`、`coverage_baseline`。`items/row_sources/missing_groups`各以 `path` 定位字典或列表、可用 `children` 遍历父记录内的列表、用 `fields` 投影字段。上下文 `root/value/parent/key` 分别为原视图、当前记录、父记录及字典键或序号；`record_locator`是转换器生成的原记录JSON pointer。

字段表达式支持 `$path`（缺省会报错；可显式设 `default`）、`$literal`、`$first`（第一个非空值）、`$enum`（明确枚举映射）、`$join`、`$in`、`$each`（列表映射）、`$as_list`、`$lookup`（字典关联）。直接读取的 `null` 原样保留；不使用布尔默认值把空值换成零。未知角色不能依据名称、说明关键词或数量正负推定。

条目投影字段为 `id/title/unit/quantity/original_quantity/dimensions/coverage_state/scope_hint`，局部或未知条目另列 `pending_scope`；可选 `display/original_unit/comparison_item_id/original_row_present/current_zero_evidence`。明细投影字段为 `id/item_id/title/unit/quantity/state/basis/member_keys/evidence_member_keys/scope_hint/coverage_state`，也可直接传完整 `scope/coverage`。主量须有 `evidence`；参考须有 `reference_relationship/reference_prerequisites`，有已证逐行包含关系时给 `reference_current_row_ids`；历史/退役须有 `history_reason`。所有原记录保存在 `source_records`，同ID的参考补充源只能显式 `duplicates: replace`，两份原记录均保存。

## `delivery.items` 与角色

`delivery`沿用 `qto-review-delivery/1.0`。新增可选 `items`；不提供时保持旧数据、指纹和意见规则。提供时，每项包含：

| 字段 | 含义 |
|---|---|
| `id/title/unit` | 稳定业务编号、名称、本次量单位 |
| `quantity/original_quantity` | 显式数字或null，null与已证0不可互换 |
| `original_unit` | 原量单位；省略时为本次单位，异单位必须填 |
| `scope` | `included/excluded`明确范围 |
| `coverage` | `state=complete/partial/unknown`、`computed_scope/uncomputed_scope` |
| `current_row_ids/reference_row_ids/historical_row_ids` | 引用完整 `quantity_rows` 的稳定编号，参考和历史不回流主量 |
| `dimensions` | 文字键值对象，供楼栋/系统/类别筛选 |
| `display` | 可选对象，如规格、数量说明、显示顺序及默认可见性，不能覆盖规范数字 |

所有明细必须有条目归属；`items=[]`不能隐藏非空明细。无原清单仍可提供独立工程量条目，原量为null、`original_row_present=false`。同一主明细不得重复计入两个条目。条目主量与主明细合计仅以浮点容差核对，不重写原数字。显式有据本期排除可0，并保留 `current_zero_evidence.reason/source_refs`；历史退出而本期未证可null。

正式比较明细中 `excluded.period` 省略等同 `current`，沿用“本期全部已证排除须0”。新增 `historical` 只适用于同时完整保留在正式delivery历史/退役集合的明细，不再从历史退出推出本期0；无delivery的旧格式不接受此新例外。

## 冻结采用记录的迁移

`recorded_adoption`须声明原记录的 `role_path` 及明确 `current_roles`；只允许这些原记录进入 `adopted_record`。它以 `delivery.projection_provenance.input_sha256` 绑定实际输入字节，并在每条明细 `evidence.provenance` 保留 `record_id/record_locator/role_path/role_value/input_sha256`。

契约强制 `verification_scope=frozen_record_identity_only`、`new_measurement_performed=false`和固定说明：“冻结采用记录迁移，仅核对记录身份，本次未重新量算或核证几何及规则输入，不代表正式核准。”即使输入省略或改写notice，规范化也会恢复这项边界。来源已采用记录不提升为本轮重新核证，不凭旧方法已批补造 `input_facts`。原 `sources/source_sha256`身份保持；delivery的改变只重绑定结果指纹，使旧意见可作为历史保留而非自动恢复为当前。

对缺件中已有事实，可用 `recorded_missing_facts.facts_path` 保留原事实文本及原JSON定位，标明同样的迁移验证范围，不能把原记录身份核对说成本轮重新核图。

## 参考包含关系

`relationship=includes_current`且 `association_state=resolved`（默认）时，逐项校验关联主明细存在、单位相同、范围包含及参考数值不小于所指主量。不能以换状态绕过已声明的正式关系。

多条主明细存在明确互斥已算范围且物理成员不重复时，另校验参考不小于有据互斥量合计；参考明确关联某条目全部主明细时，也不得小于该条目已核对的唯一当前量出口。范围或物理成员重叠、且没有明确唯一量出口时，不盲加未证关系，只保留能证明的逐行下限。此校验仅检查包含声明一致性，不把参考加入主量。

原资料只有范围级关系声明但未给逐主明细对应时，规范化可证关系为 `relationship=unknown`，保留 `source_claimed_relationship`、`association_state=scope_only`、`scope_statement`和完整原记录。显示“原记录关系声明；逐明细包含范围未证，不得相加。”不能自动把同清单项全部主量挂入参考。无本次主量仍保留原参考值；未知关系、历史或参考均不得默认相加。

## 常驻比较统计

`delivery.comparison_statistics`为 `qto-review-statistics/1.0`，包含完整逐项 `items`、`slices`、`counts`、按单位的 `by_unit`，以及 `comparable_items/comparable_segments`。没有跨项数量总计或跨单位数量总计。

逐项保存 `item_id/unit/original_unit/current_quantity/original_quantity/coverage_state/comparison_state/reason/delta/rate/source_segments/tags`。每个来源段保存 `source_id/unit/state/reason/delta/rate`；只有正式资格成立才保留差额与比例。比例为小数，展示百分数时乘100。多来源分别保留来源段，不拼接为一个差额。

没有比较来源段时仍消费明确 `original_row_present`：true且原量null为“原行存在、原量未填”；false才声明无原行。未声明存在性时保留unknown，不从null猜不存在；正式比较的 `kind=extra`也提供明确的无原行依据。覆盖发现项行号稳定排序，避免进程哈希种子使反馈结果指纹漂移。

切片 `all/current_unknown_original_known/positive/negative/consistent/comparable/zero/not_comparable/extra/has_reference/complete/partial/coverage_unknown`完整列出稳定 `item_ids/count`。正负按实际差额符号，`zero`为精确零，`consistent`含正式容差内数据，允许与正负类别交叉。`overlapping_slices=true`及说明必须展示，分类数字不能机械相加；不可比类别为条目口径，可比段数和条目数分别标明。

## 独立覆盖检查

无覆盖基准时 `coverage_check.status=unknown`、`baseline_state=unavailable`，不能写“无遗漏”。数值相同、容差内、原量有值或只有名称的空清单行，都不能自动形成图上应算对象。

显式 `coverage_baseline` 格式：

```json
{
  "state": "explicit",
  "source_refs": [{"source_id": "RECORD", "locator": "原对象表/第1页"}],
  "objects": [{
    "id": "physical-object-1",
    "item_ids": ["ITEM-1"],
    "member_keys": ["OBJECT-1"],
    "row_ids": ["DETAIL-1"],
    "scope": ["一号支路"],
    "relationship": "one_to_one"
  }]
}
```

`scope`、预期物理成员或明细关系必须明确。合法多对一用 `relationship=aggregate`，合法拆分用 `split`，均须具体 `basis`；已证范围外排除须 `excluded=true`、`basis/source_refs`。检查分别报告 `uncovered_object/missing_detail/no_evidence/one_to_many/many_to_one/scope_uncovered/explicit_exclusion`，不读取差额来判漏量。

基准声明的 `item_ids` 必须由这些条目自己的 `current_row_ids` 承接。即使位置相同、成员存在且每行只使用一次，跨条目错接也报告 `wrong_item_ownership`，保留 `actual_item_ids`，并按本条目未承接继续报告未覆盖；尚未指定条目的基准对象报告 `item_unassigned`。检查不自动重归条目或修改工程量。

输出 `coverage_check`完整包含逐项 `items`、全部 `findings`、按问题代码 `counts`、总状态和原因。逐项保留 `expected_scope/covered_scope/missing_scope/excluded_scope/row_ids/status/findings`；无基准或本项无明确基准时仍为unknown，不把局部检查提升为全项目完整性结论。

## 同源消费和验收范围

HTML与Excel均读取同一规范化view和完整delivery；`qto_review_delivery.canonical_delivery_data(view)`提供剔除生成检查、统计和覆盖派生字段的业务深复制。`result_fingerprint`绑定包含delivery的规范结果；原source身份不因迁移改变。反馈快照保留完整delivery，旧意见历史不下发为当前取舍。

去标识反例和合法对照覆盖null/0、历史退出、本期已证排除、无图/无清单、混合单位、完整/局部、参考包含及未证关联、已批方法但输入未证、真实取舍和旧反馈。真实项目转换核查只证明冻结数据保全、接口和生成行为，不等同于真实DWG数量准确性、正式采用或双侧发布验收。
