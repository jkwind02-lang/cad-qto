# 当前采用与缺资料只读交付契约

适用于共享生成器 `build_qto_review_html.py`。在原 `qto-review-view/1.0` 或 `1.1` 中显式增加 `delivery`，其 `schema` 为 `qto-review-delivery/1.0`。未声明该扩展的输入沿用原界面、校验和结果指纹。不是项目专用适配器，不需外部 JS 或 CDN。

**当前采用仅指本轮工作采用，不代表工程正式核准。** 专业宿主负责采证、计算与事实真实性；共享校验器核对证据声明、来源身份、规则输入状态、范围与角色关系，不自行认定图纸事实。没有证据的数值不得声明为 verified；方法或规则已获同意不等于本次输入已核实。

## 1. 正式入口及必填字段

`normalize_view()` 在既有对照校验后调用 `normalize_delivery(view)`，再绑定结果版本；无图页、无清单及无对象均可使用本扩展。仍须提供真实持有的任务资料/核查记录等来源文件身份 `sources`，不得虚构图纸或来源哈希。仅有清单名称、两侧均无量也无对象不自动生成业务裁决。

| delivery 字段 | 语义及校验 |
|---|---|
| `mode` | `read_only` 或 `decisions`，无业务取舍必须只读 |
| `assistant_work_complete` | 必须为 true；仍可识图、匹配、计算或纠错时先做完，不用只读卡替代执行 |
| `adoption_boundary` | 规范化时固定为“当前采用仅指本轮工作采用，不代表工程正式核准。”，始终展示，不允许输入覆盖 |
| `adoption_note` | 可补充分工边界，不能替代固定的非正式核准说明 |
| `current_member_keys` | 当前采用对象稳定 `catalog_key` 集合，须等于所有 current 明细 `member_keys` 的并集 |
| `source_evidence_member_keys` | 只作来源证据定位，不展示为当前量；其对象原记录的数量不进入主量 |
| `retired_member_keys` | 退役/历史图元，只供历史读取，不能回流当前量或参考定位 |
| `quantity_rows` | 全量明细，见第2节；界面每页60项，分页与搜索不截断数据 |
| `missing_groups` | 真正缺外部资料的共性及逐项缺件，见第3节；没有时用 [] |
| `decision_targets` | 真正业务取舍，见第4节；没有时用 [] |

三个成员集合必须互斥并完整覆盖 `objects`，不能依赖页面白名单。无对象时三个集合都为空。这里的角色按本轮结果确定，不从历史意见或保存的 HTML 反向覆盖。

单项业务取舍若属于尚未答复的共性问题，须在 `decision_targets` 显式开放该共性取舍；否则生成前拒绝，不形成前置问题被隐藏、单项又无法保存的界面。已关闭的共性不构成待答前置条件。

## 2. 工程量明细

每条明细须有稳定 `id`、`title`、`unit`、`quantity`（有限非负数或显式 null）、`state`、`basis`、`scope`、`coverage`、`member_keys` 和 `evidence_member_keys`。

- `scope: {included: [范围键], excluded: [范围键]}`，使用能落到具体对象/回路的业务范围键。适用范围非空，排除范围显式填写，无排除用 []。
- `coverage: {state: complete|partial, computed_scope: [...], uncomputed_scope: [...]}`。已算/未算范围互斥并完整覆盖 included；complete 不得有未算范围，partial 必须列出未算部分。
- `member_keys` 连接明细与图元的稳定身份；不能使用仅证据图元充当采用成员。没有几何时可为空，仍保留资料证据定位。
- `evidence_member_keys` 只连接来源证据。当前或参考明细不能引用退役图元。图面标签只显示身份与证据角色，不把对象原记录数值回填主量。

`state` 有四种：

1. `current` 为当前主量，quantity 不得 null，computed_scope 非空，evidence.state 必须 verified。已核实的明确0可保留；缺值不推成0。
2. `reference` 为参考值，允许 null，必须提供参考关系及前提；不能与主量默认相加。
3. `historical` 和 `retired` 只进历史记录，必须提供 `history_reason`；不提供当前定位按钮。

证据 `evidence`：`{state: verified|pending, method: measured|rule, source_refs: [{source_id, locator}], input_facts: [...]}`。verified 需要至少一处具体来源定位；source_id 必须存在于视图 sources。规则推算的 current 明细还必须有非空 `input_facts`，每项 `{id, statement, state: verified, source_refs: [...]}`，每个输入都必须已证并可定位。规则已批但输入 pending 或没有输入事实，主量拒收，允许改列参考待核。

reference 明细额外必须有：

```json
{"reference": {
  "relationship": "includes_current",
  "current_row_ids": ["M1"],
  "prerequisites": ["本方案包含M1；其余路径仍需标高复核"],
  "addition": "do_not_add"
}}
```

relationship 可取 `includes_current`（包含所列主量）、`excludes_current`（不含）、`unknown`（关系未知）。包含时必须列明当前主量 id，单位须一致，参考范围须覆盖该主量范围，已知参考数值不得小于所指单条主量。该校验不假定多条明细可相加：交叉范围与去重仍归专业计算责任。未知关系不得被页面解释为可相加。

## 3. 缺资料只读交付

`missing_groups` 每个共性或子项包含：

- `id`、`title`、显式 `scope`；子项适用范围必须为父项 included 的子集，并排除父项已排除内容。
- `verified_facts: [{statement, source_refs}]`，列本子项已核事实；没有时显式 []。
- `minimum_required: [{id, description, scope, provider, impact, recompute_action}]`，逐件给出最少具体缺件、窄范围、提供方、影响和补齐后助手回算动作。缺件 scope 必须在本项范围内。
- 可选 `children`。父项没有直接缺件时，须至少有一个完整子项。子项不继承父卡事实、缺件或全部适用范围；字段省略会拒收。

本接口不把助手可继续执行的工作标成外部缺件，也不把无量无对象的名称壳推给用户。必须先完成现有资料足以支持的工作，再把真正外部缺件按提供方交清。

## 4. 真实业务取舍及意见

仅当确实有业务选择时使用 `mode: decisions`，提供非空 `decision_targets: [{kind: issue|common, id, reason}]`，关联既有 comparison 的 handler=decide 问题或共性问题。reason 写明需要取舍的业务内容。1.1 的既有单入口、共性答复、特例及冲突机制继续处理真实取舍；没有真实取舍时不挂载审核填写区，不强制项目零裁决。

共性目标的既有适用 issue/item 可以填写特例；其他事项只读。缺件列表不自动转成审核表单。本扩展不改0008完整入口与迁移范围，也不代替专业助手重算。

## 5. 版本、保存及反馈交接

delivery 中采用、证据、参考、覆盖或缺件语义变更会进入对象/组/对照及全局成果指纹，避免同一来源文件下错误沿用旧意见；采用整体交付上下文保守失效，宁可显式重核。没有 delivery 的1.0/1.1指纹不增加空字段。

保存单HTML、导出JSON、导入合并及 `read_qto_review_feedback.py` 均消费该契约：

- 当前 `delivery_snapshot: {result_fingerprint, delivery}` 始终由当前视图重建；导入的旧快照只能保存到 `historical_delivery_snapshots`，不得成为当前采用依据。
- 退役对象意见标 unmatched；只读交付中的其他旧意见标 stale，保留文字及完整修改历史，不下发改量动作。旧图页已移除的自定义标记只留历史，不重新挂入图面。
- 反馈交接 JSON 直接携带当前 delivery、当前快照及历史快照；真正业务意见仍通过已有 issue/common/特例动作交接。所有交接 `quantity_changes` 仍为0，意见须由专业回算落实。

界面是离线自包含单HTML，只有用户主动调用插件反馈时使用原有网络反馈服务。只读交付默认展示“工程量”“资料缺口”，参考与主量分别列示，不制造跨单位总数。历史在单独入口可读。

## 6. 可直接复用的非项目示例与验证

`tests/review_delivery_fixture.py` 为虚构“海岚仓库”合成用例，包含局部/完整覆盖、m/台混合单位、主量/包含主量的参考/null参考、仅证据图元、退役量、逐支路缺件和可选真实取舍。`view()` 的返回值直接交共享生成器，无项目适配器或前端补丁。

```text
python -m pytest tests/test_review_delivery_20261018.py -q
python skills/_qto-shared-evidence/scripts/build_qto_review_html.py --input 输入.json --output 新成果.html --local-only
python skills/_qto-shared-evidence/scripts/read_qto_review_feedback.py --view 输入.json --feedback 保存交付.html --output 交接.json
```

该组合覆盖合同输入正反例、旧指纹黄金值、无图无清单、零/真实裁决、未知值、历史与退役、共享生成器、模拟DOM交互、单HTML保存恢复、导出及反馈读取。它不是实际工程量验收，也不等同于原生浏览器视觉验收。
