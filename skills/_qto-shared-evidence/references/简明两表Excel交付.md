# 简明两表 Excel 交付

用户需要 Excel 时，使用共享入口 `scripts/build_qto_delivery_excel.py`。输入与共享 HTML 生成器相同的正式 `qto-review-view` JSON，经同一个 `normalize_view` 校验后生成“工程量汇总”“工程量明细”两张主表。不自动生成 HTML，不因有此入口要求每次任务同时交付多种格式，不重新识图、量算或批准工程量。

## 正式调用

在共享 scripts 所在目录执行，输出使用新的业务名称；已有工作簿与回执拒绝覆盖。

```powershell
python build_qto_delivery_excel.py --input "D:\业务任务\正式交付视图.json" --output "D:\业务任务\工程量汇总明细.xlsx" --report "D:\业务任务\工程量汇总明细_核对回执.json"
```

需要核对已有 HTML 与 Excel 是否同源时，加 `--html "D:\业务任务\工程量复核.html"`。入口只读取共享生成器内嵌的 payload，不运行页面脚本。实际 HTML 业务数据或结果版本不同会失败，不输出新工作簿。没有传 `--report` 时，默认保存同名 `.核对回执.json`。完整逐项核对在回执文件，命令行只打印摘要。

Python 环境需要 `openpyxl`。本入口不启动 Excel；数据输出不使用公式或缓存值，不需要原生重算。需要原生打印、宏或宿主兼容验收时另按实际用途检查，并遵循独立隐藏实例的退出保护。

## 输入与兼容边界

- 正式采用数据位于 `delivery`，优先读取可选 `delivery.items` 的条目，明细取 `delivery.quantity_rows`。原量及其单位、当前量、范围、覆盖、主量/参考/历史归属须先由专业结果确定。
- 已有 `delivery/1.0` 没有 `items` 时，兼容为每条 quantity row 一条汇总；参考或历史行的汇总本次采用量保持空白。它不会补出并不存在的原清单量或可比结论。
- 没有 `delivery` 的旧视图明确拒绝。先使用正式 `convert_qto_review_delivery.py --help`，按该转换入口要求提供采用与证据映射；不能把旧技术合计直接当成当前采用量。
- `items.original_unit` 可选，缺省采用该条 `unit`；异单位原量须明确填写原量单位。比较通过 `comparison_item_id`（缺省条目编号）绑定正式比较条目。没有正式可比条件或当前量/原量/单位不一致，不输出业务差额。多个独立来源段不跨来源相加，完整比较段保留在业务记录。

## 两张主表

汇总表优先显示条目编号、名称、必要规格/维度、范围、单位、本次采用量、原量及原单位、可比差额/比例、具体原因、覆盖情况及三类明细入口。所有条目保留，可筛选，不按隐藏行或默认筛选丢记录，不汇总混合单位。

明细表独立列出本次主量、参考量、历史及退役量；仅对应状态的数量列写入数值，其余留空。参考是否包含主量、前提和范围同时保留，不能与主量相加。缺件以具体提供方、影响范围及回算动作追加在明细表；全部原业务记录在同表最后一列完整留档。

序号使用正式稳定编号；汇总主量/参考/历史入口跳至对应第一条明细，每条明细可返回所属汇总。多个关联编号全部可见。内部链接使用由稳定编号生成的工作簿命名定位，不依赖用户可见中文名称拼接。两个表保留标题行、筛选和冻结窗格，不隐藏记录。

未知数量保持 Excel 空单元格，有据数值 0 保持数字 0。原文本以文字写入，即使以等号开头也不会转成公式。长依据与完整业务记录超出单元格安全容量时逐字符分段续存，每段不超过 15000 字符，兼顾中文和 UTF-16 字符，不截断记录。日常阅读可展开单元格或编辑栏，超长内容连续续行查看；原完整业务结构也可由末列连续 JSON 记录核对。

冻结采用记录 `evidence.method=adopted_record` 强制在两表开头及对应明细证据列显示“来源采用记录迁移、本次未重算、仅核对原记录身份”的边界，不依赖可选 `notice`；不得把原记录状态写成此次重新核实几何或规则输入。

## 生成检查与验收范围

每次保存后重新打开临时工作簿，核对每条汇总的当前量、原量、单位和业务差额，每条明细的状态、数量、单位、成员、完整依据及完整业务记录。全部 delivery 业务字段（含缺件、取舍和扩展字段）另做精确重组指纹核对，再生成正式成果及回执。回执保留输入与工作簿 SHA256、`source_sha256`、`result_fingerprint`、`delivery_sha256` 和逐项检查。完整业务记录的指纹精确相等；Excel 数字因格式序列化采用不超过 1e-14 的浮点复核容差，完整 JSON 仍保留输入数值。

同源核对通过是交付数据保全检查，不代表重新量算真实 DWG、人工工程量核准或双宿主发布。交付前按用途检查两表中文、长说明可查看、空值/零值与导航可读性；需要正式打印时再核验实际分页。
