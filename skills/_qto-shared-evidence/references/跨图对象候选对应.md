# 跨图对象候选对应

用于模型已经从不同视图提取观察对象后，按明确约束筛选对应候选。工具检查来源文件身份、对象上下文和约束一致性，不代替图面语义判断，不按最近坐标配对，也不产生工程量。

## 可调用入口

```powershell
python -B scripts/qto_object_correspondence.py --input 跨图观察与请求.json --output 跨图候选与解释.json
```

Python 接口：`resolve_correspondence(document, base_dir=None)`。相对源路径按 `base_dir` 解析；CLI 按输入 JSON 所在目录解析。调用复用 `qto_cad_source_contract.verify_source_file`，来源哈希变化即拒绝旧观察。

## 输入

`schema_version` 为 `qto-object-correspondence/1.0`，包含下列数组：

- `sources`：`source_id`、`kind`（`drawing` 或 `technical_document`）、`path`、`sha256`。人工底稿不作为对象对应证明。
- `observations`：每项有 `observation_id`、`source_id`、`locator`（实体路径、页码或明确图面位置）、`view_id` 和 `kind`（`instance`、`port`、`detail`）。模型从图纸提取 `building`、`floor`、`system`、`object_tag`、`detail_index`、`connection_role`、`continuation_id`、`object_type`、`specification`、`variant`；没有依据时省略或留空值 `null`。字段有值时使用非空文字。`identity_key` 可用于本轮模型有证据建立的同一对象标识，不从坐标近邻自动产生。
- `requests`：`request_id`、`relation`、`from_id`、`target_ids`（本次检查的候选观察 ID）、`match_fields`（明确要求相等的上述字段）。目标列表由模型或已有检索工具提供，不声称已经搜索全部图纸。
- `interpretations` 可省略。只在模型完成判图、确需向下游交接时填写，见后文。

三种关系具有不同约束和复用方式：

| relation | 对象种类与必需上下文 | 身份约束 | 允许的对应方式 |
|---|---|---|---|
| `same_physical` | 同类 `instance` 或 `port`，楼栋、楼层、系统相同；端口还要求连接角色相同 | `match_fields` 至少含 `object_tag` 或 `identity_key` | 同一实物可有平面、剖面和系统等多个观察，不强制一对一 |
| `floor_continuation` | 两侧均为 `port`，楼栋、系统、连接角色相同，楼层不同 | 至少含 `object_tag`、`continuation_id`、`identity_key` 之一 | 一个观察可有多个待核候选；数量出口另有唯一实物 ID |
| `detail_applicability` | `instance` 对应 `detail` | 必须以 `detail_index` 作匹配约束；型号/规格条件可追加 | 多个实际实例可使用同一典型详图；重复同号详图保留多候选 |

已知楼栋、系统、连接角色冲突不能通过省略 `match_fields` 绕过；同一实物和典型详图关系中，双方已知的类型、规格或变型冲突同样保留。典型详图可不限定楼栋或楼层，这不自动扩展其其他适用条件。不同标注用语的同义关系应由模型先依据本项目证据说明并规范字段，工具不预置项目词典。

示例请求（所列 ID 必须已登记）：

```json
{
  "request_id": "立管接口对应",
  "relation": "floor_continuation",
  "from_id": "下层观察",
  "target_ids": ["上层候选甲", "上层候选乙"],
  "match_fields": ["continuation_id", "object_type"]
}
```

## 结果与模型判读交接

每个请求输出所有候选的匹配项、冲突项和缺失约束，状态为：

- `unique_candidate`：显式约束完整且只有一个匹配候选；仍为 `candidate/unreviewed`。
- `multiple_candidates`：多个约束完整候选，不按坐标距离或数量选择。
- `insufficient_constraints`：仍有可能对应的对象，但缺少识别或上下文约束。
- `no_candidate`：本次目标列表均有冲突；不表示整个资料库里不存在对应对象。

候选不能直接改成正式采用。模型判图后可添加 `interpretations` 项：`interpretation_id`、`request_id`、`target_id`、`decision_origin: model`、`basis`、`source_refs`。每侧引用必须分别包含 `observation_id`、`source_id`、`locator`，并与输入观察一致。可以另外引用补充来源；文件哈希在本次调用再次验证。工具只核验身份和引用，不验证自然语言解释是否正确，也不认证人的签字。

只有约束完整且无冲突的目标可被显式选择。缺字段时先回图补齐观察，不能靠一段解释文字跳过冲突。输出 `pairings` 一律为 `working/unreviewed` 且 `formal_adoption_allowed: false`。一对多观察和多实例共用典型详图可以分别作多个解释，不强制唯一匹配。

### 向既有管网拓扑交接

仅 `floor_continuation` 的解释可声明 `export_cross_view_link: true`，并提供 `link_id`、`physical_id`。两侧观察须有 `route_ref`，格式为 `{segment_id, end: start/end}` 或 `{segment_id, part_index, parameter}`（参数 0 到 1）。`locator` 必须定位到该管口，不能仅引用整台多端口设备。每个 `physical_id` 指向同一段跨图延续实物，不能重复导出；多个楼层之间不同实物段应有不同 ID。

导出同时按无向管段端点配对和无向原始来源管口配对去重。后者由源文件哈希、逐管口定位、楼栋、楼层、系统和连接角色组成，允许同一典型图明确应用于不同实际楼栋/楼层。正向、反向、改观察 ID、改视图名称、改连接/实物 ID，或将相同源文件登记为另一来源 ID，均不能给同一实际连接增加数量出口；同一来源管口的管段别名也不能重复导出。不同原始管口之间的独立连接仍可分别交接，此检查不将所有关系强制为一对一。当前不解析自由文本定位的同义写法；模型须使用稳定、逐管口定位，既有管网引擎仍须执行端点和实物重复检查。

输出 `cross_view_links` 含 `link_id/physical_id/a/b/system/source_ids/basis` 及模型工作状态，可传给现有 `qto_pipe_topology.prepare_network`。管网引擎继续校验实际管段、系统和空间归属。本工具不声明 DN 连续，不提供起止标高，不设置 `route_is_vertical`，不产生连接长度。标高组件另行提供有来源、基准和测点类型的事实；同一实物多视图及典型详图适用关系只输出证据配对，不生成拓扑连接。

## 验证边界

跨楼栋同号、供回水错配、多楼层同号、重复详图、源文件变化和证据定位不一致均有反例；一对多视图、多实例共用详图可通过。集成测试将显式跨层配对送入原拓扑计算器，未提供高度时竖向仍保持未决。合成验证证明约束和交接行为，不代表新项目已完成独立识图，也不评价未列入候选列表的遗漏。
