# 局部识图与对象操作

索引属性以原始 ATTRIB 句柄和完整实例路径标识；同一块允许多个同名属性。父块的 `attributes` 是兼容摘要，重复标签时须读取 `attribute_instances` 或实际子属性对象，不能据摘要抹掉不同值、重合对象或阵列单元。

本工具把源图的可定位对象交给模型查看，并把模型逐对象形成的判断交给现有计算链。它不按图层、块名、最近文字或几何相似度自行认定工程对象。源码中不保存项目名称、句柄、固定范围或答案。

## 入口与来源

脚本：`scripts/qto_recognition_workbench.py`。需要 `ezdxf`，使用共享中性几何、单位与模型识别台账模块。首轮直接读取经 SHA-256 校验的 DXF；已有中性取证包可取其中 `exchange_dxf` 与 `authoritative_source` 字段组织来源文件，无需再复制图元。它不能代替 DWG 转换、代理对象解释或动态块可见状态核验。

来源 JSON：

```json
{"path":"D:/项目/工作区/交换副本.dxf","sha256":"实际DXF的SHA256","authoritative_source":{"path":"D:/项目/原图.dwg","sha256":"实际DWG的SHA256"}}
```

来源本身即正式 DXF 时省略 `authoritative_source`。若来源为 DWG 转换件，索引检查相邻的 `.dxf.export.json`；缺转换记录或仍需几何复核时保留提示，不声称原 DWG 已完整读取。

读取同时捕获解析器的源身份诊断与警告。重复实体句柄导致稳定实例身份冲突时停止关联，不采用解析器重分配的身份冒充原句柄；若仍可生成观察索引，非空 `source_identity_issues` 也会阻止 `apply`。旧索引缺此字段时需要重建。没有警告只表示未报告冲突，不证明所有原图实体已无损保留。

大图优先局部索引，范围从实际总览确定。以下坐标仅说明命令格式，不是任何项目默认范围：

```text
python -B qto_recognition_workbench.py index --source 来源.json --bounds 0 0 10000 8000 --output 局部索引.json
python -B qto_recognition_workbench.py context --index 局部索引.json --query 查询.json --output 局部上下文.json --svg 局部上下文.svg
python -B qto_recognition_workbench.py family --index 局部索引.json --object-id 真实实例ID --output 同族候选.json
python -B qto_recognition_workbench.py apply --index 局部索引.json --operations 识别操作.json --ledger 模型识别台账.json --output 管网推算输入.json
```

不传 `--bounds` 时展开指定布局，适合已知大小可控的图纸。大图递归展开可能耗用大量内存，不能把全布局展开作为每次局部识图的前置条件。

## 局部上下文与完整性

查询 JSON 可组合 `bounds:[xmin,ymin,xmax,ymax]`、`text_pattern`、`object_ids`、`entity_types`、`layers`。`include_descendants:true` 展示已索引的容器后代；`context_padding_raw` 从匹配对象向外查找上下文。`neighbor_distance_raw` 只给出三维端点距离候选，不自动确认连接。数值以本图原始坐标单位解释。

`max_objects` 只控制展示数量，被省略的 ID 列在 `omitted_object_ids`。无可定位范围的对象和未展开容器在 `unlocated_object_ids` 完整列出，`unlocated_count` 给出总数，`unlocated_objects` 仅提供最多50条摘要，完整记录从同一索引查询。不能把摘要截断解释为未知对象减少。局部索引先缓存块定义的可测量范围，再展开相交实例；部分范围不能证明位于窗口外的块保留 `pending_scope_uncertain` 容器。该状态不等于其后代为零，也不等于范围外。需要扩大窗口、查看定义、原生 CAD 补读或另行识图处置。正权样条控制点和直线/圆弧多段填充边界可提供保守定位范围，但仍无测量结果，不以控制折线或外框作为工程量。

完整路径区别父块、子图元与阵列单元；阵列按实际行列和 OCS 位移展开，重合单元也保留不同实例 ID。当前记录里的几何均已转换为当前布局 WCS。不可见图元、疑似动态块、外部参照与未知几何保留问题。文字以锚点定位；SVG 是识图辅助预览，不是原生 CAD 的完整字体/遮挡/打印呈现。

SVG 的 1 基序号对应同份上下文 JSON 的 `objects` 顺序；二者记录相同 `index_sha256`。`family` 只按类型及几何长度分布缩小候选，展示属性、图层、名称差异与同名不同几何的例外；相同描述不证明构形或工程用途相同。

## 将已识别对象交给管网计算

沿用 `qto-model-recognition-ledger/1.0`。每条纳入、排除或容器记录要有实际对象 ID、源文件证据、图面观察和适用范围。模型判断始终为 `working / unreviewed`；工具只能核对来源及对象范围，不能证明一段文字判断正确，更不能用通用“已查看”话术充当逐对象审阅。

操作文件的主体：

```json
{
  "index_sha256":"与当前索引一致",
  "network_id":"本次网络标识",
  "scope_object_ids":["真实管线ID","真实标注ID"],
  "scope_basis":"本次完整工程边界及参考对象的实际判定",
  "unit":"m",
  "parameters":{"snap_tolerance":0.0001,"gap_max":0.1},
  "parameter_basis":"按本图尺寸、精度与图面复核确定的依据，不沿用示例数值",
  "assignments":[{"adjudication_id":"对应台账ID","object_ids":["真实管线ID"],"role":"pipe_centerline","system":"本次实际系统","space_id":"实际图页或楼层空间","observation":"为何这些几何是该系统管道中心线"}],
  "relations":[],
  "endpoint_review":{"complete":false,"basis":"实际末端覆盖情况","unresolved_object_ids":[]}
}
```

单位正常时依图中 INSUNITS 换算。INSUNITS 未设时，仅允许通过 `unit_declaration:{raw_unit,adjudication_id,annotation_object_ids,observation}` 引用当前图的真实单位说明并记录模型适用判断。原文有多种单位时须再提供 `source_excerpt`，引用适用于本次量测的完整原文条款，工具按完整单位词核对，不会把“毫米”中的“米”当作米制依据，也不允许节选截断单位词。原图标高以米而尺寸以毫米时必须区分，不改原图单位，不将乘数或损耗混入换算。

允许的 `relations`，每项都需要唯一 `relation_id`、本专业 include 台账的 `adjudication_id` 和具体 `observation`：

| kind | 对象及必要字段 | 转换结果 |
|---|---|---|
| `dn_annotation` | `target_object_id`、`annotation_object_id`、`annotation_text`、`dn` | 当前真实文字的唯一 DNn/nA 匹配后形成推算种子；不按距离绑定 |
| `root` | `target:{object_id,end}`，可填 `root_role:scope_interface` | 根接口位置取真实几何端点 |
| `terminal` | `target`、`terminal_type`，可填 `support_object_ids`；声明 `port_dn` 时必须同时提供 `port_dn_annotation_object_ids` | 端口DN由本图真实标注及模型对应得出，不按类型默认；仍需核对全部末端覆盖 |
| `scope_boundary` | `target` | 范围外接关系未完整的边界，管件不按完整节点宣称 |
| `change_node` | `target` | 已识别的变径/规格传播边界 |
| `junction` | `members:[{object_id,end},...]`、`decision:connect/separate/unresolved` | 由现有拓扑引擎核对坐标、系统、图页后处理连接 |
| `valve` | `object_id`、`connected_object_ids`、`valve_type` 或 `candidate_types` | 在线附件锚点、块族来自真实图元，类型证据与实例 `inferred` 层级传入现有引擎，连接只取模型明确识别的同系统管段 |
| `gap_classification` | `a:{object_id,end}`、`b:{object_id,end}`、`classification`、`quantity_action:scenario/exclude/restore_omission`、可选 `scenario_include` | 交给现有断口引擎；不会手写缺口长度，附件占位仍由引擎检查 |

`target` / `members` 也可使用 `{object_id,part_index,parameter}` 定位真实曲线段上的点，其中参数在 0—1 内。`gap_classification` 限真实路径两端。任何关系均不接受手写位置、长度替换原图。直线、折线和公共读取器支持的参数曲线保留完整几何；曲线不会降级为弦长。

`scope_object_ids` 之外不自动声明已完成。未处置范围内对象以及不能证明范围外的未定位对象列入 `workbench.unprocessed_objects`。存在未决时不能声明 `endpoint_review.complete:true`。输出为既有 `qto-pipe-network-inference-input/1.2`，可直接调用 `infer_pipe_network.py --input ... --output ...`。输出包含原图路径、实例路径、模型识别台账及工作采用范围；局部轴线或源曲线长度不能自行升级为净管长、安装完成量或整项目覆盖。

其他专业可使用同一索引、局部查看、同族候选和原始对象清单；当前 `apply` 不生成其专业计算输入。跨图对应使用相邻的 `qto_object_correspondence.py`，保留候选与模型明确配对的区别，不以近邻或唯一候选自动补量。

## 按问题读取有大小上限的证据页

已有索引的持续识图使用共享 `scripts/read_cad_scope.py`。先写明本次工程问题，再查与问题有关的对象、文字或局部范围；读到证据后由模型解释，并进入模型工作记录或下一项补读任务。原 `workbench context` 接口保持原行为。

查询 JSON 必须包含非空 `question`，可组合上述 `bounds`、`object_ids`、`text_pattern`、`entity_types`、`layers`、`include_descendants`、`context_padding_raw` 和 `neighbor_distance_raw`。分页限制使用 CLI/API 独立参数，不写入查询。示例中的对象 ID 必须替换为当前索引真实对象：

```json
{"question":"这些对象的图面和标注是否支持同一工程用途？","object_ids":["当前索引中的真实对象ID"]}
```

从共享 scripts 目录调用：

```text
python -B read_cad_scope.py --index 局部索引.json --query 问题查询.json --output 证据页.json --artifact-dir 取证产物 --max-objects 60 --max-bytes 24000 --svg 本页预览.svg
python -B read_cad_scope.py --index 局部索引.json --query 问题查询.json --output 下一证据页.json --artifact-dir 取证产物 --max-objects 60 --max-bytes 24000 --cursor 上一页的next_cursor
```

默认 `mode=summary`、`max_objects=60`、`max_bytes=24000`；`--mode detail` 可返回完整对象记录。对象数硬上限为 1000，响应字节数硬上限为 262144。`max_bytes` 至少为 1024，但实际 metadata、问题文本和一个对象引用可能要求更大预算；工具会明确报出不足并退出 2，不返回无法前进的空页。0 匹配的查询可以正常返回空页，其未定位对象仍单独保留。

响应 schema 为 `qto-cad-scope-response/1.0`。CLI 的标准输出和 `--output` 文件内容相同，采用紧凑 UTF-8 JSON 并包含末尾一个换行；`response_bytes` 精确包含 metadata、问题文本、游标和文件引用，整体不超过 `max_bytes`。API 使用 `serialize_response(response)` 获得同一编码。再次缩进或转义为另一种 JSON 编码不属于该字节契约。

每页返回问题、对象摘要、来源和索引身份、已返回数、后续页剩余数、当前页未展示数、未定位数与读取问题计数。`page.next_cursor` 不为 `null` 时按同一查询继续；游标绑定索引、查询、mode、max_objects 和 max_bytes，不能跨条件使用。修改查询或分页限制需开启对应的新读取序列。每页保留 `answer_status="evidence_only_model_interpretation_required"` 和 `unanswered_question_count=1`：读取器提供证据，问题的工程含义仍需模型解释。读完分页不等于完成构件识别、确认连接或覆盖整个项目。

完整内容通过实际产物引用取回：

- `manifest_ref` 指向与索引哈希和查询绑定的取证包，包含完整查询、来源身份、索引范围、读取警告和记录文件。
- `records.selected` 是按稳定对象 ID 排序的完整匹配记录 JSONL；`records.not_selected` 是未被查询选中的对象账，不将其解释为工程对象不存在。
- `records.unlocated` 保存全部未定位对象记录，即使它们没有被窗口或类型条件选中。未定位账与匹配账可能重叠，不能简单相加。
- `page_inventory_ref` 保存当前页对象和完整遗漏范围；`returned_line_range` 与 `omitted_line_ranges` 按 `selected.jsonl` 的 1 基行号、闭区间定位，因此完整遗漏 ID 列表无需返回模型上下文。
- 每个展示对象都有 `detail_ref`，指向该对象未经截断的完整记录，保留几何、源实例路径、属性与问题字段。单个复杂对象超出响应预算时返回摘要与该文件引用；摘要文字截断会明确标识。完整几何供后续量测工具从文件读取，避免再次将整个几何文件塞回模型上下文。

请求 `neighbor_distance_raw` 时，端点距离候选写入独立 JSONL，响应只含数量、引用和覆盖说明。候选仅比较**本页已返回的不同对象之间的直线段端点**，同一对象内部、跨页对象、其他曲线端点及真实工程连接不由此证明。每页 SVG 也只对应本页对象顺序与索引身份；曲线采样用于预览，不改变 detail 中的几何或工程量。

Python API：

```python
read_scope(index, query, artifact_dir, *, cursor=None, mode="summary",
           max_objects=60, max_bytes=24000,
           index_path=None, query_path=None, svg_path=None) -> dict
```

提供 `index_path`、`query_path` 时，同时核对磁盘文件与传入内容并保护输入文件。每次调用都会核验当前来源和索引；缓存产物必须与当前源记录重新推导的内容一致才能复用。它复用已有索引，不重建 DXF，也不声称实现空间增量解析。查询超出局部索引边界时，需要另行扩大索引并建立新读取序列。索引和文件哈希证明内容身份，不证明工程解释正确。

自动生成的文件仅写入 `artifact-dir` 内按指纹命名的取证包；已有且内容不同的证据不会被覆盖。显式 JSON/SVG 输出保护 index、query、源图、权威来源、已声明输入证据和已有取证包，符号链接与硬链接同样核对。其他输出文件沿用工作台的可重写行为。并行任务使用各自的响应/SVG 输出文件，共享同一来源和查询时可以复用相同取证包。
