# 原生文字基类8格式依据

本次支持范围为 `TCH_TEXT`、基类版本8、161数字流与162文字流分离的TU容器。基类的context为隐含0，不读取context字节；不扩大为所有原生类别或所有版本8容器已支持。既有版本9/context16、版本10/context17路径保留。

## 静态来源及定位

来源为本机已安装 `IExtDbObject.grx` 的只读静态指令，不加载、执行或附带该模块。模块FileVersion/ProductVersion均为 `23.0.0.0`，SHA256为 `66ffd0c2185c01dc264c4345cd48839d2908b462347e53dfb7d7f547eea22572`。RVA均相对于此模块映像基址，其他模块或版本不据此直接认定同布局。

- `ItEntBase::DwgInFields`，RVA `0x1c4f0`：`0x1c525`通过filer槽`0x158`读取基类版本。`0x1c548..0x1c556`以阈值9调用`0x217b0`。
- wrapper `0x217b0`：`0x217ba..0x217ca`在版本小于阈值时只设置context=0并返回，不读取filer；版本达到阈值才在`0x217d5`通过槽`0x158`读取context。故版本8在版本字节后直接是首个标量，不能补读context或改头成版本9。
- wrapper标量字节槽`0x158 -> 0x21fc0`、双精度槽`0x188 -> 0x222c0`在context=0分支转发底层filer；沿用已有BitStream的RC及BD读取，未作加密字符串或偏移猜测。
- `TDbText::dwgInFields`，`0x55e30`：先在`0x55e6c`读TDbEntity；在`0x55e86`读文字版本；`0x55eac..0x55ebd`以阈值3建立文字自身wrapper，和基类context分开。文字字段顺序见下表。
- 底层实体字段表 `0x5dbf0/0x5cf70` 与属性表 `0x642c0`沿用已实现的有类型读取；二者接收原filer，不套用基类标量编码。分离文字流按TU的BS字符数及UTF-16LE消费，引用按独立有序表消费。

## TCH_TEXT派生读取顺序

文字版本RC，支持已有0..4；版本>=3才读取该文字wrapper的context。随后依次读取340样式引用、TU原文字、3BD位置、两个标量、RC对齐值；文字版本>1再读标记字节，版本>3再消费两个330引用。相关调用区间为 `0x55ef5..0x55fc0`。位置及标量沿用既有文字专用解码，不从图面拟合，不赋予工程量含义。

## 完整性与验证边界

仅当数字位、字符串位及有序引用全部消费到声明末尾时返回 `SERIALIZATION_COMPLETE`。未知版本、不匹配类/容器、截断、错引用类型和未消费尾部继续保留诊断；未知单位和专业含义保持未知。隐含context在轨迹中记录数值0和零宽消费区间，便于复核。
