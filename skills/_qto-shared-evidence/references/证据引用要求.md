# 证据引用要求

## 目标

让每个范围判断、中性事实和工程量结果能够回到具体来源位置复核。只有文件名或无对象定位的汇总数字不构成充分证据。

## 资料编号

每份被选资料分配本次任务内唯一的资料编号，并记录：

- 项目内路径；
- 文件类型、版本、大小和 SHA-256；
- 图号、文档标题或表名；
- 已选择、已排除或暂不确定结论；
- 选用范围和限制。

## 证据编号

每条实际使用的事实分配唯一证据编号。证据记录至少包含：

| 字段 | 要求 |
|---|---|
| 证据编号 | 本次任务内唯一 |
| 来源类型 | CAD、PDF、图片、表格、文档、用户确认或缓存 |
| 资料编号 | 指向资料选择台账 |
| 中性事实 | 原始几何、文字、表格值或条款内容 |
| 定位 | CAD 句柄/布局/坐标，PDF 页码/边界框，表格行列/单元格，文档条款号等 |
| 来源身份 | 版本或 SHA-256 等可核对身份 |
| 提取方式 | 工具、版本和关键参数 |
| 质量状态 | 直接读取、转换、OCR、人工确认等 |
| 限制 | 置信度、缺失、冲突或范围限制 |
| 缓存编号 | 使用缓存时必填，并能回到缓存身份核验记录 |

## 结果引用

每条工程量结果必须：

1. 引用一个或多个证据编号，或在待确认/证据不足状态下明确缺少何种证据；
2. 引用实际采用、判为不适用或证据不足的规则编号；
3. 保留结果范围、单位和状态；
4. 说明由中性事实到专业结果的关键推导；
5. 将影响数量的缺失或冲突列入未决事项。

证据引用不能用同目录中的旧结论、旧发布状态或模型记忆替代。项目事实证据、规则来源、用户确认和计算派生过程必须分开记录。

## 证据强度

- 直接事实：可由原文件或权威中性缓存直接复核。
- 转换事实：经过格式转换、OCR或几何计算，必须记录方法和质量。
- 用户确认：记录确认内容、时间和适用范围。
- 推导结果：由专业 Skill 使用明确规则从证据得到，不属于公共层中性事实。

不得把“未发现”自动写成“数量为零”。只有在范围完整、提取方法能够发现该对象且检查通过时，专业 Skill 才能判断是否为零。
