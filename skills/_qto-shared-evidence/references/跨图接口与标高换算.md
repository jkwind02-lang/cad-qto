# 跨图接口与标高换算

本能力接在已有 `cross_view_links` 后面。跨图对应由本次图纸中的实物编号、楼层、系统和接口证据建立；对应成立不等于管长已经确定。模型负责识图和判断来源测点，脚本核对来源引用、测点转换、基准和算术，不会自动从楼层名推导设备口高度。

## 使用已有管网入口

在 `cross_view_links[]` 中添加 `elevation_facts`，再运行原来的 `infer_pipe_network.py`。不带此字段的旧输入保持原来结果；带此字段时以新事实复算，未决也不回退使用旧 `from_elevation/to_elevation` 数字补量。

- `system` 必须与接口两侧管段系统相同。接口两侧管段仍由已有拓扑检查系统及图纸空间。
- 同一 `physical_id` 只保留一个计量出口。若已有实测管段计量，继续使用 `quantity_owner_segment_id`；标高计算作为核对信息，不再加一次长度。
- `from` 对应接口 `a`，`to` 对应接口 `b`；其 `reference_id` 及转换后的 `target_reference_id` 用于记录实际测点。模型仍须核对这些测点确为本次接口，脚本不会凭同名自动关联。
- 结果在 `vertical_quantities[].elevation_calculation` 中。`value` 为有路线证据的长度；`vertical_projection` 只是竖向投影，两者不可混用。

## 标高事实输入

`elevation_facts.schema = "qto-elevation-link/1.0"`。入口字段：

| 字段 | 内容 |
|---|---|
| `system` | 与管网一致的系统身份；不按字符串相似度合并供回水 |
| `from` / `to` | 两端原始标高事实 |
| `sources` | 来源目录，沿用依赖计算的 `id/sha256` 字段，增加定位和原始数值事实 |
| `target_datum` | 可选统一基准，默认采用 `from.datum_id` |
| `datum_transforms` | 明示基准换算，不同基准没有路径时保持未决 |
| `route` | 竖直、直线、一次水平加竖向或尚未确定；缺失时不输出全长 |
| `calculation_id` | 可选稳定计算身份，给前后两次依赖复算使用 |

两端事实包含 `fact_id/value/unit/datum_id/reference_id/measurement_kind/source_ids/basis/level`。单位支持 `mm/cm/m/ft/in`，数值保留原单位。`level` 为 `confirmed/inferred/scenario`，结果按所用事实和转换中的较弱层级输出；输入允许降低采用层级，不能比来源登记的层级更强。这里的 confirmed 表示本轮采用的直接事实，不代表已经人工审阅或正式采用。

确实找到了端口但高程没有给出时，端点使用 `value:null, status:"unresolved", issue:"缺少的实际信息"`；来源目录中相应事实也登记 null 和 unresolved。保留已知起点、端口和范围，长度与投影保持 null，不为满足输入结构虚构下端数值。若端点本身也尚未识别，不应先造一个接口。

测点类型及转换：

| `measurement_kind` | 到管中心的处理 |
|---|---|
| `pipe_center` | 原值即中心高程 |
| `equipment_port_center` | 原值即设备接口中心高程；必须对应实际接口 |
| `pipe_outer_bottom` | 原值加实际外径的一半 |
| `pipe_outer_top` | 原值减实际外径的一半 |
| `structural_floor` / `finished_floor` / `other_reference` | 加有来源的带符号竖向偏置；无偏置保留未决 |

`BOP` 字样本身不作为类型。先读本图定义：若指管外底，选 `pipe_outer_bottom`；若指保温底、构造底或其他基准，不能套用管外半径。材料和系列决定的实际外径须来自规格表、厂家表或图纸尺寸；`DN` 不是外径。

外表面转换放在事实的 `centerline_conversion` 中：

```json
{
  "conversion_id": "bottom-to-center",
  "method": "outer_radius",
  "target_reference_id": "actual-pipe-port-center",
  "source_ids": ["pipe-detail"],
  "basis": "本图标高为管外底，尺寸表给出实际外径",
  "level": "confirmed",
  "outer_diameter": {
    "fact_id": "actual-OD",
    "measurement_kind": "outer_diameter",
    "value": 114.3,
    "unit": "mm",
    "source_ids": ["pipe-size-table"],
    "basis": "本次采用的材料及系列对应外径行",
    "level": "confirmed"
  }
}
```

以上仅为格式示例。外径事实必须在其引用的来源中登记为 `outer_diameter` 并与数值、单位相符；登记为 `nominal_diameter` 的事实，即使 `basis` 写着“DN等于外径”也会拒绝。

楼面等参照点转换使用 `method: "signed_offset"`，保留上述转换编号、目标测点、来源和层级，把 `outer_diameter` 换成 `offset` 数值事实（`fact_id/value/unit/source_ids/basis/level`）。向上为正、向下为负；来源中的该事实类型为 `vertical_offset`。构造层厚度、安装高度若尚未取证，不从别的项目或底稿补固定值。

## 来源与基准

`sources` 的每项使用以下字段：

```json
{
  "id": "pipe-size-table",
  "sha256": "原始来源内容的64位SHA256",
  "path": "可选的原始来源绝对路径",
  "locator": "图号/页码/表格行，或CAD实例路径及文字句柄",
  "facts": [
    {"id": "actual-OD", "value": 114.3, "unit": "mm", "measurement_kind": "outer_diameter", "level": "confirmed"}
  ]
}
```

`path` 提供时直接校验实际文件字节与哈希；不提供时检查登记的哈希、定位和引用闭合，原始证据须随取证包保留。不能把这项检查说成已自动核实图纸语义。原始事实登记可以由提取器或模型识图产生，但保留实际识别者和未复核状态；“数值相符”不能证明模型选对了尺寸或设备。

每个数值事实按 `fact_id` 匹配来源目录中的 `facts[].id`；相同量的不同单位允许换算比较。引用不仅绑定数值，还绑定会改变解释的来源字段：

| 来源事实类型 | `facts[]` 必须登记的解释字段（另含 `id/level`） |
|---|---|
| 两端标高 | `measurement_kind/value/unit/datum_id/reference_id/system`，未决值另有 `status:"unresolved"` |
| 实际外径/竖向偏置 | `measurement_kind/value/unit`；分别为 `outer_diameter/vertical_offset` |
| 测点转换 | `measurement_kind:"centerline_conversion"/method/from_fact_id/from_reference_id/target_reference_id/datum_id/system/operand_fact_id`；`id` 对应 `conversion_id` |
| 基准偏移 | `measurement_kind:"datum_offset"/value/unit/from_datum/to_datum`；`id` 对应 `transform_id` |
| 路线形态 | `measurement_kind:"route_shape"/route_kind/from_reference_id/to_reference_id/system`；`id` 对应 `route.route_id` |
| 水平位移 | `measurement_kind:"horizontal_displacement"/value/unit/from_reference_id/to_reference_id/system` |

路线和水平位移的 `from_reference_id/to_reference_id` 对应转换后的中心测点；没有测点转换时使用两端原 `reference_id`。测点转换的 `operand_fact_id` 指向实际外径或偏置的事实编号。这些关系可以由本轮模型根据图纸形成，须和数值事实一起留在证据包；不能只改运行输入的楼栋零点、端口身份、转换方向或路线形态而继续沿用矛盾的来源事实。

基准转换使用 `transform_id` 作为来源数值事实编号，来源类型为 `datum_offset`：

```json
{
  "transform_id": "building-to-survey",
  "from_datum": "building-zero",
  "to_datum": "survey-zero",
  "value": 100,
  "unit": "m",
  "source_ids": ["datum-note"],
  "basis": "本项目建筑零点与测量基准换算说明",
  "level": "confirmed"
}
```

约定为 **`z_to = z_from + value`**。支持反向和多步换算；同一连通基准链给出互相矛盾高差时拒绝。不同楼栋同名零点应使用不同 `datum_id`，不能因文字都叫“±0.000”就视为同一基准。

## 竖向投影与实际路线

- `route.kind = "vertical"`：有图纸证据证明为纯竖直路径，长度为标高差绝对值。若同时声明非零水平位移则拒绝。
- `route.kind = "straight"`：有证据证明是两端之间的一条直线，另有 `horizontal_displacement` 数值事实，按斜边长度计算。
- `route.kind = "orthogonal"`：有证据证明只含一次净水平段加竖向段，且不存在回折、绕行和额外区段，按两者之和计算。多段绕行应回到已有轴线路径计算，不能只用端点净位移。
- 缺路线、`unresolved`、或斜线/正交路径缺水平位移：保留已求得的竖向投影，`value=null`。不把跨图页面坐标差作为水平位移。

已确定路线须有 `route_id/source_ids/basis/level`。`horizontal_displacement` 使用 `fact_id/value/unit/source_ids/basis/level`，来源事实类型为 `horizontal_displacement`；值必须非负。

## 独立复算与依赖更新

可直接调用 `evaluate_elevation_link(spec, output_unit="m", expected_system=None, previous_calculation=None)`。CLI：

```text
python qto_elevation_facts.py --input 标高输入.json --output 标高计算.json --unit m
python qto_elevation_facts.py --input 更新后标高输入.json --output 更新后标高计算.json --previous 标高计算.json
```

输出文件必须尚不存在，不能覆盖输入或旧成果。返回结果包含源事实、转换、输入指纹、引用检查，以及**现有** `qto-calculation-graph/1.0` 格式的 `calculation_graph` 和 `calculation_run`；外径、标高、基准或路线改变后使用原 `recompute_qto_dependencies.py` 重算并标记受影响审阅。依赖图保存实际表达式和数值来源，未另建重算引擎。结果始终保留 `business_adoption_allowed=false`。

此模块补的是已经取证的接口标高与路径计算；它不自动认定跨图关系、不寻找真实设备口，也不解决源图没有给出的安装条件。完整性仍由对象范围、跨图对应和本轮识图检查共同判断。
