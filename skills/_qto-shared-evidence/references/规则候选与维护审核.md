# 明确方法裁决提取规则候选与维护审核

本工具只整理已保存且当前有效的方法裁决，在指定维护区导出候选，并核验维护审核的三个分支。候选草稿不是用户原话，不是数量批准，不自动修改 reference、运行包或成熟度。单项目认可只覆盖该项目、该对象和该版本；不能据此成为全局成熟规则。

入口：

- 运行侧：[qto_rule_candidates.py](../scripts/qto_rule_candidates.py) 随共享运行包交付：python skills/_qto-shared-evidence/scripts/qto_rule_candidates.py export --request 导出请求.json --maint-dir 维护目录 --name 候选_v1.json。路径从插件根开始。
- 上下文预览：同一入口 inspect --request 导出请求.json --maint-dir 维护目录 --name 上下文预览_v1.json。重放当前 producer 并输出 method_context_fingerprint，状态固定 NOT_HUMAN_APPROVAL，不生成凭据或人工结论。实际用户保存明确确认后，原批注和方法凭据均须绑定该指纹；保存为新的批注版本并重新跑 reader，不改写旧原件。旧输入、规则、数量凭据或网络对象变更，即使最后数值相同，也必须重新核对上下文。
- 维护侧：用户移交维护区候选后，由维护仓库运行 python maintenance/review_rule_candidates.py review --request 维护请求.json --maint-dir 维护目录 --name 审核回执_v1.json。maintenance 目录不随运行包交付，安装端不调用该入口。
- 两个脚本都由 Python 执行。使用新版本文件名；不得覆盖已有成果。成功退出 0；拒收退出 2，正常可写输出位置保留拒收回执。输出统一位于指定维护目录下的“规则候选”目录，禁止位于本插件源码树。维护目录由操作者明确指定，不能把项目源目录误当维护目录。
- 运行侧先消费 read_qto_review_feedback.py 的真实交接、recompute_qto_dependencies.py 的真实计算结果，再导出。维护侧重放相同核验；不是只检查一个孤立 schema。
- 支持当前依赖图对象绑定和显式 T35 电气网络原源 adapter，也可混合；两者必须完整覆盖事项有效对象。没有明确绑定、原源文件或当前版本的具体对象保留拒收，不按显示文字或裸编号猜对应，不把历史结果迁成当前。
- HTML 只保存意见与证据，不直接写共享 reference。当前页面不会自动生成下述方法凭据；不得由模型代填真人批准。没有真实方法凭据时应保留 INPUT_REQUIRED，不能宣称真实 M2 闭环。

## 本地可追溯凭据的边界

qto-human-review-evidence/1.0 专用于人工数量确认，继续由原重算器核验。方法确认使用单独的 qto-rule-decision-evidence/1.0；维护审核使用 qto-rule-maintenance-evidence/1.0，均绑定分别保存的原意见、哈希、记录、时间、来源与结果版本。

原意见须是实际保存且明确确认该方法/事项的用户记录。姓名、reviewer_type=human 和模型名称拦截只是字段守卫，哈希只证明字节一致，不能证明真人身份、授权或正式采用；工具不提供身份认证。模型可以整理草稿，不能创作原始真人意见、凭据或维护批准。测试中的匿名姓名及文件均为合成夹具，不能作为真实批准和独立工程案例。

## 导出输入

导出请求 schema 为 qto-rule-candidate-request/1.0。所有引用使用 {path, sha256}，相对路径按请求文件所在目录解析；human_decision_evidence 另含 record_id。哈希均为实际文件的 SHA256。以下字段必需：

| 字段 | 来源与约束 |
|---|---|
| view | 当前复核视图 JSON，由现有 normalize_view 重新校验 |
| feedback | 原保存 HTML/JSON 批注；只读解析，绝不执行 HTML |
| handoff | read_qto_review_feedback.py 对这份视图与批注产生的 qto-review-handoff/1.0 |
| calculation_input | 有依赖图对象时必填 qto-calculation-graph/1.0；必须和 calculation_run 成对 |
| calculation_run | recompute_qto_dependencies.py 对同一输入产生的 qto-calculation-run/1.0 |
| calculation_sources | 计算 sources 的物理文件映射 [{id,path,sha256}]；省略时复用 source_files，仍须逐条匹配实际来源 |
| calculation_rules | 计算 rules 的物理依据映射 [{id,path,sha256}]；无规则时可省略，存在规则不得仅自填哈希 |
| previous_run | 可选；原 producer 使用上一轮结果时，必须提供同一上一轮文件 |
| network_evidence | T35 电气网络证据数组，见后文；纯网络对象可以不提供依赖图，但不能省略实际分区/台账/计算 producer |
| source_files | [{id, path, sha256}]，逐一对应 view.sources；必须完整且唯一，并重读物理源字节 |
| annotation_key | 原批注中的稳定“审核事项\|事项ID”键 |
| human_decision_evidence | 方法确认凭据引用及 record_id |
| draft | 模型整理的候选草稿，结构见后文 |

view.source_sha256 是项目/复核范围/来源集合身份，不是某一个原图文件的哈希。工具分别核对集合身份和每个实际物理源。feedback 必须重新通过当前适用性判断，handoff 的项目、来源、结果、当前反馈、动作、未匹配清单及 quantity_changes=0 必须一致。已保存裁决必须属于 business_choice，current，动作明确“采用建议”或“调整处理”，具有结论和依据；暂不处理、退回、草稿、模型建议、冲突、迁移挂起、过期建议均不导出。

原批注额外明确保存 decision_type=method_confirmation、reviewer、reviewer_type=human、reviewed_at、method_context_fingerprint。不能只给候选草稿添加 human 标记。计算器重放当前输入和上一轮凭据，完整结果必须与所交 calculation_run 相同；对象必须绑定当前有效计算节点，并重读计算来源和规则的物理依据。对象展示数量须按 quantity_name 或唯一匹配精确对应当前节点，不能挂名绑定。数量单位、层级、专业、几何类型和对象分类分别核对。明确的方法裁决可以讨论保留未知量，候选保留节点 BLOCKED、原因、null 与“未决量”，不以零代替，也不把该方法确认变成数量确认。

方法确认凭据文件：

~~~json
{
  "schema": "qto-rule-decision-evidence/1.0",
  "project_id": "与视图相同的项目",
  "records": [{
    "record_id": "唯一记录号",
    "reviewer": "实际用户填写",
    "reviewer_type": "human",
    "reviewed_at": "带时区的原保存时间",
    "decision": "confirm_method_decision",
    "annotation_key": "审核事项|事项ID",
    "annotation_fingerprint": "原保存批注记录的完整 canonical SHA256",
    "decision_id": "事项ID",
    "decision_revision": "事项版本",
    "method_context_fingerprint": "inspect 对当前输入、运行结果、有效对象绑定和网络证据生成的完整指纹",
    "source_fingerprint": "当前视图来源集合指纹",
    "result_fingerprint": "当前视图成果指纹",
    "decision_result_fingerprint": "当前事项成果指纹",
    "source_feedback": {
      "path": "原保存批注文件",
      "sha256": "原保存文件SHA256",
      "annotation_key": "审核事项|事项ID",
      "saved_at": "原批注updated_at；没有时用reviewed_at"
    }
  }]
}
~~~

annotation_fingerprint 使用 qto_review_identity.fingerprint 对未经工具分类、未经改写的原 annotations[键] 计算。source_feedback 路径相对凭据所在目录解析。该记录必须唯一，身份与时间须与原批注逐字一致。不同格式时间即使代表同一时刻也不自行换算后接受。工具只验证外部交来的记录，不提供自动生成审批命令。

## T35 电气网络原源 adapter

network_evidence 的每项 schema 为 qto-rule-electrical-network-evidence/1.0，必填 network_id、decision_id、decision_revision、scope_id、network_fingerprint，以及 manifest、request、partition、ledger、calculation_run 五个 path/sha256 引用。request 是 qto-electrical-route-network-request/1.0，partition 是 partition_electrical_route_network.py 实际输出，ledger 是同次实际路径台账，calculation_run 是 calculate_electrical_paths.py 对该台账实际输出的 qto-electrical-path-result/1.0。

adapter 原样调用现有 T35 partition_network，校验 CAD 清单、当前权威原图、交换图及中性流的物理字节，再复算台账。请求项目和 scope、网络指纹、完整 partition、实际台账及完整路径计算结果均须一致。来源不匹配、缺原图、旧中性流、旧结果均拒收；不造模拟计算结果绕过 producer。

比较采用正式生产保存契约：partition 的 write_json 先递归 clean（包括 tuple/list，并删除下划线开头的字典键），再保存 JSON。adapter 对当前完整回放执行同一官方 clean 和 JSON 往返，与交入的完整生产文档比较；不清洗交入文件，不按任意子集或忽略字段比较。台账按同次保存值精确比较，独立 calculate 的完整 JSON 结果还须与原回放复算一致。运行候选和 inspect 的返回值也与本入口实际写出的 JSON 文档一致，避免内存 tuple 与保存 list 造成后续维护假失效。

真实的下划线块名（例如尺寸生成块）可能被既有 partition writer 从诊断字典中省略；adapter 不修改该 writer。method context 同时保存完整原始回放指纹与正式序列化文档指纹，原始回放指纹仍包含这些块名，原源、交换文件、中性流及凭据依赖仍逐文件核验；新增、缺失或篡改交入字段仍拒收。

执行源码的绝对目录与 CAD 业务来源身份分别处理。仅 provenance 的已知执行模块依赖字段可按 T27 公共契约规范化：实际读取每个声明模块文件，核对其 SHA、固定 skills/ 相对模块身份及当前完整执行依赖集合；同模块同字节的已核路径别名规范为 module:skills/… 身份。凭据中的单位模块记录同样先经公共 validator 核验，其他字段完整保留。CAD 原图、manifest、artifact、中性流、trace 请求及 scope 的路径和内容不规范化为模块，也不因同字节副本而忽略业务路径差异。因此同字节安装运行子树可导出候选并交维护仓库重放，模块字节、业务源路径或 scope 漂移仍失效。现有 T27 validator 要求凭据声明的原模块文件仍可读取；本工具不回指另一份旧代码冒充当前执行代码，也不放宽该 validator。

每项 bindings 是显式对象到目标映射数组，包含：

- catalog_key、object_fingerprint：本次有效对象和当前对象成果指纹。
- target_kind、target_id、target_fingerprint：明确目标与完整目标内容指纹。支持 physical_segment（实际原段）、calculation_item（实际路径复算项）、circuit_quantity（明确回路量）、connection（原源支持的连接关系）；不根据同号猜归属。
- quantity_field：从实际目标取值的字段。原段允许 length_m、conductor_quantity_m、known_conductor_quantity_m、physical_channel_quantity_m；计算项允许 length_m、known_length_m；回路量允许 complete_length_m、known_length_m；连接允许 traced_path_length_m。不可使用其他字段冒充量。
- value_source、value_name：quantity 时精确对应当前对象唯一同名数量及其值/单位/层级；attribute 时精确对应当前对象实际同名属性。关系尚无数量时 quantity_field=null、value_source=none，保留未知量，不猜数字。

映射须属于当前事项有效 scope，事项和网络 scope/版本均逐项校验；映射、目标内容及全部运行结果组成 method_context_fingerprint，原保存方法确认与凭据共同绑定。未证对象映射是待专业核对的通用输入，不归因项目资料不足，也不自动接受。已有原段属性投影可显式绑定，旧视图缺少数值时先由专业重建视图和实际用户答复，不由工具改项目文件。

网络未决字段、未决分量、整体 review_items、量层级的原始 null 都保留。完整量为 null 时仍为未知；已知分量与完整量按所选字段分别表达。计算项原 quantity_level=null 且有已知数值时标“未分类参考量”并同时保留 source_quantity_level=null，不提升为已证明量。所有网络证据仍保持 business_adoption_allowed=false。网络 target 的正式方法判断和数量核准是不同事项。

draft schema 为 qto-rule-candidate-draft/1.0，包含：

- rule_family、draft_version、proposed_rule。
- applicability：professional、object_kind、object_type、quantity_layer、unit、measurement_basis、region、contract_scope。其中前三者须分别对应实际对象的 professional、kind、category。不同对象类型应拆候选，不借通用文字掩盖对象关系。
- trigger_conditions、boundaries、exceptions、counterexamples：非空文字数组。没有例外也应明确写已核范围及尚未覆盖处，不使用空数组冒充检查。
- pending_branches：文字数组，可以为空；尚未验证分支完整列入，不宣称全局有效。
- suggested_reference：skills/专业/references/文件.md 形式的相对路径，不得越出插件目录。这里只是建议归属，不会读取或写入目标规则。

输出保留原问题、完整原答复、事项与范围快照、排除和例外挂起、源/结果/输入指纹、当前计算绑定、凭据、完整草稿及规则指纹。原答复里的历史和建议引用照样保留，草稿另标 model_organized_candidate_not_human_rule_approval。运行依赖记录覆盖实际 feedback producer、候选 consumer、重算器与本地静态导入闭包的 SHA256；维护复验时字节变化使旧候选失效，必须按新代码重新导出。维护审核入口字节单独写入审核回执的 maintenance_dependencies；安装端导出不依赖该维护文件。

## 维护审核输入与三个分支

维护请求 schema 为 qto-rule-maintenance-request/1.0，必填 candidate、review、human_review_evidence 引用；最后一个另含 record_id。原保存维护意见 review schema 为 qto-rule-maintenance-review/1.0：

| 字段 | 要求 |
|---|---|
| candidate_sha256 | 当前导出候选文件实际字节 SHA256 |
| reviewer / reviewer_type / reviewed_at | 实际审核者、human、带时区时间；与审核凭据及保存时间一致 |
| disposition | reject / project_only / general_candidate |
| reason | 实际维护判断理由 |
| applicability_review | project_specific、region_contract_limits、exception_review、covered_branch 逐项文字判断，以及当前 rule_fingerprint |
| independent_cases | 候选文件的 path/sha256 引用数组；相对原维护意见所在目录解析 |

审核凭据 schema 为 qto-rule-maintenance-evidence/1.0，project_id 为原候选项目，records 中唯一记录包含 record_id、reviewer、reviewer_type、reviewed_at、decision（等于 disposition）、candidate_sha256、review_fingerprint，以及 source_review={path,sha256,saved_at}。review_fingerprint 为原保存 review 完整对象的 qto_review_identity.fingerprint；source_review 必须精确指向该原保存意见。不得用工具回执反充原保存维护意见。

- reject：保留审核理由、范围与凭据，不生成改规则提案。
- project_only：只记录原候选的项目和有效对象范围，formal_quantity_adoption=false；不修改全局成熟度。
- general_candidate：必须至少另有一个真实独立项目案例；逐个重放案例本身的导出链。项目须不同、来源集合须不同、所有物理源字节与原项目无重用、案例不重复，并且 rule_fingerprint 完全相同，确保规则版本、对象、单位、计量/合同/地区范围、触发条件、边界与例外匹配。案例自身也须当前有效、有明确方法凭据和真实 producer。案例支持仍是审核输入，机器不能证明案例的工程真实性；匿名夹具不能冒充实际案例。

通用分支只生成 AWAIT_MAINTENANCE_CHANGE 提案，继续经维护会话改目标 reference、补覆盖分支的反例和合法对照、非作者复核及适用门禁，再按证据判断具体分支成熟度。工具不升版、不安装、不发布、不推送，也不从 HTML 改包；原批注、项目结果和源资料均只读。business_adoption_allowed、runtime_changed、reference_changed、maturity_changed 始终 false。审核回执 EVIDENCE_BOUND_REVIEW 只描述本地可追溯核验，不代表工程正式接受或身份认证。
