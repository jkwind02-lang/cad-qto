# 读取覆盖与补读

中性读取先回答图元身份和几何读到了什么。它不决定专业范围，也不证明已取得完整工程量。

`extract_cad_neutral.py` 自 `1.2.0` 起保留既有几何与文字字段，并增加 `geometry_capability`、`geometry_issue_codes`、`recommended_actions`。数量未知仍用 `null`；文字、遮罩或定位点不因没有曲线长度而被当作失败。

| 能力标记 | 本次真正取得的内容 | 后续用途 |
|---|---|---|
| `measurable_curve` | WCS 曲线几何和可计算长度 | 由专业层判断对象身份、计量口径和范围 |
| `annotation_evidence` | 文字/尺寸/引线/遮罩的定位或边界证据 | 识图和关系判断，不能据此直接计构件量 |
| `point_evidence` | 点的坐标 | 定位，不能代替构件几何 |
| `block_reference` | 插入点、变换及定义可用状态 | 按完整实例路径展开并判断对象归属 |
| `external_reference_evidence` | 底图定义、文件与页/图纸名称、引用变换及显示开关 | 检查外部依赖后另行读取内容；不代表已读取 PDF/DWF/DGN 页 |
| `specialized_adapter_required` | 中性读取器已辨认但不负责测量的实体 | HATCH 交给 `qto-surfaces-envelope/scripts/extract_surface_regions.py`，其结果另行校验 |
| `unsupported` | 对象身份及能够读取的原始资料 | 根据原因码补充专用解析或原生 CAD 取证 |
| `read_failed` | 已保留对象身份，但几何读取或序列化失败 | 保留失败原因，定位原对象补读；不得按缺失对象或零量处置 |

`geometry_status` 延续 `supported`/`unsupported`，并增加 `requires_adapter` 和 `read_failed`。`supported` 对标注仅表示该类证据已读取，不表示存在可测长度；能力标记与几何字段应一起使用。块引用有未决事项时仍保留 `block_reference` 能力，状态为 `unsupported`，不能因此把首个阵列单元或未加载参照当完整实物。

## 清单与定位

生成的 `CAD读取覆盖与待补读.json` 包含能力/状态/实体类型计数及 `pending_objects`。每个待处理项保留来源哈希关联、实体句柄、布局、父块、图层、原因码及补读建议；块定义项应结合实例路径判断影响了哪些实体。

计数基准是“布局实体 + 唯一块定义实体”，不是展开后的物理对象数量，更不是工程量覆盖率。清单始终明确 `quantity_coverage_proven: false`。是否完成某个专业范围，应由专业适配器逐对象处置后判断。

HATCH 转交专业适配器计入待处理项，但不写成读取错误；未知代理/三维/网格对象和真正读取异常保留在失败清单，异常同时保留一条中性流身份记录。相比旧版，遇到异常时流记录数可能增加，这反映对象不再静默消失。

主清单 `status` 及 CLI 退出码反映待处理状态：有待处理项为 `PARTIAL` / 3，无待处理项为 `PASS` / 0。`neutral_extraction_status` 单独表示中性读取是否发现失败；例如只有 HATCH 时它为 `PASS`，主状态仍为 `PARTIAL`。既有调用方须保留并处理退出码 3 产生的证据包，不能当作文件未生成。

## 加载阶段的源身份冲突

`read_dxf_with_diagnostics(path)` 返回 `(document, diagnostics)`，在 ezdxf 加载期间保留警告。重复实体句柄可能让解析器继续返回文档，但其内部实体字典或引用已经不能证明与原图一一对应，因此单靠遍历加载后的实体无法补回完整原始身份。

源身份冲突保存在 `source_identity_issues`，包含源句柄、原警告及原生核验建议；其他加载警告保存在 `source_read_warnings`。中性清单及覆盖文件均带出这些资料和数量，有阻断问题时主状态为 `PARTIAL`。这类来源级问题不假装已经定位为某一个可计量实例，不能据此推导遗漏量。

自提取器 `1.3.0` 起，读取器会对加载器报告的重复句柄回查原始 ASCII DXF 记录。只有同处 `OBJECTS` 的 `MATERIAL`、`DICTIONARY`、`XRECORD`，每一条完整组码和值的原始字节相同，且引用、所有者和反应器相关身份没有发现冲突或缺失，才归入 `source_identity_advisories`。检查类型只是第一道条件，不能替代全文相等。数值 `1` 与 `1.0`、字符串尾部空格、所有者或引用变化均不视为相同声明。图形、布局或块记录重复，即使几何完全相同也不能证明唯一实物，仍然阻断。

每条重复声明证据保留记录行号、完整值字节的十六进制、组码、记录哈希、依赖检查及原警告；对比采用完整记录相等，哈希只作证据标识。不会改句柄、删原记录或修复图纸。仅有已核相同声明时读取诊断为 `PASS_WITH_WARNINGS`，`source_identity_status` 为 `verified_non_graphical_repeats`，原警告带 `blocks_identity_binding: false`。这允许下游继续基于图元身份形成候选，不代表工程量完整。真正冲突继续由 `source_identity_issues` 拦截；下游不得把所有警告一律忽略。

所有者和 `ACAD_REACTORS` 作为反向关系检查目标身份，不递归展开父字典的其他子项；前向引用则递归检查。原始扫描发现但加载器未警告的重复引用目标也不会自动视作安全。二进制 DXF、扫描异常、原始记录不全或无法确定的情况不降级为提示。该检查围绕加载器重复告警及其依赖，不等于完整 DXF 审计，`parser_entity_preservation_proven` 仍为 false。

读取器不自动改号、修图、保存图纸或声称解析器保留了冲突双方；`parser_entity_preservation_proven` 恒为 false。调用方取得非空身份冲突时，应阻止依靠这些句柄直接形成确定关联和工程量，先取得身份稳定的交换副本或原生取证。无警告仅为 `no_conflict_reported`，不等于完成了整个源文件完整性审计。

## 参照、动态块与阵列

- 外部参照无子对象时标为内容未取得；有缓存子对象也不能自动证明参照来源及版本有效。保留参照路径，回到原生 CAD 核验加载状态及来源后再推进。
- 动态块扩展字典或 XDATA 标记是待原生求值的证据。仅匿名块名称符合 `*U` 形式时只记为候选，不能凭名称认定其用途或动态参数已解析。当前工具没有宣称完整解析动态块。
- 阵列引用保留行列数，并要求逐实例展开/核验；当前中性记录不是一个完整实物数量。
- 缺失块定义保留插入位置及变换，不能把缺失子对象当成“图中为空”。

对未知实体的补读建议不是自动完成证明。原生取证或专业解析完成后，保留源对象与结果的对应，不能通过删除未决记录或填零来提高覆盖比例。中性 `PASS` 也不证明 DXF 转换前后对象齐全；转换记录和源图一致性仍需独立核验。

## CAD 原生底图依赖

`external_reference` 只保存 CAD 自身已提供的 `PDFUNDERLAY` / `DWFUNDERLAY` / `DGNUNDERLAY` 事实：定义句柄、定义类型、原始路径 `declared_path`、页/图纸标识 `page_or_sheet`、OCS 插点、旋转、带符号的三轴缩放、法向、开关及剪裁原值。共同组码按 [Autodesk UNDERLAY 定义](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-3EC8FBCC-A85A-4B0B-93CD-C6C785959077.htm) 读取；[ezdxf 底图文档](https://ezdxf.readthedocs.io/en/stable/dxfentities/underlay.html) 说明外部文件不嵌入 DXF。原图实测覆盖 PDFUNDERLAY；另外两种共同字段有独立合成验证，不宣称已读取其文件格式内容。

`reference_to_definition_wcs` 保留定义坐标系的完整 4×4 变换，`reference_to_wcs` 随 `transform_row` 组合父实例矩阵，保留嵌套、旋转、镜像、非均匀缩放和 OCS。剪裁边界按原始坐标语义保留，不用它或插点冒充页边界；`bbox`、`page_extent` 及量值为 `null`，`content_status` 始终为 `not_read`。底图开关关闭也只表示原 CAD 记录状态，不能据此认定不在业务范围。

`resolve_underlay_dependency(reference, context=None)` 的 context 可显式传入绝对 `original_cad_directory` 与 `basis`。CLI 既有 `--source-dwg` 提供 `explicit_source_dwg` 依据；未指定时，仅在同名 `.export.json` 的交换哈希和仍可访问的原 CAD 文件哈希均匹配后，使用 `verified_export_receipt` 依据。清单记录依据、原 CAD 路径、哈希及收据。相对路径无此依据时保持 `unverified`，不得以 DXF 临时目录或当前工作目录查找后称存在/缺失。

路径检查只判断 `exists_at_declared_path` / `missing_at_declared_path`，不搜索 CAD 搜索路径，不下载文件，不证明别处不存在。远程、驱动器相对路径等不确定路径保持未核；文件存在仍不表示内容已读。缺失定义另记 `underlay_definition_missing`。底图内容未读保持 `requires_adapter`，进入覆盖待办和 `external_references` 清单，不能因为已取得路径和变换就标完整读取。

## 尺寸对象的类型与取值

`qto_cad_geometry.dimension_measurement_facts(entity)` 同时记录尺寸类型、定义点、方向/OCS、库接口值、DXF 缓存值、文字覆盖、图块内文字、比例因子和类型感知的几何候选。中性记录位于 `raw_geometry.dimension_measurement`，不写入 `raw_length`，避免将尺寸线计为管线。

- 对齐尺寸（类型 1）按 WCS 定义点 13/14 的距离计算；该类型不要求 angle，不能因 angle 缺省为 0 而将竖向或斜向尺寸投影到水平线。
- 旋转/水平/竖直尺寸（类型 0）按尺寸 OCS 中的方向，将 WCS 定义点差向量投影；不能用两点欧距替代，也不能再次把已是 WCS 的定义点转换一次。
- 角度、半径/直径、坐标尺寸分别保留其自身类型证据，不提供线性标定值。其他特殊尺寸类型仍需专项处理。
- 缓存值和含比例的几何不符、真正零/退化尺寸、定义点不共尺寸平面、直接文字覆盖、比例语义不明等保留候选和原因，`raw_measurement` 为 `null`。正比例时 DXF `actual_measurement` 应与原始几何乘 `DIMLFAC` 后的值比较，不能直接与未缩放值相比。库接口与类型算法不一致会保留注记；在类型/坐标定义明确且无上述冲突时可恢复原始几何值。
- `linear_factor` 与原始几何分开；`scaled_measurement_candidate` 只是带比例的候选，不是已采纳的设计尺寸。尺寸图块文字保留作核对资料，不用文本数字覆盖矛盾几何。

下游应核对 `linear_measurement_usable`、`status` 和 `issue_codes`，并核实主视图、资料版本、单位、比例和尺寸适用对象。`design_value_adopted` 恒为 false。尺寸位于块定义时保留该定义坐标系的数值；父实例变换另有来源，不能将未经解释的块缩放直接作为设计尺寸比例。

类型与坐标依据来自 Autodesk 官方 DXF 定义：[对齐尺寸](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-7A123D5D-AC98-4A9A-A8CF-1A7EF5030418.htm)、[旋转与线性尺寸](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-F0004556-493C-48D5-8619-61D6ADF05C04.htm)、[尺寸公共组码及文字覆盖](https://help.autodesk.com/cloudhelp/2017/ENU/AutoCAD-DXF/files/GUID-EDD54EAC-A339-4EBA-AEA6-EC8066505E2B.htm)。
