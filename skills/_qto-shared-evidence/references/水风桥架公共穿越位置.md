# 水管、风管和桥架的公共穿越位置

公共入口为 `scripts/calculate_penetrations.py`，计算库为 `qto_penetrations.py`，源绑定和固定生产者适配为 `qto_penetration_sources.py`。本能力计算声明范围内的管路中心线穿越位置；开洞、土建扣减、套管与防火封堵的数量出口分别保留。不把穿墙处数直接作为套管数、封堵数或体积，不默认两套管、两封堵，不采用项目临时的 450 mm 聚类。

```text
python skills/_qto-shared-evidence/scripts/calculate_penetrations.py --cad-manifest <中性取证清单.json> --request <公共请求.json> --output-dir <新的输出目录>
```

输出目录包含穿越计算结果 JSON、位置明细 CSV 和调用记录。进程退出 0 只表示该次有源计算执行完毕；必须同时读结果的 `status`、`quantities.complete_spatial_count`、`todo`、`uncertain_candidates` 及范围。所有结果均是未正式采用的工作计算，`business_adoption_allowed=false`。退出 2 表示输入或来源核验失败，不生成可采用数量。

范围或三维事实未闭合时，`spatial_crossing_count` 与 `complete_spatial_count` 均为 null；已形成空间穿越的部分小计另列 `known_spatial_crossing_subtotal`，它不代表完整量。

## 来源与专业接口

请求 `schema=qto-penetration-request/1.0`，绑定同版 `source_sha256`、`cad_manifest_sha256` 与 `layout`。源清单须采用本插件的 `qto-cad-neutral-evidence/1.0` 和完整 `qto-cad-geometry/1.1`。公共入口按清单 SHA 核验权威原图、交换 DXF 和中性流，再从真实 DXF 调用固定 `extract_cad_neutral.convert` 和 `qto_cad_geometry` 重新读取文字、完整曲线和嵌套块矩阵。中性流或请求自报的 producer、几何及数量不作为几何证明；请求不得提供待执行代码。

三种固定上游接口：

| import.kind | 所需冻结引用和选择 | 实际消费方式 |
|---|---|---|
| `pipe_segments` | `input={path,sha256}`、`segment_ids` | 接 `qto-pipe-network-inference-input/1.2` 的实画段；按完整源实例和 part 重建，逐段比较实际几何及单位；输入没有完整源身份时，只接受既有适配器生成的 `SEG-<完整源键>`，不能把补连桥冒充实画 |
| `duct_profile` | `profile={path,sha256}`、`segment_id`，可附 `claims` | 实际调用固定 `build_duct_network_from_neutral.build` 重建，验证原轮廓完整实例、part 和原曲线区间，再调用 `checked_geometry`；不信任外部自报采样线 |
| `electrical_request` | `request={path,sha256}`、`object_id` | 实际调用固定 `bind_electrical_objects.calculate` 和既有 Evidence，接 kind=tray 的原曲线区间；不按电缆条数替代桥架物理路径 |

也可直接接本轮已识别对象的 `bindings`：每项含 `source_id`，可给 `part_index`、`fraction_range=[0,1]`、`direction=1/-1`。无 `part_index` 表示保留该原实例的全部 part；部分曲线必须明确原 part 及参数范围。完整嵌套实例采用 `CAD-<插入实例>/块名/CAD-<原定义实体>`，不能只用块定义句柄。支持直线、圆弧、完整圆、椭圆弧、含 bulge 多段线及其源仿射变换；未恢复或未支持的真实几何连同源记录进入未决，不输出伪零。

MINSERT 的行数或列数不是默认 1 时，当前公共重建器尚未建立全部阵列成员的完整身份；该插入及后代的选择保留展开未决，不取第一放置冒充完整路径。检查适用于完整祖先链，普通嵌套、旋转、镜像继续按原矩阵重建。未选中的其他阵列保留在来源诊断，不影响已有完整源身份的独立选择。

每条 `routes[]` 至少具有 `id/physical_id/discipline(pipe|duct|tray)/space_id/floor_id/basis/basis_source_ids`，并且只用 bindings 或 import 之一。每个完整物理路径的顺序 part 必须连续。重复表达须显式采用同一 physical_id 且几何范围一致，反向表达也核验；不一致的同物声明阻断。不同 physical_id 即使完全同点也分别计数。部分实例、支路和相互断开的区段不能仅因同一系统名称合并为一根物理管路。

同物重复表达还须核对专业、系统、空间、楼层、有效 z_mode、高程基准和 z_basis_source_ids、实际单位、原图/衍生/方案依据层及多根实例依据。不一致时拒收，不按出现顺序采用第一条；不能以几何相同将方案或衍生层提升为原图层。单位在原源及请求级核验；相同 datum_id 的同物表达须引用一致的基准依据集合，不能由脚本擅自判定不同基准依据等价。

不同物理管路认领同一原 part 的重叠区间时，不能仅换 physical_id 就认作多管。核验逐项采用原源 SHA、完整实例路径、part 及原曲线比例区间的正长度交集；方向、绑定别名或整组引用哈希不同不证明独立，不采用包围盒代替原源身份。相邻或不重叠的合法区间继续分别计算；端点止于墙内仍按不完整穿越保留，不能因区间合法就强认完整处数。若一条源表达代表多根，逐条给 `multiplicity_evidence={source_id,expected_text,pattern,instance_index}`，pattern 从整条真实原文命名捕获正整数 count，共用同一有源根数依据，独立序号在 1..count 内且不重复；否则各重叠认领保留 physical_identity_candidate，完整处数为 null。不确定身份不自动合为一根，也不认作两根。缺完整实例、part 或区间身份的原图/衍生路径同样保留未决。源实例各自独立而模型有据判为不同实物时，仍按各自物理 ID 分别计算。

断口方案另起路径行，使用单项 `scenario_gaps[]`，其中 `from/to` 各含源绑定、`part_index` 与 `endpoint=start|end`，并给 `hypothesis_id/basis_source_ids`。补连几何只由真实端点构造，单独为 scenario 层；原图段与补连不得混在一个无分层的 bindings 列表，方案交点不进入实画确认处数。

## 墙、楼板和空间

每项 `barriers[]` 有 `id/physical_id/kind(wall|slab)/space_id/floor_id/basis/basis_source_ids/boundary`。boundary 使用与管路相同的有源完整曲线绑定，不接手填坐标。

- `form=closed_footprint`：原图完整闭合平面轮廓；可包含直线和非退化圆锥曲线。未闭合时不暗补墙边。
- `form=paired_faces`：明确同一物理墙的两条平行、有间距的有源直墙面；两面实际均相交才形成一次穿越。不得用无限延长的虚拟墙面制造穿越。
- `form=single_boundary`：只有墙边界表达时保留 boundary_intersection_candidate；它不证明物理墙实体的一次穿越。

同墙的两边界在同一物理墙对象内求进入、退出区间，一次完整通过只计一处。路线再次进入同墙形成另一处，不按距离阈值合并。重复墙表达只在 physical_id 与实际几何、空间及高度一致时去重。切触、沿边、端头止于墙内、不同标高和不同楼层/空间分别记录。

paired_faces 的进入、退出必须分别命中不同墙面；从同面进入后折返仍是未闭合的墙内路径。只有其他楼层或空间的边界时，本管路适用范围仍缺墙资料，不能因为排除了异层边界就写完整零处数。

三维计算须同时具有：有源物理单位、管路 `z_mode=source_wcs`、`datum_id`、`z_basis_source_ids`，以及墙/楼板有源 `z_bounds` 和同一高程基准。z_bounds 含 `lower/upper/datum_id/datum_basis_source_ids`；上下限从真实文字取数：

```json
{
  "source_id": "CAD-ANONYMOUS-TEXT",
  "expected_text": "HIGH=3m",
  "pattern": "HIGH=(?P<value>[-0-9.]+)(?P<unit>m)",
  "unit": "m"
}
```

pattern 必须匹配整条实际原文，并命名捕获数值 value 与单位 unit；声明单位必须与捕获单位相同。基准及适用空间仍由本轮模型结合图纸判读绑定，不由脚本猜测。源单位未知时保留 raw_DU；可引用本图说明与几何佐证按现有单位声明规则补齐，不能从管径或层高倒推平面比例。仅平面事实、无墙高度或无共同基准时只输出明确适用范围的平面候选，完整三维处数为 null。没有有效墙资料不等于零。

本次实现的是有源平面轮廓的竖向墙/水平楼板棱柱，以及单边界/双平行墙面的候选接口。倾斜任意实体、非棱柱墙体、非退化平面以外的建筑边界、未恢复原生复杂实体仍为通用余项，须保留源与未决，不改称项目资料缺失。

## 曲线、衍生中线和误差

直线、圆弧及仿射椭圆使用完整参数方程求交；不以端点弦线或固定等分折线代替。三维路线保留源 Z，按实际 z 上下界分段；相交于平面但异标高时单列 different_elevation。

T28 `geometry.derived_midline` 的 line parts 是有界显示折线，不能作为原图已绘中线，也不能用弦长和替代隐式曲线积分。公共适配器固定重建双原轮廓并调用当前 duct checked_geometry，保留 `midline_evidence`、实际曲线积分长度、长度误差、源坐标单位和 `geometry_position_error_bound`。显示折线穿越始终属于 derived_crossing_candidate；墙边界落入位置误差带时，即使显示线没有交点也进入 derived_boundary_uncertainty，可能处数为 null。不得用轮廓非等距间隙确认截面、面积、套管或封堵。数值边界、切触及误差带仍须按隐式几何或进一步证据复核。

## 已有洞口、开洞和附属量

`openings[]` 必须有独立物理身份、所属 `barrier_physical_id`、同空间/楼层和闭合源边界；高度有证据时采用同样 z_bounds。管路经已有洞口仍保留其穿越记录及 opening_refs。平面落入洞口只形成 plan_opening_candidate；共同有源高度闭合时才列中心线与洞口高度关系。多个管路只因引用同一个有源物理洞口而形成 shared_openings，点距不构成共用依据，管路穿越处数继续分别计。

同物理洞口的重复表达按完整平面边界、墙身份、楼层/空间和高度/基准去重。高度或边界矛盾保留双方来源及 opening_identity_conflict，不强合为可用共用洞口。shared_openings 仅列至少两个唯一穿越事件，重复一条事件不会变成共用洞口。

中心线落入洞口不证明整个管路截面能放入，也不自动证明不需新开洞。new_opening_required/new_opening_count 保留 null；无洞口引用时另列新增开洞候选，有引用而适配未闭合时仍保留待核。套管、封堵数和封堵体积独立为 null 并列构造/计量/尺寸待办。项目按有源规则完成这些派生量后，应在相应唯一数量出口采用，不能倒填成公共交点的既定公式。

## 文件保护与检查边界

所有输入文件和发现的上游依赖均以 SHA 冻结；计算结束再次核对。实际 DXF 从磁盘只读，不修复或重写原图。输出目录须新建或为空，写前同时预检全部输出与输入的路径同物、硬链接和 reparse/symlink 别名；不覆盖原件或既有输出。引用文件改变后必须重新计算。

匿名反例及三专业实际调用链见 `tests/test_shared_penetrations_t30_20261019.py`。测试通过证明已编码几何、来源和状态边界，不代替真实项目墙身份、计量规则、工程量完整性或人工正式采用。真实项目验证路径、句柄、局部选取配置和临时口径留在维护工作区，不进入插件源码。
