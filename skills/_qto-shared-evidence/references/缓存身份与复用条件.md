# 缓存身份与复用条件

## 原则

缓存只能减少重复的中性事实提取，不能替代来源文件，也不能继承旧计算计划、规则选择、工作包、专业判断、工程量结论或发布状态。

## 必须核对的六类事实

| 类别 | 必须确认 |
|---|---|
| 来源身份 | 原文件路径、大小、SHA-256、图号、版本和修订号匹配 |
| 提取工具 | 工具名称、版本、读取方式和关键参数适用于当前来源 |
| 单位坐标 | 图纸单位、比例、坐标系、布局/视口变换含义明确 |
| 字段语义 | 每个字段的原始含义、数据类型和缺失值含义满足当前任务 |
| 完整质量 | 已知缺失、失败对象、代理对象、OCR低置信和损坏情况已记录 |
| 任务覆盖 | 当前系统、楼层、区域、图纸类型和所需事实均在缓存范围内 |

任一决定性条件不满足时，不得静默复用。

## 复用结论

- 可复用：六类事实全部满足，可读取所需中性事实。
- 部分可复用：可复用字段和范围能够独立证明，同时明确列出缺失字段和需要补提的范围。
- 不可复用：来源、版本、参数、单位、字段或范围不匹配，必须从当前来源重新提取。
- 待确认：来源文件、参数含义或决定性身份缺失，当前不能先用后补证。

复用结论必须说明缓存编号、缓存路径及哈希、来源身份、提取工具和参数、字段语义、覆盖范围、已知缺失以及影响范围，不能只写“缓存存在”。

## 局部失效

缓存可以按图纸、布局、楼层、区域、对象类型或字段局部失效。只重建受影响部分的前提是：

- 未受影响部分身份可独立证明；
- 新旧部分使用一致且可解释的单位和字段；
- 合并后仍能定位每条事实的来源；
- 不把缺失部分补零。

## 禁止复用

不得从旧 Skill 归档或退役源建立运行时读取；不得继承旧规则状态、旧专业标签、旧计算结果或旧发布门结论。项目目录中现有的 CAD/文档中性缓存只有通过本文件的身份门后才可复用。

- 缓存元数据中的旧工具绝对路径、旧方法文件或旧项目输出路径只能作为历史记录，不得跟随调用；需要重提取时必须使用当前明确的方法，否则保持“部分可复用”“待确认”或“不可复用”。
- 缓存或门记录中的 scope、专业、楼层或系统标签不能单独证明数据已按该范围过滤；必须另有可复核的布局、空间、对象或记录筛选清单。

## 独立复测与历史隔离

用户要求独立复测、盲测或“历史只作事后对比”时，冻结前只允许读取原始资料和通过本文件身份门的中性事实缓存。旧报告、旧工程量、旧对象选择清单、旧专业推算证据和带结果数值的项目记忆/历史摘要均不得进入计算上下文。

若平台在任务开始前已经自动提供或强制读取了旧结果数值，应继续从原始对象独立计算，但最终只能声明“文件级隔离”或“存在历史上下文暴露”，不能宣称完全盲测。冻结清单应分别记录：冻结前读取的中性缓存、冻结前暴露的历史上下文、首次读取旧专业成果文件的时间和冻结文件哈希。
