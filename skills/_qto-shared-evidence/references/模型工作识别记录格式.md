# 模型工作识别记录格式

管网与点位适配器均支持 `qto-model-recognition-ledger/1.0`。这是本轮识图形成的计算输入，不是要求用户填写的审批台账。对应模板位于公共 `assets/模型工作识别记录模板.json`；其占位值须由本轮真实取证填写。

保留原 `--adjudication-ledger` 参数及配置内 `adjudication_ledger` 的ID、版本、哈希绑定，兼容旧CLI；参数值可以是新模型识别记录，也可以是真实的旧 `qto-project-adjudication-ledger/1.0` 人工/独立来源台账。不能把两种事实混写。旧格式仍不允许模型充当 confirmed_by。

## 根记录

- `schema_version、ledger_id、ledger_version、source_sha256`：版本及本轮原始来源身份，与识别配置完全一致；独立中性流输入时按该适配器要求绑定流哈希。
- `adoption_scope="working"、review_status="unreviewed"`：仅用于工作识别与计算，不等于人工核定。
- `evidence[]`：每项记录 `evidence_id、path、sha256、source_sha256、kind、locator、observation`。path可相对台账文件；kind取 drawing_view、cad_property、project_document、cross_view。裁图或中性属性文件记录自身哈希，并注明对应原始图纸的定位与来源哈希。
- `entries[]`：实际工作判断；空数组只表示尚未识别，不是完成算量或零工程量。

## 每条工作判断

- `adjudication_id`：沿用CLI字段名称的稳定识别记录ID；不表示独立签认。
- `subject_id`：对应识别配置的 rule_id；`professional_owner`为实际专业。
- `decision`：include、exclude；点位还可用 container（仅容器，继续识别子实例）。`status="active"、decision_origin="model"`。
- `recognized_by、recognized_at`：实际模型标识/本轮可核验记录及时间，不编造人工身份。
- `source_id、evidence_ids`：对应本轮项目资料与上述证据。至少一个图面/对象属性证据。
- `object_ids`：明确适用的中性 record_id；点位必须用 `PT-<完整实例路径>`，不能只用共享块定义句柄。批量族识别先核查适用与例外，再固化清单；未列对象不会被该模型规则自动采用。
- `basis、scope_basis、identity_basis、cross_check、uncertainties`：分别说明专业判断、范围、唯一实例、交叉/冲突核对和残余疑点。程序检查可追溯结构和文件身份，图纸含义仍由模型负责判断和回图复核。

模型记录不得填 confirmed_by、confirmed_at、confirmation_source。首次识别与后续人工复核分别存档；正式采用仍需项目证据、规则和真实复核/授权，不能简单修改上述状态。

## 数量与规格

模型规则只决定有证据对象进入工作计算，不自动证明全部规格或全范围完整。管网与点位报告、计数和推算证据保留 `recognition_basis`，其正式采用许可固定为 false；本轮能力成熟度不变。

管网模型文字规则要作为 seed 时，必须给出 `segment_bindings`（原文字record_id到 `SEG-原管段record_id` 的显式映射），且两端ID都在该识别记录object_ids内。先依据引线/图面关系判明，再填映射；没有明确映射只能scenario，不能以最近距离获得seed资格。人工旧格式保持兼容。

点位未声明网络端口时，默认待核对端口，不把遗漏字段当作不适用。确无网络连接需显式 not_applicable 与依据；有点位工作包但未识别完不能声称交接完整。
