# 通用成果字段与状态

## 适用范围

所有算量 Skill 的成果至少映射到本文件定义的字段。最终载体可以是 Markdown、CSV、Excel 或 JSON，但字段语义不得改变。实际项目只要形成了数字，就必须同时交付用户可直接查看的成果汇总；JSON、脚本日志和证据文件不能作为唯一业务成果。少量结果可用 Markdown 表格，多专业、多系统、多规格或明细较多时优先交付 Excel 汇总及明细。公共约定只规定成果可追溯性，不规定专业公式。任何缺口、推算或暂估同时读取 [推算、假定与发布分层协议](推算假定与发布分层协议.md)。

本文件是人可读语义合同，不强制所有交付物转换成统一 JSON。为验证最小字段和跨字段不变量，阶段 2 另提供仅用于规范化样本测试的 [工程量成果最小字段.schema.json](工程量成果最小字段.schema.json)；它不是运行内核或专业规则引擎。Schema检查结构和明确的状态关系；完整规范化验证使用 `scripts/validate_minimum_result.py`，由其运行Schema及公共业务检查。单独Schema通过不代表文字、工程语义或正式采用条件通过。

## 入口路由与执行就绪状态

入口判断和工程量结果状态是不同层次，不得再用一个 `need_input` 同时表达“路由不清”和“缺计算资料”。路由检查至少区分：

| 字段 | 含义 |
|---|---|
| `entry_skill` | 当前请求直接进入的专业 Skill、`qto-coordinator`，或不属于算量时为 `null` |
| `required_skills` | 已由当前范围和物理对象确认必需的专业 Skill；不包含协调 Skill |
| `routing_resolved` | 是否已经唯一确定直接入口；即专业 Skill、`qto-coordinator` 或不属于算量 |
| `ownership_resolved` | 当前已识别物理对象是否均已确定唯一数量出口；没有待分派对象的不适用请求为 `true` |
| `calculation_input_required` | 路由已知后，实际计算是否仍缺图纸、范围、规格、标高、拓扑、规则或其他决定性输入 |
| `execution_ready` | 是否已经具备启动本次声明范围内计算的必要输入；不属于算量的请求固定为 `false` |

单一且归属清楚的对象直接进入对应专业 Skill；全专业、多个计算链或归属不清的请求进入 `qto-coordinator`。`routing_resolved=true` 不代表 `ownership_resolved=true` 或 `execution_ready=true`。例如综合支吊架请求可以确定进入协调 Skill，但在批准方案到位前仍应是 `ownership_resolved=false`、`calculation_input_required=true`、`execution_ready=false`；“只计算给水管长度”可直接路由到管网 Skill，但没有项目图纸时仍应是 `calculation_input_required=true`、`execution_ready=false`。

## 顶层字段

原图工作成果还应显示实际识别者、识别证据与复核状态；管网/点位使用模型识别记录时传递 `recognition_basis`，含模型来源、记录文件/哈希、working、unreviewed、formal_adoption_allowed=false。规范化成果带此字段时必须保留成果分层且不得进入正式量；不需要把无关表内复核强制转换成原图识别记录。字段合同见 [模型工作识别记录格式](模型工作识别记录格式.md)。

| 字段 | 要求 |
|---|---|
| 契约版本 | 固定为 qto-result-minimum/1.0 |
| 任务范围 | 业务专业、主要物理对象、系统、楼栋、楼层或区域、图纸类型、图纸版本、输出维度 |
| 资料选择 | 已选择、已排除和暂不确定资料及原因、拟提取事实和未使用影响 |
| 证据目录 | 项目事实证据及原始定位，不与规则来源混写 |
| 本次规则清单 | 规则编号、来源、本次判定、成熟状态、执行结果和证据位置 |
| 成果汇总 | 面向用户的分专业、系统、规格、楼层/区域和单位汇总；确认量、规则推算量、方案暂估量、未决量及工作量/正式量分列 |
| 工程量结果 | 按可复核对象和同一单位分别列示 |
| 整体未决事项 | 影响整体范围或多个结果的缺失、冲突和待确认条件 |
| 推算协议版本 | 使用推算分层时固定为 `qto-inference/1.0` |
| 假定与裁决清单 | 规则推算、方案暂估、替代方案、影响和重算依赖；没有推算时可为空 |
| 插件使用与临时处理 | 插件版本与提交、卡点、改用方法、登记，见[下文](#插件使用与临时处理)；本版缺了只提醒 |

## 用户可查看成果汇总

实际项目成果不得只返回“已生成 JSON”或仅给证据目录。成果汇总至少包含：

- 本次已覆盖与未覆盖范围；
- 按专业、系统、规格、楼层/区域和单位汇总的数量；
- 确认量、规则推算量、方案暂估量、未决量分别列示；
- 工作量小计与正式量小计分别列示；
- 待确认事项、推荐方案、数量影响和确认后的重算范围；
- 可追溯到对象明细、计算证据和原始资料的位置；
- “插件使用与临时处理（非插件能力）”一节，见[下文](#插件使用与临时处理)。

未知规格或未知数量不得从汇总中消失，应作为“规格待确认”或“数量未决”单独行列示。不同单位不得形成一个综合合计。

汇总首段（第一个标题之后、第二个标题之前）必须写明本专业必需校验器的运行情况：哪些已运行及结果，哪些未运行；必需资料（如设计说明）是否已读取。有必需校验器未运行、未通过，或必需资料未读取时，成果状态只能是“调用链验证”或“候选参考”，不得标为可交付或正式。

成果中的判断按来源措辞：模型自己做出的判断（DN 文字归属、对象归族、断口分类等）只能写成“模型判断”或“模型工作识别”；“人工裁定”“人工核定”“已/经人工确认”“已/经人工复核”只在持有 `qto-human-review-evidence/1.0` 凭据时使用。“待/需/请人工确认”是待办，不算人工结论。专业汇总校验器（如管网的 `validate_pipe_user_summary.py`）对这两条做机器检查。

## 每条工程量结果的最小字段

### 范围

至少包含业务专业、主要对象、系统、楼栋、楼层或区域、规格和输出维度。无法确定的字段写“待确认”，不得省略后默认为全项目。

### 结果

包含结果名称、数值、数值状态、计算式或说明和精度。使用推算分层时另含“成果分层”：数量层级、计算完整性、置信等级、确认状态、发布状态、假定编号、替代方案、依赖成果项、是否进入工作量、是否进入正式量和重算范围。

- 数值状态“已计算”必须有数字和证据；数字可以是确认量、规则推算量或方案暂估量，但数量层级必须明确；
- 数值状态“未确定”必须使用 null，不得用 0；
- 数值状态“不适用”必须使用 null；
- 原始计算精度和展示精度应可区分，避免先四舍五入再累计。
- 每项同时包含试运行结果标记和零值复核字段；非零或未形成数值时零值复核使用 null，零值时使用包含范围覆盖、来源、规则、复核结论和说明的结构化记录。

### 单位

“已计算”或“部分计算”的每条结果只允许一个明确、可核对的单位；“待确认”“未知”“混合单位”和 m+m² 之类拼接值都不是有效数值成果单位。米、平方米、立方米、千克、吨、个、套、台、樘等不得相加为“综合总量”。需要展示多个单位时分组列示。单位尚未确定时不能形成工程单位下的正式结果；若原始单位或无量纲候选仍有意义，应分栏输出原始量。无法形成任何可核对单位时数值使用 null，并登记未决事项。

### 来源

引用证据目录中的编号。每项数值至少有一条来源，并能定位到页码、布局、实体、表格行列或等效位置；只在任务顶部罗列文件不能替代成果项级追溯。

### 规则

引用本次规则清单中的规则编号。本次规则清单记录规则名称、规则来源、适用结论、成熟状态、执行结果和证据位置：

- 适用结论：采用、试用、不适用、证据不足；
- 成熟状态：候选、试运行、正式、停用。

结果状态、规则的本次适用结论和规则成熟状态是三套概念。旧规则状态和旧测试通过不能提升新规则成熟状态。

### 状态

| 结果状态 | 含义 |
|---|---|
| 已计算 | 当前声明范围内结果闭合；不等于规则正式成熟或对外发布 |
| 部分计算 | 当前声明范围只有部分对象形成数值，范围完整性仍受未决事项影响 |
| 待确认 | 存在可裁决的事实歧义、版本冲突或规则选择冲突 |
| 证据不足 | 已走完可用推算阶梯仍不能形成有意义候选，受影响结果为 null |
| 不适用 | 经明确范围和规则判断，本项不适用 |

### 未决事项

每项至少包含编号、类型、说明、影响、所需输入和当前处理。类型包括缺资料、范围未定、来源冲突、规则冲突、质量问题和需用户确认。

## 否定结论与检索证据

“图上无”“未见”“不存在”“无平面内容”“清单项图上无”一类否定结论，只能证明检索过的范围内没有找到。它要作为不计、判定清单有误或解释数量差异的依据，必须附检索记录。每条否定结论至少写明：

| 项 | 要求 |
|---|---|
| 结论 | 原文 |
| 检索图纸 | 图纸编号、图页或布局；只查了部分图页的，写明是哪几页 |
| 检索对象 | 图层、块名、文字关键词、表格、实体类型。规格类写出常见变体（如 `4x150`、`4×150`、`4*150`） |
| 方法 | 中性取证包检索、原生 CAD 补读、PDF/OCR 文字检索或逐页查看；脚本检索写脚本位置 |
| 结果 | 命中数（为 0 也写 0），以及没能读取的部分（图片、代理对象、外部参照、扫描页） |
| 未覆盖 | 可能含该类对象但没有查的图纸 |

- 检索范围要覆盖所有可能含该类对象的图。规格类结论至少查系统图、配电或出线表、平面和材料表。对象类结论（如“某图无平面内容”）要按图层、块和实体类型查，不能只看图层说明框或图例。
- 下结论前先查本包和相邻包已有的成果：同一规格或对象已在别处计过（包括列在清单外的），就不能再写图上无。
- 反向核对（从清单、表格或另一张图回查图面）要声明覆盖的图纸集合。只出现在集合外某张图上的对象，如另一张平面上独有的箱号，列为“未核对”，不写“已闭合”。
- 检索记录不全或有没能读取的部分时，结论写成“待确认：在所列范围内未检索到”，登记为未决事项，类型为质量问题或缺资料，不进入“已确认零值”。真正的零值复核记录要引用这条检索记录。
- CAD 图用 [否定结论检索](否定结论检索.md) 的脚本出记录，记录就是上表 6 项加检索状态。
- 成果里怎么写：
  - 成果项加 `否定结论`：`{"结论": 原文, "检索记录": [记录编号], "清单量": 数或 null}`；
  - 记录本身放进成果顶层 `否定结论检索记录`（脚本输出的 `records` 原样拷入）。
- 公共校验器按此作条件检查，没写 `否定结论` 的成果不受影响：
  - 记录要存在、6 项齐全；
  - 记录状态是“有命中”的，否定结论不成立；
  - 状态是“待确认”的，该项只能是待确认或证据不足，并挂未决；
  - 只有全部记录“全覆盖未命中”，才能写“已确认零值”；
  - `清单量` 大于 0 的，至少一条记录检索过“表与说明”类图页。

## 插件使用与临时处理

形成数字的成果，汇总里必须有一节“插件使用与临时处理（非插件能力）”，写明本次用了插件的哪些能力、在哪里卡住、改用了什么办法、登记了没有（登记 20261015-0825、0759、1407）。没有卡点也要写，整表一行“无”。

**版本行**：`插件版本：0.3.10 / 提交 9382aa3`。中途换版的，写两对版本，并写换版点（从哪个包或哪一步起用新版）。

**表格六列**：

| 列 | 写什么 |
|---|---|
| 环节 | 卡在哪一步，如“系统图回路表抽取”“桥架识别” |
| 涉及Skill与插件脚本 | 如 `qto-electrical-routes`、`calculate_electrical_paths.py`；插件里没有对应脚本的写“无脚本” |
| 卡点 | 报错原文，或缺的能力。不写“不好用”“有问题”一类含糊话 |
| 改用方法与位置 | 改用的项目脚本、手工做法或自定口径，写路径 |
| 影响数量 | 是 / 否；是的写影响哪几项 |
| 登记 | 只能是四种之一：已有登记文件名（`20261015-0825_…md`）；`待协调登记`；`不进插件：<理由>`；`无`（整表只有这一行时） |

- 项目临时工具、自定口径都算“改用方法”，要当场登记，不等收尾。
- 项目交付格式只增不减插件必交项（成果汇总、HTML 复核页、本节），除非用户明示豁免；豁免写进本节，注明用户原话和时间。

**规范化 JSON**：顶层可选键 `插件使用与临时处理`：

```json
{
  "插件版本": "0.3.10",
  "提交": "9382aa3",
  "换版": [{"插件版本": "0.3.9", "提交": "9e1c98e", "换版点": "E-A-CBL2 起用新版"}],
  "记录": [{"环节": "…", "涉及Skill与插件脚本": "…", "卡点": "…", "改用方法与位置": "…", "影响数量": "否", "登记": "无"}]
}
```

`validate_minimum_result.py` 的检查：

- 有这一节时：版本号形如 `0.3.10`，提交是 7～40 位十六进制；`记录` 非空，每行六列都非空；登记只能是上面四种之一，写“无”的整表只能有一行；`换版` 是数组，每项三栏都非空。
- 没有这一节、而成果里有数值的：本版只在报告的 `warnings` 里提醒，不判失败；下一版升为必填。

## 跨字段不变量

1. 数值为 null 时，数值状态只能是“未确定”或“不适用”。
2. 数值状态为“未确定”时，结果状态只能是“待确认”或“证据不足”，且未决事项不能为空。
3. “已计算”必须有数字、来源及“采用”或“试用”规则；若数量层级不是确认量，必须引用假定与裁决清单并禁止静默进入正式量。
4. “部分计算”必须有已形成部分的数字和来源，至少关联一项确实影响完整性的未决事项；存在成果分层时，其计算完整性必须为“部分”。合计仅表示相加，名称与相邻范围、状态和未覆盖说明一起限定成果，不要求固定短语。不得将局部成果宣称为整体完整量。公共Python检查保留对明显完整性措辞的启发式识别，管网和土方复用；它不能证明自由文本与图纸含义相符，也不能判断任意未决文字是否确实影响范围，这些仍须按证据复核。来源、未决引用、单位和正式采用条件独立校验。
5. 真正的零值必须有覆盖完整范围的结构化零值复核记录，记录引用来源和采用规则并写明“已确认零值”；未知不得填零。
6. 数值存在时来源不能为空；来源丢失时不得保留“已计算”。
7. 候选规则可以“试用”；只有记录当前项目直接权威依据或已确认裁决时才可在本项目标为“采用”，且不提升全局成熟状态。停用规则不得试用或采用。
8. 采用候选或试运行规则时，结果必须明确标识为试运行结果，并按推算协议限制发布。
9. 不同单位不得合并；单位相同但对象含义、计量口径或范围不同也不得直接合并。
10. 结果引用的资料必须处于“已选择”，不能引用已排除或身份未确认资料。
11. 当前范围外的资料和相邻专业不得被静默纳入。
12. 规则推算量和方案暂估量必须有假定编号、置信等级、依赖和重算范围；不得只在脚注中说明“含暂估”。
13. `进入正式量=true` 的成果不得处于待确认或已否决状态，不得引用仍为“试用”的规则或待确认假定。
14. 同一口径的工作量与正式量分列；工作量可以包含已披露的推算和暂估，正式量只含符合发布条件的成果。
15. 否定结论用于不计、判定清单有误或解释差异时，必须引用覆盖所有可能来源图的检索记录；检索不全或没有记录的，只能列为待确认的未决事项。

## 扩展

专业 Skill 可以增加对象编号、规格、计算明细、扣减关系和质量检查等字段，但不得删除或改变上述最小字段。结构验证只检查字段和不变量，不替模型决定专业规则是否适用。
