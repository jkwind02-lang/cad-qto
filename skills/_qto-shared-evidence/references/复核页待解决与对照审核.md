# 复核页：成果、待解决问题与对照审核（qto-review-view/1.1）

0.3.13比较资格、原量null/0及跨入口审核身份、共性范围按[比较资格与审核适用性](比较资格与审核适用性.md)；本文旧的null按0及新增成员继承口径由该补充替代。

复核页就是最终成果页。它显示本次算出的全部总量，按维度分类，每条都能往下查明细组成，一直溯源到最初的依据。页面的重点是**待解决问题**：成果中没有依据或无法判断的内容，按问题性质分组，让用户答一类、解决一片。第三方数量（审计清单、招标清单、对方报量、甲方核定量）只作对比，偏差先看本次依据是否充分再归因：依据充分的偏差是清单的问题，按类型整组答复一次。

本文是面向专业会话的摘要。字段的完整定义和校验规则以插件仓库 `docs/维护/复核页审核视图契约.md` 为准；两处不一致时按契约。

## 1. 什么时候用

- 要交本次成果给用户看：用 1.1，把成果写成条目（有第三方对应的写 `third_party`，清单外新增写 `extra`），明细行写到依据。没有第三方数量时条目都写 `extra`，页面显示为“独立算量条目（未建立第三方对照）”，不会说成清单外新增。
- 计算中有没有依据或无法判断的内容：写成问题，并写**问题性质**。先想“这个口径别处会不会也遇到”：会遇到的写成**共性问题**（一条统一问法），各处出现的写成它下面的个别问题，或把条目直接挂到共性问题上。没有第三方数量也可以只写问题。
- 有第三方数量要对照：在条目上写来源段。
- 口径已经定为不计的量（例如按口径决定单定为二期的干线）：在明细行上标“已定不计”，不再写成未决。
- 只有图面对象和问题组：照旧用 1.0（[HTML交互复核与批注](HTML交互复核与批注.md)）。1.1 也能同时带图页、对象和问题组，页面上叫“图面复核”。

## 2. 页面是什么样

- **顶部**：按性质列还没答复的共性问题和单独成立的个别问题数，再加“没有依据、也没挂问题”的条目数，点了进对应分组；有对照时下面一行是一致带宽的默认规则和页面容差设置。
- **四个模式**，按顺序：
  1. **成果**（默认）：只列本次有量（合计不为空、不为 0，或有未决量）的条目，含清单外新增。
     - 按楼栋（`overview`）、分部（`section`）、品类（`category`）三级分类，分类标题写条目数、含估算条数、有待定条数，不跨条目求和。
     - 每行：名称和特征、本次各层级数量和合计、依据状况条（有依据 / 估算 / 待定三段）；挂着未答复问题的按性质显示标记，点了跳到该问题；第三方数量和结论在行尾作对照。
     - 有已定不计的行上标“另有已定不计”；成果末尾单列“已定不计”组，默认收起，列出不计的量、依据和说明。
     - 筛选：范围（全部 / 有第三方对应 / 清单外新增）、依据状况（全部有依据 / 含估算 / 有待定）、问题性质、`filter` 维度和全文搜索。`technical` 维度（如计算包号）不进筛选，只在详情的“技术来源”里出现。
  2. **待解决问题**：按八类性质分组，组标题写这一类要什么样的答复；组内先列共性问题，再列单独成立的个别问题。没写性质的个别问题放“未分类”。含估算或待定、却没挂问题的条目，以及依据不足的偏差没挂问题的条目，单列“没有依据、也没挂问题”，提醒专业补挂。已处理的默认收起；末尾单列“检索记录不全”，默认收起，只作提示。成果页选的分包、楼层等筛选会沿用到这里，选择器照样显示，可改回“全部”。
  3. **对照审核**：偏差按归因分组，不逐条审。
     - **清单的问题**：清单少计、清单多计、清单漏量、清单列了图上没有的、清单规格写错，每组整组答复一次；组内条目只能设例外。含已定不计的条目在组内和整组答复界面标“含已定不计”，并列出不计的量和依据。
     - **本次依据不足**：按所挂的共性问题或个别问题分组，点了跳到待解决问题里答复；没挂的单列“依据不足的偏差未挂问题”。
     - 无法归因（单位不同或两边都没有量）、缺图、归入他项、一致各单列，默认收起。
     - 组内按差额率、差额或编号排序；可以按结论、差异超阈值、修正标记、检索记录不全、来源间结论不一致和维度筛选。
  4. **图面复核**：原有的问题组和对象。
- **详情**：
  - 条目：本次各层级数量与依据状况；明细组成与依据（楼层区域、层级、数量、依据和图纸），清单关系不是“对应”时作标签；明细编号、定位、备注和技术维度收在“技术来源”里。已定不计的行排在计入行之后，标“已定不计”。有成员的明细行按台账标题下钻（电气叫“逐回路台账”），有图面定位时图面自动展开并高亮。没有明细的写原因：图上无（附检索依据）、归入他项（附去向）、缺图（附说明）。挂在条目上的问题按性质列出。对照审核里先列第三方的行、差额和归因。
  - 共性问题：情况；各做法并排列出影响量，标出现做法；适用范围（个别问题和条目）；答复状态。
  - 个别问题：情况、影响、现做法和可选做法、涉及量（各条目原值）、原条目原文、所属共性问题。
- **意见**：
  - 问题和共性问题的快捷结论显示为“按现做法 / 不按现做法 / 暂不定”，有做法的可以选一个做法；原因必填。
  - 答复一条共性问题，适用范围里的个别问题和条目一起生效，显示“已按共性答复（G03：按现做法）”，只能“设为例外”。例外写明这一处为什么不按共性答复、应该怎么算；与共性答复相同的不保存；共性问题没答复时不能设例外。设了例外的一处显示“此处已设例外”和本处意见；例外过期的显示“此处原设的例外已过期，须重新核对”。
  - 条目自己的数据问题在成果里写意见，明细行可以取消勾选作为例外；条目批注会记下当时的页面容差和显示的结论（`page_view`）。
  - 共性问题的适用范围变了（例如下一轮又挂进来几条），答复不过期，标“答复后新增 N 处”供抽查。
  - 合并导入时同一处有两条不同的现行意见的，标“意见冲突”，重新保存其中一条才消除；一方已过期的不算冲突，保留现行的那条，过期的进历史。冲突中的一处如有例外，重新保存前不按共性答复，显示“例外意见冲突”。同一条目落在两条共性问题下、一处按现做法一处不按的，提示“同一条目有两处答复，请核对”。
- **页面容差**：可以在顶部改一致容差，页面按它重新显示一致、多算、少算，与数据结论不同的标“原：…”。只在页面打开期间有效，不改归因，不写回数据，不使意见过期。
- **网址片段**：`#item=`、`#issue=`、`#common=`（清单的问题各组打开对照审核）、`#group=`、`#object=`、`#scene=`、`#dim=维度:值`、`#source=`、`#mode=results|resolve|audit|review`（`issues` 是 `resolve` 的别名，`extras` 打开成果并筛到清单外新增），值用 `encodeURIComponent` 编码，几个参数用 `&` 连接。

## 3. 怎么生成

**推荐：从专业自己的表格生成。** 写一份映射文件（`qto-comparison-table-mapping/1.0`），把表格列名对到标准键，再运行：

~~~text
python ../_qto-shared-evidence/scripts/build_comparison_view_from_tables.py --mapping 审核视图映射.json --output 复核视图_r1.json [--base-view 已有复核视图A.json --base-view 已有复核视图B.json] --report 表格转换检查.json
python ../_qto-shared-evidence/scripts/build_qto_review_html.py --input 复核视图_r1.json --output 复核页_r1.html --local-only --report HTML生成检查.json
~~~

- 转换脚本只搬运和改名，不计算工程量；写出前跑全部双向校验，报错时 `--report` 里列出全部问题（`problems`），一次改完再跑。映射里写了、转换不认识的键（拼错的标准键、没声明的维度、不认识的表字段）列进 `mapping_warnings`，只提醒不拦，看到就改映射。
- 数字列空白为 `null`，带 `%` 的按百分数转小数，不能解析的报错，不猜。是否列只认 是/否、true/false、1/0、Y/N。中文写的性质、处理方用 `value_maps` 转成代码。
- 表：
  - 条目、明细、来源行、去向、问题、问题挂接、问题原文、问题涉及量（`issue_impacts`）照旧。
  - **问题表**加 `nature`（性质）、`common_issue_id`（所属共性问题）、`rule_ref`（口径决定单编号）、`plugin_issue_ref`（插件登记编号）、`current_option`（现做法编号）。
  - **共性问题表** `common_issues`：`id`、`nature`、`question`、`text`、`handler`、`current_option`、`rule_ref`、`status`、`dim.<维度>`。编号不能与个别问题重号，不能以 `清单的问题|` 开头。
  - **做法表** `issue_options`：`issue_id`（共性问题或个别问题）、`option_id`、`text`、`value`、`unit`、`note`；一行是一个做法的一段影响，同一做法各行 `text` 相同；没有影响量的做法写一行，`value` 留空、`note` 写说明。
  - **共性问题挂接表** `common_issue_links`：`common_issue_id`、`item_id`，用于不经个别问题、直接归到这条口径下的条目。
  - **明细表的已定不计列**：`excluded`（是否）、`excluded_rule_ref`、`excluded_issue_id`、`excluded_note`。`excluded_note` 必填，后两列至少一个；`excluded` 为假而后三列有值的报错。
  - **成员台账**三张表：成员表 `members`（每行一个对象，可以只建对象）；挂接表 `member_links`（`catalog_key`、`detail_id`、`quantity_name`、`level`、`quantity`，按挂接取层级和数量，对象缺这个数量项时补上，已有而数值不同时报错）；汇总方式表 `detail_aggregation`（`detail_id`、`aggregation`、`aggregation_reason`、`member_quantity_name`、`member_table`）。台账标题写在 `comparison.member_tables`。
- 映射的 `comparison` 里写的 `thresholds`、`legacy_search_evidence` 原样带进视图。来源行编号表 `row_ids_table` 写 `{"path": …, "column": "row_id"}`，也可以只写路径字符串。
- `--base-view` 并入已有的图页和回图对象，可以写多次；成员台账里 `catalog_key` 相同的对象直接引用，不重建。图页编号或对象 `catalog_key` 撞号时报错；问题组编号相同时，后并入那份的组号改为 `<文件名>|<组号>`，报告列出 `renamed_groups`；`base_views` 列出每份并入的图页、对象和问题组数。
- 几包同号的图页内容相同才合为一页，不同就报错，并写明哪一项不同。底图不同时，加 `--scene-report`（各包的图面转换检查报告，可写多次），报错里列出过滤条件差在哪一层。合成前可以先只核：`--check-shared-sheets --base-view A --base-view B [--scene-report …] --report 同号图页核对.json`，不写 `--mapping`、`--output`，有不同的退出码 2。
- 报告的 `shared_objects` 统计同一实物（`object_id` 相同）的多包记录。`multi_quantity` 大于 0 说明有两条以上记录带数量，可能跨包重复计量，按 `multi_quantity_rows` 核对；`coordinate_mismatch` 是同图页同编号的点坐标不一致。
  - 像 CAD 句柄的编号（1～16 位十六进制，如 `3BFE`）只在本图唯一：不同图纸上的同号按不同实物计，不进 `multi_quantity`；各图都带数量的，单列在 `suspected_handle_collisions` 和 `suspected_handle_collision_rows`（疑似句柄撞号，列出图纸和记录）。同一图纸上的同号句柄照旧算同一实物，`multi_quantity_rows` 里写明 `drawing`。
  - 其余编号（箱号、`identity_key` 等全局编号）跨图照旧算同一实物。有记录取不到所属图纸（未定位）的同号句柄不拆开，照旧提醒。
  - 跨图共用的全局编号不要写成像句柄的样子，各包自编的流水号（如两包都有 `CAB-001`）也要带上包号或图号，否则会被当成同一实物提醒。
- 输出文件已存在时拒绝覆盖，用新的版本名。
- 电气的映射样例见 [电气复核页审核视图接入](../../qto-electrical-routes/references/复核页审核视图接入.md)。

也可以直接写视图 JSON，字段同下。

## 4. 字段要点

| 位置 | 要点 |
|---|---|
| `comparison.thresholds` | `consistent_band` 是默认一致带宽：写一个小数时所有单位通用；也可以分写 `{"计量": 0.05, "计数": 0}`，这时须给 `count_units` 列出按计数处理的单位；计数写 0 表示须相等。`difference_rate_alert` 是“差异超阈值”筛选的初始值，与容差是两回事 |
| `comparison.legacy_search_evidence` | 可选，`{"rule", "note"}`。只用于检索记录规则（e63fe30）生效前交付的成果：写了以后“图上无”的检索依据可以不全，页面标“检索记录不全” |
| `comparison.dimensions` | `role`：`overview`（总览卡片，最多一个）、`section`（分部，最多一个）、`category`（品类，最多一个）、`filter`（筛选）、`technical`（只进技术来源，如计算包号） |
| `comparison.nature_labels` | 可选，换八类性质的显示名 |
| `items[]`（条目） | `kind` 为 `third_party` 或 `extra`；`ours.levels`（确认量、规则推算量、方案暂估量、未决量，`null` 不是 0）；`third_parties[]` 每个来源一段 |
| 结论 | 一致、多算、少算由生成器按默认带宽判（可以不写，写了必须相同）；第三方无量、图上无（附检索依据）、缺图（附说明）、归入他项（附去向）由专业写 |
| 归因 | 生成器在多算、少算、第三方无量、图上无的段上补 `attribution`：本次依据充分为 `list`（清单的问题）；依据不足而差额不超过暂估加未决为 `ours`；超出为 `both`，另补 `excess`。依据不足 = 有方案暂估量、有未决量，或挂了未关闭的问题（性质为“清单的问题”的不算）。专业不写，写了必须相同 |
| `detail_rows[]` | 每层级数量之和等于条目该层级的量（已定不计的行不计入）；单位与条目相同；`aggregation` 为 `leaf`、`sum_members` 或 `declared`；已定不计写 `excluded: {rule_ref, issue_id, note}`，`issue_id` 须是已关闭的问题。整条都不计的条目，确认量写 0，其余层级写 `null` |
| `issues[]`（个别问题） | `handler`：`decide` 需要你定口径、`confirm` 需补资料或确认、`assumed` 已按假设计入、`closed` 已处理；`nature` 八类之一（挂了共性问题的取共性问题的，自己写了须相同）；`title`、`text` 必填；`current_practice` 写现在怎么算；有做法的写 `options`、`current_option`，“有多种判断方式”且单独成立的须至少两个做法 |
| `common_issues[]`（共性问题） | `nature`、`question`（一般问法，不写某栋某项）必填；`options` 每项 `id`、`text`、`impact`（`null`、一段或多段，只显示不求和），有做法时 `current_option` 必填；“有多种判断方式”至少两个做法；`item_ids` 直接挂的条目；`rule_ref` 口径决定单编号 |

八类性质：现行规则无法判断 `rule_gap`、有多种判断方式 `multi_method`、缺图纸或资料 `missing_info`、图纸矛盾或不清 `drawing_conflict`、范围分期或专业界面不清 `scope`、按假设或估算计入 `assumption`、工具或方法限制 `tool_limit`（同时登记插件问题）、清单的问题 `list_issue`（一般由生成器按归因自动归组，专业也可以手写）。

合计 = 确认量 + 规则推算量 + 方案暂估量，不含未决量。“以暂估为主” = 方案暂估量 > 0 且不小于确认量与规则推算量之和。差额率允许四舍五入到 0.1%。

## 5. 生成器检查

C3-0 结构与编号、带宽写法；C3-1 条目各层级 = 明细合计（已定不计的不计入）；C3-2 明细 = 成员合计；C3-3 来源行不漏不重；C3-4 同一对象的同一数量项只计入一行明细；C3-5 结论与字段自洽、默认带宽；C3-6 问题引用、性质、涉及量写法；C3-7 对象维度与条目一致；C3-8 来源段与行；C3-10 共性问题（编号、性质、问法、做法）；C3-11 归因与重算相同；C3-12 已定不计（说明、依据、所引问题已关闭）。任一不通过返回 `INPUT_REQUIRED`，不出半成品页。

C3-9 只提醒，列进 `comparison_exceptions`：有未决量、以暂估为主或缺图而没挂未关闭问题的条目（`不确定条目未挂问题`）；依据不足的偏差没挂问题的（`依据不足的偏差未挂问题`）；单独成立的个别问题没写性质的（`问题未分性质`）。专业应补挂问题或说明为什么不用问。

## 6. 收到意见后

用 `read_qto_review_feedback.py` 读取（1.0 和 1.1 的批注都收）。1.1 视图的输出多出：

- `common_issue_actions`：共性问题编号、性质、快捷结论、所选做法、结论、原因，展开后的适用范围（已除去例外和例外冲突中的各处）和 `added_since_answer`（答复后新增的个别问题和条目）；有例外冲突的另列 `held_by_conflict`；
- `issue_actions`、`item_actions`：自己答复的，加上由共性答复带来的（标 `via`）；例外标 `exception_of`；条目另带例外明细行和 `page_view`；
- `conflicts`：合并时两份意见不同、还没重新保存的，未采用任何一份，状态为 `REVIEW_REQUIRED`；
- `overlaps`：同一条目在两条共性答复下一处按现做法、一处不按，只提醒。

这些只是用户意见，供所属专业复核，不自动写回数量。专业按答复重算后，把问题或共性问题改为 `closed` 并写 `rule_ref`，答复的口径记进口径决定单；下一轮遇到同类，挂到同一条共性问题，不再重新问。条目的数、问题和共性问题的问法、性质、做法或处理方变了，旧意见标为过期；共性问题只是适用范围变了的不过期。
