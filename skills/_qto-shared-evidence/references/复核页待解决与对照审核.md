# 复核页：待解决与对照审核（qto-review-view/1.1）

复核页的首要目标是解决算量过程中的不确定内容和无法解决的内容：把要用户定口径的、要补资料或确认的、按假设计入的事项，以及未决量、以暂估为主、缺图这些还没算实的条目摆在最前面，让用户逐条拍板。与第三方数量（审计清单、招标清单、对方报量、甲方核定量）对照找偏差，是同一张页的另一项功能。

本文是面向专业会话的摘要。字段的完整定义和校验规则以插件仓库 `docs/维护/复核页审核视图契约.md` 为准；两处不一致时按契约。

## 1. 什么时候用

- 有要用户拍板的事项（定口径、补资料、按假设计入），或有未决量、以暂估为主、缺图的条目：用 1.1，把它们写成问题条目。没有第三方数量也可以只写问题。
- 有第三方数量要对照：同一视图里写对照条目。
- 只有图面对象和问题组：照旧用 1.0（[HTML交互复核与批注](HTML交互复核与批注.md)）。1.1 也能同时带图页、对象和问题组，页面上叫“图面复核”。

## 2. 页面是什么样

- 顶部：先是待解决计数（各类未关闭问题、有未决量、以暂估为主、缺图），下面一行是统一带宽规则。
- 四个模式，按顺序：
  1. **待解决**（默认）：问题按“需要你定口径 / 需补资料或确认 / 已按假设计入 / 已处理”分组，已处理默认收起；下面分“有未决量”“以暂估为主”“缺图”三组列条目，没挂到未关闭问题的标“未挂问题”。
  2. **对照审核**：按分节维度分组的列表，每行有对比条（第三方量一条；本次量分“确认 + 规则推算”“方案暂估”两段），可以按差额率、差额或编号排序，按结论、差异超阈值、有问题、以暂估为主、修正标记、维度筛选。
  3. **清单外新增**。
  4. **图面复核**：原有的问题组和对象。
- 详情：各来源的行并排，本次各层级数量和合计，明细行（可以取消勾选作为意见的例外），有成员的再下钻到成员台账；成员有图面定位时图面自动展开并高亮，可以上一处、下一处；没有定位时图面自动收起。没有图页的视图不显示图面区。
- 意见：条目和问题都能批注。问题的快捷结论显示为“按现做法 / 不按现做法 / 暂不定”，选“不按现做法”时在原因里写明应该怎么算。原因必填。
- 网址片段：`#item=`、`#issue=`、`#group=`、`#object=`、`#scene=`、`#dim=维度:值`、`#source=`、`#mode=resolve|audit|extras|review`，值用 `encodeURIComponent` 编码，几个参数用 `&` 连接。

## 3. 怎么生成

**推荐：从专业自己的表格生成。** 写一份映射文件（`qto-comparison-table-mapping/1.0`），把表格列名对到标准键，再运行：

~~~text
python ../_qto-shared-evidence/scripts/build_comparison_view_from_tables.py --mapping 审核视图映射.json --output 复核视图_r1.json [--base-view 已有复核视图.json] --report 表格转换检查.json
python ../_qto-shared-evidence/scripts/build_qto_review_html.py --input 复核视图_r1.json --output 复核页_r1.html --local-only --report HTML生成检查.json
~~~

- 转换脚本只搬运和改名，不计算工程量；写出前跑全部双向校验，报错时 `--report` 里列出全部问题（`problems`），一次改完再跑。
- 数字列空白为 `null`，带 `%` 的按百分数转小数，不能解析的报错，不猜。是否列只认 是/否、true/false、1/0、Y/N。
- `--base-view` 用来并入已有的图页和回图对象；成员台账里 `catalog_key` 相同的对象直接引用，不重建。
- 输出文件已存在时拒绝覆盖，用新的版本名。
- 电气的映射样例见 [电气复核页审核视图接入](../../qto-electrical-routes/references/复核页审核视图接入.md)。

也可以直接写视图 JSON，字段同下。

## 4. 字段要点

| 位置 | 要点 |
|---|---|
| `comparison.thresholds` | `consistent_band`（全页一致带宽，小数）；`consistent_band_by_unit` 按单位另给，计数单位写 0 表示须相等；`difference_rate_alert` 是筛选初始值 |
| `comparison.dimensions` | 维度及值域；`role` 为 `overview`（总览卡片，最多一个）、`section`（列表分节，最多一个）或 `filter` |
| `comparison.sources` | 第三方来源，带文件哈希；`row_ids` 最好从来源文件独立抽取，否则只能查重号、查不出漏行 |
| `items[]`（对照条目） | `kind` 为 `third_party` 或 `extra`；`ours.unit`、`ours.levels`（确认量、规则推算量、方案暂估量、未决量，`null` 不是 0）；`third_parties[]` 每个来源一段：`rows`、`quantity`、`unit`、`difference`、`conclusion` 等 |
| 结论 | 一致、多算、少算由生成器按统一带宽判（可以不写，写了必须相同）；第三方无量、图上无（附检索依据）、缺图（附说明）、归入他项（附去向）由专业写 |
| `detail_rows[]` | 每层级数量之和必须等于条目该层级的量；单位与条目相同；`aggregation` 为 `leaf`、`sum_members`（成员同名数量之和）或 `declared`（写原因） |
| `issues[]`（问题） | `handler`：`decide` 需要你定口径、`confirm` 需补资料或确认、`assumed` 已按假设计入、`closed` 已处理；`title`、`text` 必填；`current_practice` 写现在怎么算（decide、assumed 建议必写）；`item_ids` 挂接条目 |

合计 = 确认量 + 规则推算量 + 方案暂估量，不含未决量。“以暂估为主” = 方案暂估量 > 0 且不小于确认量与规则推算量之和。差额率允许四舍五入到 0.1%。

## 5. 生成器检查

C3-0 结构与编号；C3-1 条目各层级 = 明细合计；C3-2 明细 = 成员合计；C3-3 来源行不漏不重；C3-4 成员只属于一行明细（或写拆分份额）；C3-5 结论与字段自洽、统一带宽；C3-6 问题引用的条目存在；C3-7 对象维度与条目一致；C3-8 来源段与行。任一不通过返回 `INPUT_REQUIRED`，不出半成品页。

C3-9 只提醒：有未决量、以暂估为主或缺图的条目，应挂在某个未关闭的问题上；没挂的列进 `comparison_exceptions`（`不确定条目未挂问题`），报告给出条数。专业应补问题或说明为什么不用问。

## 6. 收到意见后

用 `read_qto_review_feedback.py` 读取（1.0 和 1.1 的批注都收）。1.1 视图的输出多出：

- `item_actions`：条目编号、快捷结论、结论、原因、例外明细行；
- `issue_actions`：问题编号、快捷结论、结论、原因。

这些只是用户意见，供所属专业复核，不自动写回数量。条目的第三方量、本次量、结论、明细或成员变了，旧意见标为过期；问题的分类、正文、影响、现做法或挂接条目变了，旧意见也标为过期。专业改完后重新生成视图和页面，在问题上把 `handler` 改为 `closed` 或更新现做法。
