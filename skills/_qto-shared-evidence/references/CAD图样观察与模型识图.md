# CAD图样观察与模型识图

模型需要实际观看图样，才能结合图例、文字排布、线型、符号和跨图关系判断工程含义。共享 `scripts/render_cad_view.py` 直接从来源绑定的 DXF 生成可看的 PNG 与 SVG；无需先提供管线、设备或接口分类。模型自行选择本次观察的问题、布局、范围和图层，再依据看到的内容推理或补看其他视图。绘图器不替模型解释符号或确认连接。

## 先看图样，再定位精确对象

本入口调用 ezdxf drawing 绘图器，按 DXF 属性解析颜色、简单线型、文字旋转、相对位置、块变换及其支持的填充/标注。PNG 从同一份 SVG 栅格化，SVG 的绘图样式已展开为显式属性，避免部分栅格器漏掉彩色线。输出的 `kind` 为 `derived_dxf_drawing_view`：它是用于观察的 DXF 重绘图，不是 AutoCAD 原样显示或打印结果。

将三种材料结合使用：

| 材料 | 模型从中获取什么 |
|---|---|
| 本入口的无编号 PNG/SVG | 实际看符号、线型、文字方向、表格行列和图面关系；优先打开 PNG 看图，不能仅阅读 SVG 代码就声明已识图。 |
| `read_cad_scope` / workbench 编号定位图 | 将已经观察到的位置对应到具体源对象；编号图仍是简化辅助预览。 |
| 同源索引与 CAD 精确属性 | 取真实对象 ID、文字、坐标和几何，用于测量及后续输入；不从像素或字形路径反算长度。 |

例如追一条支路，先看全局找到立管、图例和末端，再放大阀门两侧断线或接口标注，必要时另看系统图和安装表。模型判断符号占位、引线归属、交叉是否连接以及规格适用范围后，再将选定源对象交给现有计算链。图层、颜色或视觉近邻仍只是当前图纸中的线索。

## 调用

依赖 `ezdxf==1.4.4`、`Pillow`；生成供模型直接观看的 PNG 还需要 `PyMuPDF`。安装方式：`python -m pip install ezdxf==1.4.4 Pillow PyMuPDF`。仓库测试依赖文件给出本轮固定版本。

来源 JSON 沿用 workbench 格式，文件路径相对当前工作目录解析：

```json
{"path":"交换图.dxf","sha256":"实际DXF的SHA256","authoritative_source":{"path":"原图.dwg","sha256":"实际DWG的SHA256"}}
```

正式来源本身是 DXF 时省略 `authoritative_source`。查询至少说明 `question`；可选 `layout`、`bounds`、`layers`、`background` 与 `font_overrides`。下面的范围只是语法示例，应由模型根据实际图面选择，单位为所选布局的原始 CAD 坐标单位：

```json
{"question":"查看本支路与图例的符号、接口标注和连接关系","layout":"Model","bounds":[0,0,10000,6000],"background":"white"}
```

```text
python -B render_cad_view.py --source 来源.json --query 观察问题.json --svg 图样.svg --png 图样.png --output 图样说明.json --pixels 1600
python -B render_cad_view.py --index 已有索引.json --query 观察问题.json --svg 局部图样.svg --png 局部图样.png --output 局部图样说明.json
```

`--source` 与 `--index` 二选一；已有索引只用于验证并引用来源，不需要识别操作。`--svg` 和 `--output` 必需，`--png` 可选。使用模型视觉能力时应生成 PNG。`--pixels` 默认 1600，允许 256—4096，指定 PNG 最长边；放大看不清的文字时优先缩小观察范围。

布局默认取已有索引布局，无索引时取 `Model`；说明文件列出可用布局。省略 `bounds` 时按本次实际可绘内容外扩 2% 生成总览，有范围时先按原坐标裁剪。允许查看与已有局部索引不同的范围或布局，但说明中的 `index_layout/index_scope` 和实际 `layout/bounds_raw` 必须区分；其他布局和未索引区域的对象需另行索引，不能沿用原对象编号。

`layers` 是精确图层名称数组，匹配不区分大小写，只筛选显示层，不主动打开原本关闭或冻结的图层。省略时保留当前可见图层。`background` 可为 `default/white/black`，默认采用布局背景；ACI 7 等自适应颜色随背景解析。所有选项都记录在输出，不修改原图。

缺少原字体时先看 `font_observations`。工具发现声明或指定字体不在缓存中时，会在内存中重新扫描系统标准字体目录，以发现已安装但旧缓存遗漏的字体，不改原字体声明。如需使用另一个适合观察的本机字体，可明确指定 `font_overrides:{"实际文字样式":"已安装字体文件名.otf"}`；工具核对样式与字体存在并记录替代。此操作改善可读性，不表示字体或排版已与原图一致。中文不能显示时，不要把空白或方框当作原图没有文字。

API：`render_view(source, query, *, svg_path, png_path=None, output_path=None, pixels=1600, index=None, input_paths=(), expected_input_hashes=None) -> dict`。`input_paths` 用于保护调用方实际读取的来源描述、查询和索引文件；`expected_input_hashes` 将这些文件与实际解析的字节绑定。CLI 从同一份字节解析 JSON 并计算哈希，自动传入两者。API 调用者若自行解析文件，应传入同样的映射。函数生成文件并返回同一份说明内容。

## 按真实限制决定下一次观察

说明文件保留原图与权威来源 SHA-256、查询、布局、实际窗口、单位、字体及缺字诊断、绘图跳过项、读图警告和产物哈希。渲染前后都核验输入文件；来源改变或输出覆盖输入、源图、转换记录及其链接别名时拒绝发布。成功渲染仅表示生成了观察材料。

- `font_substitution`、`missing_codepoints` 和 `bigfont` 提示字体差异。缺字检查覆盖实际基础轮廓字体的 cmap；SHX 和复杂 MTEXT 内嵌字体不能据此声明完整。
- 复杂线型里的文字/形状不支持；不加载 CTB/STB。无限构造线使用渲染器有限显示长度，不能把显示端点当边界。
- 外参不自动加载，IMAGE 只显示框，PDF/DGN/DWF 底图及 OLE 内容不能由此完整观察。若题注、安装表或关键符号位于这些内容中，继续查看对应原生导出或实际底图，不能据重绘空白判缺失。
- 二维投影、动态/代理对象、自定义对象和非俯视视口受绘图库能力限制；当前可见状态需结合原生视图核对。原 DWG 转换记录即使存在，也不由本入口判定转换无损。
- 绘图诊断的图元数是所选布局在局部裁剪前的遍历数，包含展开图元，不是窗口内物理设备数。读取索引和看图都不等于已完成工程语义识别。

本实现每次完整读取 DXF 并遍历所选布局，不声称空间增量解析。提供 `bounds` 时，绘图前只跳过经有限 WCS 包络并加上整窗宽高裕量后仍完全远离窗口的简单线、圆、弧、无宽度多段线及闭合多段线边界填充；圆弧段采用已有原生曲线完整包络，不按端点估包络。最后仍按原窗口裁剪。文字、尺寸、容器、代理、未知几何、非多段线边界或开口填充、宽多段线和未证明的显示属性保留。图块插入点、文字锚点或不完整容器包络不用于剔除。

POINT还须取得渲染器最终解析的点标记大小：按其两倍尺寸保守包围圆、方框和十字等标记，不能只凭位置跳过。未解析或非法点标记尺寸继续保留；无显式窗口时沿用总览绘图。

填充图案继续用ezdxf原生裁线与OCS绘制。其原生随机小幅原点扰动改为源SHA、图元句柄及实际图案定义绑定的固定小扰动，保留原扰动幅度范围以避开边界角点；不修改源图案。这样跳过远处填充或调用方随机状态不会改变本窗口内的图案显示。`renderer.hatch_pattern_origin_jitter`披露该观察差异，显示图案仍不是测量依据，也不等价于AutoCAD原样显示。

`window_render_filter` 明示启用状态、按图元类型的远窗跳过数、原坐标裕量及解析后的点标记参数。这些是显示性能诊断，不是物理对象数量或工程覆盖证明。`drawn_bounds_before_crop_raw` 为实际保留的绘图记录范围，局部优化后不能解释成整个源布局的范围；遍历和显示限制诊断仍不代表窗口内实物。大图仍可能因未知对象、复杂填充或文字耗时，精确事实继续复用已有索引。
