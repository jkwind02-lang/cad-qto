# 插件问题登记

算量过程中发现**插件本身**的问题时，只登记，不修改插件文件（插件目录、发布目录和宿主缓存都不改）。插件只在插件仓库的维护会话里修改，修改后经发布同步到 Claude 和 Codex 两边。

## 哪些要登记

- 插件脚本报错，或算出的结果与图纸、规则不符；
- 规则缺口：某类对象、构造或计量口径插件没有覆盖；
- 识图指引含糊，按指引可以得出不同结论；
- 缺少某类能力；
- 文档与实际行为不符；
- 宿主执行偏差：当前宿主（Claude 或 Codex）没有按插件要求执行，例如漏跑必需校验器、把模型判断写成人工确认。

## 哪些不登记

只适用于本项目的计量口径、图层习惯、合同条款，写进项目自己的规则或成果说明，不进插件。拿不准就登记，由维护会话判断。

## 登记位置与命名

- 位置：插件维护目录下的 `问题登记/待处理/`。维护目录由宿主全局规则写明，或由环境变量 `CAD_QTO_MAINT_DIR` 指定；不按插件安装位置推测。找不到维护目录时，不自建别处的登记，把登记全文交给用户转交。
- 一个问题一个文件，文件名形如 `20261014-1932_claude_管网_DN文字绑定漏判.md`：登记时间、宿主、专业或 Skill 简称、问题简述。
- 先写临时文件，写完再改名；目标已存在时加序号，**不覆盖**另一会话的登记。可直接用脚本完成：

  ```text
  python <插件根>/skills/_qto-shared-evidence/scripts/register_plugin_issue.py --maint-dir <插件维护目录> --host Claude --topic 管网 --title DN文字绑定漏判 --body-file <已填好的登记.md>
  ```

- 登记引用项目图纸、路径和数量时，只写路径和哈希，不复制项目原件。

## 登记模板

使用 [`assets/插件问题登记模板.md`](../assets/插件问题登记模板.md)，字段含义：

| 字段 | 填写 |
|---|---|
| 登记时间 | 本机时间，精确到分钟 |
| 发现宿主 | Claude 或 Codex，及实际模型 |
| 项目与任务 | 项目简称与本次任务 |
| 插件版本 | 安装包 `发布来源.json` 的业务版本与提交号；没有该文件时写清单版本 |
| 涉及Skill | 实际使用的入口 |
| 类型 | 脚本报错、规则缺口、识图指引不清、能力缺失、文档错误、宿主执行偏差、其他 |
| 影响识图或数量 | 是 / 否 / 不确定 |
| 阻断程度 | 阻断、已临时处理、不影响本次 |

## 维护回写（维护会话填写，登记时不写）

维护会话处理后，在登记文末追加标题以"维护回写"开头的一节，逐行写 `- 字段: 值`。项目要知道"修好没有、哪些包要重算"时按字段读，同一登记有多节以最后一节为准：

| 字段 | 取值 |
|---|---|
| 处理版本 | 业务版本与提交；未发布时写明未发布 |
| 处理状态 | 代码已修复、单侧已安装、双侧发布完成、部分修复：说明、不修复：原因 |
| 需复跑 | 项目与包号，例如 `宁波众芯: P-FW-A、H-VEN-A`；没有写"无" |
| 复跑状态 | 未发布，待复跑；已发布，待复跑；已复跑；未能复跑：原因；本项目未触发；不需要：原因 |
| 复跑记录 | 报告路径和 SHA256；没有写"无" |

只有处理状态为"双侧发布完成"的修复才在两边安装里生效；此前项目继续按原版本和临时处理执行。

## 本次任务怎么继续

- **能绕过的：** 在项目目录里用项目脚本或手工计算做临时处理。成果里标明“临时处理，非插件能力”，登记里写明临时处理的位置。
- **绕不过且影响数量的：** 受影响部分列为未决，不填 0、不猜测；登记为“阻断”，并告诉用户。
- **阻断且影响面大的：** 提醒用户尽快安排维护会话。
