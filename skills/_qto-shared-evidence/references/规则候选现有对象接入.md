# 规则候选现有对象接入

这是现有生产格式的规则候选接口，不产生工程量批准或运行规则。原裁决/维护三分流和独立案例要求仍见[规则候选与维护审核](规则候选与维护审核.md)。

## 两个具名生产格式

`qto-rule-object-producer-evidence/1.0` 的 `producer` 只接受以下值，不承诺任意专业格式。

| producer | 当前官方输入及实际入口 | 必须保存并核验的完整产物 |
|---|---|---|
| reconciled_points/1.0 | CAD manifest、识别配置 profile、recognition_ledger；build_component_instances_from_neutral.py | qto-reconciled-instance-input/1.0 的 count_input（点位唯一实例计数输入.json），以及 count_reconciled_instances.py 实际 stdout 保存的 count_result（点位数量汇总.json） |
| bound_electrical_objects/1.0 | CAD manifest 与 qto-electrical-object-request/1.0 的 request；bind_electrical_objects.py | qto-electrical-object-package/1.0 的 package（电气对象包.json）、ledger（路径台账.json）、calculation_run（数量复算.json） |

每个文件引用均为 `{path,sha256}`。输入原件不改写，生产回放在请求目录临时工作区完成。核验 authority、exchange DXF、layout/block streams、完整配置及识别台账；直接绑定继续使用生产入口的单位/端口/part/分数区间/完整实例父链校验。物理源、交换源、业务路径和 scope 不做路径忽略。

点位回放比较**完整** count_input JSON，并实际执行 counter 比较**完整** count_result。直接绑定执行官方 CLI，比较官方 JSON 保存后的**完整** package，并核同包 ledger、quantity_result 与两份独立保存产物。拒绝只选择数值字段或丢弃未知字段来使旧结果通过。完整文档及当前数量按 canonical JSON 比较，保留 false 与 0、null 等 JSON 类型差异。直接绑定仅对既有几何单位契约已经逐路径、SHA 和完整集合核验过的执行模块路径使用既有规范化；业务原源和其它字段均保留。完整重放与完整序列化产物指纹进入上下文。

`producer_modules` 为完整运行闭包：键为固定 `skills/.../*.py` 身份，值为 `{path,sha256}`。可用 `qto_rule_object_adapter.modules(producer)`取得当前模块身份/SHA后逐项生成引用；这只是生成新请求的技术快照，不得替换旧方法确认以掩盖模块变化。每个声明路径都必须仍可读取，字节及完整集合须与实际执行代码相同。允许同字节运行子树副本导出，再由维护仓库消费；缺模块、换字节或声明旧路径失联均拒收。最终合并公共模块变更后应重新生产并取模块闭包。

## 显式映射当前对象

规则候选请求增加 `object_producer_evidence` 数组。每个条目还须有唯一 `producer_id`、当前 `decision_id`、`decision_revision` 和非空 `bindings`。

每条 binding 必须包含 `catalog_key`、`object_fingerprint`（当前归一化对象 result_fingerprint）、`target_id`、`target_fingerprint`（完整实际目标的 fingerprint）、`quantity_name`。点位目标为实际 adopted `reconciled_instances[].physical_id`；直接绑定目标为 package.objects[].id，并要求当前 catalog_key 与生产目标完全一致。同一物理目标的同一生产数量出口不能被不同对象或重复 producer 声明重复认领。出口身份由实际回放生成，不采信 binding 提交的显示标签。

点位只支持同一坐标单位、同一源和精确生产定位的 point 对象，取实际唯一实例数 1；保留完整 recognition_record、source_record_id、父链和工作完整性，不按近邻/名称合并。坐标单位未知仍为 drawing_unit，不换算为 m。当前专业、kind、目标指纹、对象指纹及数量单位/层级须一致。

直接绑定数量只能使用生产 quantity_projection 已定义字段：已知参考长度（已含根数）、完整参考长度（已含根数）、每根实画路径长度、每根附加长度、正式采用长度。完整量为 null 时仍为 null；已知小计不冒充完整量，根数不再乘一次。实际生产 pending、覆盖差集、完整源段及数量组成随目标和上下文保留。方法确认不改变数量层级，也不授予正式采用量。

`inspect` 会继续核当前有效事项和 feedback handoff，再给出 method_context_fingerprint；用户方法批注与独立方法凭据必须共同绑定该指纹。export、维护复验均重新执行生产链。来源、模块、方法版本、对象范围或完整产物变化使旧确认失效，即使展示数量恰好相同也不能沿用。

## 未有人审的真实资料

允许只读命令：

```text
python -B skills/_qto-shared-evidence/scripts/qto_rule_candidates.py inspect-production --request 生产检查请求.json --maint-dir 本轮维护目录 --name 生产检查.json
```

请求为 `qto-rule-producer-inspection-request/1.0`，含 project_id 与 producer_evidence；生产证据文件和 producer_modules 按上表提供，不需要也不产生方法或数量审批。输出固定 NOT_HUMAN_APPROVAL，列出完整实际 targets、来源/模块、生产状态和未决，不修改原视图 receipts 或 recognition review_status。此请求不能当 export 请求使用。

已有历史产物若被当前 producer 判为过期，应将相同冻结原源/配置/台账重新生产到新的业务目录，再按新产物检查，保留旧失败证据。没有真实明确方法答复、合法方法凭据和真实维护审查时，真实候选导出与成熟度闭环继续开放；不能用匿名测试凭据填平。通用候选仍只产 AWAIT_MAINTENANCE_CHANGE 提案，且另项目案例须另物理原源（同时检查 producer authority/exchange 源），单项目认可不升级全局成熟度。

## 数量出口与物理主源身份

点位只有一个固定的 `point.unique_physical_instance_count` 出口。数量展示名、catalog_key、producer_id、单位显示、scope/version 标签及 exchange_dxf 等附加证据不能创建第二个实例数。实际主源 authority 文件必须读取并核 SHA；源版本取已核 authority 内容 SHA，物理实例取 producer 产出的完整 instance_path（旧产物缺字段时只按官方 PT-物理实例路径还原），不能取块定义叶句柄、近邻或标题。出口身份与当前视图显示分离；两个标签指向同一主源同一完整实例仍拒收。

电气对象包继续保留实际 physical_id；五个官方 quantity_projection 字段分别映射固定语义出口：已知参考长度、完整参考长度、每根实画路径、每根附加长度、正式采用长度。实际不同投影出口可以分别展示，不合并为一个物理 ID 全部拒收；同一出口换名称或 producer 仍不能重复认领。

候选保存 `quantity_outlet`、其完整指纹和 `producer_authority_sources`。全局去重只依据实际主源版本、实际完整物理实例与具体生产出口，附加交换文件集合不改变主源身份。同 authority 换 exchange、增加其他证据、换项目/显示标签也不能成为“另一物理源”的独立案例。不同真实 authority 的相同 CAD 句柄、同 authority 的不同完整实例，以及同物不同官方电气投影出口保留各自合法边界。

身份键不使用交换文件等附加证据，不代表忽略它们：authority 路径、exchange、全部来源、配置、scope、完整对象及模块仍由重放与 method_context 精确保存，任何业务来源路径、模块或上下文变化仍需重验。执行模块同字节异目录规则保持原契约；同数量并不证明方法上下文当前。
