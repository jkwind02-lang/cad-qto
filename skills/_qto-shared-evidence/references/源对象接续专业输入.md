# 源对象接续专业输入

模型先确定原图、图页、局部范围和实例含义，再使用 `scripts/prepare_source_specialists.py` 将已审阅的选择接入现有点位、电气路径或面层计算。它不自动识别设备，不自动确定材料，也不按同名文字合并跨图对象。

## 有界依据检索

`search --input request.json --output hits.json` 的请求含 `terms`、`match`（`literal` 或 `exact`）及非空 `scopes`。每个范围提供 `index`、`index_sha256`、`applicability` 和 `query`；query 可按 `bounds`、`object_ids`、`entity_types`、`layers` 筛选。结果保留实际搜索范围、全部命中与超限条目、未定位对象数及转换提示。未命中仅表示本次已查范围内无匹配，不能据此断言缺资料。

## 从选择生成输入

`prepare --index index.json --operations operations.json --ledger ledger.json --output input.json` 校验原图、交换文件和索引身份，并绑定模型工作识别台账。所有输出都要求新文件名。

operations 必须给出 `target`、`index_sha256`、`scope_object_ids`、`scope_basis`。目标为 `components` 时逐项选择 `instances`，每项含 `object_id`、`adjudication_id`、`observation`、`category`、`system`、`spec`、`unit`。一个实体由多条源几何构成时，用 `member_object_ids` 明列全部成员并包含代表对象；每个成员都必须已在同一专业台账中审阅，成员不能重复或存在父子重叠。结果接入 `count_reconciled_instances.py`。它保留源成员、父块问题、原图身份和图面中心；图面中心不能用作实物端口。

目标为 `electrical` 时逐项选择 `paths`，每项含 `object_id`、`adjudication_id`、`observation`、`id`、`from_node`、`to_node`、`role`。每项只接受一条完整源曲线；程序换算其长度，不接受手填长度或几何。节点名称相同必须坐标连续；允许容差须提供 `node_tolerance_m` 和 `node_tolerance_basis`。同时声明 `project_id`、`channels`、`circuits`，按现有电气路径契约进行校验。端点事实仍走独立交接，不从图面中心推导。

两类选择均可含 `evidence_refs`。每条引用必须提供源 `index`、`index_sha256`、`object_id`、`applicability`、`interpretation`，可附精确原文 `excerpt`。同一引用只支持所写适用范围，不能把控制表材料直接替代动力回路或把典型表另计为设备。

图纸单位为 Unknown 或 Unitless 时，必须提供 `unit_declaration`，它使用同样的有源引用并额外声明 `raw_unit` 和唯一适用单位的 `excerpt`。条文含平面毫米和标高米时，模型须选出完整、适用的平面单位条款；不允许截断单位词或与 INSUNITS 冲突。

## 工作流与复核

### 面层选择接续

`target: surfaces` 接收模型明确选择的普通线网面域、表格分片和构造层。它不发现房间与做法的关系，也不包含房名、做法编号或项目构造字典。项目选择只保存在 operations 数据。当前限 Model 中普通实体/块路径，阵列路径另行展开核验。

- `definitions`：每项给出 `id`、`code`、`column_role`、`conditions` 和 `layers`。`code`、各层 `clauses` 都是 `{fragments: [有源引用], interpretation, separator?}`；分片按模型选择的顺序拼接，完整源文字仍保留。
- `surfaces`：每项给出稳定 `surface_id`、源标签 `object_id`、`adjudication_id`、原文 `name`、`scope_fields.floor`、`definition_id`、逐层 `item_ids`、侧别/计量/用途与未决引用。可用 `source_identity_evidence` 保留平面标题等语义定位依据。
- `assignment`：明确 `code/row/column/floor` 四组分片、`column_role`、上下文文件 `context: {path,sha256}` 及 `regions: {cell,row,column,floor}`。程序检查分片所属窗口、编号一致及行列/合并格范围；窗口的工程含义仍由模型判断，不是自动表格结构识别。
- `source_face`：提供实际 `request`、`result` 的 `{path,sha256}` 及 `face_id`。源边必须在已审阅台账中；程序重新调用原生线网提面，核对当前文件、单位、所选面及标签空间位置。禁止传入面积或坐标覆盖源事实。
- 每层明确 `role: finish|substrate`。结构基层只记录排除责任。饰面层的 `measurement` 为 `horizontal_projection` 或 `deferred`，不能用最薄值或待选厚度自动求体积。`coverage_basis` 由模型说明逐层覆盖依据；层 `result_use` 可细化该层用途，不影响其他层。
- 参数显式为数组；每项有 `name/unit/status/value/condition/evidence_refs`。`fixed/minimum` 保留原文中的数值，`conditional/unresolved` 的 `value` 必须为 null，可另存候选值。无参数须明确 `[]`，没有默认厚度。
- 层 `variants` 用有源 `conditions` 唯一选择条款与参数。条件含 `field/operator/values/evidence_refs`，仅 `in/not_in`；缺字段不能默认分支。房间条件不得覆盖实际源标签身份。
- 源单位未定义时，除 `unit_declaration` 外须用 `unit_context` 保留适用条款的完整上下文。关闭、冻结、不出图或 Defpoints 的构造依据被拒绝；图层状态不代替模型判断图页与责任范围。

输出直接交给现有面层计算器及其绑定验证。只形成 `reference/partial` 或未决项；`source_preparation` 保留逐表面逐层判断、条件、排除和未处理对象。合成调用示例见 `tests/test_surface_source_preparation.py`，实际工程数据不得放进该测试。

### 表格上下文与回图

`read_cad_scope` 的 query 可加 `context_regions`，每个区域给唯一 `id`、模型声明的 `role`、有限 `bounds`，以及可选对象/类型/图层过滤。只给区域时返回各区域并集；远处表头与当前表行可用独立窗口。`context_regions_ref` 指向不可变的上下文文件，分页对象带 `context_region_ids`。这只传递选择和成员，不把未知表格结构标为已证实。

回图单元格和构造范围使用有依据的框或多边形，不能用文字插入点充当范围。`attributes.source_context` 可存 `[{label,text,source_refs:[定位文字]}]`，界面单独显示模型选定原文，明示重排并保留来源。它与源图窗口互为核对；字体替代或未包含表头须披露并补取证，不能声称替代字体渲染就是原DWG打印。

注册工具 `source_evidence_search` 使用 input/output；`source_specialist_prepare` 使用 index/operations/ledger/output。工作流中准备输入使用 `stage: recognize`。必须把实际间接读取的索引、原图、交换文件、台账证据和单位/跨图依据注册为输入，来源变化会使任务失效。

输出中的 `source_preparation` 记录源索引、操作快照、单位依据、选择绑定、未决项和未处理范围。点位数量为方案暂估量，现有电气路径结果也不构成正式采用。模型仍须回图检查实例划分、规格适用性、材料冲突、未决接口及跨图对应。局部意见使用现有复核快照和修改流程重新生成输入、实际复算并核对未涉及对象；不要直接修改数量结果。

合成测试覆盖身份、单位、成员去重、路径连续和间接依赖，不代表任意图纸识别完整率。实际项目材料留在项目工作区，不能写入插件和测试夹具。
