# 源对象接续专业输入

模型先确定原图、图页、局部范围和实例含义，再使用 `scripts/prepare_source_specialists.py` 将已审阅的选择接入现有点位或电气路径计算。它不自动识别设备，不自动确定材料，也不按同名文字合并跨图对象。

## 有界依据检索

`search --input request.json --output hits.json` 的请求含 `terms`、`match`（`literal` 或 `exact`）及非空 `scopes`。每个范围提供 `index`、`index_sha256`、`applicability` 和 `query`；query 可按 `bounds`、`object_ids`、`entity_types`、`layers` 筛选。结果保留实际搜索范围、全部命中与超限条目、未定位对象数及转换提示。未命中仅表示本次已查范围内无匹配，不能据此断言缺资料。

## 从选择生成输入

`prepare --index index.json --operations operations.json --ledger ledger.json --output input.json` 校验原图、交换文件和索引身份，并绑定模型工作识别台账。所有输出都要求新文件名。

operations 必须给出 `target`、`index_sha256`、`scope_object_ids`、`scope_basis`。目标为 `components` 时逐项选择 `instances`，每项含 `object_id`、`adjudication_id`、`observation`、`category`、`system`、`spec`、`unit`。一个实体由多条源几何构成时，用 `member_object_ids` 明列全部成员并包含代表对象；每个成员都必须已在同一专业台账中审阅，成员不能重复或存在父子重叠。结果接入 `count_reconciled_instances.py`。它保留源成员、父块问题、原图身份和图面中心；图面中心不能用作实物端口。

目标为 `electrical` 时逐项选择 `paths`，每项含 `object_id`、`adjudication_id`、`observation`、`id`、`from_node`、`to_node`、`role`。每项只接受一条完整源曲线；程序换算其长度，不接受手填长度或几何。节点名称相同必须坐标连续；允许容差须提供 `node_tolerance_m` 和 `node_tolerance_basis`。同时声明 `project_id`、`channels`、`circuits`，按现有电气路径契约进行校验。端点事实仍走独立交接，不从图面中心推导。

两类选择均可含 `evidence_refs`。每条引用必须提供源 `index`、`index_sha256`、`object_id`、`applicability`、`interpretation`，可附精确原文 `excerpt`。同一引用只支持所写适用范围，不能把控制表材料直接替代动力回路或把典型表另计为设备。

图纸单位为 Unknown 或 Unitless 时，必须提供 `unit_declaration`，它使用同样的有源引用并额外声明 `raw_unit` 和唯一适用单位的 `excerpt`。条文含平面毫米和标高米时，模型须选出完整、适用的平面单位条款；不允许截断单位词或与 INSUNITS 冲突。

## 工作流与复核

注册工具 `source_evidence_search` 使用 input/output；`source_specialist_prepare` 使用 index/operations/ledger/output。工作流中准备输入使用 `stage: recognize`。必须把实际间接读取的索引、原图、交换文件、台账证据和单位/跨图依据注册为输入，来源变化会使任务失效。

输出中的 `source_preparation` 记录源索引、操作快照、单位依据、选择绑定、未决项和未处理范围。点位数量为方案暂估量，现有电气路径结果也不构成正式采用。模型仍须回图检查实例划分、规格适用性、材料冲突、未决接口及跨图对应。局部意见使用现有复核快照和修改流程重新生成输入、实际复算并核对未涉及对象；不要直接修改数量结果。

合成测试覆盖身份、单位、成员去重、路径连续和间接依赖，不代表任意图纸识别完整率。实际项目材料留在项目工作区，不能写入插件和测试夹具。
