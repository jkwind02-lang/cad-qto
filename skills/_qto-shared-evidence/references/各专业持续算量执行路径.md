# 各专业持续算量执行路径

本页把已安装的专业能力接成可继续执行的工作，不表示十三个专业都已具备自动识图或完整计算能力。工具编号及实际参数以[运行工具目录](../scripts/qto_workflow_tools.py)为准；专业计算器的输入契约、项目规则和成熟状态仍须读取。本页不规定价格、损耗率、施工默认值或项目采用口径。

## 由模型选择切入点并完成原图求量

- 本页列专业问题、已有工具和能力边界，不强制固定路线。下文“模型准备”中的根数、净长、尺寸、关系和适用范围是模型应从图纸主动求解的内容，不是向用户索取的预填条件。综合图文判断、选择算法与输入编制按[AI运用人工算量方法](人工思路识图与算量流程.md)执行。
- 完整支路、房间、构件区、桩组或道路段通常适合作为代表范围；也可从设备表、典型节点、尺寸链或异常对象切入。覆盖所需图种、主体和附属量，按来源、规格、构造和适用范围建立同族对应并处理例外；代表样本通过不能证明其余实例存在或没有变化。
- 需要精确实体时用 `cad_index` 建立来源绑定索引，用 `cad_scope` 围绕具体问题分页取证；需要图样语义时可直接用[CAD图样观察](CAD图样观察与模型识图.md)看来源DXF及相关局部，无需先完成对象分类。声明已完整读取某查询时须读完其分页；若证据已足够而提前转向，保留未查看范围。超过响应预算的记录由程序沿 `detail_ref` 读取完整几何。摘要、局部预览和“未选中”不能证明对象不存在。
- 模型分别记录图形观察与应算量项：前者对实际索引对象说明纳入、排除、证据、容器或未决；后者说明哪个实物、哪个部位、哪种数量、哪层/哪侧、什么规则与场景、哪个专业负责。公共详图可作为多个实例的依据，不能将详图上的一套构造计成新增安装实例。
- 平面、立面、系统图和表格的同一实物只建立一个物理身份；不同实际部位拆分要解释范围。`correspondence` 提供候选对应及核对支持，模型保留对应依据与例外，程序通过不等于自动认同工程语义。
- 图种或条件缺失时先建具体 issue：指出缺哪张图、哪个端点/构件/部位、哪个参数，以及影响哪些量项。模型先查已提供资料及可用来源；只有真实的设计冲突、项目范围/规则选择或取不到的关键资料才询问用户。独立且有依据的分区继续算，未知不填零。

## 统一交接方式

| 交接内容 | 工作记录与执行要求 |
| --- | --- |
| 来源与读图任务 | 登记实际 source/rule/index/input/result/evidence 文件；范围列出必需图种任务，文件存在不等于已完成读图。 |
| 对象与实例 | 工程对象关联源索引中的真实观察；设备、墙体、表面、路径或桩的身份不能由表格序号替代。 |
| 量项与责任 | 几何量、项目规则量、采购参考量分开；同一实际量项只有一个专业数值出口。改变单位或工作包不能重新计一次。 |
| 实际计算成果 | `quantity_claims` 引用 current 原生 JSON 文件及数值指针，保留实际哈希、单位和数量层级。不得把人工合计或模型口算填成程序成果。 |
| 依据与任务依赖 | 项目执行器跟踪的成果还须证明：范围、对象、量项依据及该对象的观察索引都被实际生产任务或其祖先消费。仅把规则挂到台账、刷新文件哈希或保持原总数，不能替代接入真实依赖和重算；缺口由模型补任务关系。 |
| 数组身份与修改 | 带编号数组项用 `identity_pointer`/`expected_identity`；嵌套数组每个带编号祖先以 `identity_bindings` 补齐，并核对所绑定身份在该层数组中唯一。 |
| 无 ID 数组语义 | 在 `quantity_claims[].record_bindings` 逐行登记 `{record_pointer, expected_fields}`。构件 `/groups/*` 须完整绑定 `category/system/spec/unit/quantity_level`；道路 `/items/*/layers/*` 须绑定 `name/thickness_m`，外层道路 ID 仍单独绑定。程序核对真实字段及同层唯一性，缺失或重排错配不入汇总。 |
| 其他数组结构 | 无 ID 行须显式绑定通向本次数量的分支以外全部直接上下文字段；这些上下文须能在同层唯一区分该行。纯数字数组、只有数量的行或重复语义行转为具体待办，补原生稳定身份/分项成果后再引用，不能以数量本身或行号制造身份。 |
| 工作与采用 | 候选、推算、方案及未决分别保留；`REFERENCE_ONLY`、脚本成功和对账一致不会自动改变成熟度或正式采用状态。 |

## 1. 构件、设备与末端点位

- **先读与问题：**按[构件与点位](../../qto-components-points/SKILL.md)读取图例、平面位置、设备/门窗表和系统图。核对图例示例、备用/拆除、父子块、重复视图与实际安装实例，回答“这个位置究竟安装了什么”。
- **模型准备 → 程序：**准备唯一 `physical_id` 的实例账，绑定类别、系统、规格、数量层级和本轮识别依据；`component_count` 调用 [count_reconciled_instances.py](../../qto-components-points/scripts/count_reconciled_instances.py) 计数，宽高齐备时另给派生面积。`count` 按组内 `unit` 计量，`derived_area_m2` 单独按 m² 引用；尺寸不全的 `null` 面积留待补算。表中的计划数量不能制造实例。
- **交接：**用 `endpoint_handoff` 将每个相关实例标为可交接、不适用或未决，保留端口坐标、角色和直接/候选规格；门窗洞口位置与尺寸交砌体/面层，设备基础交结构专业，实例数量仍由本专业输出。
- **回图与边界：**逐房间/分区对点，对每个父子块和表图差异留处置；核对未交接端口。计算器只复算已识别实例，不识别符号含义，也不把派生门窗面积自动当成墙洞扣减。

## 2. 管道与管网

- **先读与问题：**按[管网](../../qto-pipe-networks/SKILL.md)互读说明/图例、平面、系统图及设备接管详图，从水源/立管沿干支管追到末端；排水另核流向、坡度、通气和跨层关系。回答每一实际区段的系统、DN、起止、标高及连接关系。
- **模型准备 → 程序：**用当前源对象和工作识别记录准备分段、直接规格、全部匹配候选、根端/末端与断口说明；`pipe_prepare` 接已有索引和模型操作，`pipe_infer` 调用 [infer_pipe_network.py](../../qto-pipe-networks/scripts/infer_pipe_network.py)。低强度候选不替代直接证据，变径边界、独立竖段和未知邻段分别核对。
- **交接：**消费点位专业端口，不再计设备；平面/系统/详图共用物理身份。说明要求的附件用 `instance_requirements` 对真实实例逐个展开，再与已绘同件对应去重；竖向、净接管及典型阀组必要时调用本专业对应脚本，不能把典型图套数当安装数量。
- **回图与边界：**逐路核入口、末端、连通分量、DN分界、虚拟桥和未配规格区段，分列水平/竖向、净管/含阀件轴长、管件/阀件/保温/支架。未知高度、阀件存在性或实例范围必须限制数量层级，不能只因 DN 已知就确认件数。

## 3. 风管与风系统

- **先读与问题：**按[风系统](../../qto-duct-air-systems/SKILL.md)读取系统图、平面、截面/标高、设备表及管件详图，沿设备—干管—支管—风口追踪。区分中心线、双线轮廓、内外尺寸、矩形/圆形与保温前后截面。
- **模型准备 → 程序：**把已经定位的等截面直管整理成 `straight_sections`，逐项给根数、单段实长和截面尺寸；`duct_reference` 调用 [calculate_straight_duct_reference.py](../../qto-duct-air-systems/scripts/calculate_straight_duct_reference.py) 输出直管总长与理论展开面积。
- **交接：**风口、风机和空调箱实例数量由点位专业提供，风管在线阀件归本专业；直管、弯头/三通/变径、软接、法兰、加固、支架、保温各列应算量项，尚无计算成果的仍保留。
- **回图与边界：**回到每处分支、变截面、上下翻和设备接口核查遗漏。当前登记出口只是直管参考算术，不处理管件、法兰、咬口、损耗或清单扣减，不把它的面积小计称为完整风系统量。

## 4. 电气线路与通道

- **先读与问题：**按[电气线路](../../qto-electrical-routes/SKILL.md)将系统图、回路表、平面及桥架深化对应，逐回路从箱柜到末端；回答“哪些通道实物被共享、每根线缆实际走哪条路”。
- **模型准备 → 程序：**在路径台账中分别列水平、竖向、偏移段及端节点，准备通道和回路各自的物理 ID、顺序路径、并行根数、规格及有依据的端头附加量；`electrical_paths` 调用 [calculate_electrical_paths.py](../../qto-electrical-routes/scripts/calculate_electrical_paths.py) 检查连续性和终点并复算长度。
- **交接：**引用点位专业末端及端口；桥架/导管等物理通道与每根电缆/电线分账，专用支架跟随本专业。综合支架需真实深化依据，不能由回路数推定。
- **回图与边界：**检查 `shared_path_usage` 与 `unused_path_ids`，逐条解释未用路段、脱离通道支线、跨层和端接。程序不自动寻路；电缆芯数是规格属性，不乘入电缆根长，桥架不按回路数重复计。

## 5. 混凝土与模板

- **先读与问题：**按[混凝土模板](../../qto-concrete-formwork/SKILL.md)读取结构说明、平面编号、截面/节点与浇筑条件，按基础—柱墙—梁板的实际关系组织构件。先解释净实体、洞口、交界归属及每面的接触条件。
- **模型准备 → 程序：**同一构件只准备一套来源几何，另列实体扣增与逐面模板条件；`concrete_formwork` 调用 [calculate_concrete_formwork_pairs.py](../../qto-concrete-formwork/scripts/calculate_concrete_formwork_pairs.py)。当前完整源实体计算入口限于毫米制单角缺口筏板及等距垫层，不是任意梁板柱墙模型生成器。
- **交接：**混凝土体积和模板接触面积是两个量项；钢筋交钢筋专业，预制完成品计数交点位，二次结构先消费砌体专业定位。实体体积、物理模板面和项目规则量分别保留。
- **回图与边界：**检查浇筑接触、贴土、垫层、永久模板、施工缝、预留孔和相交扣减；零模板要逐面有依据。其他构件使用已支持的量测/明确计算方法另立任务，不能套成案例筏板，也不能以体积乘系数补模板。

## 6. 钢筋

- **先读与问题：**按[钢筋](../../qto-rebar/SKILL.md)把结构总说明、集中/原位标注、截面、节点页及钢筋表绑定到构件和配筋位置，区分纵筋、箍筋、附加筋与接头。节点版本、保护层、端部和加密区是要解决的具体问题。
- **模型准备 → 程序：**从标注、构件几何或节点选择有效线索，主动解释钢筋组、根数或实际中心排布、级别直径及逐项中心线长度，并给理论单位质量依据；`rebar` 调用 [calculate_rebar_items.py](../../qto-rebar/scripts/calculate_rebar_items.py) 精确求根数、总长和理论重量；有据候选使用 reference + working_basis，规则可按 trial 试用且 maturity 保持原样。连接件可走明确计数分支。
- **交接：**消费结构构件/砌体墙系身份与尺寸；接头、措施筋与普通钢筋组分别挂账。钢筋笼归本专业，型钢、柱脚板、锚栓和栓钉归钢结构；采购定尺/余料等参考量不得替代设计或项目规则量。
- **回图与边界：**回查首末根、洞口、加密、锚固搭接和多视图重复。程序只对模型已明确的首末等距中心或实际中心列表计数，不从单个 @ 标注决定范围、首末根或加密规则，也不选择节点或计算弯曲调整值。未知节点继续取证，独立可算部分继续；仅有“同图集”不能给全部构件配置相同钢筋。

## 7. 钢结构

- **先读与问题：**按[钢结构](../../qto-structural-steel/SKILL.md)对应构件平立面、构件表、截面表、节点与深化变更，区分轴距、净下料长、三维坡长和投影长；节点表与局部图冲突须保留双方来源。
- **模型准备 → 程序：**逐物理构件/零件准备身份、长度、明确截面/单位重或组成板件、孔洞扣减、节点位置及连接件数量；`structural_steel` 调用 [calculate_structural_steel_items.py](../../qto-structural-steel/scripts/calculate_structural_steel_items.py) 计算型材/组合截面/板件质量，以及明确计数、面积和暴露表面分支。
- **交接：**主构件、节点钢件、螺栓锚栓栓钉、楼承板、涂装/防火和措施量分别列目标；管内混凝土交混凝土，围护面板交面层，非主体骨架交龙骨。清单归组只附加关系，不覆盖物理子账。
- **回图与边界：**以构件端点—节点实例对账，检查异常跨、坡长、偏心、伸出和重复扣减；模板节点仅能用于有据对应的实际端部。程序不从标签次数认定构件根数，不以主材比例补节点板或涂装。

## 8. 砌体与二次结构

- **先读与问题：**按[砌体](../../qto-masonry-secondary/SKILL.md)对墙体材料表、平面、墙身详图与门窗洞口，逐墙段确认厚高、转角/相交、洞口和二次构件占位。门窗表樘数不是墙体扣减面积。
- **模型准备 → 程序：**准备 `wall_segments` 的净归属长度、有效高度、厚度、已成立洞口并集面积及已确认占位体积；`masonry_reference` 调用 [calculate_masonry_reference.py](../../qto-masonry-secondary/scripts/calculate_masonry_reference.py) 复算毛面积、扣洞后面积与净体积。
- **交接：**墙系负责定位构造柱、圈梁、过梁和压顶；其混凝土/模板与钢筋分别交对应专业。洞口身份来自点位，墙体两侧各层面层交面层专业，保持同一基层事实与不同量项。
- **回图与边界：**按房间/轴段追墙带连续性，检查洞口重叠、梁柱占位及重复表达。当前出口不求洞口并集、不判断占位归属、不选择清单扣减规则；这些输入不明时挂具体缺口，不能把参考算术升级为完整砌体识图。

## 9. 面层与建筑围护

- **先读与问题：**按[面层围护](../../qto-surfaces-envelope/SKILL.md)把房间/立面、材料做法、剖面、门窗洞口及局部收口对应，明确每个实际表面的构造层、侧别、材料区、设计边界及计量投影。
- **模型准备 → 程序：**已有填充或普通线网可用本专业面域工具取候选边界；模型说明房间对应和缺口分界，再准备表面/层、洞口并集、侧壁/翻边、坡度或源边区间；`surfaces_envelope` 调用 [calculate_surfaces_envelope.py](../../qto-surfaces-envelope/scripts/calculate_surfaces_envelope.py) 运行当前支持的净面积、材料分区和边界净长等分支。
- **交接：**墙体基层体积、门窗实例、幕墙/吊顶骨架交相邻专业；物理表面、各侧各层净覆盖、项目规则量和采购展开参考量分别列目标。一个面积不能无条件复制到所有构造层。
- **回图与边界：**沿全部边界检查未闭合线、重叠填充、未设填充区、柱突出、洞口侧壁、收口和上翻；按需要绑定 `frame_binding` 定位有限源边及正反向。工具不自动给闭合面匹配最近房名/做法，局部候选面域不证明整层或完整防水、幕墙范围。

## 10. 龙骨与支承骨架

- **先读与问题：**按[龙骨骨架](../../qto-framing-supports/SKILL.md)读取系统做法、分格/排布图、端部与洞口节点，分清立柱横梁、主副龙骨、沿边构件及连接实例；室内龙骨与幕墙骨架分别组织。
- **模型准备 → 程序：**根据实际排布逐件或有明确成员清单的同族组准备 `members`，给数量、单件净长、规格、角色和有据单位质量；`framing_reference` 调用 [calculate_framing_reference.py](../../qto-framing-supports/scripts/calculate_framing_reference.py) 复算总长和理论重量。
- **交接：**主体承重钢件交钢结构，面板/饰面交面层，门窗开启扇交点位，机电专用支架随各机电专业；综合支架无方案时留明确未决目标。
- **回图与边界：**核对首末根、端部收口、洞口加密、转角及接长，逐分格查漏。该参考出口要求数量和单位质量已经明确，不从 `@间距` 自动布杆，不由面板面积或经验含量生成骨架。

## 11. 土石方与场地

- **先读与问题：**按[土石方](../../qto-earthwork-terrain/SKILL.md)读取现状测量/原地面、设计及批准施工面、基础/管沟平剖面与施工口径，先统一坐标和高程基准，明确底边界、工作面、放坡/支护及土体状态。
- **模型准备 → 程序：**按实物开挖区准备有据边界和高程；`earthwork_terrain` 调用 [calculate_earthwork_terrain.py](../../qto-earthwork-terrain/scripts/calculate_earthwork_terrain.py) 处理已锁定体积、矩形体、受支持截头体、矩形坑群切片并集及同签名差值。两种矩形截头体方法使用已换算为米的输入，限上下同向矩形、四侧沿高线性变化（可非对称外扩），以 `H×(A底+4A中+A顶)/6` 精确计算；中途变坡、台阶或旋转截面须另行分段。坑群切片须披露步长及近似性质。
- **交接：**消费基础/管道边界，向回填交接开挖域与构筑物占位；桩孔及地基处理交桩基，道路结构层交道路。自然密实、夯实、松散及空方，几何/施工方案/清单/合同口径分别立项。
- **回图与边界：**检查坑槽重叠、标高分区、施工阶段和持力层不明区域；回填、余方、借方只在同范围同土体状态下平衡。当前不是任意地形曲面或完整道路断面求量器；设计室外地坪不能自动当原地面，不默认工作面、放坡或松胀系数。

## 12. 桩基与地基处理

- **先读与问题：**按[桩基](../../qto-piles-groundwork/SKILL.md)对应桩位图、桩表、说明、详图、地勘及变更，逐桩核类型、截面、桩顶/桩底/孔口基准；试桩、工程桩、废桩和补桩分开。
- **模型准备 → 程序：**先完成逐桩身份和有据分组，再给 `pile_groups` 的根数、单根有效长、圆形或矩形等截面；`piles_reference` 调用 [calculate_pile_groups_reference.py](../../qto-piles-groundwork/scripts/calculate_pile_groups_reference.py) 复算总长与理论实体体积。
- **交接：**桩身/成孔/灌注、超灌/截桩/接桩、护筒及处理区分别声明量项，钢筋笼交钢筋、承台筏板交混凝土、大面土方交土方。
- **回图与边界：**逐桩对点、对表、核异常桩长和变更覆盖。当前登记出口只支持明确等截面桩组算术，不识别持力层，不计算扩底、充盈、施工增量或一般地基处理；“一个桩型详图”不产生工程桩根数。

## 13. 道路与场地构造

- **先读与问题：**按[道路场地](../../qto-roads-siteworks/SKILL.md)把平面桩号/分区与纵横断面、结构层做法对应，逐段确认边界、有效宽度、层厚及适用范围；交叉口、变宽变坡、附属构造必须单独看。
- **模型准备 → 程序：**只将已闭合的等宽段放入 `segments`，每段给长度、宽度和逐层厚度；`roads_reference` 调用 [calculate_road_layers_reference.py](../../qto-roads-siteworks/scripts/calculate_road_layers_reference.py) 复算各段面积和逐层体积。不同层宽不同必须分别建对应范围，不能直接共用一个宽度。
- **交接：**路床以下土方交土方，挡墙实体/钢筋交结构专业，管沟/管网交其归属；路缘石、沟渠、绿化地块和未支持的变断面另列应算量项。
- **回图与边界：**回查交叉口重叠、渐变段、断面跳变、未设填充区域与各层边界。当前出口不处理曲线扩幅、超高、渐变或完整道路断面；局部 HATCH 面积不是道路全范围，也不自动证明所有结构层一致。

## 计算后继续推进

- 先运行相关专业检查，再用项目对账同时查实际索引观察和应算量项。程序不支持的分支应有具体缺口、替代取证/计算任务及数量影响；不得删掉未完成目标来获得“全通过”。
- `result_index` 只登记有效原生成果，并保留已核对的身份、记录语义、原生哈希与数值指针；分组小计同时标出单位、口径、场景、专业、构造层/侧别和数量层级。源文件、规则或输入变化后按任务依赖重算；`dependency_recalculate` 复算已声明依赖，不能代替重新识别受变更影响的工程语义。出现 `rebind_native_result` 时由模型重新核对实际行与量项，不能让程序按旧行号直接接数。
- 有可定位对象时用 `review_html` 生成工作复核页，`review_feedback` 读取意见，按实际方法/规则/对象修改输入并重新运行专业程序。意见不是直接改总数的授权；同值但依据变化也须重新判断旧意见是否仍适用。
- 完成某一专业或代表范围后，继续处理相邻交接、同族例外及尚未闭合图种任务。交付已算量、条件量、未决/不适用依据及下一步动作；不输出未经证明的全工程完整率。独立原图结果先留存，人工底稿再用于差异比对。
