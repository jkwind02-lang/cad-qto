# 计算与证据流程

## 1. 冻结任务与来源

记录项目、楼栋、楼层区域、构件类别、图纸/变更/图集/钢筋表版本、输出口径和只读项目根。对每个文件核对路径、字节数和 SHA-256；CAD 缓存还需核对源图 SHA、实体流 SHA、适配器、模式版本、单位和守恒。

## 2. 建立构件与钢筋组账

先建立构件身份，再为每个位置、方向、层位、类别、级别和直径建立钢筋组。原始标注、解析字段、采用字段和未决字段分开保存。一个文字句柄不能因邻近多个对象而自动复制为多个采用钢筋组。

## 3. 形成规则适用表

逐项判断对象识别、根数、展开、单位质量、节点、连接、措施、清单口径和覆盖完整性。成熟状态为候选的规则用 `decision=trial` 标为“试用”，由模型解释其当前适用理由，形成工作推算/方案暂估；不把试用写成成熟度提升。当前钢筋计算器的 `adopted` 仍要求 `verified` 事实及已采用的 `trial/formal` 规则，不能通过改标签使候选结果进入采用量。

## 4. 确定性复算

模型从原图求得当前钢筋组的数值及解释后，使用 [钢筋计算清单格式](钢筋计算清单格式.md) 建立运行清单。可从标注、构件几何或节点任一切入，按遇到的歧义返回相关来源；本节不规定识图思考顺序。每组计算输入至少包括：

- 稳定构件与钢筋组编号；
- 类别、位置、级别、直径和采用口径；
- 有依据的根数、首末等距中心或实际中心列表；单根中心线展开长度，或直段与逐项附加长度；
- 单位质量计算方式和依据；
- 证据、规则、状态及未决事项；
- 根数、总长度和重量三个独立成果编号。

输出必须写在候选验证目录，不得回写项目资料根。真实项目来源在运行清单中列入 `readonly_roots`，计算器会拒绝把输出写进这些目录。

参考计算的新候选/试用路径提供简短 `working_basis`，由程序复用现有假定与成果分层；不把模型推理简化为填满必填框。根数推导和长度/重量算术由程序执行。无法由当前已取得依据解释的节点参数不生成数字，能独立求得的部分继续。

## 5. 绑定验证

先验证公共最小成果字段，再通过 `validate_rebar_result.py`：

1. 核对清单、来源和生成器 SHA；
2. 重新运行计算器到临时目录；
3. 逐字节比较成果、计算证据和明细；
4. 核对根数 × 单根展开长度 = 总长度；
5. 核对总长度 × 单位质量 = 重量；
6. 检查同一钢筋组的输出维度、单位和采用角色；
7. 检查候选规则、测试证据、零值、未决项及旧归档路径。

验证器通过不代表标注归属、平法节点或清单规则经过业务核准；这些专业判断必须由案例和来源另行证明。
