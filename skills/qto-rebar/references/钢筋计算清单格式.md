# 钢筋计算清单格式

由模型从原图主动编制 `scripts/calculate_rebar_items.py` 的输入。参数“明确”是指能够指出所用数值、适用对象和推导依据，不要求用户先给出完整钢筋表。程序核对来源并求值，采用事实与有来源的工作解释保持分层；它不识别平法语义、不选择首末根布置或图集页，也不自行推定锚固、搭接、弯钩和弯曲调整。

按需读 [参考计算](#工作解释与采用量分开)、[根数推导](#明确钢筋中心的根数推导)、[钢筋组示例](#从原图解释编制的钢筋组示例)。

## 顶层结构

```json
{
  "manifest_version": "qto-rebar-manifest/1.0",
  "case_id": "稳定案例编号",
  "test_mode": false,
  "readonly_roots": ["项目只读根"],
  "scope": {
    "project": "项目",
    "building": "楼栋",
    "area": "区域",
    "drawing_type": "图纸类型",
    "drawing_version": "版本身份",
    "output_dimension": "输出维度"
  },
  "sources": [],
  "evidence": [],
  "rules": [],
  "unresolved": [],
  "bar_groups": []
}
```

## 来源与证据

每个来源必须提供 `source_id`、现存文件 `path`、预期 `sha256`、`file_role`、`source_role`、版本身份和选择理由。允许的语义角色包括 `project_drawing`、`cad_metadata`、`cad_entity_stream`、`project_document`、`approved_schedule`、`standard_reference` 和 `test_fixture`。测试夹具只能在 `test_mode=true` 且成果采用角色为 `reference` 时支撑数值。

编号沿用最小成果契约：来源 `SRC-…`、证据 `EV-…`、规则 `R-…`、成果 `QTY-…`、未决项 `U-…`；前缀后使用英文字母、数字、点、下划线或连字符。

CAD 元数据可通过 `json_assertions` 核对源图 SHA、实体流 SHA、适配器、模式版本、单位和守恒。实体流来源可提供 `expected_line_count`、`expected_source_sha256` 和 `expected_schema_version`；证据中的 `entity_assertion` 用 `entity_handle`、`layer`、`entity_type`、`geometry_type`、`closed`、`text_contains` 或 `bbox` 核对具体实体。

证据至少包含 `evidence_id`、`source_id`、`evidence_class`、`fact_status`、中性事实、定位、来源身份、提取方式、质量状态和限制。中性 CAD 对象用 `object_keys` 记录 `handle:<句柄>`；标注空间邻近但尚未完成归属时使用 `candidate`，不得支撑采用数值。

## 钢筋组

每个 `bar_group` 需要稳定的 `group_id`、`physical_object_id`、`component_type`、`bar_category`、`member_id`、`position`、`grade`、`diameter_mm`、`measurement_basis`、`quantity_basis`、`adoption_role`、`status`、来源、规则、未决项以及三个独立输出编号。

当前方法：

| `method` | 关键输入 | 结果 |
|---|---|---|
| `explicit_developed_length` | `count` 或 `count_derivation`、`developed_length_each_m`、长度依据 | 根数、总长度、理论重量 |
| `straight_with_explicit_additions` | `count` 或 `count_derivation`、`base_length_each_m`、逐项 `additions_each_m` | 根数、总长度、理论重量 |
| `count_only` | `count` 或 `count_derivation`、明确单位 | 钢筋、接头或成品计数 |
| `deferred` | 未决事项和缺失原因 | 相应结果为 `null` |

普通钢筋重量支持：

- `geometric_density`：提供公称直径、`density_kg_m3` 和 `density_basis`；
- `explicit_unit_mass`：提供 `unit_mass_kg_m` 和 `unit_mass_basis`。

输出编号示例：

```json
"outputs": {
  "count": "QTY-RB-X-COUNT",
  "length": "QTY-RB-X-LENGTH",
  "weight": "QTY-RB-X-WEIGHT"
}
```

`complete` 表示本组所声明解释下的计算输入完整且无关联完整性未决项，不等于专业识别或正式采用已经确认；`partial` 保留明确命名的已算部分并关联缺口；`unresolved` 输出 `null`；`not_applicable` 明确说明不适用。

## 工作解释与采用量分开

- `adoption_role=adopted` 保留原门槛：事实为 `verified`，引用规则为 `decision=adopted` 且成熟度为 `trial/formal`。候选、参考及测试证据不得支撑采用数值。
- `adoption_role=reference` 可计算有实际来源的 `candidate/reference` 事实，或 `decision=trial` 的可试用规则。`trial` 映射为“本次判定：试用”，并不把 `maturity=candidate` 提升为试运行或正式；停用、不适用、证据不足的规则仍不能计算数值。
- 新放通的候选/试用路径须提供下述 `working_basis`。旧版合法的 `verified` 事实与已采用规则参考复算可原样运行，不强制补写这一说明。测试证据仍仅限测试模式和参考角色。

```json
"working_basis": {
  "quantity_level": "inferred",
  "reason": "模型依据哪几处原图，将哪一组标注、排布或节点解释用于本组；为何选择这一解释",
  "evidence_ids": ["EV-B1-DRAWING"],
  "rule_ids": ["R-B1-LAYOUT"]
}
```

`quantity_level` 仅为 `inferred`（有据规则/事实推算）或 `scenario`（有据可选方案参数）；模型选择适合本次问题的层级，不能填 `confirmed`。证据与规则引用须属于本组，并覆盖涉及的候选事实和试用规则。可选 `alternatives` 为替代解释文本数组、`confidence` 为“高/中/低”（默认中）、`recalculation_scope` 为改变依据时需要重算的范围。

程序据此生成已有 `qto-inference/1.0` 的假定目录与成果分层，保留工作量、待专业复核和 `进入正式量=false`；无需模型另填一套发布表单。原生成果及计算证据都带 `quantity_level`，所有参考角色最低为 `inferred`，声明 `scenario` 时保留方案量。`已计算` 不将其提升为确认量。多方案使用独立计算清单与输出文件保留，不改钢筋身份重复累加。

## 明确钢筋中心的根数推导

当根数来自已核对钢筋表或实际实例计数时，沿用 `count`。模型已经解释出首末钢筋中心、或逐根实际中心时，可用同一计算器的 `count_derivation`；它仅求值，不自动确定排布规则。两种输入均要求 `unit="m"`、非空 `basis` 和本组 `evidence_ids`。

| `count_derivation.method` | 几何输入 | 精确行为 |
|---|---|---|
| `uniform_centres` | `first_centre`、`last_centre`、`spacing` | 同一排布轴、同一组实际首末钢筋中心；`(末-首)/间距` 必须为非负整数，再加一 |
| `explicit_centres` | `centres` 非空位置数组 | 每个位置代表本组的一根钢筋；重复中心报错，不自动认作不同层或不同肢 |

所有位置和间距都是米值；位置可为负，间距必须为正。等距模型两端均为实际钢筋中心，不是构件外缘或允许范围界线。非整除、未知端点或单位不明时不作 `round/ceil`。真实末段不等距时，模型可按来源列实际中心；复杂分区可准备有来源的程序推导文件，再将结果作为输入证据，不靠口算回填根数。若同时填写 `count`，它必须与程序推导一致。

该辅助不生成加密区、保护层、洞口截断或首末根政策；不同层、方向、长度、肢数及构造先由模型解释。原始列表里某位置出现两次时，先判断是重复表达还是不同实物，不能让计数器自行猜测。

## 从原图解释编制的钢筋组示例

对应 [识别规则中的教学片段](钢筋识别与构件配筋规则.md#一个从原图求输入的短例)。在顶层登记真实来源 `SRC-…`、原图定位 `EV-B1-DRAWING` 和规则 `R-B1-LAYOUT`；本例模型关联仍作工作判断，证据保留 `candidate`，规则用 `decision=trial,maturity=candidate`。以下为完整 `bar_groups` 项，不以示例数字补充真实项目缺失尺寸：

```json
{
  "group_id": "B1-LOWER-X", "physical_object_id": "B1-LOWER-X",
  "member_id": "B1", "component_type": "板", "bar_category": "底筋",
  "position": "底层X向，沿Y排布", "grade": "HRB400", "diameter_mm": 8,
  "measurement_basis": "本例明确首末中心及节点中心线",
  "quantity_basis": "physical_design", "adoption_role": "reference",
  "status": "complete", "method": "straight_with_explicit_additions",
  "evidence_ids": ["EV-B1-DRAWING"], "rule_ids": ["R-B1-LAYOUT"], "unresolved_ids": [],
  "working_basis": {
    "quantity_level": "inferred",
    "reason": "B1底层X向标注与该节点对应；100/1300指向同组首末钢筋中心，节点仅定义每根延伸",
    "evidence_ids": ["EV-B1-DRAWING"], "rule_ids": ["R-B1-LAYOUT"]
  },
  "count_derivation": {
    "method": "uniform_centres", "unit": "m",
    "first_centre": 0.1, "last_centre": 1.3, "spacing": 0.2,
    "basis": "本例原图100/1300/200 mm按同一基准换算",
    "evidence_ids": ["EV-B1-DRAWING"]
  },
  "base_length_each_m": 2.4,
  "additions_each_m": [
    {"name": "左端中心线段", "length_m": 0.3, "basis": "本例节点明确标出的中心线增量"},
    {"name": "右端中心线段", "length_m": 0.3, "basis": "本例节点明确标出的中心线增量"}
  ],
  "unit_mass_method": "explicit_unit_mass", "unit_mass_kg_m": 0.395,
  "unit_mass_basis": "本例材料表明确理论单位质量",
  "outputs": {"count": "QTY-B1-N", "length": "QTY-B1-L", "weight": "QTY-B1-W"}
}
```

用真实选取的来源建立顶层清单后运行现有 CLI，不手填汇总：

```bash
python scripts/calculate_rebar_items.py /absolute/work/manifest.json --result-out /absolute/work/result.json --evidence-out /absolute/work/evidence.json --detail-out /absolute/work/detail.csv
```

本例程序输出 7 根、21 m、8.295 kg，并留下间隔数、单根 3 m 的展开及参考层级。缺实际节点页时应继续检索该引用；只有根数闭合可暂用 `count_only`，长度与重量保留为未决量项。不能把 300 mm 变成新项目默认锚固长度。

## 输出与只读边界

脚本显式接收成果、计算证据和明细三个输出路径。任何输出若位于 `readonly_roots` 内，脚本立即拒绝。来源若指向旧 Skill、旧归档、旧项目计算脚本或旧结果目录，也会拒绝。

成果使用 `qto-result-minimum/1.0`，根数、长度、重量按独立成果项和独立单位输出。计算证据记录来源哈希、实体断言、输入、根数推导、工作解释、单位质量和公式；CSV 明细同时保留数量层级。用 `validate_rebar_result.py` 回放并运行公共最小成果验证；验证通过不证明模型对标注或节点的解释已经专业核准。
