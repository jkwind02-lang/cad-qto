# 高程竖段与原管网合并

已由原图识别实际管段、冷/热或供/回水端口、阀门及对应关系，而原管网只含平面投影量时，运行 `scripts/merge_pipe_elevation_segments.py`。它复用公共 `qto_elevation_facts.evaluate_elevation_link`，将逐段高程计算接到既有数量出口，不从系统示意图的线长生成真实高度，也不把每台固定长度或底稿值写入规则。

这是独立组合入口，不表示 `infer_pipe_network.py` 已自动识别全部竖段。原管网结果原样保留在组合结果的 `network_result`，附件、管件和未决事项仍须继续使用；不得以本次长度摘要替代完整管网交付。

## 原图判断

1. 先明确每段的实际上下终点。落管到角阀、阀后软管到器具口属于不同范围；不得把安装高度当所有接口共同标高。
2. 高程事实采用公共 [跨图接口与标高换算](../../_qto-shared-evidence/references/跨图接口与标高换算.md) 格式。表头只写“阀门安装高度”时保持 `other_reference`，不能直接改成 `pipe_center`。若采用“安装参照到管中心偏移为零”的方案，显式填写带来源解释的 `signed_offset`、数值 0 与 `level:scenario`；未采用任何有意义偏移方案时保持未决。
3. 建筑完成面、结构面、项目零点各用实际基准身份；同名 F 或 ±0.000 不自动相同。比例缩放的洁具图块不能将缩放系数乘安装高度。
4. 说明中的预算参考高度、将主干标高延续到未逐口注明的分支以及暂按无绕行直落，分别保留方案事实。结果按最弱层级输出，不能因下端有明确表值而升级整个竖段。
5. 对照原已绘段、已恢复断口和既有跨图竖向量，逐个登记范围互不重叠、同一完整范围、部分重叠或尚未查明。几何缺口与未决不是零。

## 输入及调用

```powershell
python -B scripts/merge_pipe_elevation_segments.py --input 合并输入.json --output 合并结果.json
```

输出 JSON 与同名 Markdown，拒绝覆盖输入、旧 JSON 或旧报告。API 为 `merge(payload, base_dir=".")`；相对原管网路径以输入文件目录为基准解析，高程 `sources[].path` 必须是绝对路径，避免换工作目录后切换来源。

顶层字段：

| 字段 | 内容 |
|---|---|
| `schema` | `qto-pipe-elevation-merge/1.0` |
| `network_id` | 与绑定的原管网相同 |
| `scope_id / scope_basis` | 本轮对象与实际上下边界 |
| `network_result` | 原 `qto-pipe-network-inference-evidence/1.2` 结果的 `path / sha256`，不能将已合并结果再次当原量 |
| `segments` | 每个实际竖向区段一条，不能输入件数、并行根数、乘数或外部数量 |

每段必需字段：

- `record_id / physical_id / extent_id`：唯一数量记录、实物和实际区段身份。范围相同的不同图视图不创建第二条数量。
- `name`：可选业务名称。`system`、`specification`（含 `dn`，有材料/系列时完整保留）、`quantity_kind:"length"`（可省）、`measurement_basis:"pipe_centerline_route_length"`、`unit:"m"`。这一入口不计算阀件净扣，不能把中心线路径量称为净管。
- `elevation_facts`：完整公共 `qto-elevation-link/1.0` 输入。外层 `schema` 字段不是 `schema_version`。路线仅允许 `vertical` 或 `unresolved`，斜管及多段绕行先分段。
- `source_ids / basis / level`：本轮模型解释与来源。来源目录复用 `elevation_facts.sources`；有实际来源文件 SHA 核验。模型识图证据不等于人工确认。
- `endpoint_bindings`：恰好两条，含 `port_id / network_record_id / source_ids / basis / level`。`port_id` 对应高程换算后的 `target_reference_id`，没有换算时为原 `reference_id`；绑定原管段、阀门或端点对象，系统和 DN 必须一致。
- `network_coverage`：四个数组 `disjoint_record_ids / same_extent_record_ids / partial_overlap_record_ids / unknown_record_ids` 与 `source_ids / basis / level`。四数组须完整、不重复覆盖 `network_items(network)` 返回的既有长度出口。

原量编号用 `segment:<segment_id>`、`bridge:<bridge_id>`、`vertical:<link_id>`。只枚举已计入的恢复断口，在线附件占位排除量不是管长；已声明 `counted_elsewhere` 的跨图记录不重复相加。原件数不进入长度汇总。不同长度单位可可靠换算为 m，面积、件数和其他口径拒绝。

## 身份、别名与共享段

同一 `physical_id`、`extent_id`、实际端口对或相同原网对象对不能通过换名称重复生成竖段。既有跨图结果的管中心端口也参加去重。两条纯竖段共享同一端口并向同一方向延伸时，会存在共享区间，须先拆分共享干段与余下支段；相反方向的真实分段可分别保留。

`same_extent_record_ids` 当前支持一个完整既有出口。只有系统、完整规格、口径及长度相符时，新增长度才为 0 并指向原出口；数量不一致保留冲突，不补差。明确不同的物理/extent 身份不得仅凭同规格、同长度抵扣。

确有原图证据表明两个标识是同一实物时，可以在 `network_coverage.identity_aliases` 中给出 `existing_record_id / alias_fact_id / source_ids / basis / level`。其来源目录须登记同 `id` 的 `physical_extent_identity` 事实，含：

`system, existing_record_id, existing_physical_id, existing_extent_id, new_physical_id, new_extent_id, from_port_id, to_port_id, level`。

来源事实逐字段绑定本次新旧身份，并要求实际文件路径与 SHA。该事实是有依据的模型别名判定，脚本不能自行从名字近似生成它。

两端绑定同一个原网对象时，仅有两个新端口名字还不能证明实际不同端口，保持 `endpoint_unresolved`。确有不同端口时，每条绑定加 `port_binding_fact_id / object_port_key`，并在来源中登记 `measurement_kind:"network_port_binding"`，含 `id, system, network_record_id, port_id, object_port_key, level`；两端的实际 `object_port_key` 必须不同，字段须和来源匹配。

## 高程一致性和结果边界

同一原测点的不同数值事实不能矛盾；不同原测点经过 `signed_offset`、外径或基准换算后落到同一个物理管中心端口时，也比较最终归一高程。比较覆盖新段之间以及保有 typed 端口的原跨图量。不同目标基准只沿有来源的 `datum_transforms` 比较；无换算路径时相关数量未决，不能假定相等。有矛盾时拒绝输入。

输出逐段 `derived_length` 与本次追加的 `quantity`，二者必须区分。前者可已算出方案，后者仍可能因重叠或身份未决而为 null。`already_counted` 的 0 仅表示合法去重后的新增余量为零；未决始终为 null。

报告分别展示原已计小计、竖向追加量和按系统/完整规格/口径/层级分开的组合小计，并列出方案前提与来源。某分组尚有未决时仅显示已算部分，分组数量仍为 null。已形成有来源方案的区段不能继续笼统写成全部未定量，也不能将其与推算原量相加后称确认工程量。管件净扣、阀后连接、套管墙身高度条件、支吊架及保温仍须按实际范围交接，不因本脚本通过而消失。
