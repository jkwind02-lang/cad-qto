# 实际实例、变径分段与逐台接管

适用于平面中的典型阀组、上下层设备、逐台固定长度和竖向等容易错配的对象。先从原图算出有证据的量，再连接参照底稿；缺口必须落实到原实体、连接区段和数量影响。

## 实际阀组与图例

1. 使用完整块实例路径作为物理身份。文字名称、块定义名称、最近轴号和汇总套数均不能替代实例身份；重复设备型号可属于不同实物。
2. 建筑边界外的图例/原型单列；使用建筑轴网、实际管线接入和标注引线共同判断。坐标最近轴号只用于定位，不改写图上或底稿中的业务名称。
3. 框式标注可用 `scripts/bind_pipe_callouts.py` 中的 `bind_callouts(doc, parent_path, instance_paths, label_pattern, ...)`。它在同一父块内检查“实物插入点—引线—框内文字”，保留完整实例路径和变换后坐标。默认仅接受几何接触（数值舍入除外），不预设绘图单位或图层。若原图有绘图缺口，由模型依据本次图纸显式提供 `endpoint_tolerance`、`gap_limit_raw` 或 `text_height_fraction` 及 `tolerance_basis`；两个框边界限同时提供时取较小值。原始容差使用共同父块坐标单位，结果记录端点/框边实际缺口、容差与依据；不按最近文字补配。
4. `bound`、`unmatched`、`ambiguous`、`shared_caption_requires_review` 分别处置。一个标注被多个实例占用时不自动增加数量。阵列块须先展开；框式绑定支持同一父块内任意朝向的直线矩形框、TEXT/MTEXT及单条LINE或开口直线段LWPOLYLINE引线；非矩形框、弧形引线、跨多个实体的分叉引线及未展开阵列仍需其他取证。无法绑定只表示该辅助器未形成对应，不能据此判定图上无标注。
5. 实例与典型详图按用途、主管规格、控制阀规格、接口与附件布置核对。只有型号吻合但无明确适用索引时，可形成带依据的模型候选套用；附件数量和图示轴长分别记录适用状态。

多管水管共用DN或一条完整引线穿过多根管道时，使用[多管引线与共用DN标注](多管引线与共用DN标注.md)的适配器字段；不把框式实例标签绑定器的端点逻辑套到多管规格栈。暖通水仍归本Skill。

## 变径处必须划分规格

先运行详图路径测量，再用 `scripts/partition_pipe_detail_specs.py --input 输入.json --output 结果.json`。它重新读取和复算源图，不采用缓存或手填的长度。

输入 `schema_version` 为 `qto-pipe-detail-spec-partition/1.0`；`detail_input` 为已保存路径输入的 `{path, sha256}`。`partitions` 覆盖每一条物理路径；每项含 `physical_group_id`、`physical_route_id` 和顺序排列的 `zones`。

- 每个区间用 `from`、`to` 指定路径中的区段索引 `segment`。区段两端用 `end: start/end`；直线中间的分界用 `point: {path, part?, fraction}` 引用真实端面中点或源几何点，不能手填里程。完整圆弧仍按曲线量测，当前不支持曲线中间分界。
- `specification` 可为 `constant_dn`（`dn`）、`transition`（`dn_from/dn_to`）或 `unresolved`（`issue`）。每项有 `review_note`。确定的每一个DN有 `annotations: [{path, text}]`，工具核对文字原文、DN及当前视图归属；语义适用仍由模型判图负责。
- 异径段单列占位轴长，不把整个控制阀/变径组件套主管DN。一个区间有两个DN来源，顺序对应两端；不从块名或绘制外径直接反推DN。
- 区间须从路径起点连续覆盖至终点，遗漏、重叠、逆序、零长、源点偏轴、规格原文不符或路径未处置均拒绝。未决规格保留长度，并使规格覆盖保持 `partial`。
- 输出为分规格的图示轴长，含阀件占位，`billable_pipe_length_m` 保持空值；制作净管长度与合同计量另按实际规则处理。

若详图标注DN、符号几何外径或块名冲突，保留各自原文和源路径。可按图示尺寸测量、按文字解释规格，但不能因此认定符号外形就是可加工尺寸。零长尺寸不能用于标定；辅助投影或局部重叠圆弧不能重复计量。

## 设备与供回水连接

1. 设备有上下层叠放时，一处平面轮廓可能对应多台设备。结合上/下层文字、立面、各管口和设备型号形成物理实例，不能只数块或只数文字。
2. 管口要按坐标、源几何及连接角色匹配；设备文字可能远离本体，不以最近文字分配。圆形竖管/接口符号的中心可能是连接点，不能把到圆周的距离当成到端口中心的距离。记录绘图偏差和使用容差。
3. 供水、回水、冷热水等分开建立拓扑标识，按当前图纸图例分别赋予 `system`。同属一个水系统并不代表管路互连。不同回路的平面交叉不构成三通，也不能充当每台支管的截断点。
4. 逐台路径明确起止边界，可列“设备端口至首个同回路分支点”或“设备端口至指定集管接口”；不同边界不得直接比较。共享干段只计一次，不随设备路径逐台重复累计。
5. 管端找不到对应设备或同一设备多出接口时，保留孤立端点、坐标、源路径和已绘长度。先检查转换、视图、上下层和缺绘；不能为了匹配底稿台数强行分配。
6. 底稿的每台固定配管系数属于对照输入。独立结果拆为水平已绘、竖向有据、阀组内部、共享干段和未绘连接；先统一边界再判断差异。底稿没有记录边界或几何依据时，不能把系数反填为图纸长度。

## 竖向与转换例外

- 指向其他楼层的文字能提供跨层方向和接口，不能提供管长。建筑楼层标高、结构标高、完成面、设备口标高、管底BOP和管中心分别记录。BOP转中心需要有来源的管外径；未知外径不默认为DN。
- 建筑剖面和楼梯的标高体系不同或互相矛盾时，列出差值方案与影响范围；最终竖向仍需管道起止标高。楼层差方案不能升格为完整立管量。
- ODA工作副本审计转换仍需目标几何核对。可从未修改的DWG工作副本直接读取 `entget`，比较所选实例的类型、层、坐标、尺寸、块变换、折线顶点和凸度，保存源/交换文件哈希、原始提取、核验范围和未支持对象。不把选定实体一致推广为整图转换无变化。
- 原生取证只打开工作副本，不保存；退出提示应确认“放弃修改”。核对原始DWG及工作副本哈希，保留失败日志。若句柄直接查询失败，先检查实体是否随外部参照加载后可查询，不立即推断图元缺失或被重新编号。
