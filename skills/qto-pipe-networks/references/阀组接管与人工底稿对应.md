# 阀组、接管、竖向与人工底稿对应

用于有人工底稿、典型阀组详图、逐台固定管长或跨视图接管的任务。模型识图建立对应；脚本只检查已经建立的关系。不能用底稿差额反推一个未画接管，也不能以总量相同证明逐组一致。

## 独立实测的执行位置

用户以底稿辅助检验技能时，先在不借用底稿数量和固定长度的情况下，从平面、系统、详图建立前三层对应并计算，再在独立结果封存后连接第四层底稿行。底稿对象数、每台4/15/20米等固定值及“层高×根数”只能用于事后比较或明确命名的底稿假定方案；不能因为检查器能接受并计算allowance就把它算作独立取量。

仅包含manual来源、identity_basis=manual或allowance的台账，是表内对应检查。补充了图纸文字/尺寸提取，也不自动使该台账成为原图数量；必须实际形成相应物理实例、区段及尺寸链。模型尚未完成这些关联时，记为识图/计算未完成，不能直接断言资料无法提供。

典型详图先按[阀组详图轴线路径计算](阀组详图轴线路径计算.md)恢复有依据的供回、旁通轴线，并单列泄水和仪表支管覆盖。轴网间干管行即使备注某阀组，也不是该典型组内管长。不同性质的数量不做“准确率”除法；先明确是否具备同口径参照值。

## 建立四层对应

1. **对象**：先列楼层/区域、系统、阀组位置和设备实例。设备型号不是实例号；同一阀组可列多个型号。同名设备、同名房间不能直接合并。汇总行、数量标签和详图视图不是新增实物。保留原图句柄或底稿行号；尚未逐个定位的汇总数量标为 aggregate，不虚构逐台身份。
2. **部位**：区分已绘平面、阀组共用管、逐台设备接管和竖向。阀组共用部分乘阀组套数，逐台接管乘设备数。每一实物区段给同一 extent_id；在平面、立面、详图、供回视图中重复出现仍只计一次。规格改变处分段，供回/并行根数单独给依据。
3. **尺寸**：区分图示实测/尺寸链、统一基准的起止标高差、人工每台固定值。平面图中的楼板标高不自动等于管中心标高。详图总体高度不等于所有管腿长度；总体尺寸与分段尺寸不同时相加。图示比例、尺寸覆盖或尺寸文字改写不明时只保留事实。固定长度仍是 allowance，即使恰与底稿汇总相符也不升级为图纸长度。
4. **底稿行**：逐行绑定相同系统、规格、单位、范围和所覆盖实例/区段。设备表、阀组表、材料表可能使用不同范围或版本。总数相同而型号/楼层数量互相抵消仍是冲突；未经版本裁决不选一个总数当真值。图号顺序不表示轴号顺序，跨页接口和 SEE PLAN 等说明优先保留。

## 对应检查脚本

运行 `scripts/audit_pipe_correspondence.py --input 台账.json --output 检查.json`。

输入 `schema_version: qto-pipe-correspondence/1.0`，字段：

| 集合 | 必填内容 |
|---|---|
| sources | source_id、path、sha256、kind（drawing/manual/other）；每次检查重新读取文件哈希 |
| members | member_id、name（可选）、kind（device/valve_group/route）、count、scope、system、identity（physical/aggregate/candidate）、identity_basis（drawing/manual/candidate）、source_refs |
| parts | part_id、member_id、role（device_connection/valve_group/plan/vertical）、extent_id、specification、unit（m/个/套）、source_refs、basis |
| comparisons | comparison_id、part_ids、manual_quantity、unit、specification、system、expected_scopes、source_refs、extent_coverage（complete/partial/unknown）；expected_member_ids 和 manual_member_count 可缺省，但缺少实例全集时不得称完整对应 |

`source_refs` 为非空的 `{source_id, locator}` 列表。定位至少到工作表单元格、图纸句柄/详图编号与区段，不能仅写“见图”。声称图纸独立实例、尺寸、起止标高或相应供回根数时，引用中必须有登记为drawing的来源；不能只把evidence_origin改成drawing而仍仅引用manual。来源分类本身须按文件内容如实登记。所有 parts 中的同一实物区段必须使用相同 extent_id，脚本遇到重复直接拒绝；异名重复仍需识图发现，脚本不会替模型识别。

`basis` 支持：

- `allowance`：value 是单个计数对象的固定值，另有 source_refs。只作底稿假定或方案；不自带图纸证明。
- `measured`：value 是已取证的单个对象米数；需 evidence_origin=drawing 与 source_refs。
- `dimension_chain`：lengths_m 列出不重叠且已经换算为米的各段，保留换算及端点依据；需 evidence_origin=drawing 与 source_refs。
- `elevation_pair`：from_m、to_m、datum、from_source_refs、to_source_refs、source_refs、evidence_origin=drawing。允许负标高，只计算绝对差；仅用于 vertical。
- `count`：整数个/套，需 evidence_origin=drawing 与 source_refs。

`runs` 缺省1；大于1必须提供 runs_source_refs，不把并行根数混入单位换算。计算为“单对象值 × runs × member.count”。独立 physical 对象的 count 必须为1；aggregate 允许多个对象但不证明逐实例对应。

输出逐部位表达式、数量、证据和每条底稿差额。`arithmetic_match` 只表示加总相等。`correspondence_complete` 还要求对象全集/范围一致、逐物理实例有图纸依据、没有固定假定且声明完整区段并提供 coverage_source_refs。该布尔值仍仅验证输入的已编码条件，不代替来源版本裁决或模型识图。结果不能直接当作正式工程量表。

存在不一致时分别列明多计/漏列对象、越界范围、数量差额、图纸依据不足及未覆盖部位，不将差额添加成管长。比较不成功的条目照常输出；结构、未知引用、重复区段和来源变化等错误才以非零状态退出。
