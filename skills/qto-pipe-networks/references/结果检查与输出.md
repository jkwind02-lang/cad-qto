# 结果检查与输出

## 输出结构

使用公共 `qto-result-minimum/1.0` 最小字段和 `qto-inference/1.0` 推算分层。实际项目必须另附用户可查看的成果汇总；多系统、多规格或明细较多时使用 Excel 汇总及明细，少量结果可用 Markdown 表格。对象明细 CSV、拓扑/DN 推算证据 JSON 用于复核，不能替代业务汇总。

结果至少按系统、规格、楼层/区域和单位分组。完整安装长度、平面已绘中心线、竖向量和确认断口增量是不同口径，不得互相冒充。

管网成果汇总至少分为以下逻辑表。使用 Excel 时应设置为独立工作表或用户无需展开隐藏明细即可看到的明确命名区块：

1. 管道长度：系统、楼层/区域、DN、数量层级、平面长度、竖向长度、确认补长、工作量、正式量；
2. 阀门与在线附件：类型、系统、DN、实例数、识别/继承依据、数量层级、确认状态；
3. 管件与变径：节点类型、上下游规格、实例数或候选数、数量层级、假定编号；
4. 断口与裁决：断口两端、虚拟拓扑桥、是否计长度、替代方案、数量影响、待确认方和重算范围。

首页或总览还必须按同一口径分列：平面已绘确认基线、确认补长、规则推算增量、已选方案暂估增量、当前工作量、正式可用量和未决影响。用户没有选定方案时显示各方案总量或区间，不把候选方案藏在 CSV。

阀门、管件或断口存在任何稳定实例/候选时，相应用户可见表不得省略。匿名附件至少按系统、块族、候选类型、DN已赋/待定和数量层级汇总；管件至少按系统、候选类型、DN组合和数量层级汇总。

生成用户汇总后运行 `scripts/validate_pipe_user_summary.py --inference <推算证据.json> --summary <成果.xlsx或成果.md>`。验证失败说明业务维度没有真正进入用户成果，不能用机器证据中已有字段代替。

无法确定 DN 的管段必须作为“DN 待确认”独立行保留长度，不得并入任一已知 DN，也不得从汇总中遗漏。阀门类型或规格不明时同样保留未分类实例数。

## 必查项

### 范围和来源

- 每份被引用资料处于“已选择”，版本与哈希可定位。
- 平面、系统图、详图、说明和表格的用途分别记录。
- 缓存六类身份均有结论；部分复用时明确可用字段和缺失范围。
- 对象明细能回到布局、句柄/稳定记录号、图层和坐标。

### 对象和守恒

- 稳定记录号唯一；同一物理对象的重复实体已排除或进入未决。
- 中心线对象选择审计已交付；重复固定几何且不接网的曲线族均有纳入、排除或未决处置，纳入 ID 与推算管段一致。
- 分系统之和等于同口径的已选对象集之和；分规格之和加未确定规格量等于相应系统量。
- 原始单位、换算因子和输出单位一致；先累计原始精度，后展示舍入。
- 三维中心线不得再叠加同一竖向；二维平面长度不得称完整安装长度。
- 虚拟拓扑桥长度、候选支路数和复核工作量不得静默进入确认量；被选择的补长方案可作为规则推算或方案暂估另列。
- 只要虚拟桥数量大于0，断口方案增量与方案总长均已输出并与桥明细守恒。
- 只要阀门/附件或管件候选数量大于0，用户成果中存在对应汇总表，不只在JSON/CSV中出现。
- 点位工作包存在时，来源实例数等于交付端点数、不适用数和未决数之和；交付端点数与管网 `terminals[]` 一致。
- DN文字匹配检测总数等于 seed、scenario 和 excluded 明细总数；阈值敏感候选至少形成两个覆盖率方案。

### 专业边界

- DN 没有使用未经校准的最近文字或无边界整网传播；末端种子没有越过三通/变径边界冒充整网规格。
- 二维立管符号、圆或箭头没有换算成竖向长度。
- 折点、交点或支路候选没有直接换算成管件数量。
- 匿名块、重叠块、图例和多视图表达已去重；类型不明的稳定实例作为未分类候选输出，没有直接当阀门正式数量。
- 洁具、泵、箱、喷头和其他设备点位没有重复进入管道对象。
- 风管、电气路径、土方和构筑物没有被静默纳入。

### 状态

- 走完推算阶梯仍无法形成候选的未知数量为 `null`，不是 0。
- “部分计算”不得冒称整体完整量；名称与相邻范围、状态、未覆盖说明共同限定小计或合计，无需固定限定短语。关联至少一项确实影响完整性的未决，存在成果分层时其计算完整性为“部分”；文字检查不能代替工程证据复核。
- 真正零值具有范围覆盖、来源、规则、复核结论和说明。
- 结果状态、规则本次判定和规则成熟状态相互独立。
- 采用试运行规则的结果标记“试运行结果=true”。
- 候选规则的试用/项目采用依据明确，停用规则没有被采用或试用。
- 确认量、规则推算量、方案暂估量、未决量以及工作量/正式量分列，假定编号和重算依赖完整。

## 最低测试场景

1. 正常：系统、范围、单位和中心线对象明确，按系统/规格输出并核平。
2. 边界：二维立管符号存在但无高度，平面已绘中心线部分计算，竖向为 `null`。
3. 冲突：喷淋管与喷头、水管与风管或连接管与设备混合，按对象链拆分且不重复。
4. 缺资料：请求“把管线都算一下”但系统/区域/版本不明，只形成目录和最少问题。
5. 规则冲突：项目合同条款与通用标准口径不同，停止受影响合并并等待裁决。
6. 推算：存在唯一虚拟断口桥、一个直接 DN 种子、一个末端端口种子和阀门实例，能形成分层结果并保持长度守恒。
7. 多方案：同一直通链存在冲突 DN 且变径位置不唯一，输出方案和影响，不把整条链清空或正式采用。
8. 对象回归：重复固定几何且两端不接网的圆弧不得静默进入确认中心线，正常管段继续计算。
9. 交接回归：点位工作包存在可连接实例但管网端点为空时，业务验证必须失败或明确限制，不能显示完整通过。
10. 交付回归：附件/管件存在时，用户汇总缺少块族、候选类型或DN组合，交付验证必须失败。

## 脚本验证顺序

当成果使用 JSON 规范化样本时：

1. 运行同级公共资源的 `scripts/validate_minimum_result.py`；
2. 运行本 Skill 的 `scripts/validate_pipe_result.py`；
3. 若中心线由确定性脚本产生，提供计算证据 JSON 给专业验证器核对分系统值；
4. 对用户汇总运行 `scripts/validate_pipe_user_summary.py`；
5. 阅读错误和警告，修正业务结果后重新验证。

脚本通过不等于规则正式，也不替代原图抽查、边界审查和真实项目复核。
