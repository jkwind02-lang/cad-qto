# 中心线计算清单格式

`scripts/measure_pipe_centerlines.py` 只做已由专业判断确认对象后的确定性汇总。它不识别专业、不自动寻找楼层、不判断图层含义，也不补 DN、竖向、断口或管件。

## 调用

~~~text
python scripts/measure_pipe_centerlines.py --manifest <运行清单.json> --output <计算证据.json> --details <对象明细.csv>
~~~

## 清单字段

~~~json
{

  "source": {

    "entity_stream": "当前项目中性图元流绝对路径",
    "metadata": "对应缓存元数据绝对路径",
    "expected_source_sha256": "当前原始图纸 SHA-256",
    "expected_stream_sha256": "图元流 SHA-256",
    "source_id": "SRC-DWG-001",
    "cache_id": "CACHE-DWG-001"
  },
  "selection": {
    "layout": "Model",
    "bounds": {
      "xmin": 0,
      "xmax_exclusive": 1000,
      "ymin": 0,
      "ymax_exclusive": 1000
    },
    "systems": [
      {
        "name": "生活给水",
        "layers": ["经当前图纸证据确认的原始图层名"],
        "evidence_ids": ["EV-SYSTEM-001"]
      }
    ],
    "allowed_entity_types": ["LINE", "LWPOLYLINE", "ARC"],

  ]

~~~

## 强制要求

- 路径必须指向当前项目，不得指向旧 Skill 或旧归档。
- 脚本现场重算原始源文件与图元流的 SHA-256；两者必须分别与运行清单及元数据记录一致。
- 空间边界、系统—图层映射和单位各自必须有证据编号。
- 系统图层不能重复映射到两个系统。
- `conversion_factor` 必须等于原始长度单位到输出单位的真实换算（例如mm→m为0.001），且有单位证据；不能混入单双线除数、根数或损耗。
- 选择使用半开区间 `xmin <= x < xmax`、`ymin <= y < ymax` 和明确布局。
- 同一物理对象重复、对象跨越范围边界、单位不一致或未知几何类型会使脚本失败，不静默跳过。

输出的 `status=CALCULATED` 只表示清单声明的对象集完成确定性求和。是否属于完整安装量由成果中的范围、规则和未决事项判断。
