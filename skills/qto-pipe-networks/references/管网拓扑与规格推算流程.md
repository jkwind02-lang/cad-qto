# 管网拓扑与规格推算流程

## 适用范围

当管道存在断口、DN 未逐段标注、主支管需要识别、变径位置不完整、阀门规格需继承或设备端口可提供约束时读取本文件。直接属性完整的简单管段不必执行全部步骤。

本流程用于工程量识别和设计事实复原，不替代水力计算或设计责任。由洁具当量、流量或常规最小管径反算的上游 DN 必须标为方案暂估，不能冒充图纸确认 DN。

## 1. 原始对象与系统边界

曲线对象进入中心线前先做对象选择审计。除系统、图层和测量形状外，重点检查重复固定几何曲线、两端均未接入其他中心线、块内/端点附近重复符号和历史选择规则变化。命中异常只把该对象族转为未决，不停止其他管段；在项目证据裁决前不得把异常对象计入确认基线。

先锁定唯一管段对象、原始中心线、单位、楼层/区域和系统。系统图、平面图、详图和设备表分别建证据关系，不把系统图二维示意长度加入平面工程量。

管段至少保留 `segment_id、system、start、end、raw_length、source_id、record_id`。端点坐标只用于当前受控坐标系，不跨未校准图纸直接吸附。

## 2. 断口分类与虚拟拓扑桥

先盘点未连接端点，再按证据分类：

- 真实开口或系统边界；
- 阀门、设备或管件占位；
- 图纸断线、省略画法或提取缺失；
- 跨层、不同标高或跨视图延续；
- 交叉但不连接；
- 暂无法分类。

同系统、端点方向相容、距离在项目校准阈值内、候选配对唯一且没有跨标高/跨系统冲突时，可以建立 `topology_bridge`。拓扑桥只用于连通分析，默认 `quantity_included=false`，不得自动增加管长。

是否把断口距离计入工程量另设 `quantity_decision`：确认补长、占位不补长、项目口径不扣、方案暂估补长、待确认或不适用。这样允许先建网，再结合 DN、占位对象和计量条款裁决长度。

一旦形成唯一虚拟桥，必须把数量影响汇总为三个互不混合的口径：不补长的确认基线、全部唯一桥补齐的上界方案、已分类并允许暂估桥的优选方案。没有任何方案被确认时仍保留各方案数值，不以 `null` 代替已经能复算的虚拟长度。

项目未提供断口分类时，通用引擎仍应把唯一同向短断口列为自动几何候选方案；如在线附件占据桥接路径，则默认“只补拓扑、不补管长”。自动分类均为候选或暂估，不升级为确认量，但不得再把全部断口留成一个没有组成的“未分类”总数。

多个近似候选、方向不相容、疑似交叉或存在占位冲突时保留多方案，不强行桥接。

供水与回水等不同回路分别建立拓扑 `system`，不能只用上层系统名称把两路合并。逐台支管截取只寻找同回路连接点；跨回路平面相交既不构成三通，也不是支管终点。共享干段只计一次；原图端口和逐台路径的处理见[实例规格与逐台接管](实例规格与逐台接管.md)。

## 3. 网络定向与主支管

按系统建立图。根节点优先来自水源、系统入口、立管、设备出口、排水立管或用户确认接口。没有根节点时仍可形成无向连通分量，但主支管只作候选。

从根节点遍历，记录每条管段的：

- 距根深度和上/下游节点；
- 下游末端数量、末端类型和已知需求；
- 节点度数、是否环网、是否桥接；
- 角色：主干、支干、支管、末端连接、环网或未定。

主支管不能只按线长、线宽、图层或空间位置判断。环网、多源系统和回水系统允许多根或无唯一方向，角色可保持“环网/未定”，不影响其他可闭合 DN 区段继续传播。存在根节点和末端时，必须把逐段角色、下游末端数和未定原因输出；不得只建立图而不形成角色表。

## 4. DN 与其他规格种子

种子按强度分级：

1. 对象直接属性、明确引线、系统图与实例唯一绑定：确认种子；
2. 经项目图纸方言校准的标注—区段关系：高/中置信规则种子；
3. 点位 Skill 输出的设备或洁具直接端口规格：端点确认或规则种子；
4. 仅按设备类型、洁具类型、最小接口或常规设计逻辑得到：方案暂估种子；
5. 最近文字、同房间、颜色或未校准整网传播：禁止种子。

文字绑定应把检测到的全部候选交给通用引擎对账。高阈值、低阈值或第二候选差值会改变保留数量时，分别形成敏感性方案和覆盖率；未采用候选也保留排除理由，不能在项目预处理阶段消失。

设备端口种子默认只约束末端连接管，传播到第一个三通、明确变径、设备边界或其他规格种子即停止。要继续反推上游管径，必须有当前项目采用的负荷、当量、流量或设计规则，并标为设计复原方案。

阀门符号造成的断线不等于设备支路结束。有唯一接管关系时，跨符号追到同一末端，再返回首个分支点；不要把阀门前的一小段当成主管。清洗槽等多水嘴组合分别识别横向配水管与单水嘴支管，横管图注不得投给竖向接口。具体接口DN取本项目设备/器具表或图注，不固定成某个数值。

器具接口与已标横管规格不同，先判断接口是否只属于本体或竖向接管；这种情况下使用`interface_only`保留接口事实，禁止通用最小接口DN覆盖横管。不能为了消除冲突删除接口记录。

## 5. 直通链、变径边界与传播

先把没有变径证据的度 2 节点组成直通传播链。以下位置阻断无条件传播：

- 明确异径管件或变径标注；
- 三通、四通、分集水器和设备接口；
- 系统、标高、材质或压力等级变化；
- 用户确认的区段边界；
- 多个 DN 种子冲突形成的疑似变径区。

同一直通链只有一个兼容种子时，可把 DN 传播到整条链并记录方法、距离和置信等级。多个相同种子相互印证可提高置信等级。多个不同 DN 种子时不得整体清空：

1. 查找两种子之间的明确或疑似变径节点；
2. 能唯一定位时分成两个 DN 区段，并把变径件列为确认或推算对象；
3. 不能唯一定位时输出分区方案 A/B、各 DN 长度和待确认影响；
4. 与直接证据冲突的低强度种子降级或否决，不覆盖直接证据。

在三通处，上游 DN 通常不小于已知下游 DN 只能作为冲突检查，不能单独证明精确上游 DN。排水、给水、消防和暖通水分别使用当前项目明确采用的专业设计约束。能按末端类型、下游数量、负荷区间或角色规则形成多个可复算口径时，输出方案 A/B 及影响；不能因为无法确认唯一方案就把全部上游管段留空。

## 6. 阀门和管件

阀门先按稳定实例去重并绑定到管段、断口或拓扑节点。类型来自图例/编号/几何与实例唯一映射；类型不能唯一时仍输出“未分类阀门候选”。

匿名块不能单独定型，但不能因此跳过当前项目说明。先核对适用系统、DN条件、图例和安装节点，形成有对象范围的工作选型；用`type_source_ids`保留说明/详图来源，不把项目阈值写成通用默认。典型设备节点应按实际实例展开附件功能与接口；与平面既有阀件逐一对照，未能确定同一实物时输出去重方案。成套供货或组合阀的功能符号数量不直接等于独立采购件数。

- 两侧同系统且 DN 一致：阀门可继承邻管 DN，数量层级不高于邻管最低层级；
- 一侧有 DN、另一侧同一直通链且无变径边界：形成规则推算 DN；
- 两侧 DN 冲突：检查是否为变径阀组或标签错绑，保留方案；
- 匿名块、图例、重叠块和多视图先去重，不因类型不明放弃已闭合物理实例数。

弯头、三通和异径件同样分为确认实例、拓扑推算实例和方案暂估实例。普通折点或交点只有在端口、角度、系统和标高关系支持时才形成推算对象。

管件规格逐管口保存，不对DN去重后作为完整规格。`ports`保留各接管的DN、方向与计量/上下文来源，`dn_combination`保留重复规格并用于汇总；DN75×DN75×DN100和DN75×DN100×DN100不能并成同一规格。组合按数值显示排序，不表示进出口方向；方向看ports与port_angles。三口具有可识别直通轴时另给branch_angle_deg，排水斜接须结合本项目连接规则判断，不能把通用三通候选直接当正三通采购。

节点的图元数不一定等于物理接管口数。对极短自由残线、容差内自环、清扫口支线、同一符号内多个折点及无连接交叉，先回图区分，再合并或排除相应物理端口。小长度本身只触发检查，不自动删除管线；保留原图元、测长和调整差额。一个排水斜三通及其绘制折角不能无证据当成若干独立采购件，按材料连接形式形成有依据的管件组合或候选。

在不同DN之间选弯头/三通作界限，需要两侧规格及连接方向的当前证据；“凡转弯必变径”“合流后一律取最大DN”和“未标末端一律沿用主管”均不能成为跨项目默认规则。

## 7. 迭代与冲突检查

断口、拓扑、DN、变径和阀门相互约束，至少迭代到以下状态不再变化：

1. 新拓扑桥不再产生；
2. 新确认/推算 DN 不再产生；
3. 变径冲突不再移动；
4. 阀门和管件的系统、规格继承不再变化。

不得为了消除冲突而删除低置信候选。输出覆盖率和守恒：原始长度、确认 DN 长度、规则推算 DN 长度、方案暂估 DN 长度、未决 DN 长度之和等于同一口径总长度；虚拟桥长度另列。

## 8. 成果

至少输出：

- 原始管段与虚拟拓扑桥明细；
- 根节点、连通分量、主支管角色和下游末端统计；
- DN 种子、传播链、变径边界、冲突和替代方案；
- 分系统、分 DN 的确认量、规则推算量、方案暂估量和未决量；
- 阀门/管件的物理实例数、类型、系统、规格和数量层级；
- 当前工作量、正式可用量、待确认影响量及假定依赖。

以上成果中，断口方案、DN方案、管件候选和阀门/附件块族汇总必须进入用户可直接查看的 Markdown 或 Excel；机器证据不能替代业务汇总。

不得把拓扑桥虚拟长度、复核候选对数或设计复原方案静默并入确认管长。
