# 管道与管网算量

先定阶段：范围/能力问答只读相关边界与能力披露；已有明细仅作表内复核；原始资料算量执行下文。表内复核不核准原图，细则按需见 [分阶段读取](../_qto-shared-evidence/references/按任务阶段读取.md)。

原图算量先读取并执行 [人工思路识图与算量流程](../_qto-shared-evidence/references/人工思路识图与算量流程.md)。模型负责依据图纸识别工程对象并形成可复核工作量，工具负责取证和计算；人工复核与正式采用另列，不以“用户尚未逐对象核定”代替模型识图。

给排水按“说明/图例及平面—系统图互读 → 立管/水源至支管、末端逐路追踪 → 分规格量水平与竖向 → 管件阀件和附属量 → 回图核对”推进；排水同时核对排出方向、坡度、通气和跨层对应。

围绕“管线中心线—规格—拓扑—派生安装量”完成一条可追溯计算链。清晰的单一管道任务直接执行；不要等待全专业协调 Skill。

## 先判定是否属于本 Skill

读取 [对象范围与相邻边界](references/对象范围与相邻边界.md)。

- 纳入给水、排水、消防水、暖通水、制冷剂、工艺管道和室外管网的管段、管件、在线阀门及附件、随管道计算的支吊架和保温。
- 排除风管及其附件、电气导管/桥架/电缆、洁具、泵、箱、喷头、检查井等设备或点位对象。
- 混合任务只处理能够独立划出的管道部分，并明确其余对象应交给哪个相邻 Skill；不得把不同单位或不同计算链合为一个结果。
- 用户只问市场价、报价或成本时不执行本 Skill；算量与报价混合时只在管道算量范围已明确且可独立交付时继续算量。

## 执行顺序

### 1. 锁定任务范围

直接读取 [图纸与资料范围筛选](../_qto-shared-evidence/references/图纸与资料范围筛选.md)。至少锁定业务专业、主要管道对象、系统、楼栋/楼层/区域、图纸类型与版本、输出维度和所需补充资料。

项目、地区、合同和标准规则的采用顺序先按公共 [现行规则来源选择门](../_qto-shared-evidence/references/现行规则来源选择门.md) 判断；规则版本或适用条件未闭合时，不得从记忆或邻近文字补规则。

范围仍可能有实质歧义时，先给出可执行的初步范围；只询问会改变结果的最少问题。缺少决定性范围时只建立低成本资料目录，不启动全项目深度提取。

### 2. 选择资料并核对缓存

原始资料按 [资料提取与来源核对](../_qto-shared-evidence/references/按任务阶段读取.md#原始资料与计算) 选择相应公共资源；未进入提取阶段时不展开其他资料类型。

公共文件缺失、不可读或版本不明时，停止受影响部分并记录缺失路径；不得回读旧 `construction-qto`、旧归档或用模型记忆补规则。

缓存只能提供中性图元、文字和表格事实。不得继承缓存中的旧专业标签、计算计划、工作包、工程量、规则状态或发布状态。

### 3. 读取本次需要的直接规则分支

按任务对象直接读取一个或多个文件，不建立第二层路由：

- 给水、热水和回水：[给水管道规则](references/给水管道规则.md)
- 污水、废水、雨水和通气：[排水管道规则](references/排水管道规则.md)
- 消火栓、喷淋及其他消防水：[消防水管道规则](references/消防水管道规则.md)
- 冷冻水、冷却水、采暖水、冷媒和制冷剂：[暖通水与制冷剂管道规则](references/暖通水与制冷剂管道规则.md)
- 工艺介质和室外市政管网：[工艺与室外管网规则](references/工艺与室外管网规则.md)

同时读取 [规则清单与成熟状态](references/规则清单与成熟状态.md) 和公共 [推算分层协议](../_qto-shared-evidence/references/推算假定与发布分层协议.md)。当前项目每条规则分别记录“采用 / 试用 / 不适用 / 证据不足”和“候选 / 试运行 / 正式 / 停用”。候选规则可以试用并形成推算/暂估；进入正式量时必须满足项目采用依据和发布条件。

### 4. 建立对象级证据并计算

读取 [计算与证据流程](references/计算与证据流程.md)。存在断口、DN 未逐段闭合、主支管、变径、阀门规格继承或末端约束时，同时读取 [管网拓扑与规格推算流程](references/管网拓扑与规格推算流程.md)，按顺序完成：

1. 划定空间范围和系统边界；
2. 先依据图例、平面/系统对应、局部图面与连接关系识别对象并确认单位；从中性取证包起算时，按 [管网推算输入格式](references/管网推算输入格式.md) 固化本轮识别配置及模型工作识别记录（或确实已有的独立裁决台账），运行 `scripts/build_pipe_inference_input.py`。有依据的模型纳入/排除可以进入工作计算；未覆盖对象继续识图，无法判明部分单列未决，不冒充人工核定；
3. 计算已绘平面或三维中心线；
4. 分类断口，先建立不默认补长的虚拟拓扑桥；
5. 接入立管、水源、设备和末端端点，分析连通分量及主支管；
6. 绑定直接 DN/规格种子，识别变径边界并受控传播；
7. 依据真实标高或三维端点计算竖向量；缺高度时可按明确层高方案形成暂估，不能冒充确认量；
8. 分别形成管件、在线阀门、支吊架与保温的确认量、规则推算量或方案暂估量；
9. 保留对象明细、公式、来源、假定、替代方案和重算依赖。

只有中性对象选择已经由项目证据明确时，才可使用 `scripts/measure_pipe_centerlines.py` 做确定性中心线汇总。该脚本不判断图层是否为管道、不传播 DN、不补竖向、不推导管件；输入格式见 [中心线计算清单格式](references/中心线计算清单格式.md)。

已有本轮模型识别或人工核定的对象清单时，先运行 `scripts/audit_pipe_object_selection.py`，再按 [管网推算输入格式](references/管网推算输入格式.md) 形成 `1.2` 输入并运行 `scripts/infer_pipe_network.py`；保留实际识别者、证据和未复核状态。点位工作包存在时直接消费其端点交接文件，不得丢弃坐标、端口角色或规格候选。未运行通用脚本时说明不支持的表达、替代测量/计算方法和未验证范围，不因此停止全部工作。

CAD 文字与管段的所有匹配候选应作为 `dn_match_candidates[]` 进入通用引擎并逐项标记 seed、scenario 或 excluded。距离、方向或第二候选差值等阈值变化会改变覆盖率时，必须提供至少两个敏感性方案；不得在项目预处理阶段只保留强阈值结果而静默丢弃其余候选。

### 5. 形成并检查成果

形成成果前直接读取 [证据引用要求](../_qto-shared-evidence/references/证据引用要求.md)、[通用成果字段与状态](../_qto-shared-evidence/references/通用成果字段与状态.md) 和 [结果检查与输出](references/结果检查与输出.md)。

- 每条结果必须有范围、数值/空值、单位、证据、规则、状态和未决事项。
- DN、竖向、断口、管件或附件缺少直接事实时，先走受控推算阶梯并输出假定与影响；只有不能形成有意义候选时才用 `null`。不得填 0、按未经校准的最近文字传播或隐藏经验比例。
- 已形成唯一虚拟桥、稳定物理实例、主支管角色或端点约束时，必须同时形成数量影响方案或候选分组；不得只把对象留在明细 CSV/JSON 而在用户汇总中继续写 `null`。
- 二维立管圆、VPIPE 标记或系统符号只能证明候选位置，不能直接证明竖向长度。
- 已绘中心线可作为“部分计算”结果。局部或不完整结果不得表述为整个项目、系统或完整施工范围的总量。小计或合计表示相加，不自动代表范围完整；汇总时将名称与对象、区域、状态及未覆盖内容一起呈现，无需固定限定短语。范围、证据、未决关联和正式采用条件分别核对，名称通过不等于这些条件已满足。
- 米、平方米、立方米、千克、个、套等分别列示。
- 使用试运行规则的每条结果明确标为试运行结果。

先运行公共最小成果验证，再运行 `scripts/validate_pipe_result.py` 检查对象审计、端点交接、断口分类、DN候选对账和管道专业约束；已有用户可见 Markdown/Excel 时，再运行 `scripts/validate_pipe_user_summary.py` 检查阀门块族/候选类型/DN、管件类型/DN组合和断口方案是否真正进入汇总。验证通过只证明结构和已编码不变量，不替代专业复核。

## 正式采用停止与局部分支继续

出现以下任一情况时，停止受影响结果进入正式量；安全且独立的部分继续，受影响部分仍输出原始事实、规则推算或多方案暂估，只有走完推算阶梯仍无法形成候选时才使用 `null`：

- 来源版本或任务范围冲突且无法裁决；
- 单位、比例、视口变换或缓存身份不能确认；
- 系统或管道对象只能靠关键词猜测；
- DN 只能靠最近文字、颜色或无校准传播得到；
- 竖向只有二维符号而无起止标高、层高对应或三维几何；
- 断口是否由阀门、设备或省略画法造成不能判定；此时允许建立不补长的候选拓扑桥和多方案；
- 管件端口、类型、规格或连接关系未闭合；
- 支吊架依赖专项方案但方案缺失；
- 项目计量条款与通用标准冲突且优先级未确认；
- 当前真实案例暴露会改变数量的规则错误。

## 禁止事项

- 不读取、导入或调用旧 Skill、旧归档、旧规则目录或旧脚本。
- 不把旧测试通过、旧 `active` 状态或旧项目结果当作新规则成熟度。
- 不建立数据库、服务、统一规则引擎、跨专业状态机或报价模块。
- 不为凑齐成果而生成无证据的 DN、竖向、断口、管件、阀门、支吊架或保温确认量；受控推算和暂估必须披露证据、规则、置信等级和假定。

## HTML图面复核交付

原图算量形成对象明细后，默认按公共[HTML交互复核与批注](../_qto-shared-evidence/references/HTML交互复核与批注.md)生成可离线点选的复核页，支持问题分组、成员例外、结论与原因、保存和处理回执。沿用共享生成器，不在项目重写前端；收到意见后由本专业复算并更新采用状态，用户方法意见不自动等于数值确认。纯问答、无图表内复核及用户指定其他形态按实际范围处理。

## 已识别对象的路径与重算接续

本轮对象关系已由模型读图形成后，按公共[按人工算量顺序执行与重算](../_qto-shared-evidence/references/按人工算量顺序执行与重算.md)使用完整曲线分段、跨图接口、端口坐标或电气路径台账；修改已确定的参数/规则时保留依赖重算结果。只读取与本任务相关的小节，不自动扩大专业范围。原始识图责任、候选成熟度和正式采用边界不变。
