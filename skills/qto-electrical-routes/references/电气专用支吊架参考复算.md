# 电气专用支吊架参考复算

本入口补齐已识别桥架/线槽对象到专用支吊架副数、杆件长度、钢重、连接件和有据涂装量的参考计算。模型仍须读图判断适用范围、构造与来源；本工具不识别支架、不自动深化、不作锚固或承载力验算。综合支吊架不进入本入口。

## 责任和复用

- 桥架/线槽物理长度继续归既有对象绑定或路径复算入口；本入口只引用同版上游对象，不重新识图或重复输出通道量。
- 计算继续使用 `qto-calculation-graph/1.0` 和 `recompute_qto_dependencies.py`；没有另建数值重算器。
- 已选方案可以形成分层的工作候选；不表示参数是图纸事实，也不等于人工核准或正式采用。人工凭据声明另列，本入口不自证凭据。
- 项目旧选择未被宿主消费、未核当前说明、将方案混入实际量、把钢重复制为刷油量，属于项目或宿主责任。不得把这些现象计成独立插件缺陷。

## 实际命令

```text
python skills/qto-electrical-routes/scripts/calculate_electrical_supports.py --input 支吊架输入.json --output-dir 新的支架复算目录
python skills/_qto-shared-evidence/scripts/recompute_qto_dependencies.py --input 新的支架复算目录/计算依赖.json --output 依赖CLI首轮.json
python skills/_qto-shared-evidence/scripts/recompute_qto_dependencies.py --input 参数改变后的目录/计算依赖.json --previous 依赖CLI首轮.json --output 依赖CLI次轮.json
```

支架CLI也可给 `--previous 旧目录/依赖复算.json`，沿用同一引擎生成受影响节点与旧复核失效记录。结果目录必须不存在，保护旧成果和批注。退出0只表示输入、来源和本范围参考复算执行通过；未知量仍以null显示。输入/来源/单位/身份不符退出2，不写可消费结果。

## 输入 `qto-electrical-supports/1.0`

顶层含 `project_id / sources / segments / support_groups`。

`sources[]` 必须含唯一 `id / path / sha256`；相对路径以输入文件目录解析。计算前后读取真实文件逐个核对原字节SHA256。`PARAM:`为内部保留前缀。参数内容另外进入局部哈希，不把同一个全输入哈希挂到所有计算节点上。

### 已识别物理段 `segments[]`

| 字段 | 必填含义 |
|---|---|
| `id / physical_id / system / spec` | 稳定段身份、物理身份、系统、规格；不得重复认领 |
| `orientation` | `horizontal / vertical / inclined`；不得混组套用构造 |
| `upstream_id` | 被引用上游对象id |
| `upstream` | `source_id / object_pointer / length_field`，从真实JSON文件定位对象 |
| `length` | 有源m值，须等于上游字段并引用上游来源 |
| `width` | 显式m参数；缺失可null，不猜通用宽度 |

上游schema只接既有 `qto-electrical-object-package/1.0` 或 `qto-electrical-path-result/1.0`，对象kind须为tray/trunking。上游存在项目、physical_id、system、spec、unit时核对一致。长度字段仅接 `complete_length_m / known_length_m / known_path_length_each_m / length_m`，不允许拿质量字段改名充长度。已知子范围和完整范围仍须由作者选对字段并说明，不能把小计当完整量。

每个数值参数统一写：

```json
{"value":1.8,"unit":"m","quantity_level":"方案暂估量","basis":"本轮明确选择的匿名间距方案","source_ids":["方案依据"]}
```

单位必须与字段一致，不静默换算；null数值须保留未决。数值、来源、依据、层级不能靠字段名称猜补。可用层级为确认量、规则推算量、方案暂估量、未决量。

### 唯一支承组 `support_groups[]`

组含 `id / system / basis / source_ids / runs / spacing / rounding / events / event_scope / placements / construction / working_count_basis`。

`runs[]` 是独立支承通道段，含 `id / segment_ids / length_segment_id`。`length_segment_id`须属于本run；同一桥架段不得分给两个支架组。多层共架须额外给 `shared_support_identity / basis / source_ids`。本入口按主段长度只计一次，不乘层数。成员长度不同须先按真实共享范围分段；不以同宽、同系统或几何近邻自动合并。共同支承身份是显式证据声明，仍需回图审阅。

`rounding` 必须给 `scope: per_run / continuous_group` 和 `method: ceil / ceil_plus_one`，并给basis/source_ids。连续组另给 `continuous_channel_id / run_sequence`，按声明顺序列全部run，且规格一致；同宽多段不会隐合。`ceil`是按间距的规则整数，`ceil_plus_one`另外计首末规则中的一副；端部事件已含于基础时必须把净增写0并说明included_by。

`event_scope` 明确 `status: complete / pending / not_applicable` 和依据。pending时最终含事件副数未决；不得把漏查的端部、转角、分支或设备附近加固当0。not_applicable须有依据且events为空。

`events[]` 含唯一id、全局唯一physical_support_id、kind（end/corner/branch/equipment/anti_sway）、run_ids、净增net_addition（0或1）、basis/source_ids。一个端部/转角实物被多个run引用时，在同一事件的run_ids列出，不能重复添加两个事件。净增0须给included_by，说明已被哪个基础或事件覆盖。该规则不生成未画的加固布点。

`placements: null` 表示缺实际布点；不能从L/s或ceil补实物。提供数组时，每项给 `id / physical_support_id / run_ids / chainage_m / basis / source_ids / source_binding`。source_binding含source_id与JSON pointer，源记录的physical_support_id、run_ids、逐run里程chainage_m须与请求一致，且里程不得超出对应有源段长。一个支架支承多个run仍只记录一个physical_support_id。相同实物重复提交拒绝。

实际布点另给 `placement_scope: {status: complete / partial, basis, source_ids}`。partial仅保留observed_placement_count，完整实际副数null；未声明完整范围的空数组不能变成实际安装0副。complete是来源范围声明，不替代工程复核或全图遗漏审查。

`working_count_basis` 必须显式选择 `equivalent / rule_integer / actual_placements`。三种口径仍全部并列输出；没有已选或有源构造时，不生成当前工作副数选择。

### 构造与附属量

`construction: null`只阻断构件量，已知长度和副数继续。提供时包含id、quantity_level、basis/source_ids、selection_status（selected/proposed/source_defined）、applicable_orientations和components。竖向段不得消耗只适用于horizontal的构造；其附属量null且说明原因，不影响已知段长。

`components[]`：

| 字段 | 含义与单位 |
|---|---|
| `id / kind` | 构件身份；crossarm / rod / connection |
| `count_each` | 每副件数，参数unit为1，整数；缺失保留null |
| `length_each` | 横担或吊杆每件长度m；本入口不默认由宽度或层高生成 |
| `unit_weight` | 型材/杆件理论单重kg/m，必须有来源；不是成品实称质量 |
| `exposed_perimeter` | 有几何/展开依据的每米外露周长m；长度×周长才得到m² |
| `mass_each / area_each` | 连接件每个/每套质量kg、展开面积m²；可分别未知 |
| `count_unit` | connection必须为个或套；两者不混加 |
| `surface` | galvanized / non_galvanized / unknown |
| `paint_required / paint_basis` | 布尔或null；非null必须有独立basis/source_ids |
| `scope` | supply与installation分别为included/excluded/unknown |

每个构件亦须basis/source_ids。非镀锌且有据paint_required=true，质量才进入对应kg刷油量；kg计量和m²计量分别输出。kg不能复制到m²。镀锌构件进入本入口的非镀锌刷油分支会被拒绝；镀锌或有据不刷标not_applicable，未知表面处理/刷油责任标unknown，均不写成0。供货和安装范围始终分列，unknown不默认包干。

## 输出与依赖

输出 `支架参考复算.json / 计算依赖.json / 依赖复算.json`。按组、物理段和系统保留来源、方向、共架身份、取整层级、事件净增、构造、各口径副数、构件长度m、钢重kg、连接件个/套、涂装kg与m²。系统汇总保留构件类型、表面处理、供装范围和数量层级，不把不同口径混成一个量。完整量有未决则null，另给已知小计；已知小计0不表示未知完整量为0。

折算副数和规则整数副数从既有graph执行；实际整数副数来自源记录唯一身份。型材缺单重只阻断质量；缺展开周长只阻断面积。构造变化不污染其他组、间距变化不保留旧派生值。原引擎核验旧确认凭据；无凭据旧current不会继承，来源/规则/数值指纹变化需要重审。

输出保留输入原字节、输入内容、脚本原字节、graph内容和来源文件指纹。business_adoption_allowed、official_adoption、human_approval均为false；原人工凭据声明另列为未由本入口核验。真实工程采用仍按专业和公共审批契约执行。

HTML继续用共享scene/view与 `build_qto_review_html.py`。支架数量只投影到唯一支架组对应的对象一次；共享成员引用组ID，不重复累计。HTML静态检查的线索退出2与真实浏览器离线行为分开记录，不能把静态线索直接报成已通过或浏览器失败。
