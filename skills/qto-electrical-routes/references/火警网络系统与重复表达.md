# 火警等网络的系统角色、代号与多平面表达（T34）

本入口从真实源图中性事实、点位适配实例账和本轮已识别的实际连接继续。复用 L1 追踪、T35 原段拆分、03 原图绑定、T36 依据分层和共享 HTML；不增加几何引擎、点位计数器或人工批准入口。模型负责读图判明角色、连接、适用图和项目设计代码，软件核对来源、约束、传播边界和参考复算。普通识图不要求用户逐对象批准后才运行，未决只阻断其依赖分支。

## 复用、通用新增和项目参数

| 层次 | 内容 |
|---|---|
| 已有复用 | 同源原图和完整实例身份、实际端口、trace/T35分段及路径、T32回路来源、T33桥架占用、T36标高/附加依据、03对象包与共享scene/HTML、T39唯一出口检查 |
| 本次通用新增 | 项目角色规则约束系统、真实文字与原边显式绑定、无分歧度2链传播、冲突和原边去向、按明确逐边决定导出选定工作台账 |
| 留在项目输入 | S/D/F/B/C等代码含义、设备角色解释、设计规格根数、主图适用范围、端点查找半径、桥架比较带宽、相似度门槛和主次表达解释 |

800mm设备半径、200mm桥架带、50%端点相似度或某张图为主图均不是通用事实。本入口没有这些默认值。层高减安装高不能自动代表实际端口之间完整竖向；未画模块连接、竖向、端接和预留没有依据时保留 null/未决。

## 1. 系统角色与代号入口

```text
python skills/qto-electrical-routes/scripts/infer_electrical_network_roles.py --cad-manifest <本轮中性事实/CAD中性取证清单.json> --request <系统角色请求.json> --output-dir <新的系统角色结果目录> --build-review
```

请求 schema 为 `qto-electrical-network-role-request/1.0`：

- `network_request`：完整的 `qto-electrical-route-network-request/1.0`，直接沿用[T35契约](无回路号混连网络拆分与归属.md)。实际连接的 from/to、端口、回路依据、经由、分段参数和原图范围在此给出；不要求调用者预填全部原子分段。保持 `trace_request.unit.declaration` 原值。源图、manifest及流身份变化拒绝旧请求。
- `point_instances:{path,sha256}`：点位适配器真实生成的《点位唯一实例计数输入.json》。核验 `geometry_review` 实例集指纹及源图SHA。每个角色绑定引用的实例必须与实际端口的完整 `instance_path`、源图SHA一致。匹配但工作包不完整时继续合法子集并公开未决；凭据不匹配直接拒绝。
- `endpoint_role_bindings:[{object_key,point_physical_id,roles,source_ids}]`：当前源图识别的设备角色及依据，角色不由设备名称、块名或图层名猜出。`point_physical_id` 保留点位原值；设备角色可对应多个系统，不能静默选一个。
- `project_role_rules:[{id,roles,systems,source_ids}]`：项目图例/系统说明文字所支持的角色组合和候选系统数组。双方端点系统候选取相容部分；冲突和未知保持未决。
- `connection_system_bindings:[{connection_id,system,source_ids}]`：需要从多个相容系统中继续消解时使用的本轮有源解释。它不能覆盖有据端点角色冲突。
- `connection_contexts:[{connection_id,building,floor,revision,scope_id,sheet_id,source_ids}]`：当前关系的实际适用范围。任一字段未知时该关系保留未决，不能跨楼层/版本/范围传播。
- `design_codes:[{id,expression,text_source_ids,components}]`：真实设计代码表文字及模型对其的解释。`components` 每项为 `{system,kind,spec,parallel_count}`；kind为wire/cable，根数必须显式正整数或null，不默认三根、一根或芯数。表达式可为 `2S+2D`，各成分分别解释且按对应系统接入，不能将总线、电源合成一个系统数量。
- `text_edge_bindings:[{id,text_source_id,expression_id,source_ranges,basis_source_ids}]`：文字必须在原图真实存在且恰好为该代码表达式，`source_ranges` 为本轮T35原子区间 `{source_id,part_index,fraction_range}`。每条绑定带判图依据；不按最近距离自动确认。原区间需要进一步切分时先使用T35现有分段参数，不能以部分重叠扩到整条边。只有默认条款而无边旁代码时，不伪造text绑定；由项目在既有 `circuit_specs/segment_parameters` 显式采用条款并保留来源。

先运行既有T35获取原子边，再用公共端点图整理原子端点邻接。仅无分歧度2链、相同系统/回路/完整上下文传播；分支、断点、不同语境、未知身份停止。当前传播端点并点为0，只认精确相接，数值近似接触保守保留未决。曲线端点只作为邻接载体，测长始终为T35原曲线复算量，邻接载体弦长不参与计量。多种代码落在同一可传播链时整链保留冲突，不按距离或顺序选择。

本入口不根据角色或代码制造回路编号。`circuit_id` 须来自本轮源图已识别连接或已有T32结果的回路身份；无编号仍可输出原边、系统候选和代码，完整导线量留未决。项目内部追溯ID与图上实际编号分列，内部ID不显示成真实设计编号。设计代码与已有回路规格/根数冲突时相应分段参数置未决，由既有T35继续保留已知部分。

### 输出与实际CLI链

`网络系统角色结果.json`（`qto-electrical-network-roles/1.0`）保留点位原始物理ID、完整实例来源、geometry_review、系统角色候选、每条原边、代码种子、传播和冲突。原坐标 `source_points` 与米制端点分列；没有配准转换时不伪造比较坐标。

`既有网络计算请求.json` 是可直接消费的T35请求：代码解释写成原接口 `circuit_specs[].segment_parameters` 的原段约束，原回路上下文/端口/关系保持。CLI实际再次调用 `partition_electrical_route_network.py`，比较其结果与内嵌复算一致；其 `路径台账.json`、reference计算、原图scene/HTML均来自既有入口，不复写算法。`实际调用回执.json` 逐条保留真实子进程退出码、stdout/stderr；子0不能覆盖父层未决3。

`--build-review` 在T35最终scene上补角色、代码与来源属性，另存T35原场景检查，再调用共享 `normalize_view` 和HTML生成器。`火警网络场景检查.json` 记录投影前后FP、最终view/HTML SHA及解包后规范身份；不会拿投影前PASS冒充最终状态。离线页面可点选查看完整角色、传播种子、数量未知与依据。

### 既有T32/T36/T33/03接续

T32已识别回路号、端点和规格仍先按[系统图与桥架候选取证](系统图与桥架候选取证.md)对账，再放入T35原 `connections/circuit_specs`；本入口既不重抽表格，也不把设备类别当回路号。其真实来源继续留在 `circuit_source_ids/source_ids`。

可选 `downstream_requests:[{id,kind,request:{path,sha256}}]` 实际执行准备好的原接口，输出和退出码独立记录：

| kind | 原入口与用途 |
|---|---|
| `paths` | `calculate_electrical_paths.py`，读取同项目 `qto-electrical-path-ledger/1.0`；已明确竖向用T36 `elevation_difference/elevation_link`，假定/未画连接依原层级列段 |
| `objects` | `bind_electrical_objects.py`，原图/manifest SHA须相同，按03实际端口和原曲线绑定；可继续build-review |
| `trays` | `route_circuits_on_trays.py`，原图/manifest SHA须相同，T32回路及T33桥架来源按原请求核验，输出既有path_ledger/shared_path_usage |

`id`为本轮接续的安全文件名，不能含路径分隔符。每个请求真实SHA绑定，来源前后复核。下游路径不是从设备半径、安装高度或桥架带自动补出的；未准备好有据请求时不强行接续。桥架物理长度与每根线缆占用继续分别计量，不新增设备点位数量出口。

## 2. 多平面非几何重复表达

```text
python skills/qto-electrical-routes/scripts/match_electrical_network_expressions.py --request <多平面表达请求.json> --output-dir <新的表达选择目录>
```

请求 schema 为 `qto-electrical-network-expression-request/1.0`。`expressions` 每项：

- `id`、`role_result:{path,sha256}`、本表达的 `connection_ids`；单表达须处于同一楼栋/楼层/适用版本/范围/图页/系统/回路。不同表达不要求几何走法一致。上下文从角色结果继承，不允许另填来覆盖。
- `applicability:{current,basis,basis_source_ids}`：模型有据核对本图适用性。current只能true/false/null，未知或失效不能选主。
- `endpoint_identities:[{object_key,identity_key,basis,basis_source_ids}]`：保留真实点位物理ID、源SHA及完整路径；identity_key仅为本轮有源工作解释，不覆写真实 physical_id。缺身份仍待核。可选 `{t16_result:{path,sha256},pairing_id}` 保留已有T16配对的来源与 `working/unreviewed`，不升级为人工证明或正式同物。

导出与逐边规格比较仅使用所选连接上下文、系统、回路及范围内的台账行；共享几何上的其他回路不随同导出，也不能替所选回路填补未知覆盖。同回路共边的附属长度也按原请求的 `connection_id` 选择，未选连接的端接或预留不混入。原边及原始各回路数量继续保留。T16配对须由该配对一侧的 `source_key` 对应当前权威源SHA、中性清单SHA、适用版本和完整源实体/实例路径；来源目录中另有当前图或只有同号句柄、交换DXF相同，均不能代替该绑定。

候选约束为同层、同适用版本、同实际范围、同系统同回路、有据物理端点身份以及规格根数。相同设备集合本身不证明线路同物；并行线路、不同规格/不同根数、不同回路不能合。工具不使用端点百分比自动扣量。

只有本轮明确的 `decisions` 才可选择工作主表达：

```json
{
  "id": "本轮有据工作决定",
  "primary_expression": "主表达",
  "secondary_expression": "次表达",
  "role_result_sha256": {"主表达": "完整SHA256", "次表达": "完整SHA256"},
  "basis": "源图本轮适用性及线路表达判断",
  "source_refs": [
    {"expression_id": "主表达", "source_ids": ["原图依据"]},
    {"expression_id": "次表达", "source_ids": ["原图依据"]}
  ],
  "edge_pairs": [{"primary_edge_id": "本轮原子ID", "secondary_edge_id": "本轮原子ID", "basis": "逐边对应理由"}]
}
```

决定必须绑定两侧最新角色结果SHA；旧来源、范围外原边、主次链/环、多重认领直接拒绝。原边多对一可表达不同分段，但其实际长度不相互证明，也不按次图近似网络计主图线长。逐边规格/根数未知或冲突不执行该边处置。原边全量保留 `edge_dispositions` 和原数量快照；未对应边不丢、不填0，继续列已知参考和未决。

### 工作层唯一出口和对账

`多平面网络表达结果.json` 保留原始两侧边、原数量、候选约束、每边主次去向、理由及覆盖。`selected_working_ledger`/`选定工作路径台账.json` 是新建的既有路径契约，仅把明确次边交由所选主边代表；未对应边仍留工作台账并加 `expression_correspondence_unresolved`，已知量可继续，完整量为null。所有源成果不变，`source_quantity_mutation=false/quantity_mutation_allowed=false`，不自动认定真实线路同物。

CLI实际调用 `calculate_electrical_paths.py`，保存 `选定工作数量复算.json`，再导出既有 `qto-package-quantity-rows/1.0` 成果行和 `qto-package-reconciliation/1.0` 对账请求，实际调用T39 `qto_coordination.py handoffs`。内部工作出口ID明确标识为内部；实际原图版本、完整原边来源与物理ID另列，不把内部ID冒充设计编号。未给完整设计/清单基准时 `complete=false`，T39维持UNVERIFIED/退出3；不伪造接收方确认或工程全量验收。原边守恒和所选工作出口完整基准是不同检查，不能互相代替。

所有入口 `official_adoption=false/business_adoption_allowed=false/human_approved=false`。返回0表示本范围工作候选或选定台账处理完成，3表示有合法未决（包括T39完整基准未核），2表示来源/输入/执行错误。匿名实际DXF、真实点位适配、CLI与离线HTML交互只证明通用接口和开发行为，不构成真实项目DWG全范围识图、正式工程量、人工复核、发布或安装验收。
