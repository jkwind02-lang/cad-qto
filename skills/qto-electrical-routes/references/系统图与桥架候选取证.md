# 系统图与桥架候选取证

这三个入口是通用能力增强：T38 说明条款取证、T32 回路表及端点对账、T33 桥架识别与沿网适配。不是对既有长度参考器的 bug 修复，不自动建立项目规则或正式采用。顺序为说明适用范围 → 系统图回路身份 → 桥架物理身份 → 已核回路沿网。

## 共同输入与状态

四个执行脚本位于本专业 `scripts/`，均使用：

```text
python <脚本> --cad-manifest <CAD中性取证清单.json> --request <请求.json> --output <新版本结果.json>
```

读取中性布局图元流和块定义流，检查完整 WCS 几何契约、身份冲突、流哈希及原始权威文件哈希；结束前再次核对。上游候选文件必须用 `{path: 绝对路径, sha256: 内容哈希}` 绑定，原图与候选依赖在本次执行前后保持一致。旧输出不覆盖。

共同字段：`layout`；`unit: {factor_to_m, basis}`；`expand_blocks` 为本轮要展开的块名（递归展开仍受此白名单约束）；`opaque_blocks` 是明确只保留实例、不读取内部文字/曲线的图符块，不能借此声称内部已覆盖。未展开块、缺几何、未配对和跨范围均留待办。源身份采用 `CAD-句柄/块名/CAD-内部句柄` 的实例路径，不按块定义句柄认同物。

工程单位已在中性清单明确时，复用公共单位换算核验，不能将根数或倍率混进换算。单位未知时，T33 须给 `unit.declaration`：`raw_unit/source_ids/source_excerpt/geometric_corroboration`，复用公共单位原文与几何佐证校验；不能只填一个“按毫米”字符串。图示坐标单位与标注值单位分开。

纯文字 T38/T32 可用 `unit: {mode: "cad_coordinates", basis: "仅文字结构取证…"}`；此时请求坐标字段后缀全部改为 `_cad`，如 `bounds_cad/columns_cad/row_tolerance_cad/table_extent_cad`，结果亦用 `_cad`，`coordinate_unit=cad_unitless`、`measured_length_allowed=false`。不得把这种原始坐标当米或用作 T33 路径长度。

结果 `CANDIDATE_ONLY`、exit 0 表示本次请求范围内没有待办；有待办为 `REVIEW_REQUIRED`、exit 3；契约/来源无效为 `INPUT_REQUIRED`、exit 2。这些都不是正式采用凭据。所有结果 `business_adoption_allowed=false`、`official_adoption=false`。未完成不写零；图纸全局完整性不能由当前框选无待办证明。

## T38：extract_design_clauses.py

请求 `schema=qto-design-clause-request/1.0`。`regions` 每项有 `id/bounds_m/text_layers`；文字来自本次中性 TEXT/MTEXT，不能输入手写条款代替。支持已给列区间 `columns_m:[[xmin,xmax],…]`，或 `column_gap_m` 按条号起点聚成候选列；后者需按本图排版校准并复核，重叠区域/列拒绝。`clause_start_pattern` 可按当前条号画法设置。每列按 Y 降序、X 升序重排，保留换行、例外、分期原文及每个源句柄。无条号前导/续页文字仍保留，但列待办；非水平文字不自动旋转解释。跨页续条和复杂表格内说明需模型回读源图后处理。

每个 region 必有 `applicability: {basis_handles, targets}`。`basis_handles` 必须能回读到实际说明文字；每个 target 必有 `building/system/phase/revision`。明确全域填 `*`，未知填 `null` 并列待办。范围取值是模型依据源句形成的结构化事实，脚本保留原句供回核，不靠文件存放目录、图号前缀或关键词自动推适用。

`packages:[{id,scope:{building,system,phase,revision}}]` 与 `executions:[{package_id,clause_id,disposition,basis}]` 可做多包对账。`disposition` 为 `applied/not_applicable/pending`；非 pending 必须写依据。每一条执行声明都进入 `package_checks`，保留包范围、条款范围、范围源句及声明原依据。显式范围适用但未执行/被判不适用的列待办，同条款多包差异单列。范围外不强制执行，但若声明 `applied`，仍报“范围外条款被执行”；范围外明确 `not_applicable` 为合法对照，适用范围未知的声明保持待办。输出条款、源句、说明文字覆盖差集及多包执行差集；不自动把条款译成型号、根数或安装量。

## T32：extract_electrical_circuits.py

请求 `schema=qto-electrical-circuit-request/1.0`。必填 `bounds_m/text_layers/table_line_layers/row_tolerance_m/table_extent_m`，其中 `table_extent_m={left,right,up,down}` 是从表头向四侧的候选搜索范围；`circuit_pattern/spec_pattern/box_title_pattern` 按本次图面命名确定。`header_pattern` 默认“回路编号”；`row_patterns` 支持 `spec/destination/upstream/state/count/method/control_code/control_spec/control_count`。不能直接输入已编好回路行冒充文字抽取。

每张表由真实表头建立，右界截在同排下一表头前；列界优先使用横跨表头的实际竖表线，缺表线才保留按列位的候选界。并列表、列标签多候选、箱标题缺失均留证据。字段带文本源句柄及 `field_binding_status=table_cell_candidate_requires_review`。控制电缆偏列时，若原图 LEADER 首端落在目标单元格、末端在文字容差内，或无分支LINE引线链的另一端唯一落在目标单元格，按引线列归属并保留引线来源；`leader_layers/leader_text_tolerance_m` 必须按本图指定，`leader_snap_tolerance_m` 可显式设置端点并点容差。LINE引线分支/闭环或多引线不能唯一判断时，不据最近文字强定。

`design_clauses` 绑定 T38 结果，同时给 `effective_scope:{building,system,phase,revision}` 和本图 `scope_basis_source_ids`；自动列出适用条款 ID，源句和例外继续由专业回读，不自动执行换型。未绑定说明时仍可提取表格，但明确规则适用性未闭合。

`endpoint_candidates` 每项 `id/label/physical_source_id/label_source_ids/scope_id/binding_basis`；物理来源必须是本图真实 INSERT，标签须在本中性文字回读。终点关系不按距离自动选。`confirmed_bindings:[{circuit_id,endpoint_id,basis_source_ids}]` 只接受同范围同标签候选；同名多实例保留全部。`endpoint_instances` 保留实例来源，沿网阶段若已有已选终点，不允许静默换成另一个原图或另一个物理实例。

`n#a` 从实际控制编号行抽取，`control_code_pattern` 可按本图代码格式设置。每条 `control_links` 保留父箱/回路、源文字、同范围同代码物理候选及歧义；候选若给 `source_box`，还须与本回路箱一致。不因短号相同认同一物理终点，不把动力电缆规格或根数复制给控制电缆。确认单代码可在本回路绑定中给 `control_endpoint_id`；多代码用 `control_endpoint_ids:{代码: 实例ID}`，均需源依据。未知控制规格/根数为 null 并留待办。

`endpoint_reconciliation` 逐物理实例区分 `selected/candidate_unselected/excluded/unreferenced`。只有有据选定的实例才进入 `consumed_endpoint_ids`，有引用但未确认的候选仍在 `unconsumed_endpoint_ids`。`endpoint_instances_not_in_ledger`、未引用/被排除差集和待办保留实际物理源、标签句柄、范围、供电箱及对应行。`endpoint_candidate_checks` 保留同名候选被范围或供电箱排除的原因和两侧来源，不把“输入里原样保存过”称为已对账。

已解析行的本箱、引自、去向直接生成 `parsed_box_relationships/box_upstream_checks`，互证箱到箱出线与接收箱的上级声明，并列 `upstream_uncovered_boxes`；不要求重复手填这些已有事实。矛盾保留双方行、状态/分期和源句柄，不据此改设计或补根设备。出线行“引自本箱”只说明该出线来源，不能倒推本箱的供电上级；没有本箱上级声明也没有入线事实时，单列 `boxes_without_parent_claim_in_scope`，不冒称上级关系完整。

`feeder_rows` 还可补模型从其它当前干线表/系统图取得的显式互证事实：`box/circuit_code/upstream/destination/source_ids`。脚本核引自/去向冲突及未入回路台账的出线；`expected_boxes` 列出应覆盖的箱身份，不由少量已解析回路倒推完整配电系统数。已有上级声明却没有相应出线覆盖、出线指向本箱但本箱缺上级声明，均保留来源待办；表外上级不凭名称猜根。

原八类验收分别保留：

1. 表头数与实际解析数、漏表差集。
2. `~` 等省略列保留原文字与待办，不猜展开数量。
3. 同排并表截界、表线列界、原生引线偏列绑定及行来源。
4. 取消、二期、预留、备用及箱上方共用范围说明分列状态；状态不能被当正常回路消去。
5. 引自、去向与干线互证冲突。
6. “预留/备用”不作为平面设备端点。
7. 未入台账规格文字、未对入的 UPS 等出线。
8. 预期箱和上级对应覆盖差集；同箱同回路重复身份不静默合并。

未知根数为 null，不默认为一根。源图笔误、重名、回路表/平面文字不一致仍需专业判断，不能由列位算法自改设计。

## T33：recognize_cable_trays.py

请求 `schema=qto-cable-tray-request/1.0`。必填 `bounds_m`、至少一种 `center_layers/edge_layers`、`pair_tolerance_m/parallel_angle_deg/geometry_z_tolerance_m/width_range_m`。支持双边线和中心线+边线；块内曲线用本实例 WCS 变换。三条以上边线有多重配对时不按最窄间距任取；局部重叠只保已识别段，边尾留待办。圆弧、弯通/三通实物、竖向构造、支架不会从平面线自动补数。

双线/中心线配对同时核实际 INSERT 实例上下文；两个不同物理块实例即使复用定义句柄、坐标完全重合，也分别保留稳定源路径与候选，不跨实例配边或几何去重。跨越范围的每条源线在 `coverage.scope_records/crossing_source_ids` 和待办中保留，不硬裁成完整段；完全框外的线逐源标为 outside 合法排除。

`annotation_layers/annotation_pattern/annotation_radius_m/annotation_width_factor_m` 必填。模式可有命名组 `spec/width/elevation`，宽度标注值按显式系数转米。实际 LEADER 用 `leader_layers/leader_text_tolerance_m` 定位箭端和文字端；无分支LINE链保留两种方向候选，再由文字端和目标段的唯一空间关系约束。分支/闭环/多目标保留待办；仅邻近文字只给候选，不自动取最近规格。显式 `annotation_bindings` 必有 `segment_id/text_source_id/basis_source_ids`。

`attribute_tags:{spec,width,elevation}` 可按实例真实属性名读取：实例 attribute 值与 ATTDEF 默认文字分别保留；默认值不替代实例属性。独立 width 属性输出 `width_attribute_m/attribute_width_evidence`；`attribute_width_factor_m` 可独立声明，未另给时只沿用用户已显式声明的 `annotation_width_factor_m`，不内置毫米。非正数、多值或与规格/量得宽度冲突保留待办；可闭合时输出 `effective_width_m`。明确实例属性或有据标注已给宽度时，缺少边线不是未知宽度；多重几何配对仍不由此猜选。属性/旁注/量得宽度/标高冲突逐项待办。`elevation_bindings` 每项 `segment_id/elevation_m/datum/basis_source_ids`；CAD平面图元 z 不自动当工程标高。每段稳定 ID 绑定实例源路径及几何，输出真实起终 WCS Z、宽度、规格、标高候选与冲突。

## T33：route_circuits_on_trays.py

请求 `schema=qto-circuit-on-tray-request/1.0`。绑定 `tray_candidates`、`circuit_candidates` 的路径和哈希，给 `project_id/scope_id/snap_tolerance_m/endpoint_tolerance_m/equal_length_tolerance_m`。

`tray_confirmations` 每项含 `segment_id/physical_id/width_m/spec/datum/basis/basis_source_ids`。不能重复确认同一物理桥架。识别阶段每条未决须在 `resolved_problems` 逐项写明确处理依据，未闭合段不入网。标高必须选择：

- `elevation_mode=wcs_geometry`：采用本次已核三维几何，原起终 Z 都保留；
- `elevation_mode=drawing_elevations`：分别写 `start_elevation_m/end_elevation_m` 和各自 `start_elevation_source_ids/end_elevation_source_ids`。不能用一个标高覆盖真实竖向段。

`circuit_bindings` 按 `circuit_id` 给 `system/basis/basis_source_ids/from/to`。只处理正常候选、规格和正整数根数已明确的回路。from/to 不是手填任意坐标：须给 `manifest_sha256/physical_source_id/physical_id/instance_path/port_source_id/locator/basis/basis_source_ids`。`physical_id` 等于本图实际 INSERT 源身份；`instance_path` 匹配展开实例；端口必须在该实例内部，从实际 `POINT`（`locator=point`）或连接线端（`line_start/line_end`）读取 WCS 坐标。可写 `point_m` 进行坐标一致性核验。HATCH中心、文字、框中心、单独插入点没有连接口资格；同句柄异源、借相邻同名实例端口、虚构坐标均拒绝。

同基准三维网络复用公共线段图并点、分量和 T 接取证，在真实分支与端口投影处分段；X交叉不自动连。路径列明每个物理段的遍历区间。断网、多条等长和端点离网保留待办，不退直角估。出桥架末段距离与网络长分开，不自动补线。

结果有物理桥架 `channel_items`、各回路各根电缆 `circuit_items`、`shared_path_usage`、图节点及 `path_ledger`。桥架物理长按本次确认身份计一次；每个回路的每根电缆独立累计遍历长度，不能对所有回路全局去重。网络路径依据始终 `network_model`，不冒充 `actual_drawn_path`。显式竖向边保留为 vertical，斜边为 offset；没有提供完整端接/余量链时，输出只是沿网分量，`complete_quantity=false`、未决部分另列。路径台账可交已有复算器继续参考计算，不据新 schema 自动升级正式量。

## 边界及项目接续

新增接口不内置项目路径、图号、坐标、箱名、型号、支架模型或端点相似度阈值。框选范围、列位容差、图例、属性名、适用范围及同物判断均要来自当前项目。T34火警系统推断、T35混连拆分、T36依据分层、T37支架参数增强不由本次接口顺带宣称完成。
