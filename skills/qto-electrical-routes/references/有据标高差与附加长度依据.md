# 有据标高差与附加长度依据

这是 `qto-electrical-path-ledger/1.0` 的兼容增强，用于已识别路径的参考复算。它补充有据标高差和 extras 的结构化依据；旧枚举被拒绝不等于旧长度算法错误。本接口不自动识图、不证明原图完整，也不授予正式采用资格。

## 路径依据与标高差

`paths[].length_basis` 为 `actual_drawn_path`、`network_model`、`elevation_difference`、`device_distance` 或 `assumption`；声明后必须有非空文字数组 `basis_ids`。前两类沿用原有语义；`elevation_difference` 是有据纯竖向路径，不是任意公式的通行类别。`device_distance`、`assumption` 始终为方案暂估。

`elevation_difference` 行除通常的 `id/from_node/to_node/role/length_m/source_ids` 外，必须给：

| 字段 | 约束 |
|---|---|
| `role` | 只能是 `vertical`；有水平位移的斜线或折线另按实际路径分段 |
| `system/scope_id` | 非空；每个采用该段的通道/回路必须具有完全相同的系统与适用范围 |
| `elevation_link` | 完整 `qto-elevation-link/1.0` 事实对象，复用公共 `qto_elevation_facts.evaluate_elevation_link` |
| `elevation_link.project_id/scope_id/system` | 分别等于台账项目及本路径范围、系统 |
| `elevation_link.from/to` | 各含 `fact_id/value/unit/datum_id/reference_id/measurement_kind/source_ids/basis/level`；`value` 未决时为 `null`，另写 `status: unresolved` 和 `issue` |
| `elevation_link.route` | `kind: vertical`，并有 `route_id/source_ids/basis/level`；来源事实登记这两个端点之间的纯竖向路线，不能只由楼层差反推路线形态 |
| `elevation_link.sources` | 来源目录各含 `id/sha256/locator/facts`。可选绝对 `path` 提供时实际核验文件哈希。嵌入 facts 是模型的来源解释，仍须随证据包保留原资料 |
| `elevation_link.endpoint_bindings.from/to` | 各含 `fact_id/reference_id/entity_id/port_id/source_ids/basis/level`；真实实体及实际接线/连接口各有稳定 ID |

每个端点绑定引用的来源 `facts` 必须含相同 `id`，`measurement_kind: electrical_endpoint`、`reference_id/entity_id/port_id` 与绑定逐字段相同；`reference_id` 须与路径的 `from_node/to_node` 相同。源事实与绑定的 `level` 均为 `confirmed/inferred/scenario`，绑定不能提升来源层级。不同端点不得复用同一标高事实。

所有实际参与的标高、测点转换、换算操作数、基准转换、路线形态和实体端口事实，都在它们所引的 `sources[].facts` 中逐项登记相同的 `project_id/scope_id/system`；`basis_ids` 覆盖这些事实 ID，路径的 `source_ids` 覆盖其真实引用来源。只有任意两个数字、若干非空 ID、来源目录外的引用、来源值与输入值不符、身份或适用范围不符，都不能升级为有据标高差。

直接电气中心测点用公共类型 `equipment_port_center`，这里既可表示设备接线口中心，也可表示已识别桥架/母线的连接口中心，身份仍由端口来源事实证明。`pipe_center` 不用作电气端点。箱底、设备底、结构楼面、建筑完成面等只是参考点，不能自动成为接线口。参考点使用公共 `finished_floor/structural_floor/other_reference` 类型，并通过有据 `centerline_conversion.method: signed_offset` 及带符号 `offset` 转换；转换后的 `target_reference_id` 必须闭合到本路径实际端点。实际转换还须在来源中登记 `from_fact_id/from_reference_id/target_reference_id/datum_id/system/operand_fact_id`。

同一 `datum_id` 可直接相减。不同基准须给有源 `datum_transforms`（`z_to = z_from + value`），不隐含基准相等；缺换算时保留未决。归一化后 `Δz = z_to - z_from`，纯竖向长度 `L = abs(Δz)`；负高差允许，长度不为负。`length_m` 必须与复算值相符（绝对容差 0.000001 m）；零长不建立计长路径。

公共事实转换全部成立，且任何参与事实及端点均未达到 `scenario` 时，这一段为规则推算。有情景端点、情景标高或情景换算时，声明类别仍可记录 `elevation_difference` 以保留计算来源，输出的 `effective_length_basis` 为 `assumption`，按方案暂估。不能通过声明为 `inferred` 提升来源中的 `scenario`。

端口绑定的采用层级同时进入 `elevation_checks` 的 `quantity_level` 以及 `calculation_graph/calculation_run` 中有效 `route_length` 的层级。该可消费电气路线的层级上限是规则推算量：即使所有来源事实和端口采用均为 `confirmed`，有效 H 与路线出口仍是规则推算；含 `scenario` 为方案暂估，长度未决仍为未决量。`evidence_level` 如实保留 `confirmed/inferred/scenario`，不为收敛路线层级而改写来源等级。端口绑定记录、适用上下文和实际所引来源进入该计算节点的语义指纹；即使标高数值及路线层级不变，端口采用层级或合法身份解释改变也会改变指纹。原始标高和算术事实仍保持它们自己的层级，不能用原始算术事实的较强层级覆盖有效电气路线的采用边界。

有效但未决的标高输入须同时令路径 `length_m: null`。结果的该向 `length_components_each_m` 和全项 `length_m` 为 `null`；已知部分写 `known_length_m`，`unresolved_path_ids` 和 `pending_components: ["path:<路径ID>"]` 公开缺口。来源身份错误等非法输入直接报 `INPUT_REQUIRED`（CLI 退出 2），不会偷偷采用原先填写的长度。未决不是零。

## 预留、端接与 extras

每项 `extras[]` 仍给 `id/node_id/length_each_m/basis/source_ids`，`node_id` 只能指本项起终端；中间预留独立分段。新输入再给 `length_basis/basis_ids`：

| `extras[].length_basis` | 含义及层级 |
|---|---|
| `project_rule` | 项目明确端接、预留等条款，依据号指具体适用条款；规则推算 |
| `actual_drawn_path` / `network_model` | 已画或沿网得到的明确端部长度；规则推算 |
| `device_distance` / `assumption` | 设备距离方案、经验或假定的端接/预留；方案暂估 |

`basis_ids` 声明后必须为非空文字数组；来源与条款适用仍由模型根据原图/项目文件判定，脚本不扫描 `basis` 中的中文关键词。附加率不默认存在；本接口仍输入有依据算出的每根长度，须在 `basis` 中保留百分比、适用长度、算式和来源。没有条款、端接长度或附加率时不自动填零。

整项 `quantity_level` 取路径和 extras 最弱依据。含任一 `device_distance/assumption` 则为方案暂估；完整分类且没有弱项才可为规则推算。`quantity_basis` 反映包括 extras 的最弱已知类别，`length_basis` 仍只反映几何路径类别；`extra_by_basis_each_m` 单列每根附加量，避免误认为路径长度。

旧 paths 缺 `length_basis` 时，沿用已发规则的数值与层级，并保留 `length_basis_missing` 提醒及 `basis_classification_complete: false`；不得据此宣称依据完整。旧 extras 无分类时保留原数值，不猜其类别：`length_basis_missing_extra_ids` 和 `extra_length_basis_missing` 披露缺项；没有已知弱项时 `quantity_level/quantity_basis` 为 `null`，有已知弱项时仍可判为方案暂估；`basis_classification_complete` 为 false。调用方不得把 `null` 层级回填成规则推算。旧 `route_items` 参考格式及四种路径类别继续读取，不改原有长度算式。

## 有据局部量与完整方案互斥

有据水平段/有据 H 只是所述边界内的量。端接、绕行、额外竖向等未闭合时继续填 `pending_components`，依据类别不会清除未决，也不会把局部安全小计升为完整三维路径。`complete_quantity` 只表述已声明路径范围的完整性；调用方必须正确申报范围和未决，不因它为 true 就认为整张图已完备。

同一物理对象若需同时表达“有据局部”与“含假定的完整方案”，在 channels/circuits 中分两项：保持相同 `physical_id/scope_id/system/kind/spec/parallel_count`，赋不同 `id/path_scheme_id`，并声明同一非空 `alternative_group_id`。有据项保留它的 `pending_components`，完整方案各项仍按最弱依据分级。同组至少两项，每项方案 ID 唯一；没有互斥声明时，重复 physical_id 仍报错。

结果 `alternative_groups[].combination_policy` 及对应 `summary` 行为 `mutually_exclusive`。汇总为每个方案单独一行，不提供可相加的组总长；下游禁止再把这些行求和成同对象数量。回路不能同时引用同组互斥通道，所选互斥通道的 `path_scheme_id` 必须与回路一致。`scope_claims` 仍只比较同一实物、范围与 `path_scheme_id`，有未决分量的局部项不与完整总长下界比较。不同互斥方案不互套下界。

所有结果保持 `official_adoption: false` 和 `business_adoption_allowed: false`。定向合成及 CLI 验证证明接口、计算和状态约束，不能代替真实 DWG 识别、工程量验收或人工正式采用。
