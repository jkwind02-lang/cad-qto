# 高影响假定裁决与相关范围重算

本流程由可执行脚本 `../../_qto-shared-evidence/scripts/qto_impact_recompute.py` 提供。沿用 `qto-review-workflow/1.0` 的 `decision_id`、原有 HTML 保存批注及 reader 交接；不再按同名、分类或成员重叠创建另一套事项身份。源图普通识别、路径补证与首轮可继续的计算仍由专业执行，不能把普通识图责任交给用户。

## 首轮工作及集中队列

先完成有依据的分支。低影响、可回算项写明内部暂用口径后继续；决定性资料缺失的分支保留多方案或未决，不按零闭合。将高影响事项写入已有 `review_workflow.decisions`：`recommendation` 为推荐，`business_options` 为替代，`evidence` 为来源，`scope` 为对象及排除范围，`impacts` 按单位、数量层级、范围保留 `value` 或 `min/max`，未知用 `null`。`impact_context` 补充首轮状态、未确认内部工作口径和决定性暂挂成员。

```text
python -s skills/_qto-shared-evidence/scripts/qto_impact_recompute.py 请求.json --queue-only --output 高影响队列.json --queue-markdown 高影响队列.md
```

队列排序显式列出决定性缺口、未知影响、系统数、回路数、依赖传播、互斥和同单位内数量位次。未知不按零；不同单位不相加。`same_source_groups` 可以集中展示同源小事项，但每个成员的 `decision_id`、范围、例外、原影响数量及位次完整保留。队列的可继续范围是专业提交的当前工作安排，不是脚本已完成读图的证明。

## 请求与变更边界

输入 `schema` 为 `qto-impact-recompute-request/1.0`，必要字段如下：

| 字段 | 内容 |
|---|---|
| `view` | 原 `qto-review-view/1.0` 或 `1.1`，开启已有审核事项工作流 |
| `feedback` 或 `handoff` | 原 HTML 保存的反馈 JSON，或原 `read_qto_review_feedback.py` 生成的完整 `qto-review-handoff/1.0`；交接内原答复及动作重新核验，不执行自由文字；仅生成队列时可省略 |
| `state.version` | 原专业输入版本，非空业务版本名 |
| `state.calculation_graph` | 可选，原 `qto-calculation-graph/1.0`；复用来源、规则、单位和人工复核凭据契约 |
| `state.networks[]` | 可选，`id`、`manifest_path`、`request`；每项是一个需要重识别的有证相关范围 |
| `bindings[]` | `member_key` 显式绑定当前复核对象；`node_ids/network_ids/system_ids/circuit_ids` 显式绑定专业输入和影响范围；`network_targets[]` 为该成员实际使用的 `{network_id,collection,target_id}` |
| `impact_context[]` | 以 `decision_id` 绑定 `internal_working_basis/first_pass_state/blocking_member_keys/exclusive_with_decision_ids/shared_source_id` |
| `decision_changes[]` | 专业根据用户方法答复准备的明确输入变更；不是执行用户自由文字或模型猜测的补丁 |

每个变更必须包含 `decision_id`、当前选择的 `business_option_id`、`expected` 和非空 `mutations`。`expected` 的四字段由本脚本 `--queue-only` 输出的 `before` 原样取得：`state_version/source_sha256/result_fingerprint/input_fingerprint`。每条 mutation 保留 `member_keys`、`target_id`、完整原行 `before` 和新行 `after`，新增/删除的一侧为 `null`。不按数组下标或显示名称匹配对象。

参数 mutation 使用 `kind=parameter`、`collection=node/source/rule`。节点只可变 `value/source_ids/rule_ids/quantity_level/basis/basis_ids/evidence/semantic_context`；公式、依赖关系、对象拆合不能伪装成参数变更。共享参数或依据传播越出声明成员时暂挂，尤其不能越过成员例外；需专业明确拆分或补全实际作用范围。

关系/归属 mutation 使用 `kind=relationship`、`network_id` 和 `collection=endpoint_objects/connections/circuit_specs`，稳定身份依次为 `object_key/id/circuit_id`。目标须在 `bindings[].network_targets` 中明确列出，mutation 的成员须等于使用该目标的全部实际成员，并全部通过本事项的例外/排除门；同属一个网络不构成目标授权。拟新增规格也须先按有据的现有受影响成员明确绑定，不能自动使新增物理成员继承共同答复。网络 `request.schema` 必须为 `qto-electrical-route-network-request/1.0`，原图指纹须在当前 view 来源中；参数结构见 `partition_electrical_route_network.py`。`trace_request.routes` 不接收手填替代路径。

## 真实专业重算

```text
python -s skills/_qto-shared-evidence/scripts/qto_impact_recompute.py 请求.json --output 输入变更与重算回执.json --queue-markdown 高影响队列.md
```

先复用现有 `normalize_view → validate_feedback → handoff_actions` 的适用性、版本、冲突、迁移和成员例外门。只处理当前明确采用/调整的业务方案。退回核查、未答复、草稿、方法同名、过期版本及新增范围不进入计算。两个变更指向同一输入目标时，两者均暂挂，不按新旧时间选一份。

参数实际调用 `recompute_qto_dependencies.recalculate`，包括来源/规则变化后的依赖传播、同值异依据失效和可核验人工凭据复用。关系变化实际调用 `partition_electrical_route_network.partition_network(manifest_path, request, base_path)` 重新识别相关网络，重建原段、对象和台账，再调用已有 `calculate_electrical_paths.calculate(ledger)` 并核对返回数量。适配契约为 `qto-impact-electrical-network-adapter/1.0`，只接受 `qto-electrical-route-network-partition/1.0`；模块缺失、契约变化或来源不匹配时，该分支返回未成功并暂挂，不能写成已完成语义重算。其他独立有效分支继续处理。

输出含前后输入版本/源指纹/结果指纹、每条完整 `input_diff`、作用范围与例外、真实前后计算值、受影响节点、移除/新增对象及回执。`before.result_fingerprint` 是答复时复核视图指纹，`calculation_result_fingerprints` 是本轮前后真实计算结果指纹；`after.result_fingerprint` 使用新计算结果指纹，并显式要求重新生成复核视图，不能把旧 HTML 显示的结果当作新结果。下一轮先更新视图，再重新生成队列取得新的 `expected`。

网络范围输入有任何语义变化，保守禁止该范围旧数量确认继承，即便数字相同；网络计算器不核验人工凭据，回执不会伪称已证实存在某个旧人工确认。无关网络只复用其未变输入指纹，不声称本轮核准过它的数量。需要更细的失效范围时，专业应先按有证的独立子网拆开 `state.networks`，不可凭同名继承确认。

本脚本生成可审阅的新本地输入版本和回执，不实际回填项目，不建立人工数量确认，不升级正式采用。输出 `RECALCULATED` 只表示执行了该请求的专业重算；`REVIEW_REQUIRED` 保留仍需处理的未决、冲突或失效，不能当作正式数量验收。JSON 业务状态与命令退出码分开核对：成功生成可审阅回执返回 `0`；输入损坏、输出重名等不能生成回执时返回 `2`。
