# 电气复核页审核视图接入

把电气已整理的审核表（`review_data\` 下的 items、extra、members、targets、issues、issue_links、issue_sources、buildings）接到公共复核页（1.1）。页面默认打开“成果”，列出本次全部条目（含清单外新增）和明细依据，审计清单只作对照；“欠缺条件与资料”从成果反推还要定的口径和要补的资料。通用说明见 [复核页：成果、欠缺条件与对照审核](../../_qto-shared-evidence/references/复核页待解决与对照审核.md)。

## 1. 步骤

1. 复制 [电气审核视图映射样例](电气审核视图映射样例.json) 到 `review_data\` 的上一级，改名为 `审核视图映射.json`；填项目编号和审计清单文件的名称、SHA256。
2. 转换并检查：

   ~~~text
   python ../_qto-shared-evidence/scripts/build_comparison_view_from_tables.py --mapping 审核视图映射.json --output 复核视图_r1.json --report 表格转换检查.json
   ~~~

3. 报 `INPUT_REQUIRED` 时看 `表格转换检查.json` 的 `problems`，按下节改表后重跑，不要改映射去绕过检查。
4. 通过后生成页面：`build_qto_review_html.py --input 复核视图_r1.json --output 电气复核页_r1.html --local-only --report HTML生成检查.json`。
5. 有图页和回图对象的包（例如已有项目视图的），加 `--base-view 已有复核视图.json` 并入。

## 2. 表格要满足的

- **图上无**：每条都要有检索依据。items 表的 `检索图纸`、`检索对象`（多个用“；”分隔）、`检索方法`、`检索命中数`（为 0 也写 0）必填；`未能读取`、`未覆盖`、`检索记录`（项目里检索记录的位置）、`检索说明` 可选。检索记录不全的，不能写“图上无”，改为问题条目。
  - 例外：检索记录规则（提交 e63fe30）生效前交付、又不回头补的成果，在映射的 `comparison` 里把 `legacy_search_evidence` 写成 `{"rule": "e63fe30", "note": "规则生效前交付，不回头补检索记录"}`。这些“图上无”可以不全，页面标“检索记录不全”，不转成未决或待确认。表里没有的检索列要从映射里删去，否则报“映射的列不存在”。新做的成果保持 `null`。
- **清单有误已修正**：`修正说明` 里写清修正了什么。
- **缺图**：`缺图说明` 里写缺哪部分图。
- **来源行**：`source_row_ids.csv`（单列 `row_id`）从审计清单原件逐行抽取，映射用 `row_ids_table` 指向它，来源行才是真正的双向核对。审计清单有多份原件时，在映射 `sources[].files` 里逐份写文件名和 SHA256。
- **明细单位**：members 表每行的单位必须与所挂条目的单位相同；不同的要改成同一单位，或拆到对应条目。
- **清单无量**：`差额` 可以写本次合计（按清单量 0 计），`差额率` 留空。
- **一致、多算、少算**：生成器按默认带宽判，计量单位 ±5%，台、个、套、组、座、系统、处、根、块、只须相等（样例的 `thresholds.consistent_band` 分写计量、计数，`count_units` 列计数单位）。表里写的结论必须与这条规则相同。审核时可以在页面上另设容差重新显示，不改数据。
- **问题涉及量多段**：一个问题影响几个单位的量时，加 `issue_impacts` 表（问题编号、数值、单位、说明），在映射的 `tables.issue_impacts` 里接入；数值为空时说明必填。
- **不确定内容挂问题**：有未决量、以暂估为主、缺图的条目，应在 issue_links 里挂到某个未关闭的问题上；没挂的会在检查报告的 `comparison_exceptions` 里列为“不确定条目未挂问题”，不拦生成，但应逐条补问题或说明为什么不用问。
- 单价、合价、金额影响列不读取，复核页只对数量。

## 3. 逐回路下钻

各包的 `cable_ledger.csv` 要在复核页里下钻到回路时，先补一列“挂到哪行明细”（填 members 表的 `member_id`），再在映射的 `tables.members` 里接入：

~~~json
"members": [{"path": "<包>/cable_ledger.csv", "constants": {"professional": "qto-electrical-routes", "category": "回路"},
             "columns": {"object_id": "回路编号", "detail_id": "挂接明细"},
             "quantities": [{"name": "水平长度", "unit": "m", "level": "规则推算量", "column": "水平"}],
             "attributes": {"起点箱": "起点箱"}}]
~~~

不按规格或楼层猜回路归属；没补列的台账不接入。明细行要按成员合计时，把它的 `aggregation` 写成 `sum_members` 并写 `member_quantity_name`（members 表加这两列，在映射的 `detail_rows` 列里接入）。

挂接可以单放一张表（`catalog_key`、`detail_id` 两列），作为 `tables.members` 的第二项接入。成员的数量项按映射 `quantities` 里写定的名称、单位和层级从成员表的列读取；现在还不支持按列取层级，也不支持从挂接表取数量。回路台账按回路分层级、数量写在挂接表里的，暂不能直接接入，留作后续。
