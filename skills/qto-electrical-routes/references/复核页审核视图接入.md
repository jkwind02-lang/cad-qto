# 电气复核页审核视图接入

把电气已整理的审核表（`review_data\` 下的 items、extra、members、targets、issues、issue_links、issue_sources、buildings，以及共性问题、做法、逐回路台账几张表）接到公共复核页（1.1）。页面默认打开“成果”，按楼栋、分部、品类列出本次全部条目（含清单外新增）和明细依据；“待解决问题”按问题性质列出还要定的口径和要补的资料，用共性问题答一类、解决一片；审计清单只作对照，偏差按本次依据是否充分归因，清单的问题按类型整组答复。通用说明见 [复核页：成果、待解决问题与对照审核](../../_qto-shared-evidence/references/复核页待解决与对照审核.md)。

## 1. 步骤

1. 复制 [电气审核视图映射样例](电气审核视图映射样例.json) 到 `review_data\` 的上一级，改名为 `审核视图映射.json`；填项目编号和审计清单文件的名称、SHA256。表里没有的可选列（例如检索记录、不计口径）从映射里删去，否则报“映射的列不存在”。
2. 转换并检查。已有图页和回图对象的包（例如 E-A-CBL2、E-S3 已有的项目视图），每份写一个 `--base-view` 并入：

   ~~~text
   python ../_qto-shared-evidence/scripts/build_comparison_view_from_tables.py --mapping 审核视图映射.json --output 复核视图_r1.json --base-view ../E-A-CBL2/review/E-A-CBL2_复核视图_r3.json --base-view ../E-S3/review/E-S3_复核视图_r2.json --report 表格转换检查.json
   ~~~

3. 报 `INPUT_REQUIRED` 时看 `表格转换检查.json` 的 `problems`，按下节改表后重跑，不要改映射去绕过检查。几份基础视图的问题组编号相同时，后并入那份的组号自动改为 `<文件名>|<组号>`，报告的 `renamed_groups` 列出改了哪些，`base_views` 列出每份并入的图页、对象和问题组数；图页编号或对象 `catalog_key` 相同时报错。
4. 通过后生成页面：`build_qto_review_html.py --input 复核视图_r1.json --output 电气复核页_r1.html --local-only --report HTML生成检查.json`。
5. 看报告里的 `mapping_warnings`：映射里写了、转换不认识的键（拼错的标准键、没声明的维度等）列在这里，没有读取，应改映射。再看 `comparison_exceptions`：“不确定条目未挂问题”“依据不足的偏差未挂问题”“问题未分性质”三类只提醒，不拦生成，应逐条补挂问题、补性质，或说明为什么不用问。

## 2. 表格要满足的

- **维度**：样例里楼栋是总览、分部是分级、品类取 `项目名称`；计算包号只作技术来源（`technical`），不进筛选和分类。
- **图上无**：每条都要有检索依据。items 表的 `检索图纸`、`检索对象`（多个用“；”分隔）、`检索方法`、`检索命中数`（为 0 也写 0）必填；`未能读取`、`未覆盖`、`检索记录`（项目里检索记录的位置）、`检索说明` 可选。检索记录不全的，不能写“图上无”，改为问题。
  - 例外：检索记录规则（提交 e63fe30）生效前交付、又不回头补的成果，在映射的 `comparison` 里把 `legacy_search_evidence` 写成 `{"rule": "e63fe30", "note": "规则生效前交付，不回头补检索记录"}`。这些“图上无”可以不全，页面标“检索记录不全”，不转成未决或待确认。新做的成果保持 `null`。
- **清单有误已修正**：`修正说明` 里写清修正了什么。
- **缺图**：`缺图说明` 里写缺哪部分图。
- **来源行**：`source_row_ids.csv`（单列 `row_id`）从审计清单原件逐行抽取，映射用 `row_ids_table` 指向它，来源行才是真正的双向核对。审计清单有多份原件时，在映射 `sources[].files` 里逐份写文件名和 SHA256。
- **明细单位**：members 表每行的单位必须与所挂条目的单位相同；不同的要改成同一单位，或拆到对应条目。
- **已定不计**：口径已定为不计的明细（例如按口径决定单定为二期的干线），members 表 `不计` 写“是”，`不计说明` 必填，`不计口径`（口径决定单编号）和 `不计问题`（已关闭的问题编号）至少写一个。这些行不计入条目的量，整条都不计的条目确认量写 0、其余层级留空。它们在对照里常落进“清单多计”，页面会在组内和整组答复界面标“含已定不计”并列出依据。
- **清单无量**：`差额` 可以写本次合计（按清单量 0 计），`差额率` 留空。
- **一致、多算、少算**：生成器按默认带宽判，计量单位 ±5%，台、个、套、组、座、系统、处、根、块、只须相等（样例的 `thresholds.consistent_band` 分写计量、计数，`count_units` 列计数单位）。表里写的结论必须与这条规则相同。审核时可以在页面上另设容差重新显示，不改数据。
- **问题性质**：issues 表的 `问题性质` 写八类之一（现行规则无法判断、有多种判断方式、缺图纸或资料、图纸矛盾或不清、范围分期或专业界面不清、按假设或估算计入、工具或方法限制、清单的问题），样例用 `value_maps` 转成代码。挂了共性问题的可以不写，写了要与共性问题相同。性质为“工具或方法限制”的同时登记插件问题，编号写进 `插件登记编号`。
- **共性问题**：别处也会遇到的口径写进 `common_issues.csv`（编号、性质、问法、情况、处理方、现做法编号、口径决定单编号、状态、楼栋）。问法写一般问法，不写某栋某项；编号不能与个别问题重号。个别问题的 `共性问题编号` 写它所属的共性问题；不经个别问题、直接归到这条口径下的条目写进 `common_issue_links.csv`（共性问题编号、条目编号）。已答复过的口径，下一轮同类挂到同一条共性问题，不再新开。
- **做法**：`issue_options.csv`（问题编号、做法编号、做法、影响数值、单位、说明）一行是一个做法的一段影响，问题编号可以是共性问题或个别问题；同一做法各行的“做法”文字相同；没有影响量的做法写一行、数值留空、说明必填。有做法的问题要在 `现做法编号` 写现在按哪个做法算；“有多种判断方式”的至少两个做法。
- **问题涉及量多段**：一个问题影响几个单位的量时，加 `issue_impacts` 表（问题编号、数值、单位、说明），在映射的 `tables.issue_impacts` 里接入；数值为空时说明必填。
- **不确定内容挂问题**：有未决量、以暂估为主、缺图的条目，以及含方案暂估量或未决量的偏差，应挂到某个未关闭的问题或共性问题上。
- 单价、合价、金额影响列不读取，复核页只对数量。

## 3. 逐回路下钻

逐回路台账按三张表接入，样例里都在 `review_data\`：

- `ledger_members.csv`：一行一个回路（`catalog_key`、包号、楼栋、箱号、回路号、规格、起点楼层、终点楼层、层级、图纸、依据等），只建对象。基础视图里已有同一 `catalog_key` 的回图对象时直接引用，不重建。
- `ledger_links.csv`：回路挂到哪行明细（`catalog_key`、`detail_id` 填 members 表的 `member_id`、`数量名`、`层级`、`数量`）。层级和数量按挂接取，一个回路可以挂几行明细、各带自己的数量。
- `ledger_detail_agg.csv`：明细行的汇总方式（`detail_id`、`aggregation`、`aggregation_reason`、`member_quantity_name`）。按成员合计的写 `sum_members` 并写 `member_quantity_name`；映射用常量 `member_table: circuit` 指向 `comparison.member_tables` 里的“逐回路台账”，页面下钻按钮就显示这个标题。

不按规格或楼层猜回路归属；挂接表里没有的回路不进下钻。明细写 `sum_members` 时，挂到它的回路数量之和必须等于明细的量，不等时报错。

## 4. 图面：各包用映射出图面视图

各包不再自己写 `review_view.py`，写一份图面映射，用公共脚本出图面视图（规则见 [HTML交互复核与批注](../../_qto-shared-evidence/references/HTML交互复核与批注.md) 第 7 节）。

1. 复制 [电气图面映射样例](电气图面映射样例.json) 到包目录的 `review\`，改名为 `图面映射.json`。样例按点位表 `fix.csv` 加走线表 `x\wire.csv` 写，路径相对 `review\`；图页取共用的 `共享事实\D###_图页台账.csv`。台账“状态”列里“现行、待核”归为平面是样例的写法，按本项目核定。
2. 生成并检查：

   ~~~text
   python ../_qto-shared-evidence/scripts/build_review_scenes_from_tables.py --mapping 图面映射.json --neutral-root <项目>/_中间/neutral --output <包号>_图面视图_r1.json --report 图面转换检查.json
   ~~~

   底图从中性取证清单登记的交换 DXF（`exchange_dxf`）还原，先核哈希；DXF 不在或哈希不符时报 `INPUT_REQUIRED`。报 `INPUT_REQUIRED` 时看 `problems`，改表后重跑。通过后看报告：
   - `tables[].unlocated` 按原因列未定位对象；`sheet_conflicts_unused` 是台账里编号重复、本包没用到的图页，转给整理台账的人。
   - `scenes[].restoration` 是本页看不出、须回原图的数目，`dropped_layers` 列大块里没画的图层。漏了和本包有关的建筑图层，在映射 `background.large_block_layers` 里补。
   - `scenes[].symbols` 是符号对账：本页符号数、已计、未计、同位置重复。“未计”和“同位置”不为零的，打开页面图面工具栏“符号对账”，点数字看红圈位置，核是漏计、重复计还是本来就不该计。
   - `checks.S-5.symbol_note` 出现，说明对象表没映射 `handle` 列，对账认不出已计的符号。
3. 各类表的写法：

   | 表 | 写法 |
   |---|---|
   | 箱位、命中、点位实例（`box_loc*`、`box_hits`、`x\ins.csv`、`fix.csv`） | 点，`x, y`；句柄作 `object_id`，同时映射到 `handle`（符号对账靠它认已计的符号） |
   | 走线、桥架（`x\wire.csv`、`tray_segments`、`tray_pairs`） | 线，`x1, y1, x2, y2`，`group_by: ["sheet", "handle"]` |
   | 系统图回路（`circuits.csv` 的 `col_x, table_y`） | 点，落在系统图图页上，与平面上的同一回路 `object_id` 相同 |
   | 米制或局部原点（`wire_cc*.csv`、`gnd_downcond.csv`） | 声明 `transform`；不声明就只能用句柄或标未定位 |
   | 运行时算出的路径或点（直角示意线、井间连线） | 由包脚本导出成表：线用 `points` 列（JSON 点列表），点用 `x, y` |
   | 按比例缩放画的图页（模型空间里放大画的详图等） | 图页表加一列映射到 `length_factor`（每个坐标单位折合多少米），页面“量距”才按实长换算；1:1 画的毫米图不用给 |

4. **回路两端坐标表**（例如 E-A-CBL2 的回路起终点，原来只在 `cable_calc.py` 运行时有）：由包脚本导出 `circuit_ends.csv`，一行一个上图回路。必填列：`object_id`、`catalog_key`（与审核表里同一回路的键一致）、`sheet`（起点所在图页）、`from_x`、`from_y`、`to_x`、`to_y`、`title`、`category`、`status`；建议列：`box`、`circuit`、`device`、`from_floor`、`to_floor`、`locate`（定位方式）、`level`。坐标是场景坐标时映射写 `"coords": "scene"`。没有两端坐标的回路（按工艺分区估、取中位数、二期不计等）照样一行，坐标留空，`unlocated_reason` 写 `estimated` 或 `no_geometry`，`unlocated_note` 写为什么。映射把 `x1, y1, x2, y2` 接到两端坐标，页面画箱到终点的连线；要画直角示意线，再导出 `points` 列。
5. 几层换到同一坐标系看（例如各层桥架平面换到一层桥架框）：在映射 `scenes` 里写叠图，`base` 是本层桥架平面、叠图自身的 `dx, dy` 是本层到一层的平移，`overlays` 叠同层电力平面并写各自的 `dx, dy` 和图层过滤。
6. 接进审核页：各包图面视图都作 `--base-view` 交给第 1 节的转换，同一图页自动合为一页。灯具、箱、开关插座这类计数对象用成员挂接表核“图上个数 = 明细数量”；走线、桥架用定位挂接表 `member_refs`（`catalog_key`、`detail_id`），只回图、不核数量，所挂明细行写 `declared` 并说明理由。
7. 体量（2026-10-16 实测，底图从交换 DXF 还原）：E-A-LGT 全包 16,039 个对象、40 页，生成约 4.5 分钟，页面约 6.2 MB，浏览器打开约 0.9～1.2 秒、内存约 170 MB，切页中位 12 毫秒、最慢约 0.1 秒；E-A-CBL2 页面约 0.86 MB，E-S3 约 0.55 MB。
