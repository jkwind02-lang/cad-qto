# 无回路号混连网络拆分与归属（T35）

## 工作责任与输入证据

专业模型从原图识别完整实例、实际连接口、照明/插座/动力/控制类别，以及供电、控制或串接关系。通过 `partition_electrical_route_network.py` 将这些已识别对象和关系交给既有 L1 走线追踪及参考计算器。工具自动寻找已画路径、在分支和共享边界切分原段、计算原段区间并整理归属。关系输入不要求预先写出所有最终分段答案。

源图对象和关系足以闭合的局部直接继续处理。缺资料或冲突局部保留未决，专业模型继续读系统图、平面图、图例、完整实例及连接口；普通识图责任不转为要求用户逐段判图。只有决定性外部资料确实缺失时才提出针对性补充要求。

沿用本专业对象绑定的 `connection_port` / `curve_node` 来源结构。实际设备端口由实例内 POINT 或连接线端回取，完整 `instance_path` 与原图清单指纹必须一致。曲线节点只作为原线路节点；不会因该节点靠近设备而升级为设备端口。仅插入点、外包框中心或任意坐标不能补定实际连接口。

类别来自源图识别依据和明确供电/控制关系。普通图层名、块名、最短距离、类别优先级、总长度比例均不决定类别或回路归属。项目识图半径、块名映射、固定导线根数和跨包扣量各自保留在项目输入中。

## 版本化接口

请求 `qto-electrical-route-network-request/1.0`，结果 `qto-electrical-route-network-partition/1.0`。

- `project_id`、`scope_id`：本次明确任务及范围。
- `cad_manifest_sha256`、`source_sha256`：当前中性清单及权威原图指纹，必须与实际来源相符。
- `trace_request`：既有 `qto-drawn-route-request/1.0` 的单位、图层、范围、块展开和容差参数。不得写 `routes`；实际端点与关系在本工具内重建路线。所有容差明确按米给出，单位换算沿用既有原图单位核验。
- `endpoint_objects`：`object_key`、`category`、`source_ids`、`endpoint_binding`。类别为 `lighting/socket/power/control/source/junction/unknown`。绑定结构沿用 `bind_electrical_objects.py::endpoint`。未知类别明确用 `unknown`。
- `connections`：`id/from_object/to_object/relation/source_ids`。`relation` 为 `supply/control/interconnect`。可给 `circuit_id` 和同源 `circuit_source_ids`；没有回路号时为 null 或省略。允许沿用 L1 的 `via_handles/via_basis/bridge_pairs`，分别还需原图 `via_source_ids/bridge_source_ids`。`category` 显式声明须有 `classification_source_ids`，不能覆盖互相冲突的负荷端点。
- `circuit_candidates`：关系下的候选回路数组，每行 `circuit_id/source_ids`。多候选须有确定选项及 `circuit_selection_source_ids` 才采用；其余保留歧义。`alternative_group_id` 标记互斥的连接解释，同组多个解释存在时全部列待核，不能合计为同时存在。模型核图后提交唯一有证解释，再次运行。
- `circuit_specs`：已证回路的 `circuit_id/kind/system/spec/parallel_count/extras/pending_components/source_ids`。`kind` 为 wire/cable。根数为正整数或 null；规格、附加和完整量分量未知时明确 null。`extras=[]` 与 `pending_components=[]` 是有据、明确的范围声明，不由工具默认补齐。
- `segment_parameters`：位于 `circuit_specs` 下的分段参数数组，每项 `id/source_ids`，以 `source_ranges[{source_id,part_index,fraction_range}]` 或 `connection_ids` 限定适用原段区间/已证关系，给出局部 `kind/system/spec/parallel_count`。原段会在参数变化边界实际切分；共享区间多个局部声明不一致时列未决，不按数组顺序采用。未被局部声明改变的字段仅沿用本回路明确给出的全局参数；全局参数未知时继续保留 null。
- `extras`：逐项 `id/connection_id/at/length_each_m/length_basis/basis/basis_ids/source_ids`，`at` 为 from/to。附加定位到该关系实际端头，每项仅加一次。仍沿用现有计算器的依据分层。中途附加应以实际节点和关系分段，不藏成全回路重复附加。
- `sheets`：回图时提供原图坐标的 `sheet_id/floor/bounds`；当前底图链支持 m/mm。其他单位先用既有同源转换链，不能只改显示单位。

调用函数：

```python
from partition_electrical_route_network import partition_network
result = partition_network(manifest_path, request, base_path=request_directory)
```

实际 CLI：

```powershell
python skills/qto-electrical-routes/scripts/partition_electrical_route_network.py --cad-manifest 中性事实/CAD中性取证清单.json --request 混连请求.json --output-dir 混连拆分结果 --build-review
```

退出码 0 为该声明范围内参考处理完成，3 为已生成含未决的可回图结果，2 为输入/执行失败。参考完成不代表正式工程量采用、真实图纸识别验收或发布安装完成。

## 拆分、支路和回路

逐关系调用既有 `trace_drawn_routes`，复用同一中性几何、来源绑定、端点接续、T 接和经由约束。仅已画端点接触形成 T 接，交叉图线保持不连。每段保留来源句柄、完整实例、原曲线部分序号、参数区间及平面/空间长度。原曲线区间由共享几何重新测量，不继承声明长度。

所有已追踪关系及分段参数的区间边界共同切分原段，形成 `physical_segments`。切分、关系认领和参数适用比较共同复用对象绑定的 `normalize_cuts`：边界必须同时在 2 ULP 内且沿原曲线移动不超过 1 nm，才视为数值表示等价；任一显式声明的正跨度均受保护，不能坍缩成零。原始 `source_ranges` 保留原值，`interval_normalization` 另列原值、规范值和实际物理移动量。多 ULP 的真实间隙及真实微段保留；不使用固定 round、工程接续容差或单一宽容差合并。同一原段同时被照明和控制路径使用时，公共区间列出各关系 owner，支线及只被一路使用的区间分开。每条关系保持有序 `path_ids`，公共段只保存一份几何。拆分前后逐关系长度守恒；曲线回图按原曲线离散，不用端点弦冒充原曲线。

无回路号且实际关系闭合时，可得到 `PARTITIONED_REFERENCE` 路径和类别分支。`branch_groups` 仅整理同源端点、同类关系的分支，`is_electrical_circuit=false`。此编号供追溯和重识别定位，不作为回路号、线路根数或计算规格。

环网无有证经由约束、等长候选、T 两侧回路标注冲突、经过其他箱的未决关系、未画补连或重合扣减，保留可回图候选和问题。混连端点互相冲突、供电关系不足或互斥解释并存时，也保留未决。不能用“最短”或优先级消解这些语义问题。

## 数量与输出边界

`physical_segments.length_m` 是已画原段区间的平面测长。共享已画线段不证明一根物理导管，故 `physical_channel_quantity_m` 保持 null，导管等物理通道应按已证实际构件另外绑定计量。

已证回路按原段区间取并集：同一回路分叉后的公共导线段只计一次；不同回路在同一已画段上的导线各自计算。全局附加或路径归属不明时，该回路不送入现有计算器，其完整量保留 null；根数/规格等仅部分区间未知时，已证区间继续参考计算，完整量保留 null，未知字段定位到原子区间。已证原段长度始终保留。`known_conductor_quantity_m` 是共享区间中已证部分，任一 owner 仍无回路归属或缺根数等时，完整 `conductor_quantity_m` 为 null。

`ledger` 采用既有 `qto-electrical-path-ledger/1.0`，`reference_calculation` 调用既有 `calculate_electrical_paths.calculate`。原子区间对象带回路父键并分别计算，分支不强塞成现有只允许首尾串接的单链 logical circuit。`complete_length_m` 仅在本次明确的已画平面范围及已声明完整量分量全部闭合时给出；未知竖向、端头、预留、未画连接继续列 `pending_components`。本工具不计灯具、插座或控制设备点数，末端点位由 points 负责唯一计数。

所有结果 `official_adoption=false`、`business_adoption_allowed=false`。`--build-review` 调用既有 reference CLI、场景生成器和 HTML 生成器，输出每个实际子进程退出码。每个实际原子把回路分段 kind/system/spec/parallel_count、已知及完整导线量、未决字段、未决分量和具体原因投影到公共场景可见属性及详情；局部参数未知、冲突或完整量分量未闭合时，图面状态为 `REVIEW_REQUIRED`。`geometry_status` 仍保留几何分段状态，`quantity_status` 单独表示量和参数是否闭合。不能以可下载源 JSON 代替图面可见内容，回图不提高量级或采用状态。

## 受影响范围重识别

`source_fingerprint/network_fingerprint/scope_id` 是重识别和反馈对象的来源边界。输出 `objects`、`connections`、原子区间 ID、来源参数和 `affected_scope` 可用于定位。修改 `endpoint_objects/connections/circuit_specs` 或 L1 经由/接续约束后，重新调用 `partition_network`：从当前源图重建图、路线、原段区间、共享 owner、ledger 及 reference 结果。源指纹变化时必须重新取证和刷新请求，禁止只改 pending 标记后继承旧数。

当前函数重建整个已声明 `scope_id` 的相关子网；调用方先用对象/关系依赖确定需要的 scope，范围外结果不混入。人工审核凭据、正式采用与跨包责任仍按既有契约处理。


## 类型化投影后的检查身份

scene生成器的初始检查对应CSV转换完成时的视图。逐原子类型化属性回填后，再调用公共 `qto_review_contract.normalize_view` 保存最终规范视图；`场景检查.json` 绑定此最终result_fingerprint，同时在 `projection_check` 中记录投影前/后指纹、规范化步骤和原检查文件SHA。初始完整检查原字节另存为 `场景生成原检查.json`，不将初始检查冒充为未发生投影。HTML生成后以公共 `unpack_payload` / `normalize_view` 核对内嵌规范身份与最终view/检查回执一致，未闭合则返回失败。投影不改变业务计算。
