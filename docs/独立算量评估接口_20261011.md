# 独立算量评估接口

本工具是维护用测试工具，不随专业运行包发布。它保留既有 `maintenance/benchmark/scripts/score_benchmark.py`（2026-10-14 从旧开发源 `_qto-benchmark` 迁入）的物理对象集合差异、重复出口和未决检查思路，用一个轻量 JSON 接口接入实测输出，不要求重建阶段基准清单。

## 评价边界

- 先依据原图形成本次独立结果，保存结果、源文件指纹和冻结收据，再接触参照进行对照。`freeze_dataset` 只记录执行时刻，拒绝传入历史时间或覆盖既有文件；已存在旧结果保持原历史，不补造“事前冻结”。
- 独立性检查仅检查来源身份、角色声明及生成关系。填入 `independence` 不证明盲测或独立推理。`historical_exposure` 明示是否曾接触过该项目参照；同一历史项目仍是回归，不宣称新项目盲测。
- 人工底稿是参照，不能自动视为真值。按原始图纸另行裁决的参照可声明 `adjudicated_drawing`；无法裁决的记录设为 `adjudication_status: disputed` 或 `status: unresolved`，不参与数量误差评分。
- 不自动匹配相似名称、不从总量反算、不用结果生成期待值。直接复用结果的身份、声明从结果派生的参照及来源角色为 `result_output/frozen_result/frozen_takeoff` 的参照均不能作独立验证。参照来源路径或哈希与已声明的结果成果文件一致时，即便将角色改称人工底稿，也不能通过；哈希按大小写无关比较。双方共享同一原始图纸则允许，不能据此推定参照循环生成。
- 源文件及已声明路径的成果文件哈希默认现场核验；`evidence_refs` 和显式证据状态也会检查，但不能证明引文支持工程结论。输出明确保留这些限制。

## Python API 与调用

```python
from evaluate_takeoff import INPUT_VERSION, source_ref, freeze_dataset, evaluate

# metadata、records 应由当前专业算量/独立参照转换，不由评估器猜测。
result = freeze_dataset({"metadata": result_metadata, "records": result_records}, result_path)
# 在独立结果冻结后准备参照；也可加载已有真实冻结收据，不重写其时间。
reference = freeze_dataset({"metadata": reference_metadata, "records": reference_records}, reference_path)
report = evaluate({
    "schema_version": INPUT_VERSION,
    "result": result,
    "reference": reference,  # 无参照时为 None，返回 NOT_ASSESSED
    "tolerances": {"absolute_by_unit": {"m": 1e-6, "m2": 1e-6, "kg": 1e-6}, "relative": 1e-8},
})
```

命令行：`python -B maintenance/evaluate_takeoff.py --input 输入.json --output 评估结果.json`。默认核验来源文件哈希；诊断选项 `--skip-source-file-check` 会在输出中明确记录未核验来源。比较发现差异仍正常生成报告；无效输入或独立来源/范围未建立时退出码为 2。

## 输入字段

顶层为 `schema_version: qto-independent-evaluation-input/1.0`、`result`、`reference` 和可选 `tolerances`。两个数据集均为 `{metadata, records}`。

| metadata 字段 | 含义 |
|---|---|
| `artifact_id` | 本次成果唯一业务编号；结果和参照不得相同 |
| `role` | 结果 `frozen_takeoff`；参照 `independent_reference` |
| `scope_id` | 可比工程范围编号；两侧必须一致 |
| `scope_complete` | 布尔值；只表示提供者声明本数据集是否覆盖该范围 |
| `basis` | 如 `drawing_takeoff`、`manual_worksheet`、`independent_drawing_review`、`synthetic_oracle` |
| `sources` | 非空列表 `{path, sha256, role}`，使用绝对业务路径；可用 `source_ref(path, role)` 创建 |
| `frozen_at`、`records_sha256` | 由 `freeze_dataset` 新建当前收据；加载历史收据时按真实值保留 |
| `historical_exposure` | 建议明确 `true/false/unknown`，原样保存在报告中 |
| `derived_from_artifact_ids` | 如有生成依赖如实声明；不能将参照派生自结果后再称独立 |
| `reference_authority` | 参照必填：`manual_reference`、`adjudicated_drawing` 或 `synthetic_oracle` |
| `independence` | 参照必填：`{independent_of: [结果artifact_id], method: 参照独立形成方式}`；只是声明 |
| `artifact_path`、`artifact_sha256` | 可选既有原始成果身份；已知时提供，可检测同文件/同哈希复用 |

每条 `records`：

```json
{
  "record_id": "当前明细唯一编号",
  "physical_object_key": "同一物理对象的稳定编号",
  "quantity_kind": "pipe_axis_length",
  "classification": "管道",
  "specification": {"dn": 32, "material": "明确材料"},
  "unit": "m",
  "measurement_basis": "本次明确的计量口径ID",
  "status": "determined",
  "quantity": 4.0,
  "evidence_refs": ["源图文件/父块路径/实体句柄及采用事实"],
  "relations": {"system": "供水", "from_port": "接口A", "to_port": "接口B"}
}
```

`status` 可为 `determined/unresolved/excluded`。未决数量必须 `null`，原因放 `unresolved_reason`；缺依据但报确定值进入 `unsupported_determined`。可显式声明 `evidence_status: supported/pending/absent/unsupported`；字段一旦提供，只有 `supported` 有资格参与参照数量评分，其他状态（包括未知状态）进入 `reference_unsupported`，数量对比覆盖率不把这些记录作真值。省略该字段只保留“已提供引用”的旧接口语义，并不代表工具已证实引用内容。参照争议用 `adjudication_status: disputed/unresolved`。参照关系只核对提供的字段，不猜测未提供的关系。

匹配键是 `physical_object_key + quantity_kind`。同一构件体积与模板面积可为两个 quantity_kind；不同构造层/侧面应有各自物理表面编号。同键重复不会自动汇总或任取一行，也不允许靠改单位、规格掩盖重复出口。

## 输出解释

- `differences` 分别列出漏项、误纳、参照未覆盖的输出、重复、关系错配、分类/规格错配、结果未决、缺依据确定值、参照争议/未决和不可比项。
- 分类、规格及计量口径严格比较；单位仅做明确的同维换算（mm/cm/m，平方/立方单位，g/kg/t）。绝对容差以归一后的 m、m2、m3、kg 等单位配置。不把 DN 当实际外径，不猜测“套/组/个”换算。
- `quantity_comparisons` 保留逐项绝对误差，按单位分别累计绝对误差，不提供跨单位总误差，也不以正负差抵消。
- `reference_object_coverage` 只表示已提供参照中应有对象的出现率。出现但未决仍属于“出现”，因此必须同时查看 `quantity_comparison_coverage`、未决列表及分项误差；全未决不能冒充全准确。
- 参照为空或没有可评数量时为 `NOT_ASSESSED`。参照不完整时，额外输出进入 `unreferenced_output`，不武断称为误纳；分项完全相同时最多返回 `NO_DIFFERENCES_IN_PARTIAL_REFERENCE`。
- 完整声明范围内无已知差异返回 `NO_DIFFERENCES_WITHIN_DECLARED_REFERENCE`，不返回“全准确”。`all_accurate` 始终为 `null`，避免将有限参照结果冒充完整正确性保证。
