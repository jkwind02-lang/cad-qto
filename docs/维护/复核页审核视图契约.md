## 2. 顶层

```json
{
  "schema": "qto-review-view/1.1",
  "...": "1.0 的全部字段不变",
  "sources": [{"id": "AUDIT-B03", "title": "审计清单 3#动力中心.xlsx", "sha256": "<64位>"}],
  "scenes": [],
  "objects": [],
  "comparison": {
    "display_terms": {"third_party": "清单"},
    "handler_labels": {},
    "thresholds": {"difference_rate_alert": 0.2, "consistent_band": {"计量": 0.05, "计数": 0},
                   "count_units": ["台", "个", "套", "组", "座", "系统", "处", "根", "块", "只"]},
    "legacy_search_evidence": null,
    "dimensions": [],
    "sources": [],
    "items": [],
    "issues": [],
    "member_tables": []
  }
}
```

- **顶层 `sources`** 照旧是复核身份的一部分（`source_sha256` 由它算出），只放稳定的输入：图纸、第三方清单文件。**不要放每轮都会变的成果表**，否则每次重算都换身份，旧批注就导不进来了；成果变化由结果指纹跟踪（第 9 节）。没有图纸的视图，列第三方清单文件即可。
- `scenes` 可以为空。这时全部 `objects` 必须是 `kind: "unlocated"`、`scene_id: null`，页面不显示图面区。不允许为了过校验造空图页。
- 有 `comparison` 时 `objects` 可以为空（全部明细都是“本行即依据”时，见 5.1）。没有 `comparison` 时仍至少要一个对象。
- `comparison` 可以只有问题：`sources`、`items` 都为空、只有 `issues` 时，页面只有“欠缺条件与资料”（第 14 节）。没有第三方数量的专业也能这样把待定事项交给用户。
- `display_terms.third_party`：页面上“第三方”一词换成什么，例如“清单”。只改显示，数据取值不变（结论仍写 `第三方无量`，页面显示“清单无量”）。默认“第三方”。
- `handler_labels`：问题四类的显示名，可以换成专业自己的叫法（第 6 节）。
- `thresholds.difference_rate_alert`：“差异超阈值”筛选的初始百分比（小数，默认 0.2），页面上可以临时调，只影响筛选。
- `thresholds.consistent_band`：“一致”带宽的默认值，即差额率绝对值，写小数；`0` 表示须相等。有任何要按数字判结论的来源段时必填。
  - 可以写一个数，所有单位都用它。
  - 也可以按单位类别分写，如 `{"计量": 0.05, "计数": 0}`。这时须同时给 `thresholds.count_units`，列出按计数处理的单位；不在其中的单位都按计量。
  - 生成器按默认值判一致、多算、少算（5.4 节）。页面顶部显示这条规则，用户可以在页面上临时改容差。
- `legacy_search_evidence`：可选，只用于检索记录规则生效前交付的成果。规则指《通用成果字段与状态》“否定结论与检索证据”，提交 e63fe30。
  - 整份视图的成果都在规则生效前交付、不回头补检索记录时，写 `{"rule": "e63fe30", "note": "为什么不补"}`。
  - 写了以后，“图上无”的检索依据可以不全或没有，页面标“检索记录不全”（第 5 节）。
  - 规则生效后交付的成果不能用这一项。新旧成果混在一起时，分成两份视图。
- 没有 `comparison` 时，就是现在的复核页。

## 3. 维度 `comparison.dimensions`

```json
[
  {"id": "building", "title": "楼栋", "role": "overview",
   "values": [{"id": "3#动力中心", "title": "3#动力中心", "order": 3, "merged_from": ["3#动力中心（桥架、配管部分）"]}]},
  {"id": "division", "title": "分部", "role": "section",
   "values": [{"id": "030408", "title": "电缆"}, {"id": "030411", "title": "配管"}]},
  {"id": "package", "title": "分包", "role": "filter", "values": [{"id": "E-3-1", "title": "E-3-1"}]},
  {"id": "system", "title": "系统", "role": "filter", "values": [{"id": "电气系统", "title": "电气系统"}]}
]
```

- `role` 三种：`overview` 总览卡片的维度，恰好一个；`section` 列表分节的维度，最多一个；`filter` 只用来筛选，个数不限。
- 值域封闭：条目、明细行、对象、问题上的维度值，必须在对应的 `values` 里；没带的显示为“未归”。
- `order` 可选，决定总览卡片和分节的顺序；没写的按 `values` 的顺序。
- 子单位并入所属楼栋（例如“（桥架、配管部分）”）由专业在数据里做好，原名记在 `merged_from`，界面不做合并。
- 问题的维度值可以是数组（一个问题涉及几栋楼）；条目、明细行、对象的维度值只能是单值。

## 4. 第三方来源 `comparison.sources`

```json
[{
  "id": "AUDIT",
  "kind": "审计清单",
  "title": "IDM 项目审计清单（电气系统）",
  "files": [{"title": "3#动力中心.xlsx", "sha256": "<64位>"}],
  "basis_note": "工作表“表10.2.2-16 分部分项工程清单与计价表”，只取电气相关项",
  "row_ids": ["AUDIT|3#动力中心|电气系统|11", "AUDIT|3#动力中心|电气系统|13"]
}]
```

- `kind` 取值：审计清单、招标清单、对方报量、甲方核定量、其他（选“其他”要在 `title` 写明）。
- `row_ids` 是这个来源全部条目的稳定编号，由专业从来源文件抽取，不能重复。生成器据此检查每一行恰好出现一次（C3-3）。
  - 编号要在来源内唯一。同一楼栋里有几个系统各自编序号时，只用“楼栋 + 序号”会撞号（电气实测有 66 组、155 行）。
  - 编号至少要带上系统，例如“来源|单位工程|系统|序号”。
- 来源文件的哈希进入条目结果指纹（第 9 节）。
- 可以有多个来源，同一工程内容写成一个对照条目，各来源并排（5.3 节）。
- 来源文件里的单价不抽取，也不进视图。

## 5. 对照条目 `comparison.items`

一个对照条目是“本次量”和各来源数量能对上的最小单位。本次量只写一份，各来源各写一段，放在 `third_parties` 里。

```json
{
  "id": "清单|3#动力中心|电气系统|93",
  "kind": "third_party",
  "ours": {"quantity_name": "配管长度", "unit": "m",
           "levels": {"确认量": null, "规则推算量": 1897.99, "方案暂估量": 287.55, "未决量": null},
           "total": 2185.54,
           "note": "末端支路全程穿管，其余只计出桥架段"},
  "third_parties": [
    {"source_id": "AUDIT",
     "rows": [{"row_id": "AUDIT|3#动力中心|93", "seq": "93", "code": "030411001001", "name": "配管",
               "features": "暗配 JDG20", "unit": "m", "quantity": 1934.9}],
     "unit": "m", "quantity": 1934.9,
     "difference": {"value": 250.64, "rate": 0.1295},
     "conclusion": "多算",
     "third_party_corrected": false,
     "disposition_note": "……",
     "redirect_to": [],
     "search_evidence": null}
  ],
  "dimensions": {"building": "3#动力中心", "division": "030411", "package": "E-3-2", "system": "电气系统"},
  "detail_rows": []
}
```

| 字段 | 要求 |
|---|---|
| `id` | 稳定编号，跨轮次不变，全视图唯一。单来源时可以用 `来源|楼栋|序号` 一类写法；多来源时建议用与来源无关的写法 |
| `kind` | `third_party`：至少一个来源段；`extra`：清单外新增，`third_parties` 为空数组 |
| `name`、`features` | 可选。`extra` 条目必须有 `name`（页面标题用）；`third_party` 条目没写时，页面取第一个来源段第一行的名称和特征 |
| `ours.unit` | 必填 |
| `ours.levels` | 键只能是《通用成果字段与状态》的四个数量层级：确认量、规则推算量、方案暂估量、未决量。值是数字或 `null`；没写的键按 `null`。`null` 是未计算，与 0 不同 |
| `ours.total` | 本次合计 = 确认量 + 规则推算量 + 方案暂估量，**不含未决量**；三项都是 `null` 时为 `null`。可以不写，生成器补上；写了就核对（C3-5） |
| `estimate_dominant` | “以暂估为主”标记，生成器按固定规则补：方案暂估量 > 0 且方案暂估量 ≥ 确认量 + 规则推算量（`null` 按没有）。专业写了就必须与规则一致 |
| `third_parties[]` | 每个来源最多一段，按 `sources` 的顺序排列 |
| `third_parties[].rows` | 这一段涵盖的来源行，可以多行：来源把同一内容拆成几行，或几项合成一行时，都在这里列全。每行 `row_id`、`unit` 必填，`quantity` 是数字或 `null` |
| `third_parties[].quantity` | 等于各行数量之和（同单位）。来源没给量写 `null`，不能补 0；只有部分行有量时，按有量的行求和，并写 `quantity_note` |
| `third_parties[].unit` | 与 `ours.unit` 不同时必须写 `unit_mismatch_note`，这一段不画对比条，不参与差额率排序，`difference` 写 `null` |
| `third_parties[].difference` | `{"value": 本次合计 − 该来源数量, "rate": value ÷ 该来源数量}`，专业给出，生成器只核对。来源数量为 0 时 `rate` 写 `null`。结论为一致、多算、少算时必填；其他结论可以写 `null`。结论为“第三方无量”且来源数量为 `null` 时，可以按来源数量 0 写：`value` 等于本次合计，`rate` 写 `null` |
| `third_parties[].conclusion` | 按来源分别下结论，只能取：`一致`、`多算`、`少算`、`第三方无量`、`图上无`、`缺图`、`归入他项`。前三种由生成器按默认带宽判，专业可以不写；写了必须与带宽判定相同（5.4 节）。页面可以按用户设的容差重新显示这三种。后四种由专业写，页面照显示 |
| `third_parties[].third_party_corrected` | 第三方条目本身有误、本次已按正确内容计算时写 `true`，并写 `correction_note`。这是标记，与结论并存（例如“多算”且“第三方条目有误已修正”） |
| `third_parties[].disposition_note` | 处置说明，可选 |
| `third_parties[].redirect_to` | 结论为“归入他项”时必填，列去向条目的 `id`，可以多个 |
| `third_parties[].search_evidence` | 结论为“图上无”时必填，见下表；视图声明了 `legacy_search_evidence` 的可以不全、只写 `note` 或为 `null` |
| `third_parties[].missing_drawing_note` | 结论为“缺图”时必填 |

`search_evidence` 沿用共享《通用成果字段与状态》“否定结论与检索证据”：

| 键 | 要求 |
|---|---|
| `drawings` | 必填。检索了哪些图纸、图页或布局 |
| `targets` | 必填。检索对象：图层、块名、文字关键词、表格、实体类型及常见写法变体 |
| `method` | 必填。中性取证包检索、原生 CAD 补读、PDF/OCR 文字检索或逐页查看；脚本检索写脚本位置 |
| `hits` | 必填，数字。为 0 也写 0 |
| `unread` | 可选。没能读取的部分 |
| `uncovered` | 可选。可能含该类对象但没查的图纸 |
| `record_ref` | 可选。项目里检索记录的位置 |
| `note` | 可选。文字说明，例如只记了查过哪些图 |

检索记录不全的，按共享规则不能写“图上无”，应作为未决事项处理。

唯一的例外是视图声明了 `legacy_search_evidence`：成果在规则生效前交付，问题收集会话 2026-10-15 定不回头补。这时：
- 检索依据缺项或为 `null`，不报错；
- 生成器在该段补 `search_incomplete: true`，并列进 `comparison_exceptions`（`检索记录不全`）；
- 页面在列表和详情里标“检索记录不全”，已有的检索依据、`note` 和处置说明照样显示；
- 这些段不转成未决或待确认，不计入顶部欠缺计数。“欠缺条件与资料”末尾单列一组“检索记录不全”，默认收起，只作提示（第 14 节）。

### 5.1 明细行 `items[].detail_rows`

```json
{"id": "E-3-2#93-1", "area": "1F", "level": "规则推算量",
 "quantity": 859.41, "unit": "m",
 "basis": "末端支路 5 回路，回路路由长（水平直角距离＋竖向）合计",
 "drawing": "D0xx", "locator": "1F 配电平面", "relation": "对应", "note": "",
 "dimensions": {"package": "E-3-2"},
 "aggregation": "sum_members",
 "member_keys": ["电气回路|E-3-2|1AL1-WL3"], "member_table": "circuit"}
```

- `id` 全视图唯一；`level` 取四个层级之一；`quantity` 数字或 `null`；`unit` 必须与所属条目的 `ours.unit` 相同。
- `area`（楼层区域）、`drawing`、`locator`、`relation`（例如“对应”“对应-修正”“清单外新增”）、`note` 都是显示用的文字，可选。
- `aggregation` 三种：
  - `leaf`（默认）：本行就是最小依据，没有成员对象，`member_keys` 为空。没有图面数据的包都用这种；
  - `sum_members`：本行数量等于成员对象同名、同单位、同层级数量之和（C3-2），要写 `member_quantity_name`，指明合计成员的哪个数量项；
  - `declared`：有成员（供回图和下钻），但本行数量不由成员合计得出，要写 `aggregation_reason`。
- 成员就是 `objects`，`member_keys` 填对象的 `catalog_key`。逐回路台账的每一行都可以是一个对象：有回图坐标的用 `line` 或 `point`，没有的用 `unlocated`。
- 同一对象的同一数量项只能进一行明细（C3-4）。
  - 数量项按数量名区分。`sum_members` 行取 `member_quantity_name`。`declared` 行可以写 `member_quantity_name`，不写时取所属条目的 `ours.quantity_name`，两者都没有时按整个对象算。
  - 一条回路同时给电缆长度、电缆头、配管、穿线几个条目供数时，各行的数量名不同，不算重复。
- 同一数量项确需拆给几行时，在每个相关明细行写 `shared_member_split: [{"member_key": …, "share": 0～1, "basis": "拆分依据"}]`。同一对象同一数量项的各份额之和为 1，`sum_members` 合计时按份额计。

### 5.2 成员台账表头 `comparison.member_tables`

```json
[{"id": "circuit", "title": "逐回路台账",
  "columns": [{"key": "attributes.起点箱", "title": "起点箱"}, {"key": "attributes.回路号", "title": "回路号"},
              {"key": "quantities.水平长度", "title": "水平 m"}, {"key": "quantities.竖向长度", "title": "竖向 m"},
              {"key": "attributes.图纸", "title": "图纸"}, {"key": "source", "title": "定位"}]}]
```

`key` 只能取对象已有的字段：`id`、`title`、`status`、`source`、`detail`、`attributes.<名>`、`quantities.<数量项名>`。界面不另算。

### 5.3 多来源并排

- **对齐由专业做**：把各来源里说的是同一内容的行归到同一个条目。来源之间拆分口径不同（例如招标一行对应审计两行），就把两行都列进审计那一段的 `rows`。界面不自己猜哪些行对应。
- **对不上的照样显示**：某来源没有这项时，条目里只写有的来源段。列表里缺的那一列显示“无对应”，与“第三方无量”区分开：后者是来源有这一行，但没给数量。
- **列表一行**：本次量只显示一次，后面每个来源占一列，显示该来源数量、差额率和结论。只有一个来源时与单来源设计相同，不多出空列。
- **当前对照来源**：顶部选择器，默认是 `sources` 的第一个。按差额率或差额排序、“差异超阈值”筛选、总览卡片计数，都按当前对照来源算；切换来源不改数据。只有一个来源时不显示选择器。
- **筛选**“来源间结论不一致”：同一条目里各来源段的结论不全相同。只有一个来源时不显示。
- **详情**：各来源的行并排列出（序号、编码、名称、特征、单位、数量），下面是本次各层级数量和明细行。

### 5.4 一致带宽：默认值与页面容差

用户 2026-10-15 的答复：“第 1 项我选：页面可设容差，默认计量 ±5%、计数必须相等。”

- **哪些来源段按带宽判**：与本次同单位、来源数量不为 `null` 也不为 0、本次合计不为 `null`，且结论不是第三方无量、图上无、缺图、归入他项的段。
- **默认带宽**取 `thresholds.consistent_band`：
  - 写一个数时，所有单位都用它；
  - 分写成 `{"计量": b1, "计数": b2}` 时，单位在 `count_units` 里的用计数带宽，其余用计量带宽。
- **怎么判**：按数据算 `r = (本次合计 − 来源数量) ÷ 来源数量`，不用专业四舍五入后的差额率。
  - `b > 0`：`|r| ≤ b` 为一致；否则 `r > 0` 多算，`r < 0` 少算。
  - `b = 0`（须相等）：本次合计与来源数量在数值容差内相等为一致；否则按正负判多算、少算。
- **生成器**按默认带宽判：
  - 专业没写结论的，按判定写进数据；写了而与判定不同的，报错（C3-5），不允许逐条另判；
  - 在按带宽判的段上补 `band_check: {"rate": r, "equal": 本次合计与来源数量是否在数值容差内相等}`，供页面按容差重新显示，页面不再自己算比值。
- **页面容差**：
  - 顶部显示默认规则，例如“一致：计量 ±5%，计数须相等”。旁边可以改容差：分写时计量、计数各一个输入，否则一个。另有“恢复默认”。
  - 只有带 `band_check` 的段按页面容差重新显示一致、多算、少算。第三方无量、图上无、缺图、归入他项，以及单位不同、来源数量为 `null` 或 0 的段，照数据显示。
  - 与数据结论不同的段标出原结论，例如“多算（原：一致）”。
  - 总览计数、结论筛选都按页面显示的结论算。
  - 页面容差只在本页打开期间有效，不写回数据，不改指纹。保存的批注会记下当时的页面容差和显示的结论（第 9 节）。
- 来源数量为 0 而本次有量的，不按带宽判，由专业写“第三方无量”。
- 默认带宽或 `count_units` 改了，重新生成后受影响条目的结论随之改变，这些条目上的旧意见标为过期，因为结论在指纹里。页面容差只改显示，不使意见过期。
- “差异超阈值”筛选的百分比与容差是两回事，仍可以单独调，只影响筛选。

## 6. 问题条目 `comparison.issues`

```json
{"id": "A01", "handler": "decide",
 "title": "引下线：内柱“上下贯通”接地线是否计入",
 "text": "各楼接地平面在内柱上画了“上下贯通”接地线……",
 "impact_text": "A 第 291 项若只计外侧柱为 681.0 m（本次 1439.2 m，清单 1429.66 m）……",
 "impact": null,
 "current_practice": "A、B、3# 计入内柱",
 "item_ids": ["清单|A-晶圆厂房|电气系统|291"],
 "dimensions": {"building": ["A-晶圆厂房", "B-封装厂房"]},
 "source_refs": [{"ref": "E-A-FFU-Q02", "text": "原条目原文……"}],
 "group_id": null, "status": "待定"}
```

- `handler` 取四个代码：

  | 代码 | 默认显示名 | 页面 |
  |---|---|---|
  | `decide` | 需要你定口径 | 展开 |
  | `confirm` | 需补资料或确认 | 展开 |
  | `assumed` | 已按假设计入 | 展开 |
  | `closed` | 已处理，仅留记录 | 默认收起 |

  显示名可以用 `comparison.handler_labels` 换成专业的叫法，例如 `{"decide": "需要你定口径（会改数量）", "confirm": "需设计、业主或清单编制方确认"}`。
- `title`、`text` 必填。`impact_text` 是影响的文字说明。
- `impact` 可选，只显示，不参与任何合计：
  - 写一段时为 `{"value": 数字或 null, "unit": "m", "note": "…"}`；涉及几个单位时写成多段数组；
  - `value` 有数字时须有 `unit`，为 `null` 时须有 `note`；
  - 定性影响可以只写 `impact_text`，`impact` 写 `null`。
- 一个问题涉及多个包时只写一条，原各包编号放在 `source_refs`。`source_refs` 每项可以是编号文字，也可以是 `{"ref": 编号, "text": 原文}`。
  - 要保留合并前各原条目的原文时用 `{"ref", "text"}`。例如电气 171 条原条目合并成 88 条，原文都放这里，满足不删减。
  - 表格输入用 issue_sources 表。
  - 电气意见第 8 处建议的 `source_texts` 与此作用相同，不另设字段。
- `item_ids` 可以为空（清单外或整体性问题）。生成器从 `item_ids` 反向建索引，条目详情里显示挂在它身上的问题。
- `group_id` 可选，连到现有问题组，以便回图。`status` 可选，只显示。
- `current_practice` 写“现在是怎么算的”。`decide`、`assumed` 两类建议必写，用户据此判断要不要改；不写时页面显示“未写现做法”。
- **涉及量**：页面在每条问题下按 `item_ids` 逐条列出挂接条目的本次各层级数量（确认、规则推算、方案暂估、未决）和合计，只显示各条目已有的数，不跨条目求和。
- 问题批注的快捷结论显示为“按现做法”“不按现做法”“暂不定”，数据里仍存 `同意`、`要改`、`待定`（第 9 节）。选“不按现做法”时，原因里写明应该怎么算。

## 7. 网址定位

| 片段参数 | 作用 |
|---|---|
| `#item=<条目 id>` | 打开成果，选中该条目并回图；同时给了 `#mode` 且该模式里有这个条目时，在该模式里打开 |
| `#issue=<问题 id>` | 打开欠缺条件与资料，选中该问题 |
| `#group=<问题组 id>` | 复核视图的问题组模式 |
| `#object=<catalog_key 或对象 id>` | 复核视图的对象模式 |
| `#scene=<图页 id>` | 切到该图页 |
| `#dim=<维度 id>:<值 id>` | 总览进入该维度值 |
| `#source=<来源 id>` | 切换当前对照来源 |
| `#mode=results\|resolve\|audit\|review` | 指定模式：成果、欠缺条件与资料、对照审核、图面复核；`issues` 作为 `resolve` 的别名，`extras` 打开成果并筛到清单外新增 |

- 几个参数用 `&` 连接，值用 `encodeURIComponent` 编码。
- 只在页面内的数据里查找。找不到时顶部提示“未找到 …”，停在默认视图，不报错。
- 同一页内改片段（例如点了页内链接）时，监听 `hashchange` 照样响应。
- 选中目标后用 `history.replaceState` 更新片段，复制地址栏就能分享当前位置。
- 不联网、不执行片段内容、不把片段写进 HTML 结构。
- 外部文件引用写法：`工程量图面复核_E-3-2_r1.html#item=%E6%B8%85%E5%8D%95%7C...`（整段 `encodeURIComponent`）。

## 8. 无图纸与图面区收起

- `scenes` 为空时不渲染图面区，列表和详情铺满整页。
- 有图页时，当前选中的条目、问题或对象没有任何可定位成员，图面区自动收起，详情和明细表加宽；切到有定位的目标时自动恢复。
- 顶部提供“图面：自动 / 展开 / 收起”开关，手动选择在本页打开期间一直有效。
- 《HTML交互复核与批注》第 3 行“不强制建立虚构图页”与原契约“至少一张图页”相矛盾，按本节改正（1.1 起允许无图页；1.0 仍要求图页，不变）。

## 9. 审核意见与闭环

- 新增两种批注键：`对照条目|<item id>`、`问题|<issue id>`。记录分别带 `item_snapshot: {item_id, result_fingerprint}` 或 `issue_snapshot: {issue_id, result_fingerprint}`，以及记录本身的 `result_fingerprint`。
- 快捷结论 `verdict` 取：`同意`、`要改`、`待定`，可以不填。问题批注上这三个值分别显示为“按现做法”“不按现做法”“暂不定”（第 6 节），条目批注上照原样显示。已保存的批注**必须写原因**；选了快捷结论的，结论文字可以留空，读取时以快捷结论为结论；没选快捷结论的，结论文字必填（与现有规则相同）。
- 条目批注可以取消勾选个别明细行，记在 `excluded_detail_row_ids`，只能是本条目的明细行。
- 条目批注另记 `page_view: {"consistent_band": 当时的页面容差, "conclusions": {来源 id: 当时显示的结论}}`，页面容差等于默认值时也记。它只说明审核人当时看到的结论，不参与过期判定，读取程序原样带进 `item_actions`。过期判定仍绑数据原结论和结果指纹。
- 草稿、保存、修改历史、合并导入、保存带批注 HTML、导出 JSON 都沿用现有机制。
- **结果指纹**（生成器重算，不信任传入值）：
  - 条目指纹覆盖：各来源段的行（编号、编码、名称、特征、单位、数量）、该来源文件哈希；本次各层级数量、单位、合计；各来源段的数量、差额、结论、修正标记与说明、处置说明、去向、检索依据、缺图说明；明细行（编号、数量、层级、单位、依据、聚合方式、成员、拆分）；成员对象的指纹；维度值。
  - 问题指纹覆盖：处理方分类、标题、正文、影响、现在的做法、关联条目。
  - 任何一项变了，旧意见标为过期（stale），旧的数字确认不能继承；条目或问题不在了标为 unmatched。视图总指纹纳入这两类指纹。
  - 页面标题、`revision`、显示用语、“差异超阈值”筛选值、页面容差变化，都不使意见过期。默认带宽变化只通过改变的结论使相关条目过期（5.4 节）。
- `read_qto_review_feedback.py` 输出新增 `item_actions`、`issue_actions`，每条带编号、快捷结论、结论、原因、例外明细行、更新时间，以及“供所属专业复核；未自动写回数量”。
- `receipts` 的键同样支持 `对照条目|…` 和 `问题|…`，回执沿用 `source_annotation_updated_at` 与 `source_result_fingerprint` 双重绑定。

## 10. 生成器双向校验

任何一项不通过，生成器都返回 `INPUT_REQUIRED` 和具体条目，不出半成品页。所有显式声明的例外，都列在 `HTML生成检查.json` 的 `comparison_exceptions` 里。

| 编号 | 检查 | 方向 |
|---|---|---|
| C3-0 | 编号唯一：条目、明细行、问题、来源；来源段的 `source_id` 存在；维度角色个数合法；维度值都在值域内；`consistent_band` 是非负数，或分写的计量、计数两个非负数并有 `count_units`；`legacy_search_evidence` 有 `rule` 和 `note` | 结构 |
| C3-1 | 每个条目各层级的本次量，等于其明细行同层级数量之和；明细行的单位与条目单位相同 | 条目 → 明细行 |
| C3-2 | `sum_members` 明细行的数量，等于成员对象指定数量项（同单位、同层级，按拆分份额）之和；`declared` 有原因；`leaf` 没有成员 | 明细行 → 成员 |
| C3-3 | 每个来源的 `row_ids` 与各条目中该来源段 `rows` 里的行一一对应，不漏、不重、不越界 | 来源 ↔ 条目 |
| C3-4 | 同一成员对象的同一数量项（按数量名）最多进一行明细（跨条目也算）；拆分的份额合计为 1 | 成员 → 明细行 |
| C3-5 | 每个来源段的结论与字段自洽：归入他项有 `redirect_to`、目标存在且不是自己；图上无有完整检索依据（声明了 `legacy_search_evidence` 时不全只提醒，标检索记录不全）；缺图有说明；第三方无量时该段数量是 `null` 或 0；修正标记有说明；同单位且有差额时，差额 = 本次合计 − 该段数量、差额率 = 差额 ÷ 该段数量；一致、多算、少算与默认带宽判定相同（5.4 节），按带宽判的段必须有差额，带宽缺失时报错；`ours.total` 与各层级一致；`estimate_dominant` 与规则一致 | 条目内部 |
| C3-6 | 问题引用的条目、维度值、问题组都存在；`handler` 合法；`impact` 为 `null`、一段或多段，每段有数字时有单位、为 `null` 时有说明 | 问题 → 条目 |
| C3-7 | 对象带维度值时，与其所属条目一致；不一致的在对象上写 `dimension_mismatch_note` | 对象 ↔ 条目 |
| C3-8 | 每个条目每个来源最多一段；来源段数量等于其各行数量之和（部分行无量时有 `quantity_note`）；`extra` 条目没有来源段 | 来源段 ↔ 行 |
| C3-9 | **只提醒，不拦**：有未决量、以暂估为主、或有来源段结论为“缺图”的条目，都应挂在某个未关闭（`closed` 以外）的问题上；没挂的列进 `comparison_exceptions`（`不确定条目未挂问题`），报告给出条数，页面在“待解决”里标“未挂问题”。生成器在每个条目上补 `uncertain`（“有未决量”“以暂估为主”“缺图”标签数组）和 `uncertain_unlinked`，供页面分组；“有未决量”指未决量不为 `null`、0，或有未决量层级的明细行 | 不确定内容 → 问题 |

数值相等的容差为 `1e-6 × max(1, |值|)`。差额率允许专业四舍五入到 0.1%（小数容差 0.0005，含边界），例如表里写 `-61.4%`、按数据算是 −0.61424，算一致；按数据算是 0.3145、表里写 `31.4%` 也算一致。`null` 只能和 `null` 相等，不能当 0 用；唯一的例外是“第三方无量”的差额按来源数量 0 核对（第 5 节）。

## 11. 体量

- **目标规模**（宁波众芯电气，电气会话 2026-10-15 核对）：第三方条目 1460 条（审计清单电气相关；处置为已算 911、修正 45、图上无 292、缺图 86、归入他项 126），清单外新增 164 条，明细 1913 行，问题 88 条，两包已有回图对象约 1400 个；后续补图后逐回路台账会到数千条。
- **不设大小上限，不分页，不截取**。复核页只保存到本机，在线上传已停用（插件共用收件配置 `enabled: false`）。20 MiB 只是在线上传的上限，不是页面容量上限；上传停用后与页面无关。
- **生成前预估**：报告里写各类计数，以及原始 JSON、gzip、HTML 三种字节数。
- **2 MB 提醒值**照旧，只提醒打开性能，不截断。
- 原 E5 的期望“超限时按问题对象优先截取”：按“不删减内容”的原则不做。
- **前端**：列表分页显示，排序和筛选在内存数据上做；明细和台账在下钻时才渲染。实测打开明显卡顿再议，不预设分文件。

### 12.1 映射文件 `qto-comparison-table-mapping/1.0`

```json
{

  "view": {"project_id": "宁波众芯机电算量", "review_id": "电气审核与复核", "title": "电气工程量审核与复核",
           "revision": "r1", "sources": [{"id": "AUDIT-A", "title": "审计清单 A-晶圆厂房.xlsx", "sha256": "<64位>"}],
           "scope_notes": [], "summary": []},

                     "value_maps": {"level": {"确认": "确认量", "规则推算": "规则推算量", "方案暂估": "方案暂估量", "未决": "未决量"}}}],

```

- 路径相对映射文件。CSV 一律 UTF-8（可带 BOM），第一行是列名。
- `columns` 把下表的标准键映射到项目列名；**列名和标准键相同的可以不写**。`constants` 给整张表写固定值。`value_maps` 按标准键做取值替换。`list_separators` 声明哪些列是多值、用什么分隔（默认 `;`）。
- 数字列：空白为 `null`；带 `%` 的按百分数换成小数；其余不能解析的报错，不猜。
- 是否列（`third_party_corrected`、`estimate_dominant`）：`是`、`true`、`1`、`Y` 为真，空白和 `否`、`false`、`0`、`N` 为假，其他值报错。
- 维度 `values_from`：`"data"` 表示取数据里出现过的值（按首次出现顺序）；或者指向一张表，给出值列和可选的 `title`、`order`、`merged_from` 列（同一值多行时 `merged_from` 合并）。也可以直接写 `values`。
- 来源 `row_ids_from: "items"` 表示该来源的 `row_ids` 取各条目该来源段的行编号；这时 C3-3 只能查出重号，查不出漏行，报告里会写明。能从来源文件独立抽取时，用 `row_ids_table` 指向一张单列表（列名 `row_id`），C3-3 才是真正的双向检查。

### 12.2 标准键

**items（对照条目表；一行一个“条目 × 来源段”，清单外条目一行一条）**

| 键 | 含义 |
|---|---|
| `id`、`kind`、`source_id` | 条目编号、`third_party`/`extra`、来源编号 |
| `dim.<维度 id>` | 维度值 |
| `name`、`features` | 名称、特征（清单外条目必填 `name`） |
| `unit` | 本次单位（必填） |
| `quantity_name`、`ours_note` | 本次数量项名、本次说明 |
| `确认量`、`规则推算量`、`方案暂估量`、`未决量` | 本次各层级数量；项目列名常是“确认”“规则推算”等，在 `columns` 里映射 |
| `total`、`estimate_dominant` | 可选，写了就核对 |
| `row_id`、`seq`、`code`、`row_name`、`row_features`、`row_unit`、`row_quantity` | 本段只有一条来源行时，直接写在这里；`row_name`、`row_features`、`row_unit` 没写时取 `name`、`features`、`unit` |
| `tp_quantity`、`tp_unit` | 来源段数量和单位；没写时取 `row_quantity`、`row_unit` |
| `difference`、`difference_rate`、`conclusion`、`disposition_note` | 差额、差额率、结论、处置说明 |
| `third_party_corrected`、`correction_note` | 修正标记和说明 |
| `unit_mismatch_note`、`quantity_note`、`missing_drawing_note` | 见第 5 节 |
| `search_drawings`、`search_targets`、`search_method`、`search_hits`、`search_unread`、`search_uncovered`、`search_record_ref`、`search_note` | 检索依据各项（`search_note` 是文字说明） |
| `redirect_to` | 去向条目编号（多值）；也可以用 redirects 表 |

同一 `id` 出现多行时，每行是一个来源段（每个来源一行），条目级的键（维度、本次量等）各行必须相同，不同则报错。一个来源段对应多条来源行时，用 **source_rows** 表（键：`item_id`、`source_id`、`row_id`、`seq`、`code`、`row_name`、`row_features`、`row_unit`、`row_quantity`）列全，items 表里该段的单行键留空。

**detail_rows（明细表）**：`id`、`item_id`、`level`、`quantity`、`unit`、`basis`、`area`、`drawing`、`locator`、`relation`、`note`、`dim.<维度 id>`、`aggregation`、`aggregation_reason`、`member_keys`（多值）、`member_quantity_name`、`member_table`。

**redirects（去向表）**：`item_id`、`target_item_id`，可选 `source_id`（多来源时指明是哪一段的去向，单来源可省）。

**issues（问题表）**：`id`、`handler`、`title`、`text`、`impact_text`、`current_practice`、`dim.<维度 id>`（多值）、`source_refs`（多值）、`status`、`group_id`。`handler` 用 `value_maps` 把项目的类别名映射到四个代码。

**issue_links（问题关联表）**：`issue_id`、`item_id`。**issue_sources（问题原条目表）**：`issue_id`、`ref`、`text`。**issue_impacts（问题影响表，可选）**：`issue_id`、`value`、`unit`、`note`，一行一段，同一问题多行即多段。

映射的 `comparison` 里写的 `thresholds`、`legacy_search_evidence` 原样带进视图。

**members（成员台账表，可选；每行成为一个对象）**：`catalog_key`、`object_id`、`detail_id`（挂到哪行明细，会补进该行的 `member_keys`）、`title`、`category`、`status`、`professional`、`detail`、`source`、`dim.<维度 id>`；数量列在映射里声明 `"quantities": [{"name": "水平长度", "unit": "m", "level": "规则推算量", "column": "H"}]`，属性列声明 `"attributes": {"起点箱": "box"}`。这样建的对象是 `unlocated`；`catalog_key` 与 `--base-view` 里已有对象相同的，不新建，改为引用已有对象（保留其回图坐标）。

## 13. 用户答复（2026-10-15）

1. **“一致”怎么判**：用户最终答复（问题收集会话转达）：“第 1 项我选：页面可设容差，默认计量 ±5%、计数必须相等。”
   - 默认带宽按单位类别分写：计量 ±5%，计数须相等。生成器按默认值判，不由专业逐条判。
   - 页面上可以自设容差，按容差重新显示一致、多算、少算，见 5.4 节。
   - 用电气现有数据试过：计量 ±5%、计数须相等时，与电气现有结论完全相同。若全部单位统一 ±5%，会有 11 条（套、个）由多算或少算变为一致。
2. **多来源**：有多个第三方时并排。一个条目带多个来源段，见 5.3 节。
3. **导出**：先不做，需要时由模型直接生成 Excel。
4. **金额影响**：不考虑价格，只算量。单价、`priced`、`amount_impact`、按金额排序全部删除。
5. **20 MiB 分页**：取消。20 MiB 是在线上传的上限，不是页面容量上限；在线上传已停用，页面不设上限、不分页（第 11 节）。

## 14. 页面要点

- **模式**（有 `comparison` 时，按下面顺序排列；用户 2026-10-15：复核页就是最终成果页，第三方数量只作对比）：
  1. **成果**（默认）：本次算出的全部条目，包括有第三方对应的和清单外新增的。
     - 按 `overview`、`section` 维度分类列出，每行先显示本次合计和各层级（对比条先画本次），第三方数量和结论在下一行作“对照”。
     - 点进去先看本次各层级数量、明细组成与依据（楼层区域、数量、层级、计算依据、图纸、定位、关系），再下钻到成员台账，有定位的回图。对照放在后面。
     - 筛选：范围（全部 / 有第三方对应 / 清单外新增）、有问题、以暂估为主、有不确定内容、检索记录不全、其他维度，以及全文搜索。不跨条目求和。
  2. **欠缺条件与资料**（原“待解决”）：从成果反推，准确计算还欠缺什么。全部从现有字段推导，专业不用另填（用户选定）。
     - 先列问题，按 `decide`（缺口径）、`confirm`（缺外部确认或资料）、`assumed`（按假设计入、待证实）、`closed` 四类分组，`closed` 默认收起。
     - 再列条目里还没算实的内容，分“有未决量”“以暂估为主”“缺图纸”三组。缺图纸的显示缺图说明，没挂问题的标“未挂问题”（C3-9）。
     - 末尾单列一组“检索记录不全”，默认收起，只作提示（第 5 节）。
     - 每组可以收起。有现有问题组时，提示“另有 N 个图面问题组待复核”，可以跳到图面复核。
  3. **对照审核**：与第三方数量对照的列表和详情（原“审核”），详情先列第三方数量，再列本次成果。
  4. **图面复核**：现有的问题组和对象（原“复核”）。
  - 默认打开成果；没有任何条目时打开欠缺条件与资料（`comparison` 只有问题时）；两者都没有内容而有问题组时打开图面复核。
  - 原“清单外新增”并进成果，用“范围”筛选；`#mode=extras` 打开成果并筛到清单外新增。
  - 没有条目时不显示“成果”；没有对照条目时不显示“对照审核”；没有对象和问题组时不显示“图面复核”；欠缺条件与资料始终显示（为空时写“没有欠缺条件或待定事项”）。
- **顶部**：
  - 先是欠缺计数：各类未关闭问题数，有未决量、以暂估为主、缺图纸的条目数。点了进入欠缺条件与资料对应分组。检索记录不全不计入。
  - 下面一行是一致带宽的默认规则和页面容差设置（5.4 节），以及“差异超阈值”的当前百分比。没有对照条目时不显示这一行。
- **总览**：按 `overview` 维度出卡片，另有“全部”。
  - 每张卡片先显示成果条目数（含清单外条数），再显示欠缺计数：未关闭问题数、有未决量、以暂估为主、缺图纸。
  - 最后显示对照计数：条目数、各结论计数（按页面显示的结论）、差异超阈值数、第三方无量但本次算出数、清单外条数。
  - 多来源时对照计数按当前对照来源算。
- **列表**（对照审核模式）：
  - 按 `section` 维度分节；
  - 每行：编号、名称和特征、单位；对比条（第三方量一条，本次量分“确认 + 规则推算”和“方案暂估”两段；有未决量时另标“未决”文字，不画进条）；“第三方量 → 本次合计”；结论和差额率；有问题的标记；多来源时每个来源一列；
  - 排序：差额率（绝对值）、差额绝对值、编号；
  - 结论按页面容差显示，与数据结论不同的标“原：…”；
  - 筛选：差异超阈值（阈值可调）、有问题、以暂估为主、结论、来源间结论不一致、修正标记、检索记录不全、其他维度；另有全文搜索。
- **详情**：
  - 各来源的行并排，与本次说明对照；各层级数量和合计；
  - 明细行表（楼层区域、数量、层级、依据、图纸、定位、关系），有成员的再下钻到成员台账；
  - 有定位的成员在图面上高亮，可以上一处、下一处；
  - 归入他项的可跳到去向条目，图上无的显示检索依据（不全的标“检索记录不全”），缺图的显示说明，修正的显示修正说明；
  - 挂在本条目上的问题，可以跳过去。
- **问题**（在欠缺条件与资料里）：每条显示问题、影响、现在的做法、涉及量（第 6 节）、原条目原文，可以跳到相关楼栋、条目和问题组；批注选“按现做法 / 不按现做法 / 暂不定”并写原因。
- **审核意见**：条目、问题两级都能批注，见第 9 节。
- **保存**：只有本地保存。
