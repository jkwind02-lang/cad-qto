# 维护流程

## 两类会话

| 会话 | 谁来做 | 工作目录 | 可以做 | 不可以做 |
|---|---|---|---|---|
| 日常会话 | Claude 或 Codex | 各项目目录 | 使用插件；登记问题；必要时在项目目录里做临时处理并标明 | 修改插件仓库、发布目录、缓存 |
| 维护会话 | Claude 或 Codex，由用户指定 | 插件仓库 | 处理登记、修改插件、测试、发布并同步两边安装、回写处理结果 | 与另一个维护会话同时进行 |

## 维护锁（`maintenance/maint_lock.py`）

锁文件是插件维护目录下的 `维护中.json`，用 `os.open(..., O_CREAT | O_EXCL)` 原子创建。只有 `FileExistsError` 表示已有锁；目录不存在、权限或磁盘错误另报原因。

| 命令 | 作用 |
|---|---|
| `acquire --model M --scope S [--bind-pid auto]` | 取得锁；返回 `owner_token` |
| `start-heartbeat` | 启动隐藏的心跳辅助进程（每 60 秒）；需要锁已绑定会话进程 |
| `status` | 查看持有者、心跳间隔、是否疑似异常、绑定进程是否仍在 |
| `heartbeat` | 手动刷新心跳（无辅助进程时由各工具调用刷新） |
| `release --commit C` | 只有持锁会话可以释放；释放记录追加到 `维护锁历史.jsonl` |
| `takeover --user-confirmed "用户确认内容" --model M` | 经用户确认后接管 |

锁内记录宿主、模型、主机名、会话标识、本次锁标识、开始时间、范围、最近心跳和心跳方式。会话标识取本进程实际能拿到的值：Claude 用 `CLAUDE_CODE_SESSION_ID`，Codex 用 `CODEX_THREAD_ID`；都没有时生成一个并在本次维护中保持。工具判断"当前会话是否持锁"时用这个会话标识，人工在终端操作时设置 `CAD_QTO_LOCK_TOKEN` 为锁标识。

**心跳辅助进程的生命周期**

- 启动时绑定一个经核实对应会话生命周期的进程，记录进程号和创建时间。Claude 侧用 `--bind-pid auto`：取 `CLAUDE_PID`，并核实它是本条取锁命令的祖先进程；长驻的桌面进程不能当作会话仍活跃的证明。
- 每次写心跳前核对绑定进程仍在（进程号加创建时间，防止进程号复用）、锁仍属于本持有者；任一不满足就停止心跳并退出，不删除锁，并在锁历史里记一条退出原因。
- 心跳只就地改写已存在的锁文件，不会在释放之后把锁"写回来"。
- 无法取得会话常驻进程时（例如 Codex 尚未核实对应进程）不启动辅助进程，锁的心跳方式记为"按工具调用和关键步骤刷新"，疑似异常阈值从 2 小时放宽到 6 小时。

**异常退出后的接管**

- 临时命令的进程号不能代表维护会话。连续超过阈值无心跳只标"疑似异常"，不自动判定会话结束。
- 接管必须经用户确认。工具会拒绝在原心跳辅助进程仍在运行时接管。接管时：原锁内容追加到 `维护锁历史.jsonl`；检查未提交改动、原会话范围及文件哈希，保留原内容，明确归属后接续，确需丢弃时请用户决定；检查安装核对记录，等待另一宿主不等于安装失败。
- 新接管取得新的锁标识，旧持有者及其辅助进程不能再更新或删除新锁。

## 开工检查

记录 `git status` 和当前提交。发布批次必须有清楚的修改归属：已登记、能确认属于本会话同一批次的未提交改动可以接续；陌生改动先只读核验归属，无法判断或与本次冲突时再请用户裁定，不覆盖、不替他人提交。

## 登记处理（`maintenance/triage_issues.py`）

- 登记位置：插件维护目录的 `问题登记/{待处理,处理中,已处理,不进插件}/`。一个问题一个文件，文件名形如 `20261014-1932_claude_管网_DN文字绑定漏判.md`。
- 维护会话用脚本列出 `待处理/`，按 Skill 分组、合并重复、标出"阻断"和"影响识图或数量"，用 `--claim` 移入 `处理中/`。
- 分类：插件缺陷、方法改进、宿主执行偏差、项目特例（移到 `不进插件/`）、资料问题、不能复现。
- 同事通过 HTML"保存并反馈"上传的意见，由维护会话取回后按同一模板转成登记。
- 回写时区分：代码已修复、单侧已安装、双侧发布完成、工程复验范围；补齐提交号、版本及原任务是否需要复跑。等待另一宿主或恢复未完成的条目保留接续状态。

## 日常会话遇到问题

见运行包内的[插件问题登记](../../skills/_qto-shared-evidence/references/插件问题登记.md)：能绕过的在项目目录里临时处理并标明；绕不过且影响数量的列为未决、登记为阻断并告诉用户；影响面大的提醒用户尽快安排维护会话。
