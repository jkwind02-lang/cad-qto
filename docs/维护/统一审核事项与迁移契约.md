# 统一审核事项、旧意见迁移与简化填写

本扩展对应 T03 的稳定事项与完整迁移续项、T41 的可选单入口配置。原有显式 `decision_id` 冲突保护继续保留，并非本次才增加。默认旧页和未启用扩展的视图沿用原行为。

## 数据与生成入口

最终 `qto-review-view/1.0` 或 `1.1` 视图在顶层提供 `review_workflow`，与 `objects`、`comparison`、`delivery` 同级：

```json
{
  "review_workflow": {
    "schema": "qto-review-workflow/1.0",
    "enabled": true,
    "migrate_legacy": true,
    "default_tab": "decisions",
    "decisions": [{
      "id": "终点方法A",
      "revision": "1",
      "title": "终点资料缺少时的处理",
      "question": "是否保留方案暂估，并在资料补齐后复算？",
      "kind": "business_choice",
      "is_common": true,
      "group_label": "水平线路",
      "scope": {
        "member_keys": ["电气对象|P1"],
        "excluded_member_keys": [],
        "basis": "仅当前楼层水平线路，不含竖向、附属量和二期范围"
      },
      "refs": [{"kind": "object", "id": "电气对象|P1"}],
      "facts": ["平面水平路径已核实"],
      "gaps": ["缺终点设备布置资料"],
      "impacts": [{"unit": "m", "value": null, "level": "方案暂估量", "scope": "水平段"}],
      "business_options": [{"id": "estimate", "title": "保留方案暂估"}],
      "evidence": [{"id": "E1", "state": "verified", "source": "平面图P1及核查底稿", "detail": "仅支持当前水平段方法，不证明终点实长"}],
      "recommendation": {
        "id": "R1", "version": "1", "status": "current",
        "text": "保留方案暂估，补资料后复算",
        "reason": "已核水平段，终点位置仍缺资料",
        "assistant_source": "本轮专业助手分析",
        "evidence_ids": ["E1"], "business_option_id": "estimate",
        "scope_member_keys": ["电气对象|P1"]
      }
    }]
  }
}
```

`id` 表示稳定工程事项，`revision` 表示事项版本。事项事实、建议、成员成果和适用排除范围进入结果指纹；更新不会自动复用旧确认。项目负责决定分组、工程口径、业务做法、事实与未知、证据充分性和参考建议；插件不生成工程数量或项目分类。

`kind` 为 `business_choice`、`data_gap` 或 `category`。后两者只有只读卡片，不出现输入区。业务动作固定为采用建议、调整处理、退回核查、待资料确认、暂不处理；具体施工/计量做法来自本事项的 `business_options`，另行记录。未知影响值用 `null`，保留单位、层级和范围，不跨单位相加。

`refs.kind` 为 `object/group/item/issue/common/delivery_item`。其中 object 的 `id` 使用 `catalog_key`，例如 `电气对象|<physical_id>`，其余使用相应对象的 `id`。`item` 指 comparison 条目，`delivery_item` 指 delivery 工程量项（兼容未提供 items 时的当前/参考 quantity_rows），避免跨通道裸编号同号异义。现有目标顶层 `decision_id` 也可显式指向本事项。两种映射给出不同身份时列为歧义，不按裸编号、标题或成员重叠合并。

生成流程：

1. `build_review_scenes_from_tables.py` 将 `mapping.view.review_workflow` 原样传到输出视图顶层；对象、组支持标准 `decision_id` 列/常量。对象 `attributes.decision_id` 对应的原始列只有一个显式值时提升为对象顶层 `decision_id`；合并对象存在多个值时拒绝生成。
2. `build_comparison_view_from_tables.py` 保留基础视图工作流，最终 `mapping.view.review_workflow` 可显式提供全范围配置并关联工程量项。多基础视图的不同工作流不自动拼接；同号组改名时相应显式 group 引用跟随调整，稳定事项编号不改名。
3. `build_qto_review_html.py` 内嵌 `review-identity.js` 后内嵌 `review-core.js`。独立 JS 消费者必须按此顺序加载；启用工作流而缺模块时停止解析，不能回退为普通对象意见。

采用 `delivery` 时，业务事项还须有已声明真实取舍目标（或其已声明共性覆盖的目标），特例可继承原事项的声明。有效成员必须属于 `current_member_keys`。不能借工作流将退役/参考成员或资料缺口改为可采用业务意见，既有 T02/T04 门控继续有效。

## 一处编辑与特例

可选界面提供工程量、审核事项与图面证据入口。图面组、对象、工程量或对照问题导航同一个事项编辑器，旧两通道填写区隐藏；没有唯一映射的证据显示待核，不能创建另一份对同事项有效的普通意见。共性优先，已处理记录默认收起，可主动展开；当前正在查看的已处理事项保留上下文。

新特例须由项目给出单独稳定事项，显式写 `exception_of`，其范围在原事项内；不允许自指、循环或嵌套。卡片显示原事项、适用和排除成员。父事项卡片显示单独处理的特例，交接扣除这些成员并列 `held_by_exception`；父事项重新采用不覆盖特例。用户逐成员排除另存 `excluded_member_keys`，不改原始数量。

`#decision=<稳定事项id>` 可直接导航。内部桥接为 `QtoReviewIdentity.active.openTarget(kind,id)`；`open(id)` 导航同一编辑器，`getFeedback()` 取得当前反馈，`refresh()` 在导入后刷新。

## 一键采用与保存恢复

一键采用仅在建议编号、版本、正文、理由、助手来源、业务做法齐全，且所引证据存在并显式 `state=verified`、建议范围等于当前适用范围时开放。`status` 非 current、带时区有效期 `expires_at` 已到期/无效、旧答复范围新增/变更、旧意见待迁移或冲突时均不能快捷覆盖。来源与依据是项目提供的数据，不是插件对证据真实性的独立验收。

统一反馈键是 `审核事项|<id>`，记录 `decision_snapshot`。采用意见保存 `recommendation_receipt`，含完整建议快照、所引证据、`user_choice=采用建议`、`reason_origin=助手建议引用` 和选择时间；引用依据不冒充用户亲写。Python 交接再核建议版本、原文、证据、助手来源及用户选择，篡改或过期后暂挂。

调整和退回只需补充一个必要说明框；选择的具体业务做法独立保存。待资料确认自动引用缺项，暂不处理也能保留，但这两类不下发专业回算动作。保存、草稿、本机恢复、导出 JSON、带批注 HTML、导入合并均使用同一事项键；记录不同的统一意见保留完整冲突候选，不按时间择一。手工重审保存保留原意见、冲突和迁移来源的历史。

## 旧意见迁移

只有同时启用工作流并显式 `migrate_legacy=true` 才迁移。否则旧通道意见保留并标为待迁移，不作为新事项已审意见。默认未启用工作流的历史页不受影响，旧原因必填和既有审核校验保持。

迁移消费旧图面、comparison 两通道的已保存意见和草稿。完整原记录（包括原话、历史、来源、快照和旧例外）保留到 `legacy_review_records`；唯一显式对应的意见转到稳定事项并标 `migration_state=review_required`，不冒充重新审核。多份已保存意见保留为完整候选冲突；草稿独立保留。无映射、多重映射列 `decision_migration_pending`。缺失或歧义的映射澄清为唯一显式身份后，归档待迁移记录可按新映射迁移，原映射历史继续保留；同键存在不同原始版本时继续暂挂，可重导原始旧反馈核对。已经对应的旧事项映射改变时也须明确核对，不冒充重新审核。明确关联到某事项的待迁移或歧义意见阻断该事项快捷采用和可执行交接。原始记录始终保留，不因新的时间戳静默覆盖。

迁移和方法选择本身始终 `quantity_changes=0`。`read_qto_review_feedback.py` 将可用统一意见放在 `decision_actions`，列出有效成员、用户排除、特例暂挂范围和建议收据。未决、草稿、待迁移、冲突和过期记录不作为可执行采用动作；交接保留其完整历史与候选。任何“已审核，待复算”都不表示人工数量核准，数量与回执仍由所属专业核查、重算后更新。

## 验证范围

`tests/test_review_identity_workflow_20261018.py` 覆盖稳定身份、327成员组与230成员交叉反例、旧双通道冲突/草稿/未知身份迁移、缺据/未核证据/过期/新增范围门控、特例与未决、旧页原因校验、交付只读门控，以及真实 CSV/中性图面到比较页的生成链路。

`tests/run_review_identity_browser_20261018.cjs` 用已有 Playwright 与实际 Edge 离线操作界面，核对跨入口同编辑器、少填字采用、调整/退回/待资料、资料缺口只读、共性不覆盖特例、保存恢复、冲突旧意见导入、原话历史草稿留存和旧页兼容。它记录浏览器版本、前后业务数据摘要、导出反馈、保存 HTML 和截图。合成验证不等于真实 DWG 或正式工程量验收。
