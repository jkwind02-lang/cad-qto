## 3. 维度 `comparison.dimensions`（A4）

```json
[
  {"id": "building", "title": "楼栋", "role": "overview",
   "values": [{"id": "B03", "title": "3#动力中心", "order": 3, "merged_from": ["3#动力中心（桥架、配管部分）"]}]},
  {"id": "division", "title": "分部", "role": "section",
   "values": [{"id": "030408", "title": "电缆"}, {"id": "030411", "title": "配管"}]},
  {"id": "package", "title": "分包", "role": "filter", "values": [{"id": "E-3-1", "title": "E-3-1"}]},
  {"id": "system", "title": "系统", "role": "filter", "values": [{"id": "电气", "title": "电气"}]}
]
```

- `role` 有三种：
  - `overview`：总览卡片的维度，恰好一个；
  - `section`：列表分节的维度，最多一个；
  - `filter`：只用来筛选，个数不限。
- 值域是封闭的：条目、对象、问题上的维度值，必须在对应的 `values` 里；没带的显示为“未归”。
- 子单位并入所属楼栋（例如“（桥架、配管部分）”）由专业在数据里做好，原名记在 `merged_from`，界面不做合并。

## 4. 第三方来源 `comparison.sources`（A1）

```json
[{
  "id": "AUDIT",
  "kind": "审计清单",
  "title": "IDM 项目审计清单（电气系统）",
  "files": [{"title": "3#动力中心.xlsx", "sha256": "<64位>"}],
  "basis_note": "工作表“表10.2.2-16 分部分项工程清单与计价表”",
  "priced": true,
  "row_ids": ["AUDIT|B03|11", "AUDIT|B03|13"]
}]
```

- `kind` 的取值：审计清单、招标清单、对方报量、甲方核定量、其他（选“其他”要在 `title` 写明）。
- `row_ids` 是这个来源全部条目的稳定编号，由专业从来源文件抽取。生成器据此检查“每个条目恰好出现一次”（见第 10 节 C3-3）。
- 来源文件的哈希进入结果指纹（见第 9 节）。
- 可以有多个来源。每个对照条目只属于一个来源；同一工程内容对应几个来源，就各写一条，用 `peer_item_ids` 互相关联。

## 5. 对照条目 `comparison.items`（A2、A3）

```json
{
  "id": "AUDIT|B03|93",
  "kind": "third_party",
  "source_id": "AUDIT",
  "third_party": {"seq": "93", "code": "030411001001", "name": "配管", "features": "暗配 JDG20",
                  "unit": "m", "quantity": 1934.9, "unit_price": 18.6},
  "ours": {"quantity_name": "配管长度", "unit": "m",
           "levels": {"确认量": null, "规则推算量": 1897.99, "方案暂估量": 287.55},
           "note": "末端支路全程穿管，其余只计出桥架段"},
  "difference": {"value": 250.64, "rate": 0.1295},
  "conclusion": "多算",
  "disposition_note": "……",
  "dimensions": {"building": "B03", "division": "030411", "package": "E-3-2", "system": "电气"},
  "detail_rows": [],
  "redirect_to": [],
  "search_evidence": null,
  "peer_item_ids": []
}
```

| 字段 | 要求 |
|---|---|
| `id` | 稳定编号，跨轮次不变；建议用 `来源|楼栋|序号` 这样的格式 |
| `kind` | `third_party` 是第三方条目；`extra` 是清单外新增（A3），此时 `source_id` 和 `third_party` 都为 `null` |
| `third_party.quantity` | 数字或 `null`。第三方没给量时写 `null`，不能补 0 |
| `third_party.unit_price` | 只在来源 `priced: true` 时出现（A6） |
| `ours.levels` | 键用《通用成果字段与状态》的数量层级：确认量、规则推算量、方案暂估量。未计算写 `null`，与 0 不同 |
| `ours.unit` | 与 `third_party.unit` 不同时，必须写 `unit_mismatch_note`。这种条目不画对比条，也不参与差额率排序 |
| `difference` | 专业给出，生成器只核对；同单位时核对差额是否等于本次合计减第三方量 |
| `conclusion` | 只能取：一致、多算、少算、第三方无量、图上无、缺图、归入他项、第三方条目有误已修正 |
| `redirect_to` | 结论为“归入他项”时必填，指向去向条目 |
| `search_evidence` | 结论为“图上无”时必填，字段沿用共享《通用成果字段与状态》“否定结论与检索证据”：图纸、图页、图层、块、关键词、命中数 |
| `missing_drawing_note` | 结论为“缺图”时必填 |
| `amount_impact` | 不由专业提供。生成器在规范化时按“差额 × 第三方综合单价”写入，界面只用它显示和排序，并标明“按第三方单价估的影响，不是造价结论” |

### 5.1 明细行 `items[].detail_rows`（B3）

```json
{"id": "AUDIT|B03|93#1F-1", "dimensions": {"floor": "1F"}, "level": "规则推算量",
 "quantity": 859.41, "unit": "m",
 "basis": "末端支路 5 回路，回路路由长（水平直角距离＋竖向）合计",
 "drawing": "D0xx", "locator": "1F 配电平面",
 "member_keys": ["电气回路|E-3-2|1AL1-WL3"],
 "aggregation": "sum_members", "member_table": "circuit"}
```

- `aggregation` 有两种取值：
  - `sum_members`：本行数量等于成员对象同名、同单位、同层级数量之和；
  - `declared`：本行数量不由成员合计得出，要写 `aggregation_reason`。
- 成员就是现有的 `objects`。逐回路台账的每一行都是一个对象：有回图坐标的用 `line` 或 `point`，没有的用 `unlocated`。下钻时“成员台账”显示哪些列，由 `member_table` 指向的表头定义决定。

## 6. 问题条目 `comparison.issues`（A5）

```json
{"id": "Q-B03-001", "handler": "需要你定口径",
 "title": "照明支路 3x2.5 线槽内是否按电缆计",
 "text": "本次 1594.8 m，清单 791 m。约一半沿 100*50 线槽敷设……",
 "impact": {"value": -800, "unit": "m", "note": "约数"},
 "current_practice": "现按电缆计",
 "item_ids": ["AUDIT|B03|105"], "dimensions": {"building": "B03"},
 "source_refs": ["E-3-2-Q07"], "group_id": null, "status": "待定"}
```

- `handler` 只能取四类：需要你定口径、需补资料、已按假设计入、已处理仅留记录。最后一类在页面上默认收起。
- 一个问题涉及多个包时只写一条，原各包编号放在 `source_refs` 里。
- 生成器从 `item_ids` 反向建索引，条目详情里显示挂在它身上的问题。
- `group_id` 可选，用来连到现有问题组，以便回图。

## 7. 网址定位（登记“复核页不支持网址直接定位”）

| 片段参数 | 作用 |
|---|---|
| `#item=<条目 id>` | 打开审核视图，选中该对照条目并回图 |
| `#issue=<问题 id>` | 打开问题视图，选中该问题 |
| `#group=<问题组 id>` | 现有问题组模式 |
| `#object=<catalog_key 或对象 id>` | 现有对象模式 |
| `#scene=<图页 id>` | 切到该图页 |
| `#dim=<维度 id>:<值 id>` | 总览进入该维度值 |
| `#mode=audit\|extras\|issues\|review` | 指定模式 |

- 几个参数用 `&` 连接，值用 `encodeURIComponent` 编码。
- 只在页面内的数据里查找。找不到时，顶部提示“未找到 …”，停在默认视图，不报错。
- 同一页内改片段（例如点了页内链接）时，监听 `hashchange` 照样响应。
- 选中目标后，用 `history.replaceState` 更新片段，复制地址栏就能分享当前位置。
- 不联网、不执行片段内容、不把片段写进 HTML 结构。
- 外部文件引用的写法：`工程量图面复核_E-3-2_r1.html#item=AUDIT%7CB03%7C93`。

## 8. 无图纸与图面区收起（登记“无图纸仍须放图页……”）

- `scenes` 为空时不渲染图面区，列表和详情铺满整页。
- 有图页时，如果当前选中的条目、问题或对象没有任何可定位成员，图面区自动收起，详情和明细表加宽；切到有定位的目标时自动恢复。
- 顶部提供“图面：自动 / 展开 / 收起”开关。手动选择在本页打开期间一直有效。
- 《HTML交互复核与批注》第 3 行“纯问答或没有图面依据的表内检查不强制建立虚构图页”和契约“至少一张图页”相矛盾，实现时一并改正。

## 9. 审核意见与闭环（B6、C1、C2）

- 新增两种批注键：`对照条目|<item id>` 和 `问题|<issue id>`。记录里分别带 `item_snapshot` 或 `issue_snapshot`（含 `result_fingerprint`）。
- 快捷结论 `verdict` 可取：同意、要改、待定，也可以不填。快捷结论不能代替原因：已保存的批注必须写原因，沿用现有规则。
- 条目级批注可以取消勾选个别明细行，记在 `excluded_detail_row_ids`。草稿、保存、修改历史、保存带批注 HTML、导出 JSON 都沿用现有机制。
- **结果指纹**：
  - 条目指纹覆盖：第三方数量、单位、单价，来源文件哈希；本次各层级数量；差额；结论；处置说明；明细行（数量、层级、依据、成员）；去向；成员对象的指纹。
  - 问题指纹覆盖：处理方分类、正文、影响量、现在的做法、关联条目。
  - 任何一项变了，旧意见都标为过期（stale），旧的数字确认不能继承。视图总指纹也纳入这两类指纹。
- `read_qto_review_feedback.py` 的输出新增 `item_actions` 和 `issue_actions`。`receipts` 的键同样支持 `对照条目|…` 和 `问题|…`。

## 10. 生成器双向校验（C3）

任何一项不通过，生成器都返回 `INPUT_REQUIRED`，不出半成品页。所有显式声明的例外，都列在 `HTML生成检查.json` 里。

| 编号 | 检查 | 方向 |
|---|---|---|
| C3-1 | 每个条目各层级的本次量，等于其明细行同层级数量之和 | 条目 → 明细行 |
| C3-2 | `sum_members` 明细行的数量，等于成员对象同名、同单位、同层级数量之和；`declared` 的要有原因 | 明细行 → 成员 |
| C3-3 | 每个来源的 `row_ids` 与该来源的 `third_party` 条目一一对应，不漏、不重、不越界 | 来源 ↔ 条目 |
| C3-4 | 每个成员对象最多属于一行明细（跨条目也算）；要拆分的，在明细行写 `shared_member_split`：成员、份额、依据 | 成员 → 明细行 |
| C3-5 | 结论与字段自洽：归入他项有 `redirect_to`、目标存在且不是自己；图上无有检索依据；缺图有说明；第三方无量时第三方量是 `null` 或 0；同单位时差额和差额率与数据一致 | 条目内部 |
| C3-6 | 问题引用的条目、维度值都存在；`handler` 合法 | 问题 → 条目 |
| C3-7 | 每个对象的维度值与其所属条目一致，不一致的要声明 | 对象 ↔ 条目 |

数值相等的容差为 `1e-6 × max(1, |值|)`。`null` 只能和 `null` 相等，不能当 0 用。

## 11. 体量与分页（C4、原 E5）

- **目标规模**：1540 个对照条目、约 2000 行明细、约 1400 个回图对象，后续补图后逐回路台账会到数千条。
- **生成前预估**：报告里写各类计数，以及原始 JSON、gzip、HTML 三种字节数。
- **2 MB 提醒值**照旧，只提醒，不截断。
- **超过 20 MiB**（“保存并反馈”的上传上限）时，生成器拒绝生成，并建议按 `overview` 维度分页，每页一栋或几栋。分页后：
  - 每页写明本页范围，以及其余各页的文件名；
  - 网址定位支持跨页链接。
- 原 E5 的期望是“超限时按问题对象优先截取”。按用户“不删减内容”的原则，改为分页，不截取。
- **前端**：列表沿用现有分页，排序和筛选在内存数据上做；明细和台账在下钻时才渲染。

## 14. 页面要点（B1～B7 对应）

- **模式**：有 `comparison` 时，默认打开“审核”；另有“清单外新增”“问题”“复核”三个模式，“复核”就是现有的对象和问题组。
- **B1 总览**：按 `overview` 维度出卡片。每张卡片显示：条目数、各结论计数、差异超阈值数、第三方无量但本次算出数、以暂估为主数、清单外条数、待审问题数。
- **B2 列表**：
  - 按 `section` 维度分节；
  - 每行显示对比条，本次量分“确认 + 规则推算”和“方案暂估”两段，再显示“第三方量 → 本次量”、结论和差额率；
  - 排序：差额率、差额绝对值、金额影响、编号；
  - 筛选：差异超阈值（阈值可调）、有问题、以暂估为主、结论、其他维度。
- **B3 详情**：
  - 第三方特征与本次说明对照，各层级数量；
  - 明细行表，再下钻到成员台账；
  - 有定位的成员在图面上高亮，可以上一处、下一处；
  - 归入他项的可跳到去向条目，图上无的显示检索依据；
  - 显示挂在本条目上的问题。
- **B4 清单外新增**：结构同 B2，没有第三方量。
- **B5 问题**：按四类分组，“已处理仅留记录”默认收起；每条可以跳到相关的楼栋和条目。
