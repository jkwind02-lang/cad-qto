## 1. 要解决什么

每张图一份识别配置。单图里没命中规则的块会记成“未决”，工作包也判为不完整（C01 实测保护在），但还有四个缺口：

1. 报告只列前 15 组未决，完整清单只在 jsonl 里。续作时容易只看已识别点数，R3 的三处漏项就是这样漏掉的。
2. 没有跨图纸集合的汇总。比如电力平面里的照明开关，落在哪份配置都没人管。
3. 没有图例逐行核对。图例里有、平面上有、清单里没有的对象，会整类漏计（接地端子板 206、按钮盒 38、静电释放 13）。
4. 非块图符适配器看不到，比如画成 HATCH 实心三角的接地端子板。

目标：**图面上的每个候选、图例的每一行都要有去向；还有没去向的，就不能说“这一类算完了”。**

## 2. 产物和分工

| 产物 | 谁出 | 内容 |
|---|---|---|
| `点位未决全量.csv` | 适配器，每份配置随报告输出一份 | 全部未决实例，一行一个，按块名、图层、父块、依据分组，不截前 15 |
| `点位覆盖台账.json` / `.csv` | 覆盖台账脚本自动生成 | 图纸集合内每个候选的去向，按图纸、图页、块名分组，并判每类是否完整 |
| `图例覆盖表_待填.csv` | 同一脚本出自动部分 | 图例图页上的每个块各一行，带平面实例数、同块多变体标记和能自动判的去向；已经填过的值原样带上 |
| `图例覆盖表.csv` | 专业会话（电气等）填写 | 补图例文字、非块图符行、去向、理由、疑似类别、检索记录；填好后再跑一次脚本 |

流程：先跑适配器（或备好项目自有计数表），再跑覆盖台账脚本；专业会话填图例覆盖表，然后再跑一次脚本。台账显示“完整”，才能交付该类数量。已证实的子量照常往下做，台账不完整只拦“这一类算完了”这句话。

命令：

```
python build_point_coverage_ledger.py --input 覆盖台账输入.json --output-dir <目录>
```

输入里的相对路径按输入文件所在目录解析。退出码 0 时，`status` 为 `COMPLETE` 或 `INCOMPLETE`；输入有问题时退出码 2，`status` 为 `INPUT_REQUIRED`，并列出全部问题，不出台账。

### 3.1 图纸 `drawings`

`drawings` 列出本专业要覆盖的整个图纸集合（从图纸目录取）。每张图纸的候选来源只能选一种：

| 来源 | 写法 | 候选是什么 | 去向从哪来 |
|---|---|---|---|
| 一、适配器报告 | `reports`：一份或多份 `点位识别报告.json` | 报告的 `artifacts.neutral_instance_dispositions` 里的全部实例（含块内嵌套） | 适配器处置，见 3.2 |
| 二、中性清单 + 项目自有计数表 | `neutral_dir`：该图的中性取证目录；计数表写在顶层 `count_tables`，按 `drawing` 归到这张图 | 中性布局 `Model` 里的全部顶层 INSERT | 句柄在计数表里的算已计，见 3.3 |
| 三、只有图例行 | 两者都不写 | 无块候选 | 只有图例覆盖表手填的非块行 |

- 同一张图纸同时写 `reports` 和 `neutral_dir`，判输入问题，要先定以哪份为准。同一图纸在 `drawings` 里出现两次也判输入问题。
- 既没有来源、图例覆盖表里也没有这张图纸的行的，列为“未覆盖图纸”，台账不完整。
- 候选编号两种来源一致：顶层块 `PT-CAD-<句柄>`，块内嵌套 `PT-CAD-<句柄>/<块名>/CAD-<子句柄>`，多层时逐级重复 `/<块名>/CAD-<句柄>`。来源二只有在 `expand_blocks` 声明了的容器块里才有后一种。

### 3.2 来源一：适配器报告

- 处置清单的 SHA256 要与报告里记的一致，否则判输入问题。同一图纸的几份报告，实例编号不能重复。
- 去向：

| 适配器处置 | 台账去向 | 类别或依据 |
|---|---|---|
| `adopted` | 已计 | 计数输入里该实例的 `category` |
| `merged` | 已计 | 写“并入 <主实例>”，类别取主实例的 |
| `excluded`、`not_applicable`、`duplicate_excluded` | 有据排除 | 处置记录的 `basis` |
| `unresolved` | 待识别 | 处置记录的 `basis`（未命中规则、规则冲突、块展开失败等） |

- 报告的 `unmatched_recognition_object_ids`（模型识别台账列了、适配器却没承接的对象）每个记一个“无去向”候选。
- 归图页用插入点换回原图坐标：处置记录的点除以配置里的 `unit.factor_to_output`。配置文件取报告 `profile.path`，SHA256 要一致。

### 3.3 来源二：中性清单 + 项目自有计数表

没有用适配器的项目脚本包（比如 Claude 电气各包），用自己的计数表出台账。

- **候选**：该图中性布局（`中性布局图元.ndjson`）里，`layout` 为 `Model`、`parent_block` 为空、类型为 INSERT 的全部记录。块内嵌套的设备块默认不单独成为候选，随顶层块的去向。
- **展开容器块**（登记 20261016-1709，第四批乙）：楼层整层画在一个块里时，在该图纸的 `drawings[].expand_blocks` 写容器块的精确块名（区分大小写，非空数组；只用于来源二）。
  - 脚本流式读一遍块定义，只展开声明的块，按每级插入的变换矩阵逐级换算；块里又有声明的块就继续展开（最多 16 层，循环引用判输入问题）。
  - 容器块内的每个 INSERT 成为候选，编号同适配器；容器本身记有据排除，依据“容器块，已按 expand_blocks 展开，块内候选另列”。
  - 判输入问题：展开的块名在块定义里不存在（或块定义没有序列化）；块内插入缺句柄、又没有可用的变换矩阵。声明了却在本图没有插入的，列进 `expand_blocks_unused`。
  - 没声明展开、而顶层块里有“计数类块名”（本图已计的块名，或出现在图例页上的块名，比较时去掉外部参照前缀）的，按块名列进 `unexpanded_container_blocks`：顶层个数、每个里面有几个、块名分布、示例编号。已计或在图例页上的顶层块不列。这样整层画在块里的图不会静默显示完整。
- **计数表 `count_tables`**：写法同 0.3.8《图面视图映射契约》第 4、6 节的表，支持 `path`、`columns`、`constants`（可以写 `{列名}` 模板）、`value_maps`。要用到的键：

| 键 | 必填 | 说明 |
|---|---|---|
| `drawing` | 是 | 列或常量；不在 `drawings` 里，或那张图不是来源二，判输入问题 |
| `handle` | 是 | 计数对象的图元句柄，比较时不分大小写；已展开容器里的对象写路径编号（前缀 `PT-CAD-`、`CAD-` 大写，句柄不分大小写，块名与图中一致） |
| `category` | 是 | 计入的类别（列或常量） |
| `sheet` | 否 | 只作对照：与按坐标归的图页不同时列进 `sheet_mismatches`，不判错 |

- **已计**：句柄（或路径编号）在计数表里的 INSERT。
- **非块计数对象**：句柄指向顶层的非 INSERT 图元（例如以箱号文字作实例键的配电箱），按已计列入台账，记一个候选，`symbol_kind` 写“非块”。
- **待识别**：不在任何计数表、也不在排除表里的顶层 INSERT。
- **排除表 `handle_exclusions`**（可选）：写法相同，键 `drawing`、`handle`、`basis`（列或常量，必填），命中的算有据排除。用于共享事实里的重叠图元表、他图计入、同一实物另一图之类。
- 判输入问题的情况，列出表名和行号：
  - 句柄在中性布局里查不到；
  - 句柄是块内图元（容器已展开时提示改写路径编号）；
  - 路径编号格式不对（前缀大小写、分隔符、少一级）、顶层句柄查不到、指向没在 `expand_blocks` 声明的块、块名大小写不符、或在展开结果里查不到；
  - 同一图纸的同一句柄（或路径编号，句柄大小写不同也算同一个）在计数表里出现两次（不论类别相同与否）；
  - 同一句柄既在计数表里，又在排除表里；
  - 已展开的容器块本身进了计数表（同一实物会在顶层和路径编号下各算一次）。

### 3.4 共用部分

- `sheets`：复用《图面视图映射契约》第 4 节的图页表写法（同样的 `columns`、`constants`、`value_maps`），`sheet_kind` 只能取 平面、系统图、表与说明、图例、详图、其他。
  - **按图形定图页**（登记 20261016-1713，第四批乙）：块候选用块定义图元范围经累计变换后的包围框中心定图页；来源一用适配器处置记录的 `scope_geometry_bbox`，来源二由脚本按块定义算（只作定图页的估计，不是计量外形；量不出的子块跳过）。量不出范围的、适配器按动态块裁决放行的，退回插入点。每个候选记 `placement_basis`（图形范围中心 / 插入点），汇总 `placement_basis_counts`。
  - 中心点落在哪张图页的范围里，就归哪张图页；同时落在几张里，取面积最小的一张。插入点与图形中心不在同一图页时，列进 `insert_geometry_sheet_mismatch`（编号、块名、插入点图页、图形图页）。
  - 落不进任何图页的写“图页未定”，不判错。
  - 没写图页表的图纸，全部候选都是“图页未定”。
- `excluded_classes`：整类有据排除（建筑底图噪声块等），按块名 `block_pattern` 或图层 `layer_pattern`（正则，至少写一个）匹配，`drawing` 写图纸号或 `*`，必须写 `basis`。
  - 可选 `sheet_kind`：只命中这类图页上的候选，与块名、图层条件同时满足（登记 20261016-1728）。取值同图页表；写详图判输入问题（详图页逐页确认，见下）。
  - 只把**待识别**的候选改成有据排除，不动已计的。
  - 已计的候选命中排除类时，列进 `counted_matches_excluded_class`，提醒专业核对，不改去向。
  - 规则命中的块名也出现在同图纸图例页上（比较时去掉外部参照前缀，图例行 `matched_symbols` 认领的块名也算）时，列进 `excluded_class_hits_legend_symbol`：规则号、块名、图例行。只提示，不改去向（登记 20261016-1800）。
    - 只看图例页以外的命中：规则只排掉了图例页上的样例，不提示（宁波众芯 B 组复验：158 条提示里 144 条是这种，收窄后剩 14 条）；
    - 图例行去向写了“不计”也照样提示：“不计”常是照着规则填的。B 组 D026 图例“暗装检测盒”（`A$C17F23191`）的理由就是“平面同名块全部有据排除：EX-TESTBOX”。
  - 规则排掉了平面页上的候选，而同名块（去掉外部参照前缀）在本输入别处已计时，列进 `excluded_class_hits_counted_symbol`：规则号、图纸、图页、块名、排掉的个数、已计的图纸。只提示，不改去向（检查点一后修，D014 句柄 8C5 按钮盒：图层规则排掉，同名块在 D010、D021 已计 17 个；B 组试算 10 组 94 个）。
- 未确认详图页的 `pending_count` 在整类排除之后统计，只数最终仍待识别的（检查点一后修：原先每页把整类排除的图框多算 1 个，D006 七页合计 216，实际 209）。
- `version_conflicts`：按 `object_ids`（候选编号）或 `block_pattern` 命中，去向改为版本冲突，单列，不进合计。它优先于其他去向。
- **A10a 图例样例自动排除**：`auto_exclude_sheet_kinds` 列出的图页类型上的待识别候选，自动改为有据排除。默认 `["图例"]`，依据“图例页上的复制件（A10）”。只收图例、系统图两种：
  - 项目确认系统图上的图符只是示意时显式加“系统图”，依据写“系统图页上的示意，不单独计数（auto_exclude_sheet_kinds）”（登记 20261016-1728，决策会话定默认关）；
  - 写详图、或写别的类型，判输入问题；
  - 数组须是图页类型名；写成别的判输入问题。数组就是全部类型，不写图例就不排图例页。
- **A10b 详图复制件要确认**（登记 20261016-1800）：详图可能是某个对象唯一的表达，详图页上的待识别不自动排除，依据后面加“详图页，可能是复制件，确认后写 detail_copy_sheets”，按图页列进 `unconfirmed_detail_sheets`。
  - 核对过是复制件的详图页，逐页写进 `detail_copy_sheets`：`drawing`、`sheet_id`、`basis` 都必填。其上的待识别改为有据排除，依据“详图页上的复制件（已确认：<basis>）”。
  - 判输入问题：图纸不在 `drawings` 里；图页表里没有这张图页；图页类型不是详图；同一页确认两次。
  - 不做逐实例对应，也不做典型间倍乘。
- 已计的候选落在图例、详图页上照旧，列进 `counted_on_legend_or_detail_sheet`；落在已打开自动排除的系统图页上，列进 `counted_on_system_sheet`。
- 汇总 `auto_excluded_by_sheet_kind` 按图例、系统图、详图（已确认）单列自动排除的个数。
- **漏页检查 `frame_blocks`**（登记 20261016-1859，第五批 G）：图页表是项目按包的范围写的，漏一整张图页时没有别的提示（D003 第 005 张室外接地 552.78 m 一直没计）。写了 `frame_blocks` 就逐个核图框：
  - 每项二选一：`block_pattern`（图框块名正则），或 `class_id`（`excluded_classes` 的规则号，取它的块名、图层正则和图纸，不看它的 `sheet_kind`：漏掉的图框不在任何图页上）。可写 `drawing` 限定图纸。两个都写、都不写、规则号不在 `excluded_classes` 里、正则写错，判输入问题。
  - 图框在图页表里，满足其一即可：图形中心落在某张图页里（和别的候选一样定页）；或图框范围与某张图页框的重合不少于两者中较小一个的一半。后一条是因为项目的图页框有的只框图面区（D003 的图页框 310×320，图框约 840×594，图框中心落在框外）；相邻图框只共一条边，图页框比图框大一圈伸进邻框的那一窄条也不到一半，所以邻框照报。图页框比图框小、图框跨两页、图框在图例页，都不报。
  - 不在图页表里的，列进 `frame_outside_sheet_table`：图纸、编号、句柄、块名、插入点、图形中心、图形范围 `geometry_box`、定页依据。
  - 嵌在另一个图框里的图框（A0 图框里的图签，展开后成了子候选）随外框，不单核，个数记 `nested_frames_skipped`。
  - 定不出图形范围的图框（只有插入点，即图框角点），插入点又不在任何图页里，没法核：列进 `frame_extent_unknown`，记“没核”，不算漏页（D022 的 5 张 A0 图框适配器没给范围，插入点在图页框外，实际对应表里的 5 张平面）。
  - 写了图页表的图纸才逐个核；`drawings` 里有来源、却没有任何图页的图纸，整图列进 `frames_without_sheet_table`（未处置的图框数、示例编号）。
  - **逐条待办**（检查点三）：报出的每个图框（可能漏页、定不出范围、整图没有图页表）各成一行，进台账 JSON 顶层 `frame_todo` 和 `图框待办.csv`：`todo_id`（FR-0001 起）、`drawing`、`kind`、`id`、`handle`、`block_name`、`insert_x`、`insert_y`、`x1`～`y2`（图形范围，没有的留空）、`placement_basis`、`hint`。复核页按句柄映射这张表就能看到。
  - **处置** `frame_dispositions`（可选，须同时写 `frame_blocks`）：每项写 `drawing`，`handle`（顶层图框句柄，大小写不论）或 `id`（候选编号）二选一，`disposition` 取 封面、目录、空白、说明或图例、旧版副本、非本专业底图、已补进图页表、其他之一（中间三个取自宁波众芯电气逐框核图的处置表），`basis` 必填。写了处置的图框不再进提醒和待办，列在 `frame_coverage.disposed`（带处置和依据），结论后接“；N 个已写处置，不再报”。没对上任何报出图框的处置列 `frame_dispositions_unused`（句柄写错，或图框已在图页表里）。格式不对、重复、取值不在表里、没写依据，判输入问题 C-5。
  - 汇总 `frame_coverage`：`frame_count`（核的图框数，不含嵌套的）、`nested_frames_skipped`、`uncovered_frame_count`（不在图页表里的和整图没图页表的合计）、`unchecked_frame_count`（定不出范围的）。`conclusion`：有未覆盖的写“可能漏页：N 个图框不在图页表里”，另有没核的接“；另有 M 个图框定不出范围，没核”；只有没核的写“M 个图框定不出范围，没核；其余图框都在图页表里”；都没有写“图框都在图页表里”。没写 `frame_blocks` 时 `checked` 为假，结论写“没写 frame_blocks，没核图框是否都在图页表里”。只报，不自动补图页，也不改 `coverage_complete`。
  - 图例页上命中 `frame_blocks` 的顶层块（图框、图签）不生成图例行，按图纸计数在 `frame_coverage.legend_frames_skipped`；已填图例覆盖表里这些块的行丢掉，列在 `legend_frame_rows_dropped`（登记 20261016-1945）。

每行是一组：图纸、图页、块名、图层、父块、去向、类别或依据都相同的候选。去向只有五种：

| 去向 | 来自 | 含义 |

| 已计 | 适配器 `adopted`、`merged`；计数表命中；图例行去向“已计”的非块行 | 进了实例计数，写类别 |

`点位覆盖台账.csv` 用英文列键：`drawing, sheet, sheet_title, symbol, symbol_kind, layer, parent_block, destination, count, category_or_basis, suspected_category, sample_ids`（每组最多 3 个示例编号）。

汇总（同一 JSON 里）：

| 字段 | 说明 |

| `by_destination` | 五种去向各多少 |
| `by_drawing` | 每张图纸的来源和各去向个数 |
| `uncovered_drawings` | 既没有来源、也没有图例行的图纸 |
| `legend_rows_without_destination` | 图例覆盖表里去向为空的行，实例数为 0、却没有检索记录的“待确认”行，以及检索记录不能确认零实例的行（第 5 节第 4 条） |
| `search_records` | 是否给了检索记录文件，读到几条记录 |
| `class_completeness` | 每个类别是否完整，不完整的写原因，见下 |
| `coverage_complete` | 待识别、无去向、未覆盖图纸、没去向的图例行都为 0 时才是 true |
| `auto_exclude_sheet_kinds` | 本次实际自动排除的图页类型 |
| `auto_excluded_by_sheet_kind` | 按图例、系统图、详图（已确认）单列自动排除的个数 |
| `unconfirmed_detail_sheets` | 还有待识别、没写进 `detail_copy_sheets` 的详图页及个数（整类排除之后仍待识别的） |
| `expanded_containers` | 每张图纸按容器块名，展开出的块内候选数 |
| `placement_basis_counts` | 按图形范围中心、按插入点定图页的候选各多少 |
| `frame_coverage` | 漏页检查：图框数、嵌套跳过数、不在图页表里的图框数、定不出范围没核的图框数、待办数、已处置的图框、结论，图例页上跳过的图框数和丢掉的图框图例行（3.4 节） |
| `frame_todo` | 报出图框的逐条待办（同 `图框待办.csv`，3.4 节） |

提醒（`warnings`，不改去向）：`frame_outside_sheet_table`、`frames_without_sheet_table`、`frame_extent_unknown`、`frame_dispositions_unused`、`sheet_mismatches`、`counted_on_legend_or_detail_sheet`、`counted_on_system_sheet`、`counted_matches_excluded_class`、`excluded_class_hits_legend_symbol`、`excluded_class_hits_counted_symbol`、`insert_geometry_sheet_mismatch`、`unexpanded_container_blocks`、`expand_blocks_unused`、`plan_count_conflicts`、`matched_symbol_conflicts`、`legend_handle_not_on_legend_sheet`、`search_record_ids_not_checked`（没给 `search_records`，零实例行的检索记录编号只查了非空）。

**怎么判哪一类不完整**：已计的候选有类别；待识别的候选还不知道是什么。所以专业会话可以在图例覆盖表里给待识别的块写疑似类别：

- 写了疑似类别的，只拖累那一类；
- 没写的，拖累同一图纸上的所有类别，台账写“类别未知的待识别 N 个”；
- 非块图例行去向空、写了疑似类别的，拖累那一类。

这样不用逐个识图，未知的东西也不会被默认成“不影响”。

**反向核对**（脚本自查）：来源一的每个处置实例、来源二的每个顶层 INSERT 和每个展开出的块内 INSERT，都在台账里恰好出现一次；计数表和排除表的每一行都能对到一个候选。

## 5. 图例覆盖表（脚本出自动部分，专业会话补全）

CSV，UTF-8（带不带 BOM 都可以），第一行用英文列键：

| 列键 | 含义 | 谁填 |
|---|---|---|
| `drawing` | 图纸 | 自动 / 手填行 |
| `legend_row` | 图例行号；自动行按图页、自上而下、自左而右编 `A001`…，手填行自己编号，同一图纸内不能重复 | 自动 / 手填 |
| `legend_handle` | 图例块的句柄（顶层块）；非块行留空 | 自动 |
| `legend_text` | 图例文字 | 专业会话 |
| `symbol` | 对应块名，或非块图符的描述 | 自动 / 手填 |
| `symbol_kind` | 块 / 非块 | 自动 / 手填 |
| `matched_symbols` | 平面上对应的块名（几个用“；”隔开），或 `@识别记录编号`；名字不同、确是同一类时写（登记 20261016-1800）。同一个块分给几行图例时写 `块名::类别`，只认领该类别的实例（登记 20261016-1945，第 10 条） | 模型 / 脚本默认 |
| `plan_count` | 平面实例数：块行为同一图纸非图例、非详图页、非自动排除图页（含图页未定）上该块（去掉外部参照前缀后同名，加上 `matched_symbols`）的候选数；非块行手填，写了 `matched_symbols` 的由脚本数 | 自动 / 手填 |
| `count_source` | 自动 / 手填 / matched_symbols / 类别一对一默认 | 自动 |
| `variant_flag` | 同块多变体：同一图纸里同一块名出现在两行以上时写“同块多变体（A006、A007）” | 自动 |
| `destination` | 去向：已计、归他专业、不计、待识别，或留空 | 预填 / 专业会话 |
| `target_or_reason` | 计入项（已计）或理由（归他专业写哪个专业，不计写理由） | 预填 / 专业会话 |
| `suspected_category` | 疑似类别（待识别时） | 专业会话 |
| `search_record_id` | 检索记录编号 | 专业会话 |

规则：

1. **自动部分**：
   - 落在 `sheet_kind=图例` 的图页里的每个顶层块，各列一行，自动填 `drawing`、`legend_row`、`legend_handle`、`symbol`、`symbol_kind=块`、`plan_count`、`count_source=自动`、`variant_flag`。
   - 该块的平面候选全部已计、而且只有一个类别时，预填 `destination=已计` 和类别。
2. **合并已填的表**：输入里给了 `legend_coverage` 的，块行按（图纸，图例块句柄）对上，非块行按（图纸，图例行号）对上。专业会话填过的 `legend_text`、`matched_symbols`、`destination`、`target_or_reason`、`suspected_category`、`search_record_id` 保留，脚本不覆盖；输出的 `图例覆盖表_待填.csv` 带上这些值，可以直接接着填。
3. **专业会话补**：
   - 补图例文字、去向、理由、疑似类别、检索记录；
   - 补非块图符行，比如 HATCH 三角，实例数手填，并在 `target_or_reason` 或检索记录里写明怎么数的。
   - 去向只能是已计、归他专业、不计、待识别，或留空；写了别的判输入问题。
4. **实例数为 0 的行必须有检索记录**：没有检索记录的 0 行判“待确认”，不算有去向。
   - `search_record_id` 写记录编号（`NS-…`，几条用“；”隔开）。记录由公共 `search_negative_evidence.py` 出（《否定结论检索》），输入 `search_records` 写检索记录文件路径（一个或数组）。
   - 给了 `search_records` 时逐条核对：编号要在文件里；记录六项齐全、检索状态与命中数一致（与公共成果校验器共用 `record_problems`）；状态是“全覆盖未命中”才算有去向。有命中的记“实例数为 0 不成立”，待确认的记“实例数为 0 未确认”，都进 `legend_rows_without_destination`。
   - 文件不存在、读不了、不是 `qto-negative-search/1.0`、编号重复或缺编号，判输入问题（C-7）。
   - 没给 `search_records` 时只查非空，这些行列进提醒 `search_record_ids_not_checked`。手填的检索记录也走这条路，不算核对过。
5. **同块多变体**（登记 1535）：一个块对应多行图例、图上又没有区分依据时，数量照计；受影响的派生量（如竖向长度）按方案分列，`target_or_reason` 写明还要补什么依据（安装说明、剖面、深化图），不默认取其中一种。
6. **非块图符**这一轮只能手填加检索。自动识别要改中性取证和适配器，不在本轮，对应待处理登记 `20261016-1221` 两条（接地端子板 HATCH）。
7. **再跑脚本**：
   - 非块行按去向计入台账，去向空的计入“无去向”；
   - 块行去向空的计入 `legend_rows_without_destination`。块行不另加候选，它对应的块候选已经在台账里。
   - 块行手填的 `plan_count` 与自动数不一致时，列进 `plan_count_conflicts`，以自动数为准。
8. 块行的 `suspected_category` 作用到同一图纸、同一块名（去掉外部参照前缀）以及 `matched_symbols` 里各块的待识别候选上。不在图例页上的待识别块，也可以手加一行 `symbol_kind=块`、`legend_handle` 留空、`symbol` 写块名，用来写疑似类别；这种行不算图例行，不要求填去向。
9. **外部参照前缀**（登记 20261016-1800）：比块名前先去掉绑定外部参照的前缀 `<名>$<数字>$`，可以多层（`A$0$B$0$C` 当 `C`）。`A$C…` 这类匿名块名、`$equip$…` 不受影响。
10. **异名对应 `matched_symbols`**（登记 20261016-1800）：
    - 模型填块名或 `@识别记录编号`（只对来源一有效，按该记录采用的实例数）。写了本图没有的块名或识别记录编号，判输入问题。
    - 默认来源只用于一对一（决策会话定）：块行去向“已计”、`target_or_reason` 的类别在本图只对应这一行“已计”图例、`matched_symbols` 没写时，脚本把本图已计为该类别的平面块名作默认值，`count_source` 写“类别一对一默认”。一个类别对应几行图例时不给默认。默认取已计候选的类别，两种来源都适用（来源二没有识别配置）。
    - 同一个块被两行以上图例认领、其中至少一行是 `matched_symbols`（含默认）认领的，列进 `matched_symbol_conflicts`，这些行都记“matched_symbols 冲突”进 `legend_rows_without_destination`。同块多变体（两行图例本身是同一个块）不算冲突，按第 5 条处理。
    - 非块行写了 `matched_symbols` 的，实例数由脚本数，不另加非块候选（那些块已经是候选）。
    - 不做按图元组成的指纹匹配：图形相同、块名不同而没填的，不自动归类，照零实例处理。
    - **按类别认领 `块名::类别`**（登记 20261016-1945，第五批 G）：同一个块在图例里是几行（D006 龙骨灯白光、黄光同为 `$equip$00003151`）时，每行写 `块名::类别`，只数该类别的平面实例。分隔符是两个半角冒号，AutoCAD 块名不能含冒号，从第一个 `::` 切开。类别取候选的类别（来源一为计数输入 `reconciled_instances` 的类别，来源二为计数表的类别），所以只认领已计的实例。
      - 这个块名下没有该类别的实例，判输入问题（C-6）；
      - 一行按类别认领自己的图例块时，不再整块认领这个块；
      - 同一块名一行写了类别、另一行没写（自己的图例块不写也算没写），或两行写了同一个类别，都算冲突，列进 `matched_symbol_conflicts`；
      - 只写块名的照旧：两行各是自己的图例块（同块多变体）不算冲突，按第 5 条处理。
