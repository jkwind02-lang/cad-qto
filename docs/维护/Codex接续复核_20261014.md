## Claude 交叉复测结论（2026-10-14）

复测宿主 Claude Opus 5.5（claude-opus-5-5），在 `e11d9b4` 上进行，用例按契约文字与复核页批注时间写法（`toISOString`，带毫秒和 `Z`）独立构造，不复用 Codex 或第一批的辅助函数，放在 `tests/test_claude_cross_review.py`，共 29 项。每个反例都核对具体拒绝原因，不只看条数；每次运行都核对数量不变、不允许正式采用。

| 脚本 | 结论 | 依据 |
|---|---|---|
| `qto_human_review_evidence.py` | 通过 | 合法凭据、批注无 `updated_at` 时取 `reviewed_at`、12.0 与 12、凭据和批注里夹杂无关条目，四种合法情形仍判已复核。15 个反例各按自身原因判未复核。换回 `99bc1ae` 的脚本后 19 项失败，其中真缺陷 13 项：6 项脚本崩溃（`annotations` 为数组、超大整数数量、继承引用为列表/字符串/数字/布尔），7 项被误判为已复核（批注复核时间不符、保存时间不符或为空、同一时刻换写法、确认重复、对象指纹不足 64 位或非十六进制）；另 6 项修补前已拒绝，只是原因文字不同 |
| `recompute_qto_dependencies.py` | 通过 | 继承引用为 `None`、空对象、空列表、非空列表、字符串、数字、布尔，均降为未复核并写原因；合法继承仍为已复核；原批注在继承前被改，降为未复核 |
| `export_dwg_exchange_dxf.ps1` | 通过 | 仍带 BOM，两种 PowerShell 解析均 0 错误。本机复现了根因：从 pwsh 启动的 Python 再调 5.1 时，子进程继承 pwsh 的 `PSModulePath`，误加载 pwsh 7 的 Utility 模块清单，找不到 `Get-FileHash`；显式导入后 5.1 自带模块被加载，可正常计算哈希。以 pwsh 为父进程跑转换测试：修补前 5.1 成功路径失败，修补后 14 项通过 |

补充两点：

- 从 Bash 等非 pwsh 父进程跑回归时，`PSModulePath` 里没有 pwsh 7 路径，旧转换测试抓不到这个回退。新用例改为强制使用 pwsh 的模块路径，修补前失败（`CommandNotFoundException`），修补后通过。
- 新增判定规则已补进 [审批凭据契约](审批凭据契约.md)：复核时间一致，保存时间逐字一致，确认项唯一，以及结构与格式要求。时间逐字比对是有意从严：B 期导出凭据时必须原样复制批注里的时间。

结论：三处修补都可进入正式发布流程。本结论只覆盖合成用例和本机两种 PowerShell，不是真实图纸准确率验收。
