# 规则候选维护接入

实际运行和凭据字段见 [明确方法裁决提取规则候选与维护审核](../../skills/_qto-shared-evidence/references/规则候选与维护审核.md)。

1. 在所属专业已完成当前计算、结果视图和明确用户方法答复后，使用现有 feedback reader 与依赖重算器生成输入交接。
2. 调用运行侧 qto_rule_candidates.py export，输出到明确指定的维护区。无真实用户方法凭据时保留拒收回执，不能由模型补成 human。
3. 维护审核者保存原意见与独立凭据，使用 maintenance/review_rule_candidates.py review 生成不采纳、仅本项目采用、通用候选三个分支的回执。通用分支必须提供另项目、另物理源、同规则版本/对象关系的独立案例；单项目不能升级全局成熟度。
4. 只有提案进入既有 [维护流程](维护流程.md)，按覆盖分支改 reference 和测试，再审成熟度。脚本本身从不改规则，不发布安装，不将项目图层、句柄、标注答案或真人材料写入运行包。
5. 候选中的 producer/consumer 导入闭包字节发生变化，或源/计算/反馈/凭据发生变化时，旧候选无法通过复验，应核查后重导出。无变化时可按冻结指纹复用。
6. 匿名测试夹具只证明机制，不记为实际维护批准、真实独立案例、真人 M2 或正式工程量采用。当前工具接受依赖图对象绑定、T35 电气网络原源 adapter，以及具名的现有点位/电气直接绑定生产 adapter；必须显式绑定当前事项、scope、对象和实际目标，不把网络目标或未绑定旧结果按裸 ID 自动迁成计算节点。
7. 用户保存方法确认前可 inspect 当前 producer 上下文，原方法意见与方法凭据须共同绑定 method_context_fingerprint。预览固定 NOT_HUMAN_APPROVAL；工具没有写人工批准的命令。输入、规则、数量凭据或网络内容变化，即使最后数量相同也须重新核对。
8. T35 回放以官方 clean+JSON 保存后的完整 partition 比较，候选自身以实际 JSON 文档比较；完整 raw 回放另入 method context，保留真实下划线块名证据。执行模块目录只在实际 SHA、固定相对 module 和完整集合已核一致后规范化，支持同字节安装子树到维护仓库交接；业务原源路径、scope、结果和凭据不作此规范化。模块字节改变仍拒收，不将任意字段删成“可比子集”。

9. [现有点位与原图对象生产接入](../../skills/_qto-shared-evidence/references/规则候选现有对象接入.md)补充两个具名格式：点位 adapter 的完整计数输入与实际计数器结果、电气直接绑定的完整对象包与台账/复算结果。先实际回源重放，再显式关联当前对象；未发生真实方法确认时仅可 inspect-production，不填人工凭据。

10. 点位唯一计数出口按已核 authority 版本及完整实例固定生成，不受展示数量名或额外交换源集合影响；电气不同官方 quantity_projection 出口分别保留。同 authority 换 exchange/标签不构成独立物理源案例，业务源 scope 和模块漂移仍按完整上下文拒收。
