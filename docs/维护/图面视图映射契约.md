## 0. 目标与边界

- 项目交一份映射 JSON，加上现有的几张表，插件就生成图面视图（图页、底图、回图对象）。不用每包写视图脚本。
- 生成的视图再用 `build_comparison_view_from_tables.py --base-view`（可写多次）并入汇总复核页，沿用《复核页审核视图契约》（下称“复核页契约”）第 12 节。
- 脚本只做四件事：搬运表格、换算坐标、按句柄回取几何、按图页范围抽底图。
- 不算工程量，不按规格或楼层猜归属，不求跨图配准（配准是 S2 的事），不造坐标。原则同复核页契约 12.3 节。
- 成果对象一个不删。体量照复核页契约第 11 节：不设上限、不分页、不截取。
- 13 个专业通用。电气先用（宁波众芯 12 包，见第 14 节）。
- 插件标准台账（点位实例、路径台账、网络端点交接表）自动生成视图拆为 **V1b** 后做：宁波众芯这 12 包都是项目自定格式，本批用不上。

## 0.1 验收标准：只看页面能判断

用户原话（2026-10-16）：“要注意一点，要还原出原图和算量有关的细节这样才能方面参照图纸进行对比审核”；“其实也就是我们体现出来的图可以在不去看原图的情况下能判断出问题在哪里”。

1. 审核人只看页面、不打开原图，就能判断一个数量对不对、问题出在哪：漏计、重复、识别错、走线和楼层不对、比例不对。
2. 缺口按问题类型逐类核，不只看“原图有、页面没有”。每类问题要在页面上看到的信息：

| 问题类型 | 页面上要看到 | 本契约的做法 |
|---|---|---|
| 漏计 | 图上同类符号全部画出，已计、未计分得清 | 符号块按原图展开（7.2）；已计的叠对象；符号对账列出未计（7.5） |
| 重复 | 同一位置有几个对象、符号是一个还是两个 | 符号对账列出同位置多计（7.5） |
| 识别错 | 符号的真实图形，包括实心填充、填充图案；块名和图块属性；图例 | 符号块全展开，带填充（7.3）；属性在对象详情里；图例图页照常出图 |
| 走线、回路 | 走线、回路号与箱号、箭头、引上引下符号、线型 | 文字按原图字高和对齐（7.3）；线型虚线；插入点在图页外的块按外包框取（7.1） |
| 楼层 | 图名、图号、楼层文字 | 图框、图名块展开 |
| 比例 | 比例文字、建筑尺寸、插图范围 | 建筑底图白名单含尺寸（7.2）；页面有比例尺 |
| 定位 | 墙、柱、轴线和轴号、门窗、楼梯、房间名 | 建筑底图按白名单图层展开（7.2） |

3. 只能回原图核的信息，要么在页面上还原，要么标“本页看不出，须回原图”并计数（7.4）。
4. 每包出图后按问题类型各抽几条，只看页面判断，结果写进项目复验记录。

## 1. 命令与输出

```text
python build_review_scenes_from_tables.py --mapping 图面映射.json --neutral-root <中性事实根> --output <包>_图面视图_r1.json --report 图面转换检查.json [--estimate]
```

- 脚本放 `_qto-shared-evidence/scripts/`。
- 输出 `qto-review-view/1.1`，不带 `comparison`：`sources`、`scenes`、`background_sets`、`objects`，可选 `groups`。写出前过 `normalize_view`。
- `--neutral-root` 下按图纸编号找中性事实目录（如 `D006\`），读 `CAD中性取证清单.json` 和 `中性布局图元.ndjson`。
- `--estimate` 只出检查报告和体量预估，不写视图。
- 输出文件已存在时拒绝覆盖，要用新的版本名（同表格转换）。
- 出错返回 `INPUT_REQUIRED` 和具体位置（表、行号、列），不出半成品。

## 3. 图纸 `drawings`

| 键 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 中性事实目录名，如 `D006` |
| `neutral_dir` | 否 | 相对 `--neutral-root` 的目录，缺省等于 `id` |
| `coordinate_unit` | 否 | 缺省 `mm`；室外总图等米制图写 `m` |
| `precision` | 否 | 底图坐标保留的小数位，缺省 `mm` 为 0、`m` 为 3 |
| `title` | 否 | 缺省取原图文件名 |

- 原图 SHA256 由脚本从 `CAD中性取证清单.json` 的 `authoritative_source` 取，写进视图 `sources`（`id` 即图纸编号），不用项目抄哈希。
- 视图 `sources` 只列被图页用到的图纸。

## 4. 图页表 `sheets`

可以写几张表（各图纸一张，或项目自己的图框表）。

| 键 | 必填 | 说明 |
|---|---|---|
| `sheet_id` | 是 | 项目图页编号，与对象表 `sheet` 列一致 |
| `drawing` | 是 | 图纸编号，多用 `constants` 给 |
| `title` | 否 | 图名；缺省取 `sheet_id` |
| `floor` | 否 | 楼层或区域，显示在图页标题里 |
| `sheet_kind` | 否 | 平面、系统图、表与说明、图例、详图、其他。S3 检索定位共用这一列 |
| `x1, y1, x2, y2` | 否 | 原图坐标的图框范围（两角，顺序不限） |
| `raster_path` | 否 | 原图栅格，用法同现有视图 |
| `length_factor` | 否 | 量距用（第 13 节）：每个坐标单位折合多少米实长，须为正数。图是按比例缩放画的才要给，例如模型空间里放大画的详图、按出图尺寸画的图；不给时，坐标单位为 mm、cm、m 的按 1:1 换算，其余单位（如 px）只量图上长度，不换算 |

- 场景编号写成 `<drawing>|<sheet_id>`，例如 `D006|D01EP-LIL-F01-A1`。几个包引用同一图页时，就是同一张图页（第 10 节合并）。
- 只给被对象引用到的图页出场景，不出空图页。
- 不给范围时，取本图页已定位对象的外包框，四边各外扩 5%（至少 1 米：毫米图 1000、米制图 1 个坐标单位），图页上写 `bounds_basis: "按对象外包框推定"`，报告列出。
- 同一图纸的 `sheet_id` 重复（同一张表或几张表）：内容相同的合并；不同的，被对象用到时报错，没被用到的只在报告 `sheet_conflicts_unused` 里列出，不出场景。
- 宁波众芯项目已有 `_中间\共享事实\D###_图页台账.csv`（图页编号、图名、楼层区域、专业系统、x1～y2、状态等），按上例映射即可，不用另建表。D006 有 86 张图页。台账的“状态”列混写了图页类别（系统图/原理图、说明/图例/材料表、详图）和核对状态（现行、待核），要填 `sheet_kind` 时由项目用 `value_maps` 归并，插件不猜。

## 5. 叠图 `scenes`（可选）

把几张图页叠在一张场景里看，例如 E-A-CBL2 的桥架平面叠同层电力平面。

```json
{"id": "S1F", "drawing": "D006", "title": "一层：桥架平面 + 电力平面动力走线",
 "base": "D01EP-CTP-F01(按目录h=1D52E推定)",
 "overlays": [{"sheet": "D01EP-PDP-F01-A1", "dx": -55725, "dy": -915800, "layers_include": ["^WIRE-动力$", "^DIM-箱柜$"]}]}
```

- 场景范围取 `base` 图页的范围；场景编号写成 `<drawing>|<id>`。
- 叠图本身可以写 `dx, dy`（缺省 0），平移 `base` 图页：几层图页换算到同一坐标系时用，例如 E-A-CBL2 各层都换到一层桥架框坐标（`box_loc_all.csv` 就是这个坐标）。场景范围、`base` 的底图和对象都按它平移。
- `overlays` 的平移量由项目声明，插件不求配准。叠上来的图页，底图和对象都按 `dx, dy` 平移。
- 叠图可以单独写底图图层过滤（覆盖第 7 节的全局设置）。
- 一张图页只能属于一个场景：作了叠图的 `base` 或 `overlay`，就不再单独出场景；同一图页出现在两个叠图里报错。

## 6. 对象表 `objects`

每张表一段映射，`key` 必填且在映射内唯一（用于缺省 `catalog_key` 和报告）。

**标准键**

| 键 | 必填 | 说明 |
|---|---|---|
| `object_id` | 是 | 物理对象编号。同一物理对象在几张图页上出现时编号相同 |
| `catalog_key` | 否 | 可以写模板，如 `电气回路|{包号}|{box}|{circuit}`（花括号里是列名）；缺省 `<key>|<sheet>|<object_id>`。全视图唯一 |
| `sheet` | 定位对象必填 | 图页编号；整表同一张时用 `constants` |
| `drawing` | 否 | `sheet_id` 在各图页表里只出现一次时可省 |
| `kind` | 否 | `point`、`line`、`polygon`、`unlocated`；缺省按几何列推断 |
| `title`、`category`、`status`、`detail`、`source` | `title`、`category`、`status` 必填（可用常量） | 显示用。`source` 缺省写“图纸 图页 句柄 …（表名 第 n 行）” |
| `professional` | 否 | 缺省取表级 `professional`，再缺省取 `view.professional` |
| `unlocated_reason`、`unlocated_note` | 否 | 项目自己声明的未定位原因（如 `estimated`）和说明（第 8 节） |

- `attributes`：`{"页面上的名称": "列名"}`，带进对象属性。
- `quantities`：可选，写法同复核页契约 12.2 节成员表。计数对象的数量一般经挂接表给（第 10 节），不在这里写。
- `filter`：`{"列名": "正则"}`，几条同时满足才取。不满足的行记为跳过（原因 `filter`）。

**几何**（按下面顺序取第一种有值的；也可以用 `geometry.mode` 指定）

1. 坐标列：`x, y` 出点；`x1, y1, x2, y2` 出线段；`points` 列为 JSON 点列表（`[[x,y],…]`）出折线或面域（`kind` 指定）。
2. 句柄：`handle` 列。按 `entity_handle` 在该图纸中性布局里回取几何，只读一遍布局，只建所需句柄的索引：
   - INSERT、TEXT、MTEXT、POINT 取插入点，出点；
   - LINE、LWPOLYLINE、POLYLINE、ARC、SPLINE 取全部几何段，出线；CIRCLE 取圆心，出点；
   - 其余取外包框中心，出点，报告注明；
   - 句柄在块内（`parent_block` 不为空）的标未定位 `handle_in_block`，查不到的标 `handle_not_found`；回取到的中性记录号写进 `source`。
3. 都没有：未定位 `no_geometry`。

**坐标口径**
- `coords: "drawing"`（缺省）：坐标是对象所在图纸的原图坐标。对象所在图页作了叠图时，按该图页的 `dx, dy` 平移。
- `coords: "scene"`：坐标已经是场景坐标，不再平移。例如 E-A-CBL2 的 `box_loc_all.csv` 已换算到一层桥架框坐标。
- `transform: {"scale": s, "dx": a, "dy": b}`：表里的坐标先换成 `x·s + a, y·s + b`，再按上面的口径处理。没写的项按 `scale` 1、`dx`、`dy` 0。用于米制或局部原点的表（如 `wire_cc*.csv` 的 `cx, cy`、`gnd_downcond.csv` 的轴网相对坐标）。插件不猜原点：这类表没有声明 `transform` 时，坐标列不用，只能用句柄，否则标未定位 `no_geometry`。

**合并 `group_by`**
- `group_by: ["列名", …]`：键相同的几行合成一个对象，只用于线。几段首尾相接的连成一条折线，不相接的作为多段 `parts`（第 15 节第 3 条）。不按端点连通自动合并。
- 每行按自己的图页定位和平移（叠图里不同图页的行各用各的 `dx, dy`），再连。同一组的行落在不同场景的报错，不按首行硬放。
- 组里任一行定位不到（图页不明、句柄查不到、句柄在块内、没有几何），整个对象标未定位，原因取行数最多的那种，`unlocated_note` 写明哪几行；找到的那部分不单独画，免得当成整条线。报告 S-4 反查：定位失败的行不能出现在已定位对象里。
- 合并后对象的 `source` 列出全部来源行号；长度只作属性显示，数量仍以明细为准：合并的表不能写 `quantities`（报错），`attributes` 列出各行的值（去重，以“、”分隔）。
- 唯一性以 `catalog_key` 为准：没写 `group_by` 而 `catalog_key` 重复的，报错并列出行号，不静默去重。`object_id` 可以重复（同一实物在不同表、或项目给了不同 `catalog_key`，各成一个对象）。实测：E-A-LGT `x/wire.csv` 11,056 行里有 120 个句柄各占多行，是多段线炸成的线段，按 `["sheet", "handle"]` 合并后为 10,741 个对象。
- 点和面不能合并：两行以上的组里有点或面（坐标给的，或句柄回取到的）报错；同一点位多行是数据问题。只有一行的组不限类型，整表写 `group_by` 时单独的点照常出。

**同一物理对象在几张图页上**（如回路的系统图表行和平面路径）：写成几个对象，`object_id` 相同、`catalog_key` 不同；作参照的那个不带数量。复核页按物理编号去重显示，现有机制已支持。

## 7. 底图 `background`

底图要让审核人不开原图也能对照判断（第 0.1 节），所以按原图还原：符号块展开、带填充和属性、文字按原图字高。中性布局缺这些显示信息（字高、颜色、图层开关、属性位置与可见性、实心填充和填充的几何），所以底图从交换 DXF 取；对象、数量仍按项目表格和中性布局，不变。

| 键 | 缺省 | 说明 |
|---|---|---|
| `source` | `dxf` | `dxf`：按 7.1～7.5 从交换 DXF 还原；`neutral`：只取中性布局顶层图元（旧规则，见 7.6） |
| `layers_include`、`layers_exclude` | 无 | 正则列表，对所有图元生效；对象已画出的图层建议排除 |
| `large_block_points` | 2000 | 展开后估计点数超过它的块算大块（7.2） |
| `large_block_layers` | 见 7.2 | 大块只展开这些图层（正则列表，写了就替换缺省） |
| `symbol_layers` | 无 | 这些图层上的块也进符号对账（7.5） |
| `duplicate_tolerance` | 1 mm | 符号对账判“同位置”的距离，按图纸单位换算 |
| `flatten` | 8 mm | 弧、圆、样条离散的弦高，按图纸单位换算 |
| `text_max_len` | 30 | 只对 `source: neutral` 生效 |

这些键可以写在全局 `background`、`drawings[].background`、叠图的 `background` 里，后者覆盖前者；叠图 `overlays[]` 里只认 `layers_include`、`layers_exclude`。

### 7.1 来源与取法

- 交换 DXF 取自该图纸 `CAD中性取证清单.json` 的 `exchange_dxf`（路径和 SHA256）。文件不在或哈希不符，返回 `INPUT_REQUIRED`，不悄悄退回中性底图。项目要改用中性底图，须在映射写 `source: "neutral"`。
- 每张图纸只读一遍 DXF。实测 D006（165 MB）读入约 35 秒，选取约 105 秒，展开约 60 秒，内存约 1.5～2 GB。
- 取模型空间顶层图元，外包框（块按展开后的外包框）与图页范围相交即取。展开后的图元至少有一个点落在图页内才画。插入点在图页外、内容在图页内的块（图框、导线箭头等）照样取到。
- 原图里关闭、冻结或不打印的图层不画，也不算“须回原图”（`Defpoints` 从不打印，带外部参照前缀的同名图层也一样）。块内 0 层的图元随所在块的图层，颜色随块的照原图处理。

### 7.2 块怎么展开

| 类 | 判定 | 展开 |
|---|---|---|
| 计数对象符号 | 块的句柄等于同一图纸上任一对象表行的 `handle`（不分大小写；别的图纸上同号的句柄不算） | 全展开 |
| 小块 | 展开后估计点数不超过 `large_block_points` | 全展开 |
| 大块 | 其余（建筑底图、绑定的外部参照等） | 只展开 `large_block_layers` 图层上的图元，其余不画，计入 7.4 |

- `large_block_layers` 缺省是天正常用的建筑图层：`WALL`、`COLU`、`柱`、`AXIS`、`DOTE`、`轴`、`WINDOW`、`DOOR`、`门`、`窗`、`STAIR`、`楼梯`、`STEP`、`HANDRAIL`、`SPACE`、`ROOM`、`房间`、`TITLE`、`图框`、`图名`、`图号`、`DIM`、`标注`、`PUB_TEXT`、`PUB_HATCH`（不分大小写，包含即算）。也就是墙、柱、轴线和轴号、门窗、楼梯台阶、房间名、尺寸、图框图名。其他专业的管道、设备、消火栓不画。
- 报告 `dropped_layers` 按图层列出没画的图元数。项目看到漏了建筑图层，就在映射里补 `large_block_layers`。
- 嵌套块逐级展开（深度上限 12），判定按最外层的块。尺寸标注按它的匿名块展开。
- 若嵌套 INSERT 炸开后的矩阵与原始定义逐级相乘的矩阵不一致（含剪切及非等比缩放叠加 90° 旋转），整个顶层块改走原始定义与完整累计矩阵；线、曲线、面、文字和属性均采用该矩阵。曲线先变换控制点，再按图纸单位容差离散。属性使用所在 INSERT 的父层坐标，避免重复插入变换。此类块不使用炸开后的外包框预筛选，仍逐图元检查是否落在图页内。其余块沿用既有展开方式。
- 块里的填充图案：从块定义里的填充求出图案线，再按插入矩阵（含镜像、旋转、非等比缩放）变到图上，方向、间距、相位与原图一致。嵌套块用逐层相乘的完整仿射矩阵（各层块定义里 INSERT 自己的矩阵连乘），不用炸开后的 INSERT 重新拼的比例和旋转：外层非等比缩放套在内层旋转上是剪切，比例加旋转表示不了（Codex 第三轮 V1-R3-H01）。不用 ezdxf 炸开后的填充求图案：它会把图案比例和角度再乘一次，镜像也会被当成旋转（Codex 第二轮 V1-R2-H05）。ezdxf 求图案线时会随机微移图案原点，以免线正好穿过边界角点；生成器固定随机种子，同一张图每次生成的底图相同。

### 7.3 图元

| 原图 | 底图图元 |
|---|---|
| 线、多段线、弧、圆、椭圆、样条 | `{"kind": "line", "points", "color", "dash"?}`；弧和曲线按 `flatten` 离散；非连续线型写 `dash`（图纸单位的划、空长度） |
| 实心填充（SOLID、TRACE、实心 HATCH） | `{"kind": "polygon", "points", "color", "fill"}` |
| 填充图案（非实心 HATCH） | 计数对象符号和小块里的画出图案线（`line`），例如圆形灯具的斜线；大块里的不画，计入 7.4 |
| TEXT、MTEXT（逐行）、可见属性 | `{"kind": "text", "point", "text", "height", "rotation", "align", "baseline", "width_factor"?, "text_axes"?, "color"}`；不截字数 |
| 不可见属性 | 不画；计数对象的属性由对象表 `attributes` 带进对象详情 |
| 点（POINT）、遮罩 | 不画，不计 |
| 图片、OLE、代理对象、找不到的外部参照 | 不画，计入 7.4 |

- `align`：`left`、`center`、`right`；`baseline`：`alphabetic`、`middle`、`top`、`bottom`。
- `height` 通常为图纸单位字高。完整仿射还原的文字保留定义中的字高，并写 `text_axes: [[bx, by], [ux, uy]]`：每一原始字体单位的基线方向和向上方向在图纸 XY 中的向量，已含累计缩放、镜像、旋转、TEXT 宽度与倾斜。页面有该字段时直接变换字形，不再叠加 `rotation`、`width_factor`；缺省时兼容原有渲染。两向量须有限且不平行。此字段不承诺 CAD 字体、MTEXT 行内排版或遮挡完全一致。普通路径（经 ezdxf 炸开的块）里拉伸方向不是 +Z 的 TEXT、MTEXT、属性（镜像块炸开后的文字，挂在镜像顶层 INSERT 上的属性），锚点先由 OCS 换到 WCS，同样写 `text_axes`；+Z 的文字照旧输出（登记 20261016-1129）。
- 颜色取原图：实体颜色、随层、随块；ACI 7 画黑色；过浅的颜色加深，白底上看得清。
- 坐标按图纸 `precision` 取整。

### 7.4 须回原图

- 每个场景写 `restoration`：

```json
{"source": "dxf", "not_shown_total": 12,
 "not_shown": {"other_layers": 9, "pattern_hatch": 3, "image": 0, "ole": 0, "proxy": 0, "xref_missing": 0}}
```

- `other_layers` 是大块里白名单外的图元数；原图本来就关着或不打印的图层不算。有这类图元时另写 `other_layers_top`：去掉外部参照前缀后图元最多的 8 个图层 `[[图层, 数目], …]`，页面提示列前 3 个，审核人据此判断没画的是不是和本专业有关。`source: "neutral"` 时写 `{"source": "neutral", "note": "底图只有模型空间顶层图元，块内内容、字高、填充都没有"}`。
- 页面在图面状态栏显示“本页看不出 n 处，须回原图”，并列出各类数目。
- 报告逐场景列 `restoration` 和 `dropped_layers`。

### 7.5 符号对账

每个场景写 `symbol_reconciliation`，按块名一行：

```json
{"block": "$equip$00001160", "label": "双管荧光灯", "layer": "EQUIP-照明", "on_sheet": 406, "counted": 406,
 "uncounted": 0, "duplicates": 0, "uncounted_points": [], "duplicate_points": []}
```

- 哪些块：本图纸的对象表 `handle` 命中过的块名（不限图页），加上 `symbol_layers` 图层上的块。
- 插入点落在这张图页里的才算这一页，跨页不重复。
- 已计按图纸隔离：只认同一图纸上对象表行的句柄（行的图纸由它的图页定），别的图纸上同号的句柄不算已计（Codex 第二轮 V1-R2-H01）。句柄比较不分大小写（V1-R2-H02）。
- `counted`：句柄在对象表里；`uncounted`：不在；`duplicates`：同块名、插入点相距小于 `duplicate_tolerance` 的第二个及以后。点位写进 `uncounted_points`、`duplicate_points`。
- **隐藏层**：插在关闭、冻结或不打印图层上的符号图上不画，不计入 `on_sheet` 和各类，单列 `hidden`（个数）、`hidden_points`；其中句柄在对象表里的记 `hidden_counted`，即“计数对象落在隐藏层上，图上看不到，须回原图”。没有隐藏层符号的行不写这三个字段。报告的场景 `symbols` 汇总同样加 `hidden`、`hidden_counted`。页面总行写“隐藏层符号 n 个不计入本页，其中 m 个是计数对象……”，面板多一列“隐藏层”，点数字标红圈。
- `label`：这个块最常见的非空属性值（如灯具名），没有就空。
- **块内符号**（登记 20261016-1403，第四批乙最低限度）：上面各行只认 Model 顶层的 INSERT。楼层整层画在一个块里的图，计数符号全在块里，原来整页显示全 0。现在逐个顶层 INSERT 往下找块里的 INSERT（逐级累计插入矩阵求插入点，图层 0 继承上级图层，隐藏图层上的连同其下各级不算），块名是计数块、或所在图层在 `symbol_layers` 上的，按插入点落在哪张图页记进这一页：
  - 计数块指本图纸对象表 `handle` 命中过的块名，块里的句柄命中也算；
  - 顶层本身已是对账符号的，块里的不再算；块里已经算过的符号，再往里的子块也不算（同一个符号不数两次）；
  - 不看 `large_block_layers`：块的图元在页面上画不画，都照数；
  - 场景写 `symbol_in_block`：`{"total": 5, "blocks": [{"block": "TB", "count": 5, "points": [[x, y], …]}]}`，按个数从多到少排，一个场景拼了几张图页时每项加 `sheet`。报告的场景 `symbols` 加 `in_block_not_reconciled`（总数）。没有块内符号时两处都不写，视图字节不变；
  - 页面：符号对账面板写“块内 N 个符号未参与对账（画在楼层块等块里）”，按块名列个数，点数字标红圈。只有块内符号、没有顶层对账行时，工具栏也显示“符号对账”按钮；
  - 这些符号只报个数和位置，不分已计、未计，也不查同位置。完整对账（展开一层参与对账，对象表用覆盖台账的路径编号）随 V1b 做。
- 页面：图面工具栏“符号对账”，列当前图页各行；点“未计”“同位置”在图上标红圈并缩放过去。
- 只对账，不改数量，不进工程量。

#### 7.5.1 对账说明表 `symbol_notes`（可选）

E-A-LGT 首次对账报的 170 处同位置和 8 个未计，全是已有处理的情况（电气查清，问题收集会话复核）。所以由项目给出说明表：能解释的情况单独显示，三类都解释不了的才算“同位置”或“未计”。

映射顶层 `symbol_notes` 是一组表，每张表写一类，`kind` 取下面三种之一：

| `kind` | 含义 | 页面列名 | 必需的键 |
|---|---|---|---|
| `removed_overlap` | 已剔除的重叠：计数前已剔除的句柄，配上保留的句柄 | 已剔除 | `handle`（剔除的）、`kept_handle`（保留的） |
| `counted_elsewhere` | 他图计入：这个符号由别的图页或别的包计入 | 他图计入 | `handle` |
| `same_item_elsewhere` | 同一实物另一图：同一实物在另一张图上已画并计入，这里是重复示意 | 同一实物另一图 | `handle` |

**表怎么写**
- 每张表都要有 `note`（说明）和 `drawing`（图纸）：
  - `note` 可以是列，也可以是常量，常量里可写 `{列名}` 模板；
  - `drawing` 可以是列或常量，映射里只有一张图纸时可以省。
- 写法同对象表，用 `path`、`columns`、`constants`、`filter`（列名 → 正则）、`value_maps`。

**直接读项目共享事实**

项目共享事实里的重叠图元表（`共享事实\D###_重叠图元.csv`，列 `kind, sheet, layer, block, handle_a, handle_b`，剔除 `handle_b`、保留 `handle_a`）可以直接读，例如：

```json
{"kind": "removed_overlap", "path": "../../共享事实/D006_重叠图元.csv", "filter": {"kind": "^块$"},
 "columns": {"handle": "handle_b", "kept_handle": "handle_a"},
 "constants": {"drawing": "D006", "note": "共享事实重叠图元表：与 {handle_a} 重叠，计数前剔除"}}
```

**怎么归类**

每个符号只归一类，按下面的顺序判断：
1. 句柄在 `removed_overlap` 里：归“已剔除”，不参与同位置判断；
2. 句柄在对象表里：已计；
3. 句柄在 `counted_elsewhere` 里：他图计入；
4. 句柄在 `same_item_elsewhere` 里：同一实物另一图；
5. 以上都不是：未计。

同位置只在没有剔除、也没有说明的符号之间判断：带任何一类说明的符号（含已计又带说明的）都不进同位置候选，结果与 DXF 里的先后顺序无关（Codex 第二轮 V1-R2-H03）。句柄比较不分大小写。

**剔除句柄不能同时是计数对象**（登记 20261016-0723）：`removed_overlap` 里的剔除句柄如果也在同一图纸的计数对象表里，按 S-5 报错并列出前几个句柄，不出视图。计数对象表应改用剔重后的表（项目按同一张重叠表剔重导出）。选报错而不是自动去掉这些对象，是因为插件只对账、不改项目的计数对象和数量；对象表多出已剔除的点，说明项目交来的计数表与实际计数口径不一致，应由项目改表。保留句柄不在对象表里时不报错，它照常显示为“未计”。

**输出字段**
- 本页 = 已计 + 未计 + 已剔除 + 他图计入 + 同一实物另一图。
- 映射给了说明表时，每行加：
  - `removed_overlap`、`counted_elsewhere`、`same_item_elsewhere` 三个计数；
  - 对应的 `*_points`；
  - `notes`：按类列出不同的说明，每类最多 5 条。
- 三类都不提供时，输出与原来完全相同，不写这些字段。

**检查**
- S-0 报错的情况：
  - `kind` 不认识；
  - 缺必需的键；
  - `note` 为空；
  - 剔除句柄与保留句柄相同；
  - 同一图纸的同一句柄写进了两类。同一类里重复出现的（例如三份叠在一起），保留第一条说明。
- S-5 报告 `symbol_notes`：每张表读了几行、在本视图图页上用到了几行。没用到的只提醒，不报错，因为说明表一般覆盖整张图纸。

**页面**
- 对账面板加“已剔除”“他图计入”“同一实物另一图”三列，点数字在图上标红圈，说明显示在提示里。
- 总行写：“……；已说明：已剔除 a、他图计入 b、同一实物另一图 c”。

### 7.6 中性底图与共用

- `source: "neutral"`：从中性布局流式抽取模型空间顶层图元，外包框整个落在图页内的；块不展开只计数；填充、尺寸、OLE 缺省不取（`include_types` 可加回）；文字截 `text_max_len` 字。只在没有交换 DXF 时用。
- 底图放进 `background_sets`，键 = SHA256（底图来源哈希 + 图页范围或叠图定义 + 过滤和展开配置）的前 16 位，场景用 `background_refs` 引用。几个包共用同一张图页、配置相同时，汇总页只嵌一次。
- 原图栅格 `raster_path` 照旧可用。

## 8. 未定位

不造坐标。下面几种都出 `kind: "unlocated"`，对象带 `unlocated_reason`（代码）和可选 `unlocated_note`：

| 代码 | 页面显示 | 何时 |
|---|---|---|
| `no_geometry` | 没有坐标 | 没坐标、没句柄，或米制/局部原点的表没声明 `transform` |
| `handle_not_found` | 句柄查不到 | 句柄在中性布局里不存在 |
| `handle_in_block` | 在块内，回不到 | 句柄是块内图元 |
| `sheet_unknown` | 图页不在图页表里 | 对象的 `sheet` 查不到 |
| `outside_sheet` | 落在图页范围外 | 定位点超出图页范围（容差为图框对角线的 2%）；原坐标写进属性“原坐标” |
| `estimated` | 估算，没有图面路径 | 项目在表里声明（如按工艺分区估的回路） |

- 图页已知的未定位对象，`scene_id` 写该图页，在这一页的对象列表里能找到；图页不明的 `scene_id` 为 `null`。
- 报告按表、原因计数。
- 页面：对象详情显示未定位原因；条目详情显示“可回图 n / 未定位 m”（第 13 节）。图面区自动收起沿用复核页契约第 8 节。

## 9. 问题组 `groups`（可选）

- 写法同现有视图的问题组：`id`、`title`、`category`、`status`、`proposal`、`reason`，成员表列 `group_id` 和 `catalog_key`（或 `object_id` 加表 `key`）。
- 电气的待定事项已经在复核页的“待解决问题”里，这里只给需要图面问题组的包用。

## 10. 与对照审核联动

**并入汇总页**
- 各包图面视图用 `build_comparison_view_from_tables.py --base-view`（可写多次）并入。
- 改 `merge_base_views`：场景编号相同时，标题、范围、来源、坐标单位、`background_refs` 都相同的合并为一张；有不同的照旧报错，报错写明哪一项不同。合并的图页列进报告 `merged_scenes`。
- `background_sets` 同键同内容合并，现有逻辑已支持。

**对象挂到明细行**（第 15 节第 2 条：计数对象用挂接表，走线、桥架用连接键）
- 已有：对象 `catalog_key` 与成员台账（`ledger_members.csv`）相同时，复用已有对象，回路下钻即可回图（现有机制，E-A-CBL2 的 882 个回路就是这样）。
- **挂接表**（复核页契约 12.2 节 `member_links`，现有）：一行“对象 → 明细行、数量名、层级、数量”。C3-2 会核“图上对象数量合计 = 明细数量”，这本身就是一道反向检查。例如 E-A-LGT 明细 `E-A-LGT#5`“1F 单管三防灯(T8LED) 22W 21 套”，挂上 21 个灯具对象，每个计 1 套，图上数不对就报。
- **连接键**（新增，只定位）：表格转换的映射里新增可选表 `member_refs`（键：`catalog_key`、`detail_id`），只把对象补进明细行的 `member_keys`，不带数量；这样的明细行汇总方式须为 `declared`。生成器另报“挂了几个对象、哪些明细行一个也没挂上”。不核数量。

**报告**
- 逐包列出：台账成员已定位、未定位各多少；图面对象没有被任何明细引用的有多少（反向）。

## 11. 体量

- 复核页契约第 11 节照旧：不设上限、不分页、不截取，成果对象一个不删；2 MB 只提醒打开性能。

- 图面工具栏“量距”，用来核比例和长度：
  - **怎么量**：依次点击图上各点。点在底图图元或对象端点 10 像素以内的，吸附到该端点；否则取点击处。
  - **怎么换算**：实长 = 图上长度 × 换算系数。
    - 图页有 `length_factor`（第 4 节）就用它，状态栏写“按本图页换算系数，每 1 单位折 f m”；
    - 没有时，坐标单位为 mm、cm、m 的按 1:1，写“按 1:1”；
    - 其余单位（如 px）只报图上长度，写“本图页没有比例，不换算实长，请对照尺寸标注”。
  - **怎么显示**：
    - 量线是虚线，每段旁边标该段长度：能换算的标实长，单位 m、保留 3 位小数；不能换算的标图上长度和坐标单位。
    - 状态栏写段数、图上合计（6 位有效数字和坐标单位），以及实长合计。
  - **结束与清除**：再点“量距”结束并清除；换图页时清掉已取的点；与“新增标记”互斥。量距结果只在页面上显示，不进批注。
  - 契约校验：场景 `length_factor` 须为正数；映射里写了非正数的，生成器按 S-0 报错。
