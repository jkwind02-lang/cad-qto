# 独立审计问题修复与复验

## 版本与结论

修复版本：`0.2.0+codex.20261011.5`。

审计基线：`3ae0b154031317249a3ca5ef363f82d1d3674f02`，即 `.4`。本轮对该提交建立独立副本，修复审计中按根因归并的12项问题，其中11项为几何、覆盖、状态或接口问题，1项为依赖缺失。新增134项回归，原96个定向检查点在修复版本中全部达到预期。检查点包含错误输入拒绝与明确未决处理，不能据此声称真实工程准确率为100%。

原专业成熟度与正式采用边界不变。修复代码尚不能替代真实图纸完整系统验收；本轮没有更新维护者电脑上的已安装插件，也没有执行真实AutoCAD/Core Console或完整陌生工程识图。

## 合并前交叉复核补修

对PR初始提交`66b95fb`交叉复核时，又发现并修正了同两类根因有关的边界：

- 极小跨零ARC，例如半径3、起角`-1e-14°`、终角`0°`，应为约`5.236e-16`的开放短弧，不能因为分别取模发生舍入而得到`6π`整圆。现在先保留原始局部角差，远距离角度使用有符号余数及补偿求和；近整圆即使数值扫角舍入为一周，仍根据来源方向保留开放状态。
- 同一个SHA-256仅大小写不同，或来源/对象/实例路径带前后空白，不能被当作不同实物。推算入口、两个下游检查器与附属量合并入口使用统一规范化身份；普通非hash标识的大小写语义、不同图纸及不同真实插入实例仍保留。

此次追加几何8项、身份防重17项，共25项回归，已包含在本轮新增134项及下方完整回归中。原96个独立算例在补修后的代码上再次重跑，预期值未改变。几何审计的独立数值参照使用含SciPy的审计环境；仓库完整回归仍只依赖`tests/requirements.txt`的新建环境。

## 数量层级与后续检查

新增共享模块[`qto_pipe_quantity_contract.py`](../skills/_qto-shared-evidence/scripts/qto_pipe_quantity_contract.py)。保留`dn_quantity_level`作为DN属性的确定性，新增阀门明细`quantity_level`表示可按该类型、规格汇总的数量层级。缺省范围/类型字段沿用现有契约，不凭空增加项目规则；显式未决不会被默认为确认。

管网汇总和逐实例附属量合并都使用共同契约。合并结果中的`status=determined`仍表示规格有可计算值，新增`status_meaning`说明其含义；它不代表人工确认，也不会提升`quantity_level`或`formal_adoption_allowed`。

[`validate_pipe_result.py`](../skills/qto-pipe-networks/scripts/validate_pipe_result.py)与[`validate_pipe_user_summary.py`](../skills/qto-pipe-networks/scripts/validate_pipe_user_summary.py)现在从逐实例证据重新核对：

- 唯一阀门ID和稳定源实例身份；
- 实例、DN、范围和类型所共同允许的数量层级；
- 系统、类型、块族、DN、数量层级五个维度的分组数量；
- 重复分组、缺组、件数及metrics.valve_count。

历史Q12的矛盾结果，即使没有新的明细quantity_level字段，也会被两个检查器拒绝；自洽的旧格式结果仍可通过。用户汇总检查器继续检查文档必须暴露的业务维度，新增的是推算证据内部一致性核对；它仍不等于逐单元格验证任意Markdown或Excel汇总表，也不代表完整正式采用流程已通过。

## 几何缓存与面域覆盖兼容

几何证据版本升为 **`qto-cad-geometry/1.2`**。旧1.1缓存可能带有错误扫角和拟合长度，并缺失必要的顶点角色；无法可靠地从旧数量倒推出正确几何。

更新后应从权威来源图纸及其交换DXF重新提取中性证据，再重建依赖这些内容、哈希和指纹的管网、构件及复核结果。不能只改schema字符串。管网、构件清单入口和后续几何消费链均保留旧缓存拒绝检查。旧批注保留为历史，重新绑定当前结果前不能直接采用。

专用面域输出新增`partial_selected_regions`及`coverage`。有效图层筛选失败、未展开代理、缺失块或外参不能解释成正常零范围。已有外参缓存但来源未核验时，区域状态为`candidate_external_reference_unverified`，并保留外参实例路径。已见HATCH数量不包含未加载外参中的未知对象，不能把它作为完整范围分母。

一般弯曲、回折或闭合的样条拟合仍明确PARTIAL。此修复未增加曲线HATCH的正式面积支持，也未扩大真实工程成熟度。

## 仍需真实工程验收的内容

本轮修复的是已经复现的程序缺陷和覆盖记录。陌生施工图的对象识别、系统与规格归属、图示省略、跨图关系、计量口径及完整应计范围，仍需要独立人工参照的完整系统验收。应同时记录漏项、误纳、重复量、分规格误差、确认量覆盖和复核工时；不能以回归数量、单条路径数值精度或多模型结果相同代替工程准确率。
