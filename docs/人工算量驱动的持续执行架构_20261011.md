# 人工算量驱动的持续执行架构

日期：2026-10-11。版本：`0.2.0+codex.20261011.6`。改进基线：主分支 `c23fc4408ee51a4279f498c97f0bb2e6ad1d2550`。

## 结论与改进目标

本轮把人工算量流程接入真实可执行的项目工作机制：读图提出问题、形成工程对象、建立应计量项、调用现有专业计算器、核对未读范围与缺量、绑定图面复核，以及收到意见后的有范围重算。现有 13 个专业入口及专业计算规则继续使用，增加一个可恢复、可并行分支、可追溯的文件执行层。

原仓库已经有人工算量顺序、模型识图职责、确定性几何计算、成果分层及 HTML 反馈的基础。主要不足是这些环节间缺少统一的实际完成检查点，任务、文件依赖、数量出口和意见重算容易由模型临时串接。补充原则文本并不足以解决长任务中漏读、重复计算、结果过期和意见未真正落到重算的问题；本轮改进重点因此落在可运行代码和完整链路。

## 一、从人工工作顺序决定架构

| 人工算量动作 | 常见失误 | 本轮实现 |
|---|---|---|
| 先确定楼层、系统、图种和规则 | 从一个文件名推定全专业范围 | 有来源的 `scopes`、已确认专业工作包、必要读图及检查任务 |
| 通读说明、图例，再围绕问题找相关图 | 全图数据灌入上下文；没有读到被当成没有 | 带工程问题的局部读取、摘要/详情/游标、真实未处理观察记录 |
| 沿系统或构件建立底稿 | 同一实物多视图重复计；墙体与两侧面层混成一个数量 | 实物身份、图面观察和应计量项分别登记 |
| 按几何及规则逐项计算 | 临时抄总数；JSON 行号变化后错绑另一个对象 | 22 个登记工具直接执行，原生文件/指针/单位/层级及行身份核对 |
| 分区推进、接续工作 | 压缩后从头重算；旧结果错当当前结果 | 文件指纹、真实完成回执、恢复、失效传播、独立分支合并 |
| 换一条顺序回图核对 | 只检查已算成功的项，漏项没有分母 | 实际索引观察账、应计量项与有效出口对账、必要图种任务未完成保持待办 |
| 整理底稿，接受复核意见 | 页面数字与计算脱节；批量意见扩散到例外 | 同一结果索引生成 Markdown 和绑定既有复核页；选中量项实际重算并保留例外 |

### 模型、程序、用户如何分工

模型承担工程理解：判断图中表达的系统/构件，核对说明与平剖详图，选择有项目来源的规则，说明同族适用范围和例外，准备原生工具输入。模型不因缺少一个全自动识别器就把识图工作转给用户。

程序承担可重复计算：源文件身份检查、图元/空间查询、长度面积体积及规则公式、实际任务依赖、数量出口核对、版本及复核意见对应。程序不会把已完成文件直接视为工程语义正确。

用户参与项目层面的事实与采用：无法通过当前资料查明的缺失图纸、设计冲突、计量选择、专业复核和正式采用。下一步队列先要求模型保存实际取证尝试；没有读图不能直接升级成“请用户识别全部对象”。

## 二、实施后的组成

| 运行模块 | 职责 |
|---|---|
| `skills/qto-coordinator/scripts/qto_workflow.py` | 建任务、下一步、实际执行、恢复、修改包、分支合并、成果/复核入口 |
| `qto_workflow_state.py` | 任务 DAG、真实文件指纹、回执及执行附属证据、局部失效和并行状态对账 |
| `qto_workflow_dependencies.py` | 按 22 个工具的实际输入契约发现间接读取文件，检查真实依赖登记 |
| `qto_workflow_tools.py` | 固定工具及参数登记、现有 CLI 适配、执行隔离目录、输出发布与证据保留 |
| `read_cad_scope.py` | 有问题、有范围、有响应预算的 CAD 读取及完整文件证据 |
| `qto_workflow_quantities.py` | 实物/观察/应计量项/原生数量绑定、唯一出口、单位和层级分开对账 |
| `qto_workflow_review.py` | 从当前结果索引绑定复核图，验证当前反馈，生成意见解释和原生重算任务 |

共享模块位于 `skills/_qto-shared-evidence/scripts/`。没有新建第 15 个 Skill，也没有将协调器变成所有简单单专业计算的必经入口。

### 文件依赖成为执行事实

源图、合同或项目规则、模型读图记录、共享事实、原生输入和结果都使用真实文件。计算器清单内部实际读取的其他文件同样必须登记：例如混凝土实体流与元数据、钢筋来源、表面/土方清单来源、CAD 原图和转换旁证、识别台账证据、复核栅格底图。

未登记或未列入相应 `input_ids` 的实际依赖阻断对应任务，给出具体路径及修复动作。错误只传播到其后继；独立工作包继续。待上游生成的文件可以先登记，不要求模型在尚未识图前填出最终数据。

任务指纹覆盖输入内容、范围、工作包、任务约定、上游结果和工具代码。程序只在实际成功生成产物、并再次检查条件未变化后记录完成。原生证据中引用的运行目录文件随回执保留身份，删除或篡改证据会使相关完成记录失效。

### 实物与量项为什么分开

人工底稿中，一面墙对应一份实物判断，却可能有砌体净体积、不同面层、两侧防水、踢脚等多个量项。一个阀门在平面、系统及详图中也可能有多份观察。把图元、实物和工程量当成同一种“对象”，会产生两类错误：多视图重复计量，以及一物多量的专业结果互相覆盖。

本轮把三者显式区分，结果再保留范围、口径、方案、量的角色、层、侧别及唯一主责出口。改变单位不能绕过去重；分单位汇总不混加几何量、项目规则量和采购参考。

原生结果绑定要求真实身份。嵌套数组核对每一层 ID；无 ID 组行核对完整必要语义字段。例如点位分组的类别、系统、规格、单位及层级，道路层的名称及厚度；只有当前位置数字相等不构成正确对象对应。

### 任务完成与范围完整分开

报告分别显示程序是否运行、哪些观察已处置、哪些应计量项有结果、哪些必要系统/剖详图任务仍未完成。已经算出的有效局部数量可以展示，缺口不填零。

索引只代表实际提取的范围。一个已声明范围对账闭合，不足以证明缺失图纸、未加载外参或尚未发现构造已经覆盖。因此保留 `engineering_completeness_proven=false`；划分了同一观察的不同范围，也保留“未由几何证明互不重叠”的边界。

## 三、执行规则如何提高效率

### 先做通代表范围，再展开同族和例外

13 个专业均增加持续执行说明，并有一份[各专业执行路径](../skills/_qto-shared-evidence/references/各专业持续算量执行路径.md)。它们说明应先看哪些来源、模型实际准备哪些输入、运行哪个既有计算器、向相邻专业交接什么、回图查什么，以及目前工具不能独立完成什么。

管网以实际入口、分支、设备接口、变径和终端串联；设备点位先形成真实实例，再交付端口；电气区分共享通道和实际回路；面层区分房间、构造层和侧别；混凝土/钢筋/钢结构保留各自专业几何、扣减、配筋或端部依据。本执行层不把项目特例写成通用识别规则。

### 只把当前问题需要的内容送给模型

局部读取默认每页 60 个对象、24,000 个 UTF-8 字节，元数据及证据引用也计入预算。完整内容留在文件，可继续按游标或对象读详情。未定位对象及未选择范围保留，不能通过响应裁剪造成“全部读取”的假象。

当前版本仍验证并加载完整 JSON 索引，预算主要改善模型上下文使用，尚未提供超大索引的磁盘流式/分片内存优化。源图或查询变化后旧游标失效，不拼接不同版本的页面。

### 恢复有效工作，并行处理独立工作

同一任务可以从真实检查点恢复；新任务、独立复测保持不同身份。修改共享事实或规则，受影响链失效；未变的独立包保留完成记录。公共运行资源变动的工具指纹目前采用保守策略，可能使多个工具一起需要复验；模型工作还核对所属专业 Skill 和规则版本，避免工具升级后继续用旧解释冒充已复核输入。

独立分支使用不同状态文件和不重叠的输出。执行期间共享读取台账，实际输出独立加锁；台账修改等待正在运行分支结束。同一任务两份分叉完成记录拒绝自动合并，避免把最后一次写入当成正确结论。

## 四、复核意见必须落到计算

复核页面从实际结果索引绑定数字及依赖指纹。页面对象和量项实物身份不同会报错；相同数字背后的规则或来源发生变化，也必须重新对应旧意见。

收到当前版本意见后，程序生成修改包，将意见送入所属专业的真实流程：解释意见、准备新版原生输入、克隆并运行受影响计算任务、回图核对差异、形成回执。意见文本本身不会直接变成尺寸、数量或确认状态。

批量组内排除成员保留原有效结果。即使专业计算器一次返回全组，只有本次明确选中的量项转向新结果。多个同包意见合并进入解释动作；同一交接文件重复导入不会重复建任务；同包多计算器共享旧输入时，新准备产物仍有独立身份和唯一生产者。

如意见会改变未选对象或共享工程条件，模型须明确补充受影响范围和依据，不能让一次“局部修改”悄悄改变其他量项。单对象意见保留实际图面目录键；同一实物的体积、面积或跨专业视图不会因只剩物理编号而一起被选中。原始只读专业清单通过独立的新版可编辑输入复算，原件仍保留。

## 五、发现并修复的实际公式问题

土方 `rectangular_frustum`、`orthogonal_offset_frustum` 曾使用 `H/3 × (A底 + A顶 + √(A底A顶))`，但输入契约并未要求上下矩形相似。对长宽分别线性变化、上下方向一致的矩形截面，该公式在不相似情形有偏差。

人工独立推导例：底部 2 m × 1 m，四边各外扩 1 m，高 1 m，顶部 4 m × 3 m；中截面为 3 m × 2 m。精确体积为：

\[
V = \frac{H}{6}(A_\mathrm{底}+4A_\mathrm{中}+A_\mathrm{顶})
  = \frac{1}{6}(2+4\times6+12)
  = 6.333333333333333\;\mathrm{m^3}.
\]

旧值为 6.299659828522119 m³，少约 0.5317%。本轮替换为适用前提明确的中截面精确式，并修正 `pit_union` 中受同一问题影响的单坑体积上限。并集本身仍采用原有切片近似，不宣称切片结果成为精确积分。

验证覆盖相似与等截面、长宽交叉变化、非对称外扩、尺寸/高度缩放、有限输入中间溢出、单/双坑、米制口径、源文件绑定、土体状态、扣减和基准。没有改变其他土方方法的业务定义。

## 六、验证与验收口径

新测试调用实际模块及原生 CLI，模型解释步骤使用明确标注的测试工作输入。下列值由独立几何/算术推导给出，不是从待验证结果反抄：

| 完整路径或反例 | 预期与观察 |
|---|---|
| 实际 DXF 的 2 m + 1 m 支路，局部读取 → 工作解释 → 原生准备 → 管网计算 | 得到 3 m；另包墙体 `(5×3−2)×0.2` 得到 2.6 m³ |
| 上述源图改为 5 m + 1 m | 支路重算为 6 m；墙体原完成记录保持有效；管网回图检查失效待重做 |
| 增加尚未读完的必要系统图任务 | 已算平面量仍展示，整体声明范围保持待办 |
| 20 墙段，各原量 2.6 m³，组意见选 18 个、排除 2 个；选中洞口改为 3 m² | 实际新版原生计算得 `18×2.4+2×2.6=48.4 m³`，例外保持原值；重复导入不建新任务 |
| 两个独立状态分支强制同时进入实际计算 | 不同输出均生成；合并保留两条完成记录 |
| 正在执行时修改台账、或执行后发布前外部改变台账 | 修改操作拒绝；发生外部变化时不发布新结果或覆盖当前状态 |
| 间接源文件漏登记/未列输入 | 受影响程序和后继阻断，独立砌体作业仍可实际完成 |
| 嵌套结果父层重排、重复 ID、无 ID 组行重排、改变复核对象绑定 | 不将旧位置上的另一对象数量纳入有效结果；要求重新建立实际对应 |
| 上述不相似矩形土方 | 精确 6.333333333333333 m³；原单坑并集上限误报消除 |

最终本地完整验证为 **1,553 项 Python 通过、9 项 Windows 限定跳过，新增 287 项回归**；另有 20 项 HTML 契约、26 项交互模拟、23 项服务及 7 项 Workers/D1/R2 运行时检查全部通过，Wrangler 构建检查通过。运行清单为 **263 项**。

各新增回归位于 `tests/test_workflow_*.py`、`tests/test_read_cad_scope.py` 和 `tests/test_earthwork_prismoid.py`。全套 Python、既有 HTML 契约/交互、服务测试和 Windows/Linux Actions 的最终结果记录在[仓库发布核对](../仓库发布核对.json)及本改进 PR 的 CI 中。

这些测试验证的是执行、数值、身份、版本、选择范围和恢复行为，不能换算为真实项目识图准确率。当前环境没有 AutoCAD/原生 DWG 转换验收，也没有新增真实完整工程的盲算量基准；没有据此提升各专业能力档位。

## 七、下一阶段怎样评价更好

后续真实项目验证应沿同一流程保存可重放记录，重点评价：按预先锁定范围的构造发现率、应计量项漏项、重复数量、已匹配量项数值误差、取证成本、人工介入原因，以及修改后受影响范围。底稿在独立结果冻结后对照，不能用底稿修补独立输入再声称识别准确。

工程发现率与数值准确性应分别统计。模型可能对已识别对象算得很准，但遗漏系统图上的对象；程序也可能算式正确而选择了错误工程对象。只有这两类问题与范围分母都单独呈现，才知道下一步应改善识图、项目规则、几何计算还是作业组织。

本轮已交付的是可执行机制及其验证，并修复发现的真实公式错误。使用命令、数据契约和持续执行要求见[项目作业台账与持续执行](../skills/_qto-shared-evidence/references/项目作业台账与持续执行.md)。仓库更新不等于维护者电脑上的插件已安装升级；本轮本机安装状态另行披露。
