# 证据定位实测修复（2026-10-12）

## 工程影响

此前面层成果即使通过原生计算和绑定复算，其做法、单位或源边证据的定位仍可能指错文件或对象。文件SHA正确，只证明文件字节一致；不能证明引用的位置存在，更不能证明该位置支撑了当前构件。

本轮使用已确认的真实图纸条件式矩形案例，对引用做单变量故障注入。原图、已确认区域、尺寸和主坐标框架均不修改。这是实图案例的可靠性回归，不是新的独立全范围算量，不据此宣称识图准确率或完整净顶棚验收。

## 改动范围

新增共享JSON定位核验函数，接入现有面层原生validator。对明确的JSON Pointer或片段，读取其登记来源并核对SHA及实际字段；框架/源边实际取用的位置必须在该证据定位本身或其下级范围内，不能静默改用另一对象。

保留现有CAD/PDF文字定位，但在检查报告中明确列为未作机器定位核验。PDF的`#page=1`等文字定位不会被误当JSON。未新增工程判断规则，未修改面积计算器、输入schema、几何方向或计量规则。

新增35项通用回归测试，涵盖原生calculator/validator贯通、三类故障、父级定位、JSON转义与片段、非法数组下标、过期SHA以及文字定位兼容。测试图形为自建接口样例，不含项目图纸或项目答案。真实资料与实际运行记录保留在任务工作区，未上传仓库。

## 仍需改进而未声称解决

- 同一做法表中选错相邻行：存在的定位不等于正确房间对应关系。
- 归一化边与真实CAD实例的独立几何比对：JSON框架一致不等于源图实体一致。
- 柱、洞口、完整周边及观察范围：仍须源图证据和专业判断，不能以局部线或“未发现”替代完整性证明。
- 本次只增强面层CLI成果验证，不宣称其他专业已有相同新增检查；自由文本定位也未自动变成已验证定位。

继续保留`business_correctness_proven=false`，条件式参考量不提升为正式采用量。测试数不是工程准确率。
