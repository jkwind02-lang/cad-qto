# 算量插件通用能力修复与验证

本轮目标是改善 `cad-qto` 的可迁移能力。项目图纸与人工底稿用于发现问题和回归；项目名称、图元句柄、容差取值、楼层对应及固定答案不进入通用计算规则。

## 已确认并修复的问题

| 原问题 | 运行代码的改动 | 验证证据 |
|---|---|---|
| 引线绑定默认端点容差0.1、框边上限30及文字高度5%，默认图层0，隐含原图尺度和表达 | 默认几何接触；容差由当前图纸输入并记录依据，使用父块坐标；不预设图层 | 三种尺度、旋转、平移、镜像和不同图层；近邻断开反例 |
| 只支持水平矩形框、TEXT、直线引线 | 任意朝向/平面的直线矩形框；TEXT/MTEXT；单条LINE或开口直线段LWPOLYLINE引线 | 旧版漏配、新版正确绑定的同输入前后证据 |
| 引线终点落在框内部就被当作碰到框边 | 改为量到边界的距离 | 框内部反例由旧版bound改为unmatched |
| 历史混凝土计算器内嵌消防泵房名称、公式、源句柄、固定面状态和固定结果校验 | 案例断言与旧适配器移到仓库测试历史；运行接口2.0从当前对象、源尺寸、轮廓和逐面条件生成结果 | 同一替代几何下，旧版仍打印原项目公式和句柄，新版使用输入事实；三组尺寸、三种面状态及源链反例 |
| 大坐标鞋带公式发生相消 | 先移到局部原点再求面积 | 同一28000000平方毫米矩形平移到大坐标后，旧版为0，新版保持面积 |

## 跨项目适用的验证方式

- 新增55项迁移/反例测试；总计425项Python回归。最终记录以本目录`全量回归结果.xml`为准。
- 钢结构用三组不同截面尺寸、长度及数量重新推导重量；装饰墙面用三组不同长高和重叠洞口计算并集扣减。没有把原项目的数值加入算法。
- 管网同一关系在坐标尺度0.001、1、1000及多种旋转、平移和父块镜像/不等缩放下验证物理身份不变；默认不以近邻补配。
- 同输入前后证据见`同输入修复前后证据.json`与`混凝土项目串入修复前后.json`。这些是程序机制验证，不新增真实项目独立识图覆盖。
- 既有真实来源引线回放：严格接触模式28个bound、12个unmatched；显式提供该图纸原有取证容差后38个bound、2个unmatched，与原封存对应一致。容差只在本轮回放脚本中，源图及封存结果哈希未变。DXF读取仍提示非目标句柄重复，不能把选定对象回放成功说成整图转换已无问题。
- 合成来源从输入清单到成果文件、公共JSON Schema、专业源链复算三个命令行步骤通过；源文件、证据和结果同时篡改数值的反例由重读源清单拦截。

## 能力边界及纠正

框式绑定是有限表达的辅助工具，不能承担整图设备识别；非矩形框、弧形/多实体分叉引线、未展开阵列等仍需模型继续取证。容差依据由模型对当前图纸形成，不要求用户逐对象代为判断。

混凝土源实体计算接口限于毫米制单角缺口筏板及等距垫层。新增的是在此明确几何类型内按任意合法输入计算、逐面条件处理和源链复算，不能宣称已经覆盖所有混凝土构件。输出名义毛体积与有证据的普通模板面；不自动推导局部净量及合同清单量。旧1.0输入必须迁移对象身份与逐面条件，错误沿用会收到明确提示。

之前项目脚本完成的上下层设备、逐台接管、共享干段分配和跨层标高对应，仍属案例中的模型识图及计算验证。通用插件已拥有的路径测量、规格分段、拓扑计算与约束能力继续保留，但不能把项目脚本本身算成已交付的自动匹配器。

运行清单235文件中，Python代码未再检出本轮检查的项目名称、特定句柄和固定答案字符串；测试数据与案例成熟度履历保留在其适用位置。这项扫描及本轮测试均不等于全插件所有算法、全部图纸和全部专业已经无缺陷。
